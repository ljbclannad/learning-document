## 🎯 快速开始

### 核心概念

**什么是ReAct Agent？**

ReAct = Reasoning (推理) + Acting (行动)

```
传统方案：
  固定流程 → 查询所有数据 → LLM分析 → 返回结果

ReAct Agent：
  Decision（下一步决策） → Action（工具调用） → Observation（执行结果）
  → 更新任务状态 → 再决策 → 调用与观察
  → ... 达到成功条件，或因预算、审批、异常而停止
```

**关键区别：**固定工作流由预定义步骤控制路径，Agent 可在授权和预算内根据观察结果选择下一步；二者都可使用 Function Calling，也都可以记录执行轨迹。固定流程并不天然缺少透明度或扩展性。

### 工作流程示例

以下是候选路径示意，`Thought` 仅作行动说明；患者自述只作为待核实线索，不能直接转为诊断或处方依据。

```
医生："分析患者张三"
    ↓
Agent Thought: "我需要先了解基本信息"
Agent Action: get_patient_profile(张三)
Observation: 35岁女性，BMI 22.5，有高血压
    ↓
Agent Thought: "有高血压，需要查用药情况"
Agent Action: get_prescription_history(张三)
Observation: 正在服用降压药
    ↓
Agent Thought: "体重目标是减重，查看进展"
Agent Action: get_weight_history(张三, 30天)
Observation: 下降3kg，但最近反弹1kg
    ↓
Agent Thought: "反弹可能有原因，查聊天记录"
Agent Action: get_chat_history(张三)
Observation: 患者说"有点焦虑"
    ↓
Agent Thought: "患者自述焦虑，整理资料供医生核对"
Agent Action: draft_prescription(待医生核对的资料草稿)
⚠️ 高风险操作 → 需要医生确认
    ↓
医生批准 → Agent继续
    ↓
Agent Thought: "现在可以生成完整分析了"
Final Answer: [完整的患者分析报告]
```

**注意：Agent自己决定了查询顺序和内容，不是固定流程！**

## 🚀 核心功能

### 功能一：智能患者分析

**传统方案：**
- 固定查询5个数据源
- 一次性分析
- 可记录查询及生成结果

**Agent方案：**
- 按需查询（根据发现决定）
- 多步推理（6-8步）
- 工具轨迹与简短行动说明可见

### 功能二：自主风险识别

**拟支持能力（需业务验收）：**
- 自动发现异常（体重波动、负面情绪）
- 主动查询相关数据
- 按业务规则形成风险标记候选
- 经授权与幂等校验后创建随访任务

### 功能三：智能处方建议

**拟支持能力（需业务验收）：**
- 分析患者情况
- 搜索相似病例（Milvus向量检索）
- 起草处方建议
- 提交医生审核（高风险操作）

### 功能四：智能回复草稿

**拟支持能力（需业务验收）：**
- 理解患者问题
- 查询相关历史
- 生成个性化回复
- 医生可编辑后发送

## 💰 成本估算

### Claude API成本（按月计算）

下列单价和输入输出占比是原方案的算术假设，不是当前官方报价或账单。缓存、路由和压缩的收益可能重叠，不能简单相加。

**假设：**
- 日活医生：100人
- 每医生每日分析：10次
- 平均每次：6步
- 每步消耗：1500 tokens

**计算：**
```
月总请求数 = 100 * 10 * 30 = 30,000次
月总步数 = 30,000 * 6 = 180,000步
月总tokens = 180,000 * 1500 = 270,000,000 tokens

Input成本 = 180,000,000 * $0.015 / 1000 = $2,700
Output成本 = 90,000,000 * $0.075 / 1000 = $6,750

月总成本 = $9,450
```

### 待验证的优化情景

通过以下优化策略：
1. 缓存常见分析结果（节省30%）
2. 使用Sonnet处理简单任务（节省20%）
3. Prompt优化减少Token消耗（节省15%）

**情景预算：约 $5,500/月，缺少验证依据，不作为承诺。**

**对比传统方案：**
- 传统方案：$3,600/月
- Agent方案：$5,500/月
- **情景总成本约为基线的 1.53 倍（增加约 53%），不是实测。**

## ⚠️ 常见问题

### Q1: ReAct Agent 与 Function Calling 有什么关系？

Function Calling 负责表达工具名称和参数；ReAct 描述决策、行动与观察的循环。两者可以结合。代码篇保留文本协议教学示例，后续可评估结构化工具调用，减少字符串解析歧义，但它不会自动解决业务授权、幂等和恢复。

### Q2: Agent会不会陷入死循环？

**A:** 初始循环示例设置了 15 步上限；以下其他保护是待实现与验证的要求：
- 最大步数限制（15步）
- 待补：检测重复行动
- 待补：总任务预算、超时收口及迟到结果处理
- 待补：人工干预

### Q3: 成本会不会太高？

**A:** 目前没有可证明成本倍率的实测结果，可评估：
- 缓存常见分析结果
- 使用Sonnet处理简单任务
- Prompt优化减少Token消耗
- 设置每日Token上限

### Q4: 安全设计如何验收？

**A:** 以下为设计要求，需逐项以权限、审批、故障与恢复用例验证：
- 高风险操作必须人工确认
- 待落实的结构化审计日志
- 工具调用、结果及审批记录可追溯
- 待实现并验证：人工干预和终止
- 需结合实际数据流、部署环境及责任边界单独评审，本文不作合规认证
