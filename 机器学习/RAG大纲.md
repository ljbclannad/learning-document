# 总目标产物（面试最有杀伤力的东西）
	1.	医疗健康 QA 服务（API + 简单管理台/脚本）
	2.	知识库治理：版本（政策生效/废止）、地区（省/市）、来源（卫健委/医保局）、文档类型（通知/指南/FAQ）
	3.	RAG Pipeline 可配置：切分策略、混合召回、重排、压缩、引用溯源
	4.	评测闭环：一套小型评测集 + 指标 + 回归测试
	5.	工程化：限流/超时/重试/降级/缓存/队列、可观测（trace/metrics/log）、成本与延迟面板
	6.	Agent/Workflow 接口：把“检索、核验、生成、合规检查”做成工作流节点（平台化味道）


## 1. 把“最小可用 RAG”跑起来（MVP）
	•	数据：先抓 30–50 篇高质量文档（医保局/卫健委/医院公开指南等），保留原文链接
	•	流水线：清洗 → 切分 → 向量化 → 检索 → 生成（带引用）
	•	关键交付物：
	•	/query API：返回 answer + 引用列表（source_url、chunk_id、文段）
	•	数据结构：Document/Chunk 的 metadata 方案草案（先写出来）

## 2. 切分与索引“做对”，别靠玄学
	•	切分策略：按标题层级、段落、表格/条款（医疗政策经常是“条款型文本”）
	•	chunk 参数实验：chunk_size、overlap、按条款切 vs 按段落切
	•	交付物：
	•	一份“切分策略对召回影响”的小实验报告（2–3 页就够）
	•	支持多索引版本（方便后面 A/B）

## 3. 召回升级——混合检索（向量 + BM25）
	•	医疗政策 QA 典型问题：大量关键词（病种、编码、报销比例、机构等级）——BM25 很能打
	•	做 Hybrid：BM25 粗召回 + 向量补充；或并行召回后合并去重
	•	交付物：
	•	TopK 召回命中率指标（Recall@K）能跑起来
	•	一套“查询改写/规范化”（同义词、简称、地区名）

## 4. 重排（Rerank）与压缩（Compress）上场
	•	重排：把粗召回的候选 chunk 用 reranker 排序（直接提升“看起来答对”的概率）
	•	压缩：把候选 chunk 做提取式压缩，减少 token、降低幻觉
	•	交付物：
	•	指标：MRR/NDCG、引用命中率（引用是否真的支撑答案）
	•	成本：平均 token 消耗下降曲线（很讨喜）

## 5. 你之前问的王牌点——metadata 硬过滤 vs 软过滤

医疗健康 QA 的“错版本/错地区”是致命事故。你要把它工程化成可解释策略：
	•	硬过滤（Hard Filter）：必须满足才进入候选
	•	地区（省/市）、文档有效期（effective_date ≤ today ≤ expire_date）、来源可信级别、机构适用范围
	•	软过滤（Soft Filter）：不直接排除，但降权
	•	相近地区（同省不同市）、旧版本但仍有参考价值、同主题不同文件类型

交付物：
	•	一个“过滤策略配置” + 日志解释（为什么某文档被选中/被降权）
	•	面试可讲的事故预案：如何避免“漏召回”与“召回错版本”同时发生

## 6. 评测闭环（你从此和“只会调参的人”分家）
	•	构建小型评测集（100–200 问足够）：
	•	有明确出处的问题（条款型、数值型、范围型、流程型）
	•	加入“陷阱题”：跨地区/跨时间版本冲突
	•	指标体系：
	•	召回：Recall@K、覆盖率
	•	生成：引用正确率、拒答率（该拒答时拒答）、幻觉率（无引用胡说）
	•	交付物：
	•	eval 脚本（一键跑全套）
	•	“每次改动必须回归”的 CI 思路（哪怕手动也行）

## 7. 工程化第一刀——稳定性与SLA
	•	超时/重试/降级：LLM 超时怎么办？embedding 服务挂了怎么办？
	•	缓存：embedding cache、检索结果 cache（按 query+filters）、热文档缓存
	•	异步：长回答/报告生成走队列（返回 job_id）
	•	交付物：
	•	压测报告：QPS/延迟/错误率
	•	降级策略：无 rerank、缩短上下文、换更快模型

## 8. 可观测与成本治理（JD 特别吃这一套）
	•	观测：trace（一次请求经历了哪些节点）、metrics（token、latency、hit rate）、log（解释性日志）
	•	成本：按租户/用户/接口统计 token & 费用；设置预算/配额/限流
	•	交付物：
	•	一个“RAG 调试面板”（简陋也行）：能看到检索候选、过滤原因、最终上下文、token 消耗
	•	成本报表导出（CSV/接口）

## 9. 平台化抽象——把 RAG 做成 Workflow 节点

你要开始对齐那个 JD 的“Agent 平台”语言：
	•	节点化：Retrieve → Rerank → Compress → Generate → Verify/Guardrail
	•	状态机：每步可重试、可回放、可审计
	•	交付物：
	•	一个简单 DAG/workflow 定义（JSON/YAML）+ 执行器
	•	插件化 Tool：例如 ICD 编码查询、费用计算规则查询（哪怕 mock）

## 10. 医疗场景加强——合规与引用“强约束”
	•	强制引用：没有证据就拒答或给出“需确认”的提示
	•	冲突检测：多个来源冲突时，按版本/权威级别选择并解释
	•	交付物：
	•	“证据不足拒答”案例集 + 规则
	•	“冲突处理策略”文档（面试超加分）

## 11. 作品集打磨（README + 架构图 + 讲述脚本）
	•	交付物：
	•	架构图（数据流 + 控制流 + 观测点）
	•	README：如何启动、如何评测、如何调试一次请求
	•	2 个 Demo 脚本：政策问答 / 报告生成

## 12. 面试冲刺（系统设计 + 深挖问答）
	•	把你项目里的关键点，整理成 6 个“可被深挖”的话题：
	1.	版本/地区过滤怎么做，怎么防漏召回
	2.	为什么要混合检索，怎么融合打分
	3.	rerank/压缩的收益与成本
	4.	评测集怎么做，指标怎么看
	5.	线上稳定性与降级
	6.	观测与成本治理、配额限流
