# 生成式 AI 技术演进时间线（截至 2026-09）

> 关注“为什么出现、解决了什么、又留下什么问题”。时间点指代表性论文或产品公开时间，不表示该技术在当年才开始研究，也不意味着后来者取代前者。下文主要讨论深度学习到大模型及 AI 应用工程，不是人工智能全部学科的完整历史。

## 总览：五条并行的技术线

| 技术线 | 起点问题 | 代表方法 | 今天继续追问的问题 |
| --- | --- | --- | --- |
| 能力 | 模型能否从大量数据中学会通用表示？ | 深度学习、Transformer、预训练、规模化、推理强化学习 | 如何以合理训练/推理成本持续提高真实任务能力？ |
| 知识 | 参数里的知识过时、不可控，私有资料不在训练集里 | RAG、混合检索、Self-RAG、GraphRAG、Agentic RAG | 如何检索到正确证据并证明答案受证据支持？ |
| 行动 | 模型只能输出文本，无法查看外界或完成操作 | CoT、ReAct、工具调用、Agent、MCP、A2A | 如何可靠地长期执行、恢复和控制副作用？ |
| 媒介 | 单一文本/视觉模型无法理解真实工作资料和环境 | CLIP、扩散模型、多模态模型、实时语音/视频 | 如何让跨模态理解、生成和行动保持一致？ |
| 效率与可信 | 参数、显存、延迟、幻觉和安全风险限制部署 | MoE、LoRA/QLoRA、FlashAttention、PagedAttention、评测与护栏 | 如何按任务同时优化质量、成本、时延与风险？ |

## 关键时间线

### 2012—2017：从手工特征走向可规模化表示学习

| 时间与技术 | 出现契机及解决的问题 | 留下的问题 |
| --- | --- | --- |
| **2012 深度卷积网络（AlexNet）** | 图像识别依赖人工设计特征。大数据、GPU 和深层网络让模型从像素中学习表示，展示了数据与计算规模的价值。[原始论文](https://proceedings.neurips.cc/paper/2012/hash/c399862d3b9d6b76c8436e924a68c45b-Abstract.html) | 任务仍依赖大量标注；语言、序列和跨任务泛化还没有解决。 |
| **2014 Seq2Seq + 注意力** | 固定长度向量难承载长句信息。编码器—解码器学习序列映射；注意力让解码器动态关注输入位置。[Seq2Seq](https://arxiv.org/abs/1409.3215) · [注意力](https://arxiv.org/abs/1409.0473) | RNN 顺序计算限制训练并行度，长距离依赖仍难。 |
| **2017 Transformer** | 用自注意力替代递归结构，显著提高序列训练的并行性，成为后续语言与多模态基础模型的主要架构之一。[原始论文](https://arxiv.org/abs/1706.03762) | 注意力计算和显存开销随上下文增长；模型仍需大量数据和算力。 |

### 2018—2022：模型变通用，但需要“会听话、查事实、会推理”

| 时间与技术 | 出现契机及解决的问题 | 留下的问题 |
| --- | --- | --- |
| **2018—2020 预训练、BERT、GPT-3 与规模化规律** | 每个任务单独训练成本高。先在海量文本上预训练，再微调或通过少量示例完成新任务；规模化规律让模型/数据/算力投入更可预期。[BERT](https://arxiv.org/abs/1810.04805) · [GPT-3](https://arxiv.org/abs/2005.14165) · [Scaling Laws](https://arxiv.org/abs/2001.08361) | 预训练目标不等于遵循用户意图；事实知识受训练数据和时间限制。 |
| **2020 RAG** | 参数化知识难更新，也无法直接覆盖企业私有资料。检索外部文档再生成答案，为模型增加可更新的知识来源。[原始论文](https://arxiv.org/abs/2005.11401) | 检索错误、切块丢上下文、证据与回答不一致，都会造成“有引用的错误答案”。 |
| **2021 多模态与生成图像：CLIP、潜空间扩散模型** | 固定类别的视觉监督难覆盖开放世界；像素空间图像生成成本高。图文对比学习使图像和语言进入共享语义空间，潜空间扩散使高质量图像生成更实用。[CLIP](https://arxiv.org/abs/2103.00020) · [潜空间扩散](https://openaccess.thecvf.com/content/CVPR2022/html/Rombach_High-Resolution_Image_Synthesis_With_Latent_Diffusion_Models_CVPR_2022_paper.html) | 跨模态推理、时间一致性、可控编辑和数据来源问题。 |
| **2021—2023 MoE、LoRA/QLoRA、FlashAttention、PagedAttention** | 全量训练、微调和服务成本快速上升。稀疏激活、低秩适配与量化降低训练/定制成本；注意力 IO 优化和 KV cache 管理提高长序列与并发推理效率。[MoE](https://arxiv.org/abs/2101.03961) · [LoRA](https://arxiv.org/abs/2106.09685) · [QLoRA](https://arxiv.org/abs/2305.14314) · [FlashAttention](https://arxiv.org/abs/2205.14135) · [PagedAttention](https://arxiv.org/abs/2309.06180) | 效率提升依赖硬件、模型结构和工作负载；低成本不自动保证同等质量。 |
| **2022 指令微调与 RLHF** | 预训练模型擅长续写，却未必理解“请按我的要求回答”。用示范数据和人类偏好训练，让模型更有用、更符合指令。[InstructGPT](https://arxiv.org/abs/2203.02155) | 偏好并不等于事实正确；人类反馈成本高，奖励设计可能有偏差。2023 年的 [DPO](https://arxiv.org/abs/2305.18290) 简化了偏好优化流程。 |
| **2022 思维链（CoT）与 ReAct** | 多步问题中直接给结论容易遗漏中间步骤；纯文本推理又无法查询外界。CoT 用中间步骤提升部分推理任务表现；ReAct 交替进行推理与外部行动。[CoT](https://arxiv.org/abs/2201.11903) · [ReAct](https://arxiv.org/abs/2210.03629) | 中间步骤可以貌似合理但实际错误；多次调用增加延迟与失败点。 |

### 2023—2024：从“聊天模型”扩展成有知识、有工具的系统

| 时间与技术 | 出现契机及解决的问题 | 留下的问题 |
| --- | --- | --- |
| **2023 工具调用与早期 Agent** | 模型在算术、实时查询及执行任务上受限。Toolformer 探索让模型学习何时调用 API；应用工程开始把模型放入“规划—调用—观察—再规划”的循环。[Toolformer](https://arxiv.org/abs/2302.04761) · [ReAct](https://arxiv.org/abs/2210.03629) | 选错工具、错误参数和错误结果会沿执行链传播。 |
| **2023 Self-RAG 等自适应检索** | 固定检索次数和固定片段数不适合所有问题。让模型判断何时检索、检索证据是否有用、回答是否受支持。[Self-RAG](https://arxiv.org/abs/2310.11511) | 模型的自我评判同样可能出错，仍需外部评测。 |
| **2023—2024 长上下文** | 文档、代码库和视频无法装进短上下文窗口。支持更长输入，减少人工切分。[Gemini 1.5 技术发布](https://blog.google/innovation-and-ai/products/google-gemini-next-generation-model-february-2024/) | “能放入”不等于“能稳定找出并使用”；相关证据在中间位置时可能显著退化。[Lost in the Middle](https://arxiv.org/abs/2307.03172) |
| **2024 GraphRAG** | 传统片段检索适合定位局部事实，却难回答“整库主要主题是什么”。实体关系图与社区摘要支持跨文档、全局问题。[原始论文](https://arxiv.org/abs/2404.16130) | 图构建和摘要预处理成本高，知识图谱也可能提取错误。 |
| **2024 Agentic RAG** | 对多跳问题，单次检索可能找不到完整证据。用查询拆解、路由、相关性判断和再次检索构成动态检索循环。[NVIDIA 原始工程示例](https://developer.nvidia.com/blog/build-an-agentic-rag-pipeline-with-llama-3-1-and-nvidia-nemo-retriever-nims/) | 这是系统设计模式，不是某个统一的模型或发明；增加时延、token 与工具选择风险。 |
| **2024 原生实时多模态** | “语音转文本→语言模型→文本转语音”的串联系统延迟高，也会丢失语气等信号。单模型联合处理文本、语音、视觉，改善实时交互。[GPT-4o 发布说明](https://openai.com/index/hello-gpt-4o/) | 开放环境中的事实、时序和跨模态一致性仍需检验。 |
| **2024 推理模型与测试时计算** | 单纯提高预训练规模和即刻输出，难解决复杂数学、代码与科学问题。训练模型进行更长的推理，并在生成时投入更多计算。[o1 原始发布](https://openai.com/index/learning-to-reason-with-llms/) | 效果依任务而异；更长推理增加成本与延迟，也不保证事实正确。 |
| **2024 MCP 与工作流/Agent 工程模式** | 每个 AI 应用都要分别对接数据源和工具，连接成本高；多步任务也需要明确编排。MCP 标准化工具/资源连接边界；工作流固定步骤，Agent 可动态选择步骤。[MCP](https://www.anthropic.com/news/model-context-protocol) · [Agent 工程模式](https://www.anthropic.com/engineering/building-effective-agents) | 协议解决接入，不解决权限、安全或任务正确性；Agent 比固定工作流更难预测。 |

### 2025—2026：推理、工具、上下文和运行环境逐步融合

| 时间与技术 | 出现契机及解决的问题 | 留下的问题 |
| --- | --- | --- |
| **2025 强化学习推理与蒸馏** | 需要让推理能力更强且更易部署。DeepSeek-R1 展示强化学习改善推理，并将能力蒸馏到较小模型。[R1 论文](https://arxiv.org/abs/2501.12948) | 推理表现、成本和安全性仍受具体任务与训练方式影响。 |
| **2025 推理中使用工具、Agent SDK** | “会想”仍不能替代实时事实查询、运行代码或操作环境。模型在解题中交替搜索、计算和查看结果；SDK 提供编排与执行轨迹。[o3/o4-mini](https://openai.com/index/introducing-o3-and-o4-mini/) · [Responses API / Agents SDK](https://openai.com/index/new-tools-for-building-agents/) | 系统可靠性取决于模型、工具契约、环境、权限与恢复机制的整体设计。 |
| **2025 A2A 与多 Agent** | 跨系统的 Agent 难以协作，复杂研究又可拆为独立子问题。A2A 探索 Agent 间互操作；并行研究系统探索分工协作。[A2A](https://developers.googleblog.com/a2a-a-new-era-of-agent-interoperability/) · [多 Agent 研究系统](https://www.anthropic.com/engineering/multi-agent-research-system) | 协调、重复工作、冲突结果、费用与审计成本上升；并非任务越复杂越该增加 Agent。 |
| **2025 上下文工程** | 长任务积累大量历史、搜索结果、工具定义，窗口即使变大也会出现噪声与注意力问题。按需装载、压缩、记笔记、选择工具，管理模型每一步真正看到的信息。[Anthropic 工程说明](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | 压缩可能丢掉关键细节，需要可恢复的原始记录和任务评测。 |
| **2026 持久 Agent 运行基础设施** | Agent 开始跨多个上下文窗口、运行数小时或数天，需要会话恢复、执行沙箱、工具发现和子任务协同。[OpenAI Agents API，2026-09-10](https://openai.com/index/introducing-the-agents-api/) | 长程可靠性、安全隔离、实际任务评测与人类监督仍是瓶颈。 |

## 它们之间是什么关系

以“分析一家公司为何连续三个月客户流失率上升”为例：**基础模型**理解问题；**RAG**读取客户反馈和复盘；**GraphRAG**适合跨大量材料提炼共同主题；**Agentic RAG**发现证据不足时改写查询、补查 SQL；**工具调用/Agent**实际执行查询并整合结果；**推理模型**处理多因子判断；**上下文工程**控制哪些证据进入每一步；**评测、权限和审计**检查结论与执行过程。它们协作解决不同瓶颈，没有单一的“最终替代者”。

## 下一阶段的发展方向：基于已出现技术的推断

1. **从单独提升模型转向模型与运行环境协同。** 推理、搜索、代码执行、多模态输入、记忆与恢复会组合得更紧密。已有的工具化模型与持久 Agent API 是证据；它不代表完全自治已成熟。[o3/o4-mini](https://openai.com/index/introducing-o3-and-o4-mini/) · [Agents API](https://openai.com/index/introducing-the-agents-api/)
2. **从扩大上下文窗口转向管理信息流。** 检索、选择、压缩、引用和可恢复记忆，会比一味塞入更多 token 更重要。[Lost in the Middle](https://arxiv.org/abs/2307.03172) · [上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
3. **从单项模型分数转向真实任务可靠性。** 对 Agent 要测任务是否完成、耗时、成本、错误恢复和风险。长任务能力评测已尝试用人类完成任务的时长作为难度刻度；旧基准也会受到污染或饱和。[METR 原始研究](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/) · [OpenAI 对 SWE-bench Verified 的反思](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)
4. **从通用问答转向受约束的领域系统。** 真实价值由数据质量、工具权限、工作流、专业评测和人工责任共同决定。Agentic RAG、MCP、多 Agent 是可选部件，不应按流行程度叠加。[Anthropic Agent 工程模式](https://www.anthropic.com/engineering/building-effective-agents)
