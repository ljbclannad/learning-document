# 从 Agent 到机器学习：学习路径

[TOC]

## 1. 为什么做 Agent 后还要学习机器学习

Agent 开发首先解决的是**如何把模型、工具、检索、状态和业务规则组织成可完成任务的系统**；机器学习解决的是**如何从数据中学习一个可泛化的预测或决策函数，并可靠地评价它**。两者并不重复：

- 只会拼装 Agent，容易把效果问题一概归因于 Prompt，却无法判断瓶颈是在数据、检索、模型能力、评测集还是编排。
- 只懂模型训练，也不等于能交付生产系统；真实应用还需要工具边界、状态一致性、权限、观测、成本与降级。
- 绝大多数 AI 应用后端工程师不需要从零预训练 LLM，但需要具备足够的 ML 判断力，能做正确的技术选型与效果迭代。

可以把学习目标分成三个层次：

| 层次 | 要回答的问题 | 典型能力 |
| --- | --- | --- |
| Agent 工程 | 怎样可靠地完成一个任务？ | Tool Calling、RAG、工作流、状态、评测、权限和观测。 |
| 机器学习基础 | 为什么系统效果好或坏，怎样证明改动有效？ | 数据划分、指标、泛化、误差分析、实验设计。 |
| 模型训练与优化 | 能否用数据改善某个模型或组件？ | 特征/表示、训练循环、微调、检索与排序模型、部署权衡。 |

学习顺序应是：**先把 Agent 做深，再并行补 ML 基础；当业务问题已经明确需要训练数据驱动的组件时，再进入模型训练。**

## 2. 先建立 Agent 的“可测量闭环”

在深入算法前，先把 [[Agent（智能体）|Agent]] 系统变成可观察、可比较的对象。否则即使训练了模型，也不知道它是否真正改善了业务。

一个最小闭环是：

```text
真实任务样本
  -> 明确成功标准
  -> 基线方案（Prompt / RAG / Workflow）
  -> 离线评测 + 失败样本归因
  -> 改动一个因素
  -> 与基线比较，并在线灰度验证
```

先积累以下资产：

1. **任务定义**：输入是什么、允许的动作是什么、完成条件与不能犯的错误分别是什么。
2. **评测集**：来自真实场景且经过去重、脱敏和标注；需要覆盖正常样本、边界样本、拒答样本和高风险样本。
3. **过程日志**：至少保留模型版本、Prompt、检索证据、工具调用、状态流转、延迟、成本和最终结果。
4. **错误分类**：例如“没有召回证据”“召回错误”“工具选择错误”“参数错误”“模型没有遵循证据”“业务规则缺失”。

注意：最终回答看起来正确，不代表系统过程可靠；反之，离线指标提高也不必然带来业务价值。评测要同时覆盖**结果正确性、过程正确性、风险与成本**。

## 3. 第一阶段：必须掌握的机器学习基础

这一阶段的目的不是背公式，而是获得判断 Agent 效果问题的共同语言。

### 3.1 数据、标签与数据划分

- **样本（sample）**：一次独立的输入—目标输出记录；在 Agent 场景中可以是一条用户任务、一次检索查询或一次工具路由决策。
- **特征（feature）**：用于预测的输入信息。传统 ML 中常人工构造；深度学习和 LLM 中通常由模型学习表示（representation）。
- **标签（label）**：希望模型学习或评测的目标，例如“是否应转人工”“哪个工具最合适”“这条召回结果是否相关”。标签质量决定学习上限。
- **训练集 / 验证集 / 测试集**：训练集用于拟合参数，验证集用于选择方案和调参，测试集只用于最后一次独立验收。

最重要的原则是防止**数据泄漏**：任何在真实推理时不可获得的信息，都不能通过特征、划分方式或人工处理提前暴露给训练过程。例如同一用户、同一文档改写版本或时间上晚于测试任务的数据，不应不加控制地同时出现在训练与测试中。

### 3.2 泛化、过拟合与偏差—方差

模型在训练数据上表现好，而在新数据上表现差，称为**过拟合**。它往往来自样本少、标签噪声大、模型或规则过度贴合历史样本，或反复根据同一验证集调优。

- **偏差（bias）高**：模型能力或信息不足，训练集和测试集都做不好；先检查任务定义、特征/上下文、模型能力和标签质量。
- **方差（variance）高**：训练集表现很好但新数据变差；应增加或清洗数据、简化模型/规则、使用正则化，或改进划分方式。
- 对 Agent 而言，Prompt 对少量样本“特调”后看似提升、换一批任务就失效，也是过拟合的一种工程表现。

### 3.3 常用指标：先与业务损失对齐

不要只看一个“准确率”。类别不平衡时，一个永远预测多数类的系统也可能有很高准确率。

| 任务 | 先理解的指标 | 关注点 |
| --- | --- | --- |
| 分类/路由 | Precision、Recall、F1、混淆矩阵 | 错放行和错拦截哪个代价更高？ |
| 排序/检索 | Recall@K、MRR、NDCG | 正确证据是否进入候选集，且排在足够靠前的位置？ |
| 生成/Agent | 任务完成率、事实正确率、工具选择/参数正确率、人工评审 | 必须拆分结果与过程；高风险任务要单独统计。 |
| 线上体验 | 成功率、P95 延迟、单任务成本、转人工率、投诉率 | 观察离线提升是否转化为真实收益。 |

**Precision（精确率）**回答“系统判为正的结果里有多少是真的”；**Recall（召回率）**回答“所有真实为正的结果里找回了多少”。安全审核倾向关注漏检，检索候选阶段倾向先提高 Recall，最终执行前再通过规则或重排提高 Precision。

### 3.4 损失函数、优化与梯度下降：理解训练在做什么

训练的本质是：定义一个衡量预测与目标差异的**损失函数（loss）**，再通过优化算法不断调整参数，让训练集上的平均损失下降。

以监督学习为例：

```text
输入 x + 标签 y
    -> 模型 f(x; θ) 给出预测 ŷ
    -> 损失 L(ŷ, y) 衡量误差
    -> 反向传播计算参数 θ 的梯度
    -> 梯度下降更新 θ
```

- **梯度下降**并不保证找到全局最优；它是在复杂参数空间中沿着局部下降方向迭代。
- **学习率**过大可能震荡或发散，过小则训练缓慢。
- **正则化、早停和数据增广**的共同目标是改善泛化，而非单纯压低训练损失。

理解到这里即可开始阅读深度学习训练代码：知道 batch、epoch、optimizer、learning rate、loss 和 validation 分别在做什么。

## 4. 第二阶段：与 LLM / RAG 最直接相关的表示学习

### 4.1 Embedding 与相似度

Embedding 将文本、图片或其他对象映射为固定维度的向量，使语义或任务相关的对象在向量空间中更接近。它是 [[RAG|RAG]] 召回的基础，但要牢记：向量相似度是近似的语义信号，不是逻辑蕴含或事实证明。

需要掌握：

1. 余弦相似度、点积和欧氏距离分别表达什么，以及为什么查询和文档向量的归一化会影响它们的关系。
2. chunk 切分、元数据过滤、混合检索、top-k 和重排如何共同决定检索质量。
3. 双塔 embedding 模型适合高效召回；cross-encoder reranker 让 query 与候选文本共同编码，通常更准确但更慢。
4. 评测检索时先看 Recall@K：若正确证据没进入候选集，后面的 LLM 无法凭空补救。

### 4.2 Transformer：理解 LLM 的能力边界

不必一开始推导所有矩阵公式，但要形成正确直觉：

- Tokenizer 把文本映射成 token ID；详情见 [[06-AI应用后端/01-模型基础/LLM|LLM]]。
- Embedding 将 token ID 映射为向量，位置编码提供序列位置信息。
- Self-attention 允许每个 token 根据其他 token 的表示聚合信息；多头注意力学习不同的关联模式。
- Transformer 层反复进行注意力、前馈网络、残差连接与归一化，最终得到用于预测下一个 token 的表示。
- 自回归生成逐 token 进行，输出受训练分布、输入上下文和采样策略影响；它不是数据库查询，也不天然保证事实正确。

这能解释很多 Agent 现象：长上下文并不等于所有内容都被同等利用；模型“知道”某条事实也不等于能稳定按业务规则执行；有副作用的操作仍必须交给受控工具和确定性校验。

### 4.3 RAG、Prompt、微调的边界

遇到效果问题时，先按问题性质选择手段，而不是默认微调：

| 问题 | 优先手段 | 原因 |
| --- | --- | --- |
| 私有、变化快、需追溯的事实 | RAG / 工具查询 | 知识在外部更新，可附带来源和权限控制。 |
| 输出格式、角色行为、固定任务习惯 | Prompt、结构化输出、少样本示例；稳定后再评估微调 | 先用低成本、可快速迭代的方法验证问题。 |
| 检索候选相关性差 | 改善数据、chunk、混合召回、重排；必要时训练 embedding/reranker | 生成模型无法修复没有被召回的证据。 |
| 路由、审核、分类等有大量稳定标签的重复决策 | 分类模型或微调模型 | 标签可直接转化为可测量的训练目标。 |
| 关键业务动作 | 工作流、规则、权限和人工审批 | 这首先是系统正确性问题，不应交给概率模型兜底。 |

## 5. 第三阶段：开始训练前要补齐的深度学习知识

当你需要微调、训练 embedding / reranker，或阅读模型训练实现时，再系统学习以下内容：

1. **线性代数**：向量、矩阵乘法、维度变换、点积、范数、特征值/奇异值的直觉。
2. **概率统计**：随机变量、常见分布、期望与方差、条件概率、最大似然、抽样误差与置信区间。
3. **微积分与自动微分**：导数、链式法则、梯度、计算图、反向传播。
4. **深度学习训练工程**：数据加载、batch、epoch、优化器、学习率调度、混合精度、显存与吞吐、checkpoint 与实验复现。
5. **预训练与微调**：因果语言模型的 next-token prediction；SFT、参数高效微调（如 LoRA）的目标与局限；训练/推理分布一致性。
6. **评估与安全**：基准集污染、评测集过拟合、人工标注一致性、偏见、隐私和线上回滚。

建议采用“概念 -> 小实验 -> 业务组件”的节奏。例如先用一个小型文本分类任务理解训练循环，再做 query—document 相关性重排，最后才尝试对真实 Agent 的某个可标注子任务微调。

## 6. 一个面向 AI 应用后端的阶段性路线

### 阶段 A：把 Agent 做成可靠系统

- 熟练实现 Tool Calling、RAG、结构化输出、工作流、会话状态、权限和可观测性。
- 为一个真实任务建立 50～200 条高质量评测样本和错误分类。
- 能回答：失败是模型问题、检索问题、工具问题、规则问题，还是评测问题？

### 阶段 B：机器学习判断力

- 掌握数据划分、泄漏、Precision/Recall/F1、Recall@K、过拟合和实验设计。
- 能为“是否转人工”“工具路由”“检索相关性”定义标签和指标。
- 用简单基线（规则、关键词、逻辑回归或现成 embedding）与 LLM 方案比较，而不是假设 LLM 必然更好。

### 阶段 C：LLM / RAG 深入

- 理解 tokenization、embedding、Transformer、自回归生成和上下文窗口的实际限制。
- 能独立诊断 RAG 的索引、召回、重排、生成和引用链路。
- 建立离线检索集与端到端 Agent 评测集，持续做 error analysis。

### 阶段 D：训练与优化一个明确组件

- 先选标签稳定、收益可测、风险可控的子问题，例如意图分类、文档重排或工具路由。
- 建立训练/验证/测试集，保留不参与调参的最终测试集。
- 以基线为参照，记录数据版本、代码版本、模型版本、超参数、指标、成本与失败案例。
- 小流量灰度上线；观察分布漂移和业务指标，随时可回滚。

## 7. 常见误区

1. **“做 Agent 必须先把传统 ML 和数学全学完。”** 不需要。先建立评测和数据思维，再按实际问题补齐训练知识，效率更高。
2. **“效果不好就微调。”** 微调不能替代缺失知识、错误工具或不可靠流程；先定位问题层级。
3. **“离线准确率高就能上线。”** 离线数据可能泄漏或与真实流量分布不同；还需灰度、监控和回滚。
4. **“Embedding 相似就等于事实相关。”** 向量相似度不能保证精确条件、时间版本、权限范围或因果关系正确。
5. **“LLM 是唯一模型。”** 规则、搜索、传统分类/排序模型和小模型，在确定性、高频、低延迟任务上可能更合适。

## 8. 推荐的实践项目

以“企业知识库问答 + 任务执行 Agent”为主线：

1. 实现带引用的 RAG 问答，记录每次 query、候选 chunk、最终证据和回答。
2. 人工标注一小批“证据是否被召回”和“回答是否有证据支撑”的样本，计算 Recall@K 与回答正确率。
3. 对失败样本分类：切分、Embedding、关键词召回、元数据过滤、重排还是生成造成的问题？
4. 为“是否应该调用业务工具 / 是否应转人工”建立标签、规则基线和评测指标。
5. 当规则和 Prompt 已到瓶颈且标签量足够时，训练或微调一个路由/重排组件，并严格与基线比较。

这样学习机器学习不是脱离 Agent 另起炉灶，而是在真实问题中逐步获得数据、模型和实验能力。
