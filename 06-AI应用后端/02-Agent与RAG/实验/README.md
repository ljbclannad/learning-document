## 验证层次与覆盖

| 源码 | 层次 | 观察结果 |
| --- | --- | --- |
| [agent_revision_lab.py](./agent_revision_lab.py) | 单进程内存状态模型 | 9 个测试；旧回调隔离、重复不改版本、证据/目标变化使草稿失效、6 种回调顺序 |
| [agent_durable_action_lab.py](./agent_durable_action_lab.py) | 本地 SQLite 事务与下游替身 | 11 个测试；稳定动作身份、独立提交、重开数据库查证、取消后保留已发生事实 |

先理解版本与条件提交，再看持久动作。两套实验验证的对象不同，不合并测试数来宣称一个完整 Agent 已通过验收。

## 运行与环境

需要 Python 3.10+，仅使用标准库。在仓库根目录分别执行：

```sh
python3 '06-AI应用后端/02-Agent与RAG/实验/agent_revision_lab.py'
python3 '06-AI应用后端/02-Agent与RAG/实验/agent_durable_action_lab.py'
```

第一份只操作内存。第二份在 TemporaryDirectory 中创建两个 SQLite 数据库，代表本地账本和下游替身，正常结束时清理；不连接网络、不调用模型，不修改业务数据库。两份均由 unittest 输出测试结果。

## 验证边界

内存模型把一次方法调用视为串行状态转换；SQLite 实验按顺序注入故障，不等于真实并发或断电。下游可查询、可幂等是替身提供的前提，不代表任意外部服务支持。真实授权、网络回执、资源端并发和部署恢复仍需集成验证。
