# LLM（Large Language Model，大语言模型）

## 1. 一张全景图

大语言模型通常是以 Transformer 为主体、通过海量文本上的“预测下一个 token”任务训练出的神经网络。它根据输入上下文输出下一个 token 的概率分布，再按某种策略逐个生成 token。

```text
文本 -> tokenizer -> token IDs -> token/位置表示
     -> 多层 Transformer -> 下一个 token 的概率分布 -> 解码 -> 文本
```

“语言流畅”不等于“事实正确”。模型从训练数据中学习统计模式与表征，不是带版本、来源和权限的事实数据库；对私有或易变知识，参见 [[RAG|RAG]]。

## 2. Tokenization：文本如何变成模型输入

模型接收的不是字符或单词，而是一串整数 token ID。一个 tokenizer 包含词表、切分规则、规范化规则和特殊 token 定义；训练与推理必须使用完全一致的版本。

典型流程：

1. **规范化（可选）**：如 Unicode 规范化或处理不可见字符。规范化越激进，越可能丢失大小写、符号等信息。
2. **预分词**：按空格、标点、数字或正则规则粗分片段。
3. **子词切分**：将片段编码为子词或字节级 token。
4. **特殊 token 注入**：按模型要求加入 BOS、EOS、PAD 或对话模板标记。

token 数不等于字数或单词数；语言、数字、空格和标点都会影响它。上下文限制、推理延迟和 API 成本通常按 token 计算。

### 2.1 常见 token 化方案

| 方案 | 特点 | 典型问题 |
| --- | --- | --- |
| Word | 一词一 token | 词表膨胀，未登录词（OOV）严重。 |
| Character | 一字符一 token | 覆盖稳定，但序列较长。 |
| 子词（BPE、WordPiece、Unigram） | 在词表大小与序列长度间折中 | 行为依赖具体训练规则。 |
| Byte-level BPE | 以 UTF-8 字节为基础，几乎可编码任意文本 | 对人类不直观，中文可能占多个字节。 |

### 2.2 BPE 的核心直觉

BPE 从较小的基本符号出发，反复把语料中高频相邻符号对合并为新 token，直到达到目标词表规模。高频词干或片段会变成更长的 token，低频词则保留为较小片段，从而避免纯词级词表的 OOV 问题。

训练产物是词表（token <-> ID）和按优先级排列的 merge 规则。编码新文本时不再重新统计频率，而是按已学习的 merge 顺序合并。并列频率的处理、预分词和边界标记都会影响最终词表，因此 tokenizer 版本必须锁定。

Byte-level BPE 先将文本转为 UTF-8 bytes，再在字节序列上应用 BPE。某些实现会将不可打印 byte 映射为可显示字符，因此调试时常见的 `Ġ`、`Ċ` 只是空格或换行等字节的显示表示；它们不是模型理解出的特殊语义。

### 2.3 特殊 token 与对话模板

特殊 token 是训练协议的一部分。BOS/EOS 指定序列边界，PAD 用于 batch 对齐，某些模型还定义角色边界、工具调用或图像占位 token。错误的 chat template、padding side、BOS/EOS 设置即使不会报错，也可能明显改变模型行为。

## 3. 从数据到训练样本

原始数据可为连续文本、指令—回答对或多轮 messages。经过 tokenizer 和数据整理后，常见字段包括：

```text
input_ids:       token ID 序列
attention_mask:  哪些位置是有效 token
labels:          计算损失的目标；忽略位置通常标为 -100
```

对 decoder-only 的因果语言模型，训练目标是预测下一个 token；实现通常由模型内部完成一位偏移。指令微调（SFT）中，常将 system/user 提示部分的 labels 置为 `-100`，只对 assistant 的目标回答计算损失。具体边界必须和所用对话模板一致。

### 3.1 Padding、packing 与长文本

- **动态 padding**：每个 batch 对齐到本批最长样本，通常比固定长度省显存。
- **packing**：把多个短样本拼入长序列，提升 token 利用率；要正确处理样本边界和 loss mask。
- **截断**：简单可靠，但可能丢掉任务关键部分；应记录被截断比例。
- **滑动窗口与 stride**：长文本切窗时保留相邻窗口重叠。它适用于长文训练或 perplexity 评估，但会带来重复 token；使用 packing 时往往不需要。

训练成本更接近“每次更新处理了多少 token”，而不是样本条数：

```text
tokens_per_micro_step ≈ micro_batch_size × sequence_length
effective_batch ≈ micro_batch_size × gradient_accumulation × data_parallel_world_size
```

先确定任务所需序列长度，再在硬件上找到不溢出的 micro batch，最后通过梯度累积调整有效 batch。有效 batch、学习率和序列长度应作为一组实验变量记录，而非孤立调参。

## 4. Embedding：ID 如何成为向量

Token embedding 是一个可训练矩阵 E，形状为 `vocab_size × hidden_size`。输入 token ID `t` 时，模型取出第 `t` 行向量 `E[t]`。这只是 Transformer 的输入表示，不等同于 RAG 使用的句向量。

常见表示包括：

- **token embedding**：把 token ID 映射为向量；
- **位置信息**：绝对位置 embedding 或 RoPE 等相对/旋转位置编码，使模型感知顺序；
- **输出投影（LM head）**：把隐藏状态映射回词表大小以预测下一个 token。许多模型与输入 embedding 共享权重（weight tying）。

检索 embedding 将文本编码为用于相似度计算的向量；它与生成模型内部的 token embedding 用途不同。查询端和文档端必须使用**相互兼容的编码契约**：模型及版本、输出维度、各自的输入模板、池化和归一化方式，以及索引的距离度量。常见系统两端使用同一模型，但也有成对训练的不同编码器，不能仅凭维度相同就混用向量。

“契约一致”不等于“前缀相同”。例如 multilingual-e5-large 在检索时要求查询使用 `query: `、文档使用 `passage: `，中文输入也如此；这是该模型训练方式的一部分，其他模型应遵循各自模型卡。[E5 官方模型卡](https://huggingface.co/intfloat/multilingual-e5-large)

若两端向量都做 L2 归一化，点积等于余弦相似度，平方欧氏距离等于 `2 - 2 × 点积`，因而排序可对应；未归一化时不能直接互换。更换模型或文档编码方式后，应重建对应向量索引并用固定查询集回归，不能让新查询向量直接搜索旧向量空间。检索链路见 [[RAG#4. 召回（Retrieval）|RAG 召回]]。

## 5. Transformer：模型怎样利用上下文

一个 Transformer block 通常由多头注意力、前馈网络、残差连接和归一化组成，多层堆叠后形成更抽象的表示。

### 5.1 Self-attention

每个 token 的表示会投影为 Query（Q）、Key（K）和 Value（V）。注意力使用 Q 与所有 K 的相似度计算权重，再对 V 加权求和：

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V
```

因果语言模型使用 causal mask：当前位置只能关注自己及之前的 token，不能看到未来 token。多头注意力让模型在不同表示子空间中学习关联；各头没有预先指定且始终固定的语义职责。

注意力机制不意味着模型能无损“读取”整段上下文。上下文越长，成本、位置泛化、干扰信息和关键证据被忽略的风险都需要通过实际任务验证。

### 5.2 前馈网络、残差与归一化

注意力负责在 token 之间交换信息；前馈网络（MLP/FFN）则在每个位置独立进行非线性特征变换。残差连接为深层网络保留信息和梯度通路，LayerNorm/RMSNorm 有助于稳定训练。架构细节会因模型而异，但这四个组件构成理解 Transformer 的基本地图。

### 5.3 从三个 token 看 Q、K、V 和 mask

下面以 **decoder-only、单层单头、无 dropout** 的教学模型为例。设三个位置的输入表示为 `X`，每行是一个 token 的向量。真实模型用不同的可训练矩阵计算 `Q=XWq`、`K=XWk`、`V=XWv`；Q 表达当前位置如何匹配上下文，K 参与匹配，V 提供被聚合的信息。这些角色是计算分工，不能把某一维直接解释成确定的人类语义。

为便于手算，暂取三个投影矩阵均为单位矩阵，`d_k=2`：

```text
X = Q = K = V = [[1, 0],
                 [0, 1],
                 [1, 1]]

QKᵀ / √2 ≈ [[0.707, 0,     0.707],
             [0,     0.707, 0.707],
             [0.707, 0.707, 1.414]]

加 causal mask 后 = [[0.707, -∞,    -∞],
                     [0,      0.707, -∞],
                     [0.707,  0.707, 1.414]]
```

softmax **逐行**计算。第一行只能看到自己，权重为 `[1,0,0]`；第二行约为 `[0.330,0.670,0]`；第三行约为 `[0.248,0.248,0.503]`。再乘 V，得到三个位置的新表示约为 `[1,0]`、`[0.330,0.670]`、`[0.752,0.752]`。除以 `√d_k` 是为了控制点积的尺度，不是把权重归一化；归一化由 softmax 完成。原始公式与多头拼接、输出投影见 [Transformer 原论文 §3.2](https://arxiv.org/html/1706.03762v7)。

mask 必须作用在 softmax 之前的分数上；把被屏蔽位置的分数设为 0 仍会得到正权重。padding mask 和 causal mask 目的不同，前者排除无效填充，后者限制信息方向。若一整行都被屏蔽，朴素 softmax 可能出现无效数值，应由实现处理无效 query，不能认为所有 mask 组合都天然安全。

### 5.4 位置、多头与一层 block 的真实边界

仅有 QKV 点积无法直接表示“某个词在第几个位置”。常见方案是在输入加入位置向量，或对 Q/K 施加与位置有关的旋转（RoPE）；不能把两种机制都描述为“给 embedding 加一个位置”。RoPE 通过旋转编码位置，并使注意力中的相互关系包含相对位置信息。[RoFormer 原论文](https://arxiv.org/abs/2104.09864)

因果 mask 提供可见范围，但不等同于完整的位置表示。改变位置编号、位置编码缩放或注意力窗口，会影响缓存兼容性；长上下文可输入也不代表模型可靠利用了远处证据。

多头注意力把表示投影到多个子空间，分别聚合后拼接，再经输出投影映射回隐藏维度。头并不预先被指定为“语法头”或“指代头”；可观察到某类关联，也不意味着所有输入下都有固定分工。

一个常见的 **pre-norm** block 可写成下面的结构示意，不代表所有模型都使用同一种归一化或 FFN：

```text
u = x + Attention(Norm(x))
y = u + FFN(Norm(u))
```

注意力在位置之间交换信息；FFN 对每个位置使用相同参数独立变换，多层叠加后两者反复配合。FFN 可采用门控结构，也可由 MoE 专家替换；MoE 并不因此省掉整个注意力部分。残差与归一化的具体先后顺序属于架构契约，加载权重时不能随意更换。

### 5.5 为什么训练可并行，生成通常要逐步进行

训练时完整序列已知，例如输入位置是 `[BOS, 我, 爱]`，对应预测目标是 `[我, 爱, 学习]`。一次前向传播可以并行计算各位置的预测，但因果 mask 保证第一个位置不能借用后两个位置的信息。标签对齐可由数据管道或模型 loss 内部完成，须确认接口约定，不能重复 shift。

推理时只有 `[BOS]`，后续输入来自前一步选择出的 token，因此常规自回归生成有依赖链。并行训练没有消除这种生成依赖。并行也只指序列位置等维度的计算安排，不意味着网络的所有层同时完成。

因果注意力中，追加后缀不会改变历史位置的表示；在模型、位置和注意力配置不变时，可以复用各层历史 K/V。下面的标准库实验验证这个性质，也展示没有 mask 时未来 token 会改变早期输出。它未实现位置编码、多层网络或真实推理引擎，不能据此推断速度。

```python
from math import exp, sqrt, isclose


def attention(q, keys, values):
    scores = [sum(a*b for a, b in zip(q, k))/sqrt(len(q)) for k in keys]
    e = [exp(s-max(scores)) for s in scores]
    weights = [v/sum(e) for v in e]
    assert isclose(sum(weights), 1.0)
    return [sum(w*v[j] for w, v in zip(weights, values))
            for j in range(len(values[0]))]


def full(xs, causal=True):
    return [attention(q, xs[:i+1], xs[:i+1]) if causal
            else attention(q, xs, xs) for i, q in enumerate(xs)]


x = [[1., 0.], [0., 1.], [1., 1.]]
y = full(x)
changed = x[:2] + [[100., -100.]]
assert full(changed)[:2] == y[:2]  # 后缀不能影响已有位置
assert full(changed, False)[0] != full(x, False)[0]
keys, values, incremental = [], [], []
for token in x:
    keys.append(token)  # 本实验 Wk = Wv = I
    values.append(token)
    incremental.append(attention(token, keys, values))
assert all(isclose(a, b) for row1, row2 in zip(y, incremental)
           for a, b in zip(row1, row2))
assert all(isclose(a, b, abs_tol=0.001)
           for a, b in zip(y[-1], [0.752, 0.752]))
print("注意力实验通过：", [[round(v, 3) for v in row] for row in y])
```

验证记录：2026-10-29，Python 3.12.9，以上代码运行通过；输出与手算值一致，因果隔离及增量计算断言通过。仅验证所示单头教学算子。

### 5.6 MHA、MQA、GQA 为什么影响 KV 显存

普通 MHA 为各 query head 配套 K/V head；MQA 让多个 query head 共享一组 K/V；GQA 将 query head 分组，每组共享 K/V。共享的是 K/V，query 仍可不同。[GQA 原论文](https://arxiv.org/abs/2305.13245)

对普通全注意力 decoder，未考虑分片、量化元数据、内存分页与共享前缀时，KV 数据量近似为：

```text
2 × 层数 × 序列数 × 缓存长度 × KV head 数 × head_dim × 每元素字节数
```

例如 32 层、1 条序列、4096 tokens、head_dim=128、每元素 2 字节：32 个 KV heads 约为 2 GiB，8 个约为 0.5 GiB。这里是同条件下的缓存算术，不是总显存；权重、激活和运行时缓冲另计。减少 KV heads 可减小缓存与读取量，但质量、核实现和批处理会影响实际收益，不能把显存缩小四倍等同于请求快四倍。部署层面继续见 [[稠密模型、MoE与条件计算]]。

## 6. 训练、微调与推理

### 6.1 预训练与微调

预训练通常以海量文本的 next-token prediction 为目标；微调则在较小、任务相关的数据上继续优化。SFT 用于学习指令遵循和任务格式；LoRA 等参数高效微调方法通过训练少量附加参数降低资源需求。

微调并非知识库更新的默认答案：它难以精确删除或引用单条事实，且可能过拟合小数据。开始训练前应先有清晰任务、数据划分、基线、独立测试集和回滚方案。

#### 6.1.1 预训练、SFT 与偏好优化分别学什么

预训练主要从大量序列中学习语言与知识的统计结构。继续预训练通常沿用语言建模目标适应领域分布；SFT 则用“给定输入应如何回答”的示范，让模型学习任务格式、交互习惯与行为模式。两者都可能改变知识和行为，区别主要在数据与训练目标，不能理解成互不影响的两个独立存储区。

以制度问答为例，SFT 样本可以示范“先核对适用日期，按证据回答，缺条件时追问”。若把每个样本都写成自信回答，即使模板很规范，模型也可能学不到拒答和追问。训练时要核对哪些 token 参与 loss：只监督 assistant 输出是常见方案，不代表所有训练器默认如此；工具消息与多轮回答的 mask 应与任务一致。

偏好优化使用同一输入下的优劣比较，强化“更希望模型选择哪种回答”。例如两份回答都包含 600 元，但更偏好同时说明例外且引用适用条款的一份。经典 RLHF 路线可先训练奖励模型，再优化策略并约束偏离参考模型的程度；DPO 则可直接用偏好对与参考策略构造优化目标，不要求先训练一个独立奖励模型。[DPO 原论文](https://arxiv.org/abs/2305.18290)

```text
SFT：输入 x + 示范回答 y → 提高示范序列在给定输入下的概率
偏好优化：输入 x + 更优 y+ + 较差 y- → 学习相对偏好
```

这不是必须固定执行的流水线，后训练也不只包含这两类方法。偏好标签有噪声、只奖励冗长或忽略事实时，优化可能放大错误倾向；奖励/偏好分数提高不等于业务正确率提高。无论采用哪种目标，模型都没有因此获得工具授权或精确事实更新能力。

#### 6.1.2 LoRA、量化与蒸馏处于不同维度

| 方法 | 改变什么 | 能解决什么 | 主要边界 |
| --- | --- | --- | --- |
| 全参数微调 | 更新全部或大部分模型权重 | 适应目标任务或领域 | 训练状态与梯度开销大，需检验通用能力退化 |
| LoRA | 冻结基础权重，训练指定层的低秩增量 | 减少可训练参数和相关训练状态 | 仍需基础模型前向/反向所需计算与激活，并非显存只剩 adapter |
| 量化 | 用较低位宽及尺度表示权重或激活等数值 | 降低部分存储、带宽需求 | 误差与加速依算法、数据和内核，不自动减少网络层数 |
| 蒸馏 | 用教师输出分布或生成样本等监督学生 | 让另一模型学习目标行为，常用于较小模型 | 学生可能继承教师错误，能力覆盖受样本分布限制 |

LoRA 的一个常见写法是 `W' = W + (α/r)BA`，其中 `W` 为 `d_out × d_in`，`A` 为 `r × d_in`，`B` 为 `d_out × r`；新增参数为 `r(d_in+d_out)`。`r` 决定增量表达的秩上限，`α/r` 是该写法的缩放约定，其他变体不能直接套用。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

在可合并的线性层与精度条件下，可把增量合入基础权重；保留多个 adapter 动态切换、使用量化基础权重或不同内核时，部署开销和合并误差应另测。adapter 必须绑定兼容的基础模型、目标模块和 tokenizer/模板版本，不能只因模型名称相似就混用。

量化和 LoRA 可以组合：QLoRA 的典型做法是冻结量化基础权重，训练低秩 adapter；它不等于“直接更新所有 4-bit 权重”，计算精度、量化存储与优化器状态也不是同一概念。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)

蒸馏还需区分教师软概率分布与教师生成文本：前者携带类别之间的相对信息，后者通常作为训练目标序列。调用一个教师 API 生成示范再做 SFT，是数据层面的蒸馏路线，不代表复制了教师内部参数或完整能力。经典知识蒸馏讨论了用教师监督更易部署模型的思路。[知识蒸馏原论文](https://arxiv.org/abs/1503.02531)

#### 6.1.3 小矩阵验证低秩增量与合并

以下 Python 标准库实验只验证 LoRA 线性代数，不执行训练，不证明低秩方案适合某个任务。取 `d_in=d_out=3`、`r=1`、`α=1`，比较“基础输出加增量”和“先合并权重再计算”。

```python
from math import isclose


def mv(matrix, vector):
    return [sum(a*b for a, b in zip(row, vector)) for row in matrix]


W = [[1., 0., 0.], [0., 1., 0.], [0., 0., 1.]]
A = [[1., 0., -1.]]
B = [[1.], [2.], [0.]]
x = [2., 3., 1.]
delta = [[sum(B[i][k]*A[k][j] for k in range(1))
          for j in range(3)] for i in range(3)]
merged = [[W[i][j]+delta[i][j] for j in range(3)] for i in range(3)]
separate = [a+b for a, b in zip(mv(W, x), mv(B, mv(A, x)))]
assert all(isclose(a, b) for a, b in zip(separate, mv(merged, x)))
assert separate == [3., 5., 1.]
assert delta[1] == [2*v for v in delta[0]]  # 本例增量行相关，秩为 1
assert 1*(3+3) == 6 < 3*3
print("LoRA 算术实验通过：", separate)
```

验证记录：2026-10-29，Python 3.12.9，合并与分开计算均得到 `[3,5,1]`，增量关系与参数数量断言通过；未进行模型训练或显存测试。

#### 6.1.4 什么时候值得微调

先区分错误来自哪里。知识未更新，应修知识源或检索；权限不正确，应修执行边界；schema 偶尔不合法，先检查结构化输出契约与验证；只有在任务定义稳定、示范足够、基础链路正确但行为仍持续偏离时，才有明确的微调假设。

例如希望模型稳定输出“条件、结论、依据、例外”四部分，可以先建立 Prompt 基线，再用覆盖正常、无答案和冲突情况的 SFT 样本对比。训练/调优/验收按任务族或资料来源隔离；除了目标任务，还要保留通用能力、拒答和安全边界回归。loss 下降只能说明更拟合训练目标，不能直接决定上线。

发布产物应同时记录基础模型、adapter/合并权重、量化方案、tokenizer、模板、数据与评测版本。每一步改变都可能影响行为，回滚也要恢复兼容组合。具体评测与错误归因见 [[AI应用评测与错误分析]]。

### 6.2 解码与采样

模型每一步输出词表概率分布。贪心解码选择最高概率 token，稳定但可能保守；temperature 调整分布尖锐程度；top-p 或 top-k 只在部分候选中采样以控制随机性。对结构化输出、工具参数和高风险结论，通常应降低随机性，并结合 schema 校验和确定性规则。

### 6.3 常见工程误区

1. 将字符数当 token 数估算成本或上下文。
2. 更换 tokenizer、词表或 chat template，却继续使用旧模型权重或旧训练数据。
3. 将 padding token 计入 loss，或错误 mask 掉应学习的 assistant 回答。
4. 只因训练 loss 下降就认为模型变好；必须看独立评测和业务指标。
5. 把模型输出当作事实或执行授权；应使用 RAG、工具、校验与权限边界。

### 6.4 一次生成请求：prefill、decode 与 KV Cache

以下以采用因果自注意力的 decoder-only 模型、常规自回归生成为例；滑动窗口注意力、混合架构、推测式解码等实现会改变计算与缓存细节。

```text
请求进入服务 -> 排队与调度 -> tokenizer / 对话模板
  -> prefill：处理已有输入，建立各层 K/V，预测第一个输出 token
  -> decode：输入刚生成的 token，复用历史 K/V，预测下一个 token
  -> 重复 decode，直到 EOS、长度限制或取消 -> 释放或回收缓存
```

**Prefill** 时，输入 token 都已知，模型可在因果掩码下并行处理这些位置；并行不代表每个位置可以看未来。最后一个输入位置的输出分布用于选取第一个生成 token。输入变长一般会增加这阶段的工作量，但实际首字延迟还受排队、批处理、缓存命中和硬件利用率影响。

**Decode** 时，下一个 token 依赖此前采样结果，常规生成需要逐步推进。利用第 5.5 节说明的因果性，在模型、位置和注意力配置不变时复用各层历史 K/V，只计算新位置。缓存避免重复计算历史表示，但新 query 仍要读取历史 K/V；上下文增长后，decode 的读取成本和显存占用仍会上升。[Transformers 缓存机制](https://huggingface.co/docs/transformers/cache_explanation)

以 100 个输入 token、3 个输出 token 为例：prefill 处理 100 个输入并得到输出 y1；随后处理 y1 得到 y2，再处理 y2 得到 y3。不能把三个输出理解为一次并行预测。达到长度上限只表示停止生成，不表示答案已经完整。

### 6.5 三种缓存分别复用什么

| 缓存 | 复用对象 | 失效或隔离边界 |
| --- | --- | --- |
| 单次生成的 KV Cache | 已计算 token 在各层的 K/V | 依赖模型、token 序列、位置和注意力配置；不是可任意编辑的文本记忆 |
| 前缀缓存 | 多次请求中可复用的前缀计算 | 由服务实现决定匹配与隔离；改变前缀、模板或模型通常影响复用 |
| RAG 检索结果缓存 | 查询得到的文档 ID、片段和版本 | 必须考虑租户、权限、语料版本、过滤条件和有效期 |

命中前缀缓存不会省掉后续回答的生成；例如 vLLM 明确将 APC 的加速范围限定在 prefill，而非生成新 token 的 decode。[vLLM 前缀缓存](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)

命中检索缓存也不会自动省掉模型读取证据的计算。缓存不能提供事实更新、长期记忆或审批恢复。涉及跨用户复用时，隔离与访问校验仍由服务端实施。

### 6.6 从时延现象定位瓶颈

对于普通文本流式生成，可按一次请求记录：

```text
TTFT = 收到第一个输出 token 的时刻 - 发起请求的时刻
TPOT = (收到最后一个 token 的时刻 - 收到第一个 token 的时刻) / (输出 token 数 - 1)
端到端时延 ≈ TTFT + (输出 token 数 - 1) × TPOT
```

该口径要求输出多于一个 token，并按 token 而非网络分块计数。客户端分块合并、网络和服务端调度都会影响观测。推理模型的隐藏计算、工具调用及首个可见文本之间可能还有额外阶段，不能仅凭客户端 TTFT 推断 prefill 用时。

| 现象 | 先收集什么证据 | 可验证的优化方向 |
| --- | --- | --- |
| 输入变长，首 token 变慢 | 输入长度、排队耗时、前缀命中、prefill 耗时 | 减少无关输入、复用合法前缀；先区分计算与排队 |
| 开始很快，但生成很久 | 实际输出长度、TPOT、并发负载 | 收紧输出任务和长度；不要把截断当作完成 |
| 并发增加后尾延迟陡升 | KV 占用、排队、调度、吞吐及超时 | 容量规划、准入限流、控制上下文长度 |

最小实验应固定模型、采样、输出上限和到达方式，分别改变输入长度、实际输出长度与并发；冷缓存和热缓存分开测。先测少量样本确认口径，再报告分位数，不能用一次请求得出吞吐结论。这里只给出验证方法，未测量真实模型/GPU 性能。

## 7. 学习与排障顺序
