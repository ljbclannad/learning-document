# 动态规划详解

返回 [[算法/算法学习导航]]。

## 核心思想与识别信号

动态规划把重复子问题的结果保存起来，并按依赖顺序计算。首先定义状态含义，再推导转移、初始值和遍历顺序；不能先写数组和双层循环再猜含义。它既可求最值，也可计数或判断可行性。

## 执行机制与正确性依据

爬楼梯的状态是到达第 i 级的方法数，最后一步来自 i-1 或 i-2。零钱兑换的状态是凑出金额 x 的最少硬币数，最后一枚硬币 c 带来 dp[x-c]+1。不同子序列的状态是源串前 i 个字符组成目标前 j 个字符的方法数，按是否使用当前源字符分成互斥两类。

## 手动推演

硬币 [1,3,4]、金额 6：dp[0]=0，dp[3]=1；算 dp[6] 时可从 dp[5]+1、dp[3]+1、dp[2]+1 转移，最小为 2，对应 3+3。这也展示了大面额优先贪心的失败。

## Java 入门模板

以下为本类型低难度代表题的完整实现，可作为理解状态与更新顺序的起点；它不是所有变式的通用答案。先说清状态含义，再修改模板。代码基线为 Java 17。

```java
class Solution {
    public int climbStairs(int n) {
        if (n < 0 || n > 45) throw new IllegalArgumentException("n 应在 0 到 45 之间");
        int previous = 1, current = 1;
        for (int i = 2; i <= n; i++) {
            int next = previous + current;
            previous = current; current = next;
        }
        return current;
    }
}
```

模板复杂度：时间 O(n)，额外空间 O(1)。本实现限制 n≤45，int 结果安全。

## 适用边界与常见错误

不可达状态用明确哨兵，不能默认零。压缩数组后，遍历方向决定读取的是上一轮还是当前轮；不同子序列必须倒序更新目标位置。计数中间状态可能比最终答案更大，不能仅凭最终结果可用 int 就认为全部状态不会溢出。

## 工程联系

资源预算、有限状态成本优化可建立 DP，但状态数量乘积可能爆炸。先估算维度与取值范围；复杂度中的“金额”是数值大小，O(n·amount) 属于伪多项式时间。
