# 堆与优先队列详解

返回 [[算法/算法学习导航]]。

## 核心思想与识别信号

堆维护局部顺序：最小堆保证堆顶最小，最大堆保证堆顶最大，并不保证整体遍历有序。它适合不断取极值、维护 Top K 和多路合并。Java PriorityQueue 默认是最小堆。

## 执行机制与正确性依据

插入和删除堆顶通常 O(log n)，查看堆顶 O(1)。求第 k 大时保留大小 k 的最小堆，堆顶是当前保留下来的最小值，也就是当前第 k 大。合并多条有序链时，每条链只暴露最前端未处理节点，堆顶必然是全局下一项。

## 手动推演

数据 [5,1,4,2]，k=2：先保留 1、5，加入 4 后弹最小的 1，保留 4、5；加入 2 后又弹 2，最终堆顶 4 是第二大。

## Java 入门模板

以下为本类型低难度代表题的完整实现，可作为理解状态与更新顺序的起点；它不是所有变式的通用答案。先说清状态含义，再修改模板。代码基线为 Java 17。

```java
import java.util.Comparator;
import java.util.PriorityQueue;

class Solution {
    public int lastStoneWeight(int[] stones) {
        PriorityQueue<Integer> heap = new PriorityQueue<>(Comparator.reverseOrder());
        for (int stone : stones) heap.offer(stone);
        while (heap.size() > 1) {
            int first = heap.poll(), second = heap.poll();
            if (first != second) heap.offer(first - second);
        }
        return heap.isEmpty() ? 0 : heap.peek();
    }
}
```

模板复杂度：逐个入堆与碰撞总时间 O(n log n)，空间 O(n)。不修改原数组。

## 适用边界与常见错误

比较器不要用 a-b 或 b-a，应使用 Integer.compare 或 Comparator。元素入堆后修改参与比较的字段不会自动重建堆，应出堆后修改再入堆。第 k 大按排序位置计，重复值也占名次。

## 工程联系

合并有序日志流与 Top K 指标可使用堆；多路日志的时间戳是否单调、迟到数据怎么处理需要额外契约。PriorityQueue 本身不是线程安全调度器。
