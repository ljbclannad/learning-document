# 哈希表详解

返回 [[算法/算法学习导航]]。

## 核心思想与识别信号

哈希表把“找某个值”变成按键定位。面试中常用它保存已见值、出现次数、分组签名或状态。选择键的语义比背 put/get 更重要：同一个键必须代表同一类问题状态。

## 执行机制与正确性依据

两数之和保存数值到下标，查找补数；异位词分组保存字符计数签名到列表；词串匹配保存单词到次数。平均情况下查找和更新可按 O(1) 分析，但哈希冲突、键构造和字符串比较都可能带来额外成本，不能把整段算法一概写成 O(n)。

## 手动推演

扫描 [4, 1, 6] 寻找目标 7：看到 4 时查 3，不存在后保存 4；看到 1 时查 6，不存在后保存 1；看到 6 时查 1，找到下标 1。先查再存使当前元素不会与自己配对。

## Java 入门模板

以下为本类型低难度代表题的完整实现，可作为理解状态与更新顺序的起点；它不是所有变式的通用答案。先说清状态含义，再修改模板。代码基线为 Java 17。

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            long complement = (long) target - nums[i];
            if (complement >= Integer.MIN_VALUE && complement <= Integer.MAX_VALUE) {
                Integer previous = seen.get((int) complement);
                if (previous != null) return new int[]{previous, i};
            }
            seen.put(nums[i], i);
        }
        throw new IllegalArgumentException("不存在满足条件的数对");
    }
}
```

模板复杂度：平均时间 O(n)，空间 O(n)。返回下标，不修改输入。

## 适用边界与常见错误

HashMap 不保证遍历顺序。计数键序列化必须有分隔符，否则 [1,11] 和 [11,1] 可能混淆。可变对象作键后若改变 equals/hashCode 相关字段，查找可能失败。算法去重仅处理内存数据，不能代替数据库的业务唯一约束。

## 工程联系

日志聚合、频次统计和按属性分组都能使用哈希表。数据量超过内存时要考虑分批、外部排序或存储系统，而不是无限扩充 Map。
