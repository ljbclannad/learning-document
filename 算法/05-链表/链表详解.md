# 链表详解

返回 [[算法/算法学习导航]]。

## 核心思想与识别信号

链表通过节点引用连接数据，不能像数组一样 O(1) 按任意位置访问。常见任务是改变引用结构，因此需要同时说明节点值与节点身份：两个值相同的节点仍可能是不同对象。

## 执行机制与正确性依据

反转需要先保存 next，再改变当前节点指向，否则后续链会丢失。虚拟头节点统一首节点和中间节点的插入删除。快慢指针以不同速度前进：无环时快指针先到末尾，有环时两者在环上相对距离逐步缩短并最终相遇。

## 手动推演

反转 1→2→3：先记住 2，把 1.next 指向 null；再记住 3，把 2.next 指向 1；最后把 3.next 指向 2。循环不变量是 prev 指向已反转前缀，current 指向未处理后缀。

## Java 入门模板

以下为本类型低难度代表题的完整实现，可作为理解状态与更新顺序的起点；它不是所有变式的通用答案。先说清状态含义，再修改模板。代码基线为 Java 17。

```java
class Solution {
    static class ListNode {
        int val;
        ListNode next;
        ListNode(int val) { this.val = val; }
    }

    public ListNode reverseList(ListNode head) {
        ListNode prev = null, current = head;
        while (current != null) {
            ListNode next = current.next;
            current.next = prev;
            prev = current;
            current = next;
        }
        return prev;
    }
}
```

模板复杂度：时间 O(n)，额外空间 O(1)。原链表引用结构被修改。

## 适用边界与常见错误

链表结构变化后应检查所有节点是否仍可达、有无意外环、尾部是否正确断开。返回头节点必须由调用者接收。普通反转默认无环；遇到带环输入会失去终止条件。递归实现简短但长链可能耗尽栈。

## 工程联系

LRU 缓存常把哈希表定位与双向链表移动结合起来；仅有链表则查找仍是 O(n)。这些面试实现未提供线程安全，不能直接用作并发缓存。
