# 贪心详解

返回 [[算法/算法学习导航]]。

## 核心思想与识别信号

贪心在每一步作局部选择，并不回头枚举所有方案。难点是证明这个选择能包含在某个全局最优解中。仅凭几个样例正确，不能说明局部最优必然推出全局最优。

## 执行机制与正确性依据

常见证明有交换论证和领先不变量。分饼干可把最小可用饼干交给最小胃口，交换不会减少满足人数；跳跃游戏维护已处理位置能到达的最远边界；分糖果把左右约束分别形成下界，最终取两者最大值，既合法又达到逐点最小。

## 手动推演

胃口 [1,2]，饼干 [2,3]：先把 2 给胃口 1，剩 3 给胃口 2，可满足两人。任何先把 3 给胃口 1 的可行分配，都能交换这两块饼干而不降低人数，说明最小可用选择安全。

## Java 入门模板

以下为本类型低难度代表题的完整实现，可作为理解状态与更新顺序的起点；它不是所有变式的通用答案。先说清状态含义，再修改模板。代码基线为 Java 17。

```java
import java.util.Arrays;

class Solution {
    public int findContentChildren(int[] greed, int[] cookies) {
        Arrays.sort(greed); Arrays.sort(cookies);
        int child = 0;
        for (int cookie : cookies) {
            if (child < greed.length && cookie >= greed[child]) child++;
        }
        return child;
    }
}
```

模板复杂度：时间 O(g log g+s log s)，扫描 O(g+s)；除排序辅助开销外 O(1) 空间。修改两个输入数组的顺序。

## 适用边界与常见错误

硬币 [1,3,4] 凑 6 时，先拿大面额会选 4+1+1，但最优是 3+3，说明“每次最大”不是普遍正确的。权重、容量和全局约束改变后，要重新证明；证明不了时考虑动态规划或搜索。

## 工程联系

资源分配和区间安排常有贪心结构，但业务里的优先级、公平性、配额可能破坏原问题的交换性质。先明确优化目标，再选择算法。
