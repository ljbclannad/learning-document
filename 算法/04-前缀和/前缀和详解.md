# 前缀和详解

返回 [[算法/算法学习导航]]。

## 核心思想与识别信号

前缀和把反复的区间求和转为两个累计值相减。定义 prefix[0]=0，prefix[i+1]=prefix[i]+nums[i]，则闭区间 [l,r] 的和是 prefix[r+1]-prefix[l]。多留一个零位能够统一从下标零开始的区间。

## 执行机制与正确性依据

静态区间求和先 O(n) 预处理，再 O(1) 查询。计数题把区间和等式改写为 prefix[left]=prefix[right]-target，扫描右端时用哈希表查询历史前缀出现次数。二维题可枚举上下边界，沿列压缩成一维，再复用一维计数。

## 手动推演

[2,-2,2] 的前缀是 [0,2,0,2]。目标 0：扫描到第二个元素时，当前前缀为 0，历史前缀 0 出现一次，对应 [2,-2]；再扫描到末尾，前缀 2 曾出现一次，对应 [-2,2]。

## Java 入门模板

以下为本类型低难度代表题的完整实现，可作为理解状态与更新顺序的起点；它不是所有变式的通用答案。先说清状态含义，再修改模板。代码基线为 Java 17。

```java
class Solution {
    public long[] runningSum(int[] nums) {
        long[] result = new long[nums.length];
        long sum = 0;
        for (int i = 0; i < nums.length; i++) result[i] = sum += nums[i];
        return result;
    }
}
```

模板复杂度：时间 O(n)，输出空间 O(n)，除输出外额外空间 O(1)。返回 long[]，这是为避免 int 累计溢出的教学接口。

## 适用边界与常见错误

计数时先查询历史，再登记当前前缀，否则 target=0 会把长度为零的区间算进去。前缀和适用于负数，但普通求和滑窗可能不适用。频繁单点修改会让后续全部前缀失效，可转向树状数组或线段树；它们不属于首批基础实现。

## 工程联系

累计请求量、静态报表区间统计可直接使用；按时间增量写入、修正历史数据时，还要评估重算成本。金额和大样本计数要确认 long 是否足够。
