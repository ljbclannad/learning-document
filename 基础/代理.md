# 代理

## 1. 代理想解决什么问题

代理的核心意图不是“替别人调用方法”，而是 **在不改动目标对象核心业务代码的前提下，对调用过程做增强**。

典型场景：

- 统一打印日志
- 权限校验
- 事务控制
- 性能统计
- 缓存
- 重试

一句话理解：

> 代理 = 不直接访问目标对象，而是先经过一个“中间层”。

调用链大致如下：

```text
调用方 -> 代理对象 -> 目标对象
```

这样做的好处：

- 对调用方屏蔽目标对象的部分实现细节
- 将日志、事务、监控等横切逻辑从业务代码中拆出去
- 满足开闭原则：增强行为时，尽量不改原有业务类

---

## 2. 静态代理

### 2.1 什么是静态代理

静态代理指的是：**代理类在编码阶段就已经写好**。

通常做法：

1. 定义一个公共接口
2. 目标类实现该接口
3. 代理类也实现该接口
4. 代理类内部持有目标对象，调用前后做增强

### 2.2 示例

```java
public interface HelloService {
    void sayHello();
    void sayBye();
}

public class HelloServiceImpl implements HelloService {
    @Override
    public void sayHello() {
        System.out.println("hello");
    }

    @Override
    public void sayBye() {
        System.out.println("bye");
    }
}

public class HelloServiceStaticProxy implements HelloService {

    private final HelloService target;

    public HelloServiceStaticProxy(HelloService target) {
        this.target = target;
    }

    @Override
    public void sayHello() {
        System.out.println("before sayHello");
        target.sayHello();
        System.out.println("after sayHello");
    }

    @Override
    public void sayBye() {
        System.out.println("before sayBye");
        target.sayBye();
        System.out.println("after sayBye");
    }

    public static void main(String[] args) {
        HelloService helloService = new HelloServiceStaticProxy(new HelloServiceImpl());
        helloService.sayHello();
        helloService.sayBye();
    }
}
```

### 2.3 优缺点

优点：

- 好理解
- 不依赖反射
- 适合简单、固定的增强场景

缺点：

- 每个目标类都可能要写一个代理类，类会越来越多
- 如果接口方法增加，代理类也要跟着改
- 横切逻辑难以复用，维护成本高

所以静态代理更适合用来理解代理思想，不适合大规模业务系统中的通用增强。

---

## 3. 动态代理

### 3.1 什么是动态代理

动态代理指的是：**代理类不是手写出来的，而是在运行期间动态生成**。

它解决的是静态代理“代理类太多、重复代码太多”的问题。

Java 里常见的动态代理方案有两类：

- JDK 动态代理：基于接口
- CGLIB 动态代理：基于继承

---

## 4. JDK 动态代理

### 4.1 使用条件

JDK 动态代理要求目标对象 **至少实现一个接口**。

如果没有接口，JDK 动态代理就无法直接代理。

### 4.2 核心原理

JDK 会在运行时生成一个代理类，这个代理类：

- 实现目标对象实现过的那些接口
- 内部持有 `InvocationHandler`
- 调用接口方法时，最终会转发到 `InvocationHandler#invoke`

所以你真正写增强逻辑的地方，通常是在 `invoke` 方法里。

### 4.3 示例

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

public class JdkProxyHandler implements InvocationHandler {

    private final Object target;

    public JdkProxyHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("before " + method.getName());
        Object result = method.invoke(target, args);
        System.out.println("after " + method.getName());
        return result;
    }

    public static void main(String[] args) {
        HelloService target = new HelloServiceImpl();

        HelloService proxy = (HelloService) Proxy.newProxyInstance(
                target.getClass().getClassLoader(),
                target.getClass().getInterfaces(),
                new JdkProxyHandler(target)
        );

        proxy.sayHello();
        proxy.sayBye();
    }
}
```

### 4.4 执行流程

调用 `proxy.sayHello()` 时，实际流程是：

1. 调用代理对象的方法
2. 进入 `InvocationHandler#invoke`
3. 在 `invoke` 中执行前置增强逻辑
4. 通过反射调用目标对象方法
5. 执行后置增强逻辑

也就是：

```text
proxy.sayHello()
    -> InvocationHandler.invoke(...)
        -> method.invoke(target, args)
```

### 4.5 优缺点

优点：

- 不需要为每个目标类单独写代理类
- 一套增强逻辑可以复用到多个接口实现类
- 非常适合 AOP 思想

缺点：

- 必须基于接口
- 由于使用反射，理解成本比静态代理略高

## 5. CGLIB 动态代理

### 5.1 为什么需要 CGLIB

如果目标类没有实现接口，JDK 动态代理就不适用了。

这时候通常会用 CGLIB。

### 5.2 核心思想

CGLIB 不是“实现接口”，而是 **生成目标类的子类**，然后通过重写方法来做增强。

所以它的本质是：

- 继承目标类
- 重写非 `final` 方法
- 在重写的方法里加入增强逻辑

### 5.3 限制

- `final` 类无法被继承，不能代理
- `final` 方法无法被重写，不能增强
- 本质基于继承，因此会受到继承机制限制

---

## 6. JDK 动态代理和 CGLIB 的区别

| 对比项 | JDK 动态代理 | CGLIB 动态代理 |
| --- | --- | --- |
| 代理基础 | 接口 | 继承 |
| 是否要求接口 | 是 | 否 |
| 生成方式 | 运行时生成实现接口的代理类 | 运行时生成目标类子类 |
| 不能代理的情况 | 目标类没有接口 | `final` 类、`final` 方法 |
| 常见使用场景 | 面向接口编程的服务层 | 没有接口的普通类 |

面试里可以这样回答：

> JDK 动态代理基于接口，CGLIB 基于继承。Spring AOP 默认优先使用 JDK 动态代理；如果目标对象没有实现接口，才会退化为 CGLIB 代理。

---

## 7. Spring AOP 和代理的关系

Spring AOP 的底层并不是“魔法”，本质上就是 **代理模式的工程化落地**。

你在业务代码里写：

- `@Transactional`
- `@Cacheable`
- 自定义 `@Aspect`

背后通常都是 Spring 给目标 Bean 创建了一个代理对象，再在代理对象里织入增强逻辑。

### 7.1 Spring AOP 选择哪种代理

默认规则：

- 如果目标类实现了接口，优先使用 JDK 动态代理
- 如果目标类没有实现接口，使用 CGLIB

也可以强制使用 CGLIB，例如：

```properties
spring.aop.proxy-target-class=true
```

## 8. Spring AOP 代理示例

下面这个例子体现的意图很清楚：**不修改业务方法本身，只给它加日志统计能力**。

### 8.1 业务类

```java
import org.springframework.stereotype.Service;

@Service
public class OrderService {

    public void createOrder(String orderNo) {
        System.out.println("创建订单: " + orderNo);
    }
}
```

### 8.2 切面类

```java
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.springframework.stereotype.Component;

@Aspect
@Component
public class LogAspect {

    @Around("execution(* com.example.service.OrderService.createOrder(..))")
    public Object around(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        System.out.println("AOP before: " + joinPoint.getSignature().getName());

        try {
            return joinPoint.proceed();
        } finally {
            long cost = System.currentTimeMillis() - start;
            System.out.println("AOP after: " + joinPoint.getSignature().getName()
                    + ", cost=" + cost + "ms");
        }
    }
}
```

### 8.3 启动类

```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.ApplicationContext;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        ApplicationContext context = SpringApplication.run(DemoApplication.class, args);
        OrderService orderService = context.getBean(OrderService.class);
        orderService.createOrder("A1001");
    }
}
```

### 8.4 运行效果

```text
AOP before: createOrder
创建订单: A1001
AOP after: createOrder, cost=3ms
```

### 8.5 这个例子里发生了什么

你从 Spring 容器拿到的通常不是原始 `OrderService`，而是 Spring 创建的代理对象。

执行 `orderService.createOrder("A1001")` 时：

1. 先进入 Spring 生成的代理对象
2. 代理对象匹配到切面规则
3. 执行 `@Around` 中的前置逻辑
4. 调用目标方法 `createOrder`
5. 执行 `@Around` 中的后置逻辑

这就是代理模式在 Spring AOP 中的实际落地。

## 9. Spring AOP 常见面试点

### 9.1 为什么 `@Transactional` 会失效

一个经典原因是 **同类内部调用**。

例如：

```java
@Service
public class UserService {

    public void methodA() {
        methodB();
    }

    @Transactional
    public void methodB() {
        // ...
    }
}
```

`methodA()` 直接调用 `methodB()`，走的是 `this.methodB()`，没有经过 Spring 代理对象，因此事务增强不会生效。

关键点：

- 代理只能增强“经过代理对象的外部调用”
- 类内部自调用不会经过代理

### 9.2 为什么 `final` 方法不适合做 AOP 增强

如果走 CGLIB，本质是生成子类并重写方法。

而 `final` 方法不能被重写，因此无法织入增强逻辑。

---

## 10. 一段适合面试的总结

可以直接概括为：

> 代理模式的核心目的是在不改动目标对象的前提下，对方法调用做统一增强。静态代理通过手写代理类完成增强，简单但扩展性差；动态代理在运行时生成代理对象，更适合日志、事务、权限这类横切逻辑。JDK 动态代理基于接口，CGLIB 基于继承。Spring AOP 本质上就是基于动态代理实现的。

---

## 11. 记忆重点

- 代理的本质：控制访问 + 统一增强
- 静态代理：好理解，但代理类会膨胀
- JDK 动态代理：基于接口，核心入口是 `InvocationHandler#invoke`
- CGLIB：基于继承，不能代理 `final` 类和 `final` 方法
- Spring AOP：本质就是动态代理
- `@Transactional`、日志、权限、缓存，本质上都可以理解成代理增强
