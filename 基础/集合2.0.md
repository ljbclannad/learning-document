# 1. HashMap原理
`HashMap` 是 Java 中一种常用的集合类，属于 `Map` 接口的实现。其主要功能是通过键值对存储数据，并支持快速查找。以下是 `HashMap` 的工作原理的详细介绍：

### 1. 基本结构

- **数组和链表**：`HashMap` 主要由一个数组和链表（或红黑树）组成。数组用于存储桶（bucket），每个桶可以存储多个键值对。
- **节点**：每个桶中的元素都是一个节点（Node），包含键、值和指向下一个节点的指针。

### 2. 哈希函数

- **计算哈希值**：插入元素时，`HashMap` 会使用键的 `hashCode()` 方法计算哈希值。
- **确定桶的位置**：通过将哈希值与数组的长度进行取模运算，确定该键值对应该存储在哪个桶中。

### 3. 处理冲突

由于不同的键可能会产生相同的哈希值（哈希冲突），`HashMap` 采用以下方式处理冲突：

- **链式法**：在同一个桶中，如果发生冲突，`HashMap` 会将新的键值对以链表的形式存储在该桶中。
- **红黑树**：如果同一个桶中的元素数量超过一定阈值（默认为 8），`HashMap` 会将链表转换为红黑树，以提高查找效率。
- 为什么 HashMap 的初始容量要是 2 的幂次
  - 这样可以通过位运算快速计算索引位置：`index = (n - 1) & hash`，减少冲突
  - 保证哈希值的分布均匀，降低链表或红黑树的使用频率


### 4. 插入与查找

- **插入**：
  1. 计算键的哈希值。
  2. 确定桶的位置。
  3. 如果桶为空，直接插入；如果不为空，检查是否已经存在相同的键。
  4. 如果存在，更新值；否则，添加到链表或红黑树中。

- **查找**：
  1. 计算键的哈希值。
  2. 确定桶的位置。
  3. 在桶中查找对应的键，遍历链表或红黑树。

### 5. 扩容

- **负载因子**：`HashMap` 有一个负载因子（默认为 0.75），表示当数组的使用率达到该值时，`HashMap` 会进行扩容。
- **扩容过程**：
  1. 创建一个更大的数组（通常是原数组的两倍）。
  2. 重新计算每个元素的桶位置，并将其插入新数组。
  
### 6. 总结

- **时间复杂度**：
  - 插入、删除和查找的平均时间复杂度为 O(1)，最坏情况下为 O(n)，但通过使用链表和红黑树可以降低最坏情况的概率。
  
- **空间复杂度**：
  - `HashMap` 使用额外的空间来存储桶和节点。

理解 `HashMap` 的原理有助于在编写 Java 程序时合理使用它，提高程序的效率和性能。

# 2.CopyOnWriteArrayList 和 Collections.synchronizedList
`CopyOnWriteArrayList` 和 `Collections.synchronizedList` 都是用于在多线程环境中安全地访问和修改列表的工具，但它们的实现机制和适用场景有所不同。以下是这两者的主要区别：

### 1. 实现机制

- **CopyOnWriteArrayList**：
  - 是一种线程安全的 `List` 实现。每当你对列表进行修改（如添加或删除元素）时，它会创建该列表的一个新的副本，并在这个副本上进行修改。
  - 这种设计使得读取操作非常快速，因为它们不需要加锁，可以在原始数组上进行。

- **Collections.synchronizedList**：
  - 是一个包装器，使用 `Collections.synchronizedList` 方法将普通的 `List`（如 `ArrayList`）包装成线程安全的列表。
  - 对于所有的修改操作，它会使用一个全局锁（通常是 `this`）来同步，这意味着在一个线程执行修改操作时，其他线程必须等待。

### 2. 读写性能

- **CopyOnWriteArrayList**：
  - 读操作性能高，因为不需要加锁，多个线程可以同时读取。
  - 写操作性能较低，因为每次写入都会复制整个数组。

- **Collections.synchronizedList**：
  - 读操作和写操作都需要加锁，因此在高并发读取的场景下，性能会受到影响。
  - 对于写操作，虽然是线程安全的，但由于加锁机制，可能导致性能瓶颈。

### 3. 适用场景

- **CopyOnWriteArrayList**：
  - 适用于读多写少的场景，例如缓存、事件监听器等，适合需要频繁读取但不经常写入的情况。

- **Collections.synchronizedList**：
  - 适用于读写操作相对平衡的场景，或在不确定读写比例的情况下使用。

### 4. 迭代器行为

- **CopyOnWriteArrayList**：
  - 迭代器是基于当前的数组快照，因此在迭代过程中不会抛出 `ConcurrentModificationException`，即使在迭代时有其他线程进行修改。

- **Collections.synchronizedList**：
  - 迭代器不是线程安全的，使用时需要手动同步，例如使用 `synchronized` 块来确保在迭代期间不发生并发修改。

### 总结

| 特性                       | CopyOnWriteArrayList                      | Collections.synchronizedList                |
|----------------------------|------------------------------------------|--------------------------------------------|
| **实现机制**               | 复制数组，写时复制                      | 使用全局锁进行同步                          |
| **读写性能**               | 读快，写慢                               | 读写都慢                                   |
| **适用场景**               | 读多写少                                | 读写平衡或不确定                          |
| **迭代器行为**             | 安全，基于快照                          | 不安全，需要手动同步                       |

这两者在多线程编程中各有优缺点，选择时应根据具体需求进行评估。

# 3. ArrayList的扩容机制
`ArrayList` 是 Java 中非常常用的动态数组实现，其扩容机制是保证其能够动态调整大小以容纳更多元素的关键。以下是 `ArrayList` 的扩容机制的详细说明：

### 1. 初始容量

- `ArrayList` 在创建时可以指定一个初始容量，如果没有指定，默认初始容量为 10。
- 初始容量决定了 `ArrayList` 能够存储的元素数量，直到达到容量限制。

### 2. 扩容时机

- 当 `ArrayList` 中的元素数量达到其当前容量时，再尝试添加元素时会触发扩容。
- 具体来说，扩容发生在调用 `add()`、`addAll()` 等方法时。

### 3. 扩容策略

- **新的容量**：当扩容时，新的容量通常是当前容量的 1.5 倍。具体计算如下：
  ```java
  int newCapacity = oldCapacity + (oldCapacity >> 1);
  ```
  这个计算方式相当于 `oldCapacity * 1.5`，确保了容量的增加。

- **复制元素**：扩容时，`ArrayList` 会创建一个新的数组，并将原数组中的所有元素复制到新的数组中。这是一个 O(n) 的操作，意味着随着元素数量的增加，扩容的耗时也会增加。

### 4. 性能考虑

- **频繁扩容的影响**：如果 `ArrayList` 经常达到其容量限制并扩容，可能会导致性能下降。为了避免频繁的扩容，建议在创建 `ArrayList` 时合理设置初始容量，尤其是在知道预计元素数量的情况下。

### 5. 例子

以下是一个简单的示例，演示了 `ArrayList` 的扩容过程：

```java
import java.util.ArrayList;

public class ArrayListExample {
    public static void main(String[] args) {
        ArrayList<Integer> list = new ArrayList<>(2); // 初始容量为 2
        list.add(1);
        list.add(2);
        // 此时容量已满，再添加元素将触发扩容
        list.add(3);
        System.out.println(list);
    }
}
```

### 总结

- `ArrayList` 通过动态扩容机制来管理其内部数组，保持对元素的有效存储。
- 在扩容时，会创建新的更大数组并复制原有元素，扩容的策略是将当前容量增加 50%。
- 使用时，合理设置初始容量可以提高性能，减少不必要的扩容操作。

# 4. ConcurrentHashMap
`ConcurrentHashMap` 是 Java 中用于支持高并发的线程安全哈希表实现，属于 `java.util.concurrent` 包。它提供了更好的并发性能，相比于 `Hashtable` 和 `Collections.synchronizedMap`，在多线程环境下具有显著的优势。以下是 `ConcurrentHashMap` 的详细介绍：

### 1. 基本特性

- **线程安全**：`ConcurrentHashMap` 设计为在多线程环境中安全地进行读、写和删除操作。
- **高性能**：通过分段锁机制或其他优化手段，减少了线程间的竞争，提高了并发性能。

### 2. 结构

- **分段锁**：在 Java 8 之前，`ConcurrentHashMap` 使用分段（Segment）机制，每个段维护一个独立的哈希表，并对每个段加锁。这使得多个线程可以同时访问不同的段。
- **Java 8 及之后**：从 Java 8 开始，`ConcurrentHashMap` 的实现变得更加细粒度，不再使用段，而是使用一种更灵活的结构，结合了无锁算法和使用`volatile` 变量来确保可见性。

### 3. 关键操作

- **读操作**：读操作是无锁的，多个线程可以同时进行读操作，而不会互相阻塞。
- **写操作**：写操作会尝试加锁，但只会锁定需要修改的部分，允许其他线程并发访问。
- **原子性操作**：提供了一些原子性的方法，例如 `putIfAbsent()`、`remove()` 和 `replace()`，这些方法能在多线程环境中安全地执行。

### 4. 性能优势

- **减少锁竞争**：通过细粒度的锁机制，`ConcurrentHashMap` 能减少线程间的竞争，提升并发性能。
- **高效的遍历**：在遍历时，`ConcurrentHashMap` 允许读取操作与写入操作并发进行，具备较高的性能。

### 5. 使用示例

以下是一个简单的示例，展示了如何使用 `ConcurrentHashMap`：

```java
import java.util.concurrent.ConcurrentHashMap;

public class ConcurrentHashMapExample {
    public static void main(String[] args) {
        ConcurrentHashMap<Integer, String> map = new ConcurrentHashMap<>();

        // 添加元素
        map.put(1, "One");
        map.put(2, "Two");

        // 使用 putIfAbsent 方法
        map.putIfAbsent(2, "Two - Updated"); // 不会更新，因为键 2 已存在

        // 遍历
        map.forEach(1, (key, value) -> {
            System.out.println(key + " = " + value);
        });

        // 输出 map
        System.out.println(map);
    }
}
```

### 6. 适用场景

`ConcurrentHashMap` 适用于以下场景：

- 需要频繁进行读写操作的多线程环境。
- 需要高效的并发访问而不希望使用全局锁的情况。
- 需要保证数据一致性和线程安全的集合操作。

### 总结

`ConcurrentHashMap` 是一个高效且线程安全的哈希表实现，适合在高并发环境中使用。其独特的设计使得读取操作非常快速，同时提供了安全的写入操作，极大地提高了并发性能。

# 5.布隆过滤器
布隆过滤器（Bloom Filter）是一种基于 **哈希算法的概率性数据结构**，用于判断一个元素是否在一个集合中。它的特点是：

- **快速查重**：可以快速判断某个元素是否可能存在于集合中。
- **空间效率高**：相比传统的哈希表，布隆过滤器可以用很少的内存存储大量的数据。
- **容错性**：可能会产生**假阳性**（即判断某个元素存在但实际上不存在），但不会有假阴性（即不存在的元素绝对不会判断为存在）。

---

### **工作原理**

1. **哈希映射**：
   
    - 初始化一个位数组（bit array），所有位初始为 0。
    - 插入元素时，通过多个哈希函数计算元素的哈希值，将位数组对应位置置为 1。
    - 查询时，同样使用这些哈希函数计算哈希值，如果所有对应位置的位都为 1，则可能存在；如果有任何一个位为 0，则一定不存在。
2. **假阳性**：
   
    - 由于多个元素可能映射到同一个位，可能会误判某个元素存在。
3. **无假阴性**：
   
    - 如果查询时发现某个位为 0，则元素肯定不存在，因为插入时所有相关位都应该置为 1。

---

### **布隆过滤器的应用场景**

1. **快速查重**：
   
    - 用于处理大规模数据，例如日志去重、网页爬虫的 URL 去重等。
    - 判断一个元素是否已经出现过，从而避免重复处理。
2. **缓存穿透防护**：
   
    - 在缓存系统中（如 Redis），布隆过滤器可用于判断某个请求是否是无效的（例如查询数据库中不存在的数据），从而避免频繁查询数据库。
3. **防止垃圾邮件**：
   
    - 邮件服务使用布隆过滤器判断某个地址是否已在黑名单中。
4. **分布式系统中的元素查找**：
   
    - 判断一个元素是否可能存在于某台服务器上，减少分布式查找范围。

---

### **布隆过滤器的优缺点**

#### **优点**：

- 高效的存储：使用位数组，占用空间小。
- 快速查找：时间复杂度为 O(k)，k 是哈希函数的数量。

#### **缺点**：

- 存在假阳性：可能误判某个元素存在。
- 不支持删除：无法简单地删除某个元素，删除可能影响其他元素。

---

### **布隆过滤器的实现示例（Java）**

以下是一个简单的布隆过滤器实现：

```java
import java.util.BitSet;
import java.util.Random;

public class BloomFilter {
    private final BitSet bitSet;
    private final int size;
    private final int[] hashSeeds;
    private final Random random = new Random();

    public BloomFilter(int size, int hashCount) {
        this.size = size;
        this.bitSet = new BitSet(size);
        this.hashSeeds = new int[hashCount];
        for (int i = 0; i < hashCount; i++) {
            hashSeeds[i] = random.nextInt();
        }
    }

    public void add(String value) {
        for (int seed : hashSeeds) {
            int hash = hash(value, seed);
            bitSet.set(Math.abs(hash % size));
        }
    }

    public boolean contains(String value) {
        for (int seed : hashSeeds) {
            int hash = hash(value, seed);
            if (!bitSet.get(Math.abs(hash % size))) {
                return false;
            }
        }
        return true;
    }

    private int hash(String value, int seed) {
        int result = 0;
        for (char c : value.toCharArray()) {
            result = result * seed + c;
        }
        return result;
    }

    public static void main(String[] args) {
        BloomFilter bloomFilter = new BloomFilter(1000, 5);

        // 添加数据
        bloomFilter.add("hello");
        bloomFilter.add("world");

        // 查询数据
        System.out.println(bloomFilter.contains("hello")); // true
        System.out.println(bloomFilter.contains("java"));  // false (可能)
    }
}
```

---

### **布隆过滤器在实际项目中的应用**

#### **场景：防止缓存穿透**

假设系统中有一个缓存层（如 Redis），以下是布隆过滤器的应用方式：

1. 在初始化阶段，将所有合法的键（如数据库中存在的 ID）加入布隆过滤器。
2. 每次查询时，先通过布隆过滤器判断：
    - 如果布隆过滤器判断某个键可能存在，则查询缓存或数据库。
    - 如果布隆过滤器判断某个键一定不存在，则直接返回空结果，避免缓存穿透。

#### **优化分布式爬虫去重**

1. 分布式爬虫需要记录已访问过的 URL。
2. 使用布隆过滤器存储 URL：
    - 在爬取新的 URL 前，检查布隆过滤器，避免重复访问。
    - 减少内存使用，适合大规模 URL 管理。

---

### **总结**

布隆过滤器是一个用于快速判断集合元素存在性的高效工具，适合在数据量大、对空间敏感的场景中应用。尽管存在假阳性，但在特定场景下（如防止缓存穿透或日志去重），布隆过滤器能够显著提高效率。

# 6. Redission中的布隆过滤器
### **使用Redisson实现布隆过滤器（Bloom Filter）**

### **1. 什么是布隆过滤器（Bloom Filter）？**

布隆过滤器（Bloom Filter）是一种**概率型数据结构**，用于判断某个元素是否存在于一个集合中：

- **可能存在**（可能误判）。
- **一定不存在**（不会误判）。

布隆过滤器相比传统的**Set或List**，具有：

- **占用内存少**：适用于超大数据量的存储。
- **查询速度快**：O(1)时间复杂度。
- **误判率**：可通过参数调整。

在Redis中，可以使用 **Redisson** 提供的布隆过滤器功能来高效实现这一机制。

---

### **2. Redisson布隆过滤器的基本使用**

Redisson 是 Redis 官方推荐的 Java 客户端之一，支持多种高级功能，如 **分布式锁、限流、布隆过滤器等**。

#### **2.1 依赖引入**

在 **Maven** 项目中引入 Redisson 依赖：

```xml
<dependency>
    <groupId>org.redisson</groupId>
    <artifactId>redisson</artifactId>
    <version>3.16.8</version>  <!-- 确保使用最新版本 -->
</dependency>
```

---

#### **2.2 Redisson布隆过滤器的使用**

```java
import org.redisson.api.RBloomFilter;
import org.redisson.api.RedissonClient;
import org.redisson.Redisson;
import org.redisson.config.Config;

public class RedissonBloomFilterExample {
    public static void main(String[] args) {
        // 1. 配置Redisson客户端
        Config config = new Config();
        config.useSingleServer().setAddress("redis://127.0.0.1:6379");
        RedissonClient redisson = Redisson.create(config);

        // 2. 创建布隆过滤器
        RBloomFilter<String> bloomFilter = redisson.getBloomFilter("user:bloomFilter");

        // 3. 初始化布隆过滤器：预计存储 100000 个元素，误判率 0.01（1%）
        bloomFilter.tryInit(100000L, 0.01);

        // 4. 添加数据到布隆过滤器
        bloomFilter.add("user1");
        bloomFilter.add("user2");
        bloomFilter.add("user3");

        // 5. 查询数据是否存在
        System.out.println("user1 是否存在：" + bloomFilter.contains("user1")); // true
        System.out.println("user4 是否存在：" + bloomFilter.contains("user4")); // 可能是 false

        // 6. 关闭Redisson客户端
        redisson.shutdown();
    }
}
```

---

### **3. Redisson布隆过滤器的核心参数**

布隆过滤器的精确度取决于 **元素数量** 和 **误判率**：

```java
bloomFilter.tryInit(100000L, 0.01);
```

- `100000L`：预计存储 100,000 个元素。
- `0.01`：误判率为 1%（即查询到的假阳性概率）。

> **误判率越低，布隆过滤器所占用的空间越大**。

---

### **4. Redis中的布隆过滤器存储**

在 Redis 里，布隆过滤器的底层实现基于 **位数组（Bit Array）**，其数据结构如下：

```shell
127.0.0.1:6379> keys *
1) "user:bloomFilter"
```

布隆过滤器的数据并不会存储实际的 Key，而是通过**多个 Hash 函数映射到位数组的不同位置**。

---

### **5. 布隆过滤器的应用场景**

布隆过滤器适用于大数据、高并发场景，防止缓存穿透和优化查询效率。

#### **5.1 防止缓存穿透**

**缓存穿透** 是指大量查询 **Redis 和数据库都不存在** 的 Key，导致所有请求直接进入数据库，影响系统性能。

> **解决方案**：
> 
> - 先使用布隆过滤器拦截不存在的 Key，减少数据库查询。

**示例：**

```java
String userKey = "user:12345";

if (!bloomFilter.contains(userKey)) {
    System.out.println("用户数据不存在，直接返回");
    return;
}

// 如果布隆过滤器中存在，再查 Redis 或数据库
String userData = jedis.get(userKey);
if (userData == null) {
    userData = queryDatabase(userKey);
    jedis.set(userKey, userData);
}
```

---

#### **5.2 防止重复请求**

在**短信验证码、支付接口防重**等场景中，可以使用布隆过滤器防止短时间内重复提交：

```java
if (bloomFilter.contains("sms:13500000000")) {
    System.out.println("验证码已发送，避免重复提交");
    return;
}
bloomFilter.add("sms:13500000000");
```

---

#### **5.3 大规模黑名单过滤**

如广告拦截、恶意 IP、垃圾邮件检测等。

```java
// 预先加载 1000 万个恶意 IP
bloomFilter.tryInit(10_000_000, 0.001);
bloomFilter.add("192.168.1.1");

if (bloomFilter.contains("192.168.1.1")) {
    System.out.println("该 IP 已被封禁");
}
```

---

### **6. 布隆过滤器的优缺点**

|**优点**|**缺点**|
|---|---|
|**占用空间小**：相比于 `Set`，大幅减少内存消耗。|**存在误判率**：可能会误判 Key 存在，但不会误判 Key 不存在。|
|**查询速度快**：O(1) 复杂度，适用于大规模数据。|**删除不支持**：无法直接删除元素（删除可能影响其他数据）。|
|**支持高并发**：Redis + Redisson 提供高效支持。|**动态扩容较难**：需要手动扩展布隆过滤器的容量。|

---

### **7. 布隆过滤器 vs 其他存储方式**

|**数据结构**|**占用内存**|**查询速度**|**是否支持删除**|**误判率**|
|---|---|---|---|---|
|**HashSet**|高|快（O(1)）|✅ 支持|❌ 无误判|
|**布隆过滤器**|低|快（O(1)）|❌ 不支持|✅ 可能误判|
|**MySQL索引**|高|慢（O(logN)）|✅ 支持|❌ 无误判|

布隆过滤器适用于：

- 数据量极大，不能全部存入 **HashSet** 或 **数据库索引** 的情况。
- 允许一定的误判（但不能有误判的场景不适合）。

---

### **8. 总结**

- **Redisson 提供了基于 Redis 的布隆过滤器（RBloomFilter）**，可用于**防止缓存穿透、黑名单过滤、接口幂等**等场景。
- **布隆过滤器的误判率可以调节**，但不能完全消除误判，适合用于 **"一定不存在"** 的判定。
- **相比传统的 Set，布隆过滤器节省内存**，适合处理**超大规模数据查询**。

**推荐：**

- **防止缓存穿透：** 在 Redis 之前加布隆过滤器拦截无效请求。
- **黑名单过滤：** 适用于广告屏蔽、恶意 IP 拦截、垃圾邮件检测等。
- **防止重复请求：** 适用于短信验证码、支付接口等。

Redisson 提供了简洁易用的 API，可以轻松实现 **高性能、低内存** 的布隆过滤器方案 🚀。

# 7. ConcurrentHashMap
---

## 🌟 一句话总结

> **ConcurrentHashMap 通过分段思想 + CAS + synchronized + volatile 实现线程安全，同时尽量避免锁的竞争，提高并发性能。**

---

## 🔧 一、核心数据结构（Java 8）

```java
transient volatile Node<K,V>[] table;
```

- 使用一个 `Node[] table` 数组存储数据，类似 HashMap。
    
- 每个桶位（table[i]）可能是：
    
    - 空
        
    - 单个节点
        
    - 链表节点
        
    - 红黑树（当链表长度超过阈值时）
        

---

## 🚦 二、线程安全的关键点

### ✅ 1. 写操作（put）的线程安全

```java
public V put(K key, V value) {
    return putVal(key, value, false);
}
```

关键方法：`putVal`

- **定位桶位**：
    
    - 根据 key 计算 hash，然后定位 table 中的 index（与 HashMap 相似）。
        
- **桶为空时 CAS 插入**：
    
    - 使用 `CAS`（Compare-And-Swap）原子操作插入首节点，无需加锁。
        
        ```java
        if (casTabAt(tab, i, null, new Node<>(...)))
        ```
        
- **桶不为空时使用 synchronized 加锁桶头节点**
    
    - 对某个桶头节点加锁（**锁粒度缩小到桶级别**）
        
        ```java
        synchronized (f) { ... }
        ```
        
    - 然后进行链表遍历或树插入操作。
        
- **链表转红黑树**：
    
    - 如果某个桶链表长度超过 8，转为红黑树（提高查找效率）。
        

### 🚨 为什么可以只锁桶而不是整个表？

- 因为只对 `table[i]` 操作，所以只需锁定该槽位即可。
    
- 多个线程可以并发操作不同的桶，互不影响，提高并发性。
    

---

### ✅ 2. 读操作（get）的线程安全

- **get 操作不加锁**，基于 `volatile` + 内存可见性。
    
    - `Node[] table` 和链表的 `next` 节点都是 `volatile` 修饰，保证对其他线程可见。
        
    - 即使在遍历链表或树时有并发写入，也能保证不会读取到不一致的状态（但数据可能是旧的，不影响正确性）。
        

---

### ✅ 3. 扩容时线程安全

- 和 HashMap 一样，当容量超过阈值（默认是 0.75 * capacity）时会触发扩容。
    
- **多个线程可以协同完成扩容！**（这是 ConcurrentHashMap 的亮点）
    

#### 扩容策略（transfer）：

- 每个线程帮助迁移部分桶的数据到新表（通过 `stride` 步长分配任务）。
    
- 使用 `ForwardingNode` 标记已经迁移的桶，防止重复迁移。
    
- 在扩容时，写操作仍然可以进行，但新的数据写入的是新表（newTable）。
    

---

## 🔍 三、对比 HashMap 与 Hashtable

|特性|HashMap|Hashtable|ConcurrentHashMap|
|---|---|---|---|
|线程安全|否|是（整个方法加 synchronized）|是（分段+CAS+synchronized）|
|性能|高（非线程安全）|低（锁整个表）|高（细粒度锁）|
|null 键/值|允许|不允许|不允许|
|使用场景|单线程|低并发线程|高并发线程|


## 💡 五、总结：ConcurrentHashMap 如何实现线程安全？

|安全手段|用途|
|---|---|
|`CAS`|插入桶头节点、控制状态（如初始化标志）|
|`synchronized`|对桶节点加锁（不是全表锁）|
|`volatile`|保证变量内存可见性（如 table 数组、链表指针）|
|分段思想|桶级别的加锁，降低锁粒度，提高并发性能|
|红黑树 + 链表|控制冲突桶的性能问题|
|并发协助扩容|多线程协同扩容，提高扩容效率|

---

如果你面试时被问到：

> “ConcurrentHashMap 为什么线程安全，性能又高？”

你可以这样回答：

✅ 它通过 **CAS + synchronized + volatile** 保证并发安全  
✅ **只对冲突桶加锁**，而不是整张表，锁粒度小  
✅ **读操作无锁**，写操作局部加锁  
✅ 支持 **并发扩容**，提升了扩容阶段的性能  
✅ 数据结构优化（链表+红黑树）减少 hash 冲突影响
