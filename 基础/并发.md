# 1. Java的线程同步
1. 在 Java 中，线程同步是用于控制多个线程对共享资源访问的机制，以防止数据不一致和竞争条件。以下是 Java 中常用的线程同步方法和机制的概述：

## 1. **内置锁（synchronized）**

Java 提供了 `synchronized` 关键字来实现线程同步。可以用于方法或代码块，确保同一时刻只有一个线程可以访问被保护的资源。
- **同步实例方法**：作用于当前实例对象，确保同一对象的实例方法在多线程下同步访问
  ```java
  public synchronized void syncMethod() {
      // 访问共享资源
  }
  ```
- **同步静态方法**：作用于当前类对象（Class级别），适用于静态成员变量的同步操作
  ```java
  public static synchronized void syncStaticMethod() {
      // 访问共享资源
  }
  ```
- **同步代码块**：可以同步某段代码，并指定锁对象（如`this`、特定对象）
  ```java
  public void someMethod() {
      synchronized (this) { // 或者可以是一个对象
          // 访问共享资源
      }
  }
  ```

## 2. **ReentrantLock**

这是 `java.util.concurrent.locks` 包中的一个更灵活的锁实现，可以替代内置的 `synchronized`。它提供了尝试锁定、可中断的锁定和公平性等高级特性。
- **示例**：
  ```java
  import java.util.concurrent.locks.ReentrantLock;
  
  public class Example {
      private final ReentrantLock lock = new ReentrantLock();
  
      public void criticalSection() {
          lock.lock();
          try {
              // 访问共享资源
          } finally {
              lock.unlock();
          }
      }
  }
  ```

## 3. **读写锁（ReentrantReadWriteLock）**

`ReadWriteLock` 允许多个线程同时读取共享资源，但在写入时会阻止其他线程的读写操作。如果写操作频繁，可能导致读操作被阻塞，进而降低性能。

- **示例**：
  
  ```java
  import java.util.concurrent.locks.ReentrantReadWriteLock;
  
  public class Example {
      private final ReentrantReadWriteLock rwLock = new ReentrantReadWriteLock();
  
      public void read() {
          rwLock.readLock().lock();
          try {
              // 读取共享资源
          } finally {
              rwLock.readLock().unlock();
          }
      }
  
      public void write() {
          rwLock.writeLock().lock();
          try {
              // 写入共享资源
          } finally {
              rwLock.writeLock().unlock();
          }
      }
  }
  ```

## 4. **条件变量（Condition）**

`Condition` 是与 `ReentrantLock` 一起使用的，用于线程间的通信。它允许线程在某些条件下进行等待和通知。
- **示例**：
  ```java
  import java.util.concurrent.locks.Condition;
  import java.util.concurrent.locks.Lock;
  import java.util.concurrent.locks.ReentrantLock;
  
  public class ConditionExample {
      private final Lock lock = new ReentrantLock();
      private final Condition notEmpty = lock.newCondition();
      private final Condition notFull = lock.newCondition();
  
      private final int[] buffer = new int[10]; // 缓冲区
      private int count = 0; // 缓冲区中的元素数量
      private int putIndex = 0; // 写指针
      private int takeIndex = 0; // 读指针
  
      public void put(int value) throws InterruptedException {
          lock.lock();
          try {
              while (count == buffer.length) {
                  // 缓冲区满，等待
                  notFull.await();
              }
              // 写入数据
              buffer[putIndex] = value;
              putIndex = (putIndex + 1) % buffer.length;
              count++;
              System.out.println("Produced: " + value);
  
              // 唤醒消费者
              notEmpty.signal();
          } finally {
              lock.unlock();
          }
      }
  
      public int take() throws InterruptedException {
          lock.lock();
          try {
              while (count == 0) {
                  // 缓冲区空，等待
                  notEmpty.await();
              }
              // 读取数据
              int value = buffer[takeIndex];
              takeIndex = (takeIndex + 1) % buffer.length;
              count--;
              System.out.println("Consumed: " + value);
  
              // 唤醒生产者
              notFull.signal();
              return value;
          } finally {
              lock.unlock();
          }
      }
  
      public static void main(String[] args) {
          ConditionExample example = new ConditionExample();
  
          // 启动生产者线程
          new Thread(() -> {
              try {
                  for (int i = 0; i < 20; i++) {
                      example.put(i);
                      Thread.sleep(100);
                  }
              } catch (InterruptedException e) {
                  Thread.currentThread().interrupt();
              }
          }).start();
  
          // 启动消费者线程
          new Thread(() -> {
              try {
                  for (int i = 0; i < 20; i++) {
                      example.take();
                      Thread.sleep(200);
                  }
              } catch (InterruptedException e) {
                  Thread.currentThread().interrupt();
              }
          }).start();
      }
  }
  ```
## 5. **使用原子变量**
Java 提供了 `java.util.concurrent.atomic` 包中的原子变量类，允许线程安全地对单个变量进行操作，而不需要使用锁。
- **示例**：
  ```java
  import java.util.concurrent.atomic.AtomicInteger;
  
  public class Example {
      private AtomicInteger counter = new AtomicInteger(0);
  
      public void increment() {
          counter.incrementAndGet(); // 线程安全的自增操作
      }
  }
  
  //解决ABA问题
  import java.util.concurrent.atomic.AtomicStampedReference;
  
  public class AtomicStampedReferenceExample {
      public static void main(String[] args) {
          AtomicStampedReference<String> ref = new AtomicStampedReference<>("Initial", 0);
  
          // 获取当前值和版本号
          int[] stampHolder = new int[1];
          String value = ref.get(stampHolder);
          System.out.println("Value: " + value + ", Stamp: " + stampHolder[0]);
  
          // CAS 操作
          boolean updated = ref.compareAndSet("Initial", "Updated", stampHolder[0], stampHolder[0] + 1);
          System.out.println("Updated: " + updated + ", New Value: " + ref.getReference() + ", New Stamp: " + ref.getStamp());
      }
  }
  
  ```
## 6. **ThreadLocal**
`ThreadLocal` 提供了线程局部变量，每个线程都有自己的独立副本，避免了线程间的竞争和同步问题。
- **示例**：
  ```java
  public class Example {
      private ThreadLocal<Integer> threadLocalValue = ThreadLocal.withInitial(() -> 0);
  
      public void someMethod() {
          threadLocalValue.set(threadLocalValue.get() + 1);
      }
  }
  ```
## 总结
在 Java 中，线程同步是确保多个线程安全访问共享资源的重要机制。根据具体需求，可以选择不同的同步方法，如 `synchronized`、`ReentrantLock`、`ReadWriteLock`、条件变量、原子变量和 `ThreadLocal`。合理使用这些机制可以有效防止数据不一致和竞争条件，提高多线程应用的稳定性和性能。

# 2. 虚拟线程
1. 虚拟线程是 Java 19 引入的一项新特性，旨在简化并发编程并提高应用程序的可扩展性。虚拟线程是轻量级线程，允许开发者更高效地使用线程，尤其是在处理大量并发任务时。以下是关于虚拟线程的详细介绍。
## 什么是虚拟线程？
虚拟线程是 Java 的一种新类型线程，它们在 JVM 中的管理方式与传统的操作系统线程不同。虚拟线程的主要特点包括：
- **轻量级**：虚拟线程的创建和管理开销较小，可以在 JVM 中创建成千上万的虚拟线程，而不必担心系统资源的耗尽。
- **非阻塞**：虚拟线程可以在 IO 操作中非阻塞地挂起，使得 CPU 可以继续执行其他任务，提升整体的并发性能。
- **简化的编程模型**：虚拟线程使得编写并发代码更简单，程序员可以像编写普通的顺序代码一样处理并发任务。
## 主要特性
1. **简化的线程管理**：
   - 使用虚拟线程，开发者可以专注于业务逻辑，而不必过多关注线程的创建、管理和销毁。
2. **高并发处理**：
   - 虚拟线程可以轻松处理大量并发连接，如网络服务器或高频交易应用，极大地提升了应用的可扩展性。
3. **协作式调度**：
   - 虚拟线程采用协作式调度，允许线程在 IO 操作时挂起，待 IO 完成后再恢复执行。这种方式比传统的操作系统线程更高效。
## 使用虚拟线程
在 Java 中，使用虚拟线程非常简单。以下是一个基本示例：
```java
public class VirtualThreadExample {
    public static void main(String[] args) {
        // 创建一个虚拟线程
        Thread vThread = Thread.ofVirtual().start(() -> {
            System.out.println("Hello from virtual thread!");
        });

        // 等待虚拟线程完成
        vThread.join();
    }
}
```
## 适用场景
虚拟线程适合以下场景：
- **高并发服务器**：如 Web 服务器和微服务架构，能够处理大量并发请求。
- **网络应用**：能够有效管理大量的网络连接而不消耗过多的系统资源。
- **IO 密集型任务**：如文件处理、数据库查询等操作，可以利用虚拟线程的非阻塞特性，提高性能。
## 注意事项
1. **兼容性**：虚拟线程是 Java 19 引入的实验性特性，可能会在未来版本中进行调整。
2. **调试和监控**：由于虚拟线程的轻量特性，传统的线程监控工具可能无法有效监控它们。
3. **性能考量**：虽然虚拟线程在 IO 密集型任务中表现良好，但在 CPU 密集型任务中，仍然需要考虑线程的调度和管理。
## 总结
虚拟线程是 Java 语言在并发编程方面的重要进展，它提供了一个简单而高效的方式来处理大量的并发任务。通过虚拟线程，开发者可以轻松编写高性能的并发应用，特别是在高并发和 IO 密集型场景中。随着 Java 的不断发展，虚拟线程有望成为现代 Java 开发中一个重要的组成部分。

# 3. 线程池
1. 线程池是用于管理和复用一组线程的技术，以提高应用程序的性能和资源利用率。它通过减少线程创建和销毁的开销，允许多个任务共享一组线程。以下是关于 Java 中线程池的详细介绍。
## 1. **线程池的概念**
- **线程复用**：线程池通过复用线程，避免频繁创建和销毁线程带来的性能开销。
- **任务管理**：线程池可以管理多个任务的执行，包括任务的调度、执行、失败重试等。
- **资源控制**：通过限制活动线程的数量，线程池可以有效控制资源使用，避免系统过载。
## 2. **Java 中的线程池**
Java 提供了 `java.util.concurrent` 包中的 `Executor` 框架来实现线程池。主要接口和类包括：
- **Executor**：顶层接口，用于定义任务的执行。
- **ExecutorService**：扩展了 `Executor` 接口，提供了更多的功能，比如关闭线程池、获取任务执行结果等。
- **ThreadPoolExecutor**：具体实现类，提供了灵活的线程池配置选项。
## 3. **创建线程池**
可以使用 `Executors` 工具类来创建不同类型的线程池。以下是常见的线程池类型及其创建方法：
- **固定大小线程池**：
  
  ```java
  ExecutorService fixedThreadPool = Executors.newFixedThreadPool(5);
  ```
- **可缓存线程池**：
  ```java
  ExecutorService cachedThreadPool = Executors.newCachedThreadPool();
  ```
- **单线程池**：
  ```java
  ExecutorService singleThreadPool = Executors.newSingleThreadExecutor();
  ```
- **定时线程池**：
  ```java
  ScheduledExecutorService scheduledThreadPool = Executors.newScheduledThreadPool(5);
  ```
## 4. **使用线程池执行任务**
通过 `ExecutorService` 接口提交任务并执行：
```java
ExecutorService executor = Executors.newFixedThreadPool(3);

Runnable task = () -> {
    System.out.println("Task executed by " + Thread.currentThread().getName());
};

// 提交任务
executor.submit(task);

// 关闭线程池
executor.shutdown();
```
## 5. **线程池配置**
`ThreadPoolExecutor` 提供了多种参数来配置线程池的行为：
- **核心线程数**：始终保持活动的线程数量。
- **最大线程数**：线程池能容纳的最大线程数量。
- **空闲线程存活时间**：当线程空闲时，保持活跃的时间。
- **任务队列**：用于存放待执行任务的队列，如有界队列和无界队列。
- **拒绝策略**：当线程池已满且任务队列也满时的处理策略。
## 6. **常用的拒绝策略**
Java 提供了几种内置的拒绝策略，用户也可以自定义：
- **AbortPolicy**：抛出异常，默认策略。
- **CallerRunsPolicy**：调用者所在的线程执行任务。
- **DiscardPolicy**：丢弃任务，不抛出异常。
- **DiscardOldestPolicy**：丢弃最旧的任务，尝试执行当前任务。
## 7. **监控线程池**
可以通过 `ThreadPoolExecutor` 的方法监控线程池的状态，如：
- `getPoolSize()`：获取当前线程池的线程数量。
- `getActiveCount()`：获取正在执行的线程数量。
- `getCompletedTaskCount()`：获取已完成的任务数量。
## 8. **总结**
线程池是一种有效管理多线程的技术，能够提高程序性能和资源利用率。Java 提供了强大的 `Executor` 框架，使得使用线程池变得简单和灵活。合理配置和使用线程池可以显著提升应用程序的并发处理能力。

# 4. 线程池的异常捕捉
在 Java 中，使用线程池执行任务时，如果任务内部出现异常，默认情况下线程池不会直接报告异常，也不会提供异常发生的线程信息。然而，可以通过一些方法来捕获和处理这些异常，以便识别出是哪个线程出现了问题。以下是一些常见的做法：
## 1. **使用 `Future` 和 `ExecutorService`**
`ExecutorService` 的 `submit` 方法返回一个 `Future` 对象，你可以通过 `Future` 来检查任务的执行状态和捕获异常。
```java
import java.util.concurrent.*;

public class ThreadPoolExceptionHandling {
    public static void main(String[] args) {
        ExecutorService executor = Executors.newFixedThreadPool(3);

        for (int i = 0; i < 5; i++) {
            final int taskId = i;
            Future<?> future = executor.submit(() -> {
                if (taskId == 2) {
                    throw new RuntimeException("Exception in task " + taskId);
                }
                System.out.println("Task " + taskId + " completed.");
            });

            try {
                // 等待任务完成并获取结果，抛出任务内部的异常
                future.get();
            } catch (ExecutionException e) {
                // 捕获任务执行中的异常
                System.err.println("Task " + taskId + " failed with exception: " + e.getCause());
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt(); // 恢复中断状态
            }
        }

        executor.shutdown();
    }
}
```

## 2. **使用自定义 `ThreadFactory`**

你可以创建一个自定义的 `ThreadFactory`，在创建线程时为每个线程设置一个名称，以便更容易追踪异常发生的线程。

```java
import java.util.concurrent.*;

public class CustomThreadFactoryExample {
    public static void main(String[] args) {
        ExecutorService executor = Executors.newFixedThreadPool(3, new CustomThreadFactory());

        for (int i = 0; i < 5; i++) {
            final int taskId = i;
            executor.submit(() -> {
                if (taskId == 2) {
                    throw new RuntimeException("Exception in task " + taskId);
                }
                System.out.println("Task " + taskId + " completed.");
            });
        }

        executor.shutdown();
    }

    static class CustomThreadFactory implements ThreadFactory {
        private int threadCount = 0;

        @Override
        public Thread newThread(Runnable r) {
            Thread thread = new Thread(r);
            thread.setName("CustomThread-" + threadCount++);
            thread.setUncaughtExceptionHandler((t, e) -> {
                System.err.println("Uncaught exception in thread " + t.getName() + ": " + e.getMessage());
            });
            return thread;
        }
    }
}
```

## 3. **实现 `Runnable` 或 `Callable` 接口的异常处理**

在实现 `Runnable` 或 `Callable` 的 `run` 或 `call` 方法时，捕获并处理异常，也可以在日志中记录线程信息。

```java
class MyTask implements Callable<Void> {
    private final int taskId;

    public MyTask(int taskId) {
        this.taskId = taskId;
    }

    @Override
    public Void call() {
        try {
            if (taskId == 2) {
                throw new RuntimeException("Exception in task " + taskId);
            }
            System.out.println("Task " + taskId + " completed.");
        } catch (Exception e) {
            System.err.println("Task " + taskId + " failed with exception: " + e.getMessage());
        }
        return null;
    }
}
```

## 4. **使用 `Future.get()` 方法**

如前所述，通过 `Future.get()` 方法可以捕获任务执行中的异常。这种方法可以帮助你在调用时明确知道哪个任务发生了异常。

## 总结

在使用线程池进行任务处理时，捕获和识别异常是非常重要的。通过使用 `Future`、自定义 `ThreadFactory`、实现异常处理逻辑，你可以有效地追踪和处理任务执行中的异常。这不仅能帮助你识别出错误的线程，还能提高代码的健壮性和可维护性。

# 5. 常见的并发工具类
Java 提供了多种并发工具类，主要集中在 `java.util.concurrent` 包中。这些工具类帮助开发者更容易地实现多线程编程，管理线程池、任务调度、同步等。以下是一些常见的 Java 并发工具类及其用途：

## 1. **Executor Framework**

- **Executor**：顶层接口，定义了执行异步任务的基本方法。
- **ExecutorService**：扩展 `Executor` 接口，提供了管理线程池和任务执行的高级功能。
- **ThreadPoolExecutor**：最常用的线程池实现，支持灵活的配置。
- **ScheduledExecutorService**：用于定时或周期性任务的执行。

### 示例：
```java
ExecutorService executor = Executors.newFixedThreadPool(5);
executor.submit(() -> {
    // 任务代码
});
executor.shutdown();
```

## 2. **Future**

- **Future**：表示异步计算的结果，提供方法来检查任务是否完成、等待任务完成并获取结果，以及取消任务。
  
### 示例：
```java
Future<Integer> future = executor.submit(() -> {
    // 长时间运行的任务
    return 42;
});
try {
    Integer result = future.get(); // 等待并获取结果
} catch (ExecutionException e) {
    // 处理异常
}
```

## 3. **CountDownLatch**

- **CountDownLatch**：用于在多个线程之间协作，允许一个或多个线程等待其他线程完成操作。
### 示例：
```java
CountDownLatch latch = new CountDownLatch(3);
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // 执行任务
        latch.countDown(); // 计数减一
    }).start();
}
latch.await(); // 等待计数为零
```

## 4. **CyclicBarrier**

- **CyclicBarrier**：使一组线程在某个点上相互等待，直到所有线程都到达该点。可以重用。

### 示例：
```java
CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    // 所有线程到达后执行的操作
});
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // 执行任务
        barrier.await(); // 等待其他线程
    }).start();
}
```

## 5. **Semaphore**

- **Semaphore**：用于控制对某个资源的访问数量。可以限制同时访问某个资源的线程数量。

### 示例：
```java
Semaphore semaphore = new Semaphore(2); // 允许两个线程同时访问
try {
    semaphore.acquire(); // 请求许可证
    // 执行任务
} finally {
    semaphore.release(); // 释放许可证
}
```

## 6. **ReentrantLock**

- **ReentrantLock**：可重入的锁，提供比 `synchronized` 更灵活的锁机制。支持公平锁和非公平锁。

### 示例：
```java
ReentrantLock lock = new ReentrantLock();
lock.lock();
try {
    // 访问共享资源
} finally {
    lock.unlock();
}
```

## 7. **ReadWriteLock**

- **ReadWriteLock**：允许多个线程同时读取，但在写入时会锁定，适用于读多写少的场景。

### 示例：
```java
ReadWriteLock rwLock = new ReentrantReadWriteLock();
rwLock.readLock().lock();
try {
    // 读取共享资源
} finally {
    rwLock.readLock().unlock();
}
```

## 8. **Exchanger**

- **Exchanger**：用于两个线程之间交换数据的同步点。

### 示例：
```java
Exchanger<String> exchanger = new Exchanger<>();
new Thread(() -> {
    try {
        String data = "Data from thread 1";
        String response = exchanger.exchange(data); // 交换数据
    } catch (InterruptedException e) {
        // 处理异常
```

# 6. 控制线程的执行顺序
在 Java 中，控制线程的执行顺序是确保多线程程序按预期执行的关键。以下是一些常用的方法和工具，帮助你控制线程的执行顺序：

## 1. **使用 `Join` 方法**

`Thread.join()` 方法可以让一个线程等待另一个线程完成。通过调用 `join()`，你可以确保某个线程在另一个线程执行完成后才继续执行。

```java
public class ThreadJoinExample {
    public static void main(String[] args) {
        Thread thread1 = new Thread(() -> {
            System.out.println("Thread 1 is running");
        });

        Thread thread2 = new Thread(() -> {
            System.out.println("Thread 2 is running");
        });

        thread1.start();
        try {
            thread1.join(); // 主线程等待 thread1 完成
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
        thread2.start();
    }
}
```

## 2. **使用 `CountDownLatch`**

`CountDownLatch` 允许一个或多个线程等待直到一组操作完成。可以用来控制线程的执行顺序。

```java
import java.util.concurrent.CountDownLatch;

public class CountDownLatchExample {
    public static void main(String[] args) {
        CountDownLatch latch = new CountDownLatch(1);

        Thread thread1 = new Thread(() -> {
            System.out.println("Thread 1 is running");
            latch.countDown(); // 完成后释放 latch
        });

        Thread thread2 = new Thread(() -> {
            try {
                latch.await(); // 等待 thread1 完成
                System.out.println("Thread 2 is running");
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        });

        thread1.start();
        thread2.start();
    }
}
```

## 3. **使用 `CyclicBarrier`**

`CyclicBarrier` 允许多个线程在某个点上相互等待，直到所有线程都到达该点。可以用来控制多线程的执行阶段。

```java
import java.util.concurrent.CyclicBarrier;

    public static void main(String[] args) {
        CyclicBarrier barrier = new CyclicBarrier(2, () -> {
            System.out.println("Both threads have reached the barrier.");
        });

        Thread thread1 = new Thread(() -> {
            System.out.println("Thread 1 is running");
            try {
                barrier.await(); // 等待另一个线程
            } catch (Exception e) {
                e.printStackTrace();
            }
        });

        Thread thread2 = new Thread(() -> {
            System.out.println("Thread 2 is running");
            try {
                barrier.await(); // 等待另一个线程
            } catch (Exception e) {
                e.printStackTrace();
            }
        });

        thread1.start();
        thread2.start();
    }
}
```

## 4. **使用 `Semaphore`**

`Semaphore` 可以用于控制对共享资源的访问，并且可以配置许可数量，从而控制线程的执行顺序。

```java
import java.util.concurrent.Semaphore;

public class SemaphoreExample {
    public static void main(String[] args) {
        Semaphore semaphore = new Semaphore(1); // 只有一个许可

        Thread thread1 = new Thread(() -> {
            try {
                semaphore.acquire(); // 获取许可
                System.out.println("Thread 1 is running");
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                semaphore.release(); // 释放许可
            }
        });

        Thread thread2 = new Thread(() -> {
            try {
                semaphore.acquire(); // 等待许可
                System.out.println("Thread 2 is running");
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                semaphore.release(); // 释放许可
            }
        });

        thread1.start();
        thread2.start();
    }
}
```

## 5. **使用 `ReentrantLock` 和 条件变量**

使用 `ReentrantLock` 结合条件变量（`Condition`）可以实现更复杂的线程顺序控制。

```java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

public class ReentrantLockExample {
    private static final ReentrantLock lock = new ReentrantLock();
    private static final Condition condition = lock.newCondition();
    private static boolean isThread1Done = false;

    public static void main(String[] args) {
        Thread thread1 = new Thread(() -> {
            lock.lock();
            try {
                System.out.println("Thread 1 is running");
                isThread1Done = true;
                condition.signal(); // 通知 thread2
            } finally {
                lock.unlock();
            }
        });

        Thread thread2 = new Thread(() -> {
            lock.lock();
            try {
                while (!isThread1Done) {
                    condition.await(); // 等待 thread1 完成
                }
                System.out.println("Thread 2 is running");
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                lock.unlock();
            }
        });

        thread1.start();
        thread2.start();
    }
}
```

通过使用上述方法，你可以有效地控制 Java 中线程的执行顺序。选择合适的工具或方法取决于你的具体需求和应用场景。在多线程编程中，控制执行顺序可以提高程序的可预测性和稳定性。

# 7. CAS
CAS（Compare and Swap）是一种用于实现并发控制的原子操作，广泛应用于多线程编程中。它是一种无锁的机制，能够在不使用传统锁的情况下，安全地更新共享数据。以下是对 CAS 的详细介绍。

## CAS 的基本概念

CAS 操作包含三个参数：
1. **内存位置**（V）：需要更新的变量的内存地址。
2. **旧值**（A）：希望更新的值的当前值。
3. **新值**（B）：希望设置的新值。

CAS 操作的逻辑是：
- 如果内存位置的当前值等于旧值（A），则将内存位置的值更新为新值（B）。
- 如果不相等，则不进行任何操作。

## 工作原理

CAS 是一种原子操作，通常由 CPU 提供并支持。它确保在多线程环境中，多个线程对同一数据的更新不会导致数据的不一致。

1. 线程读取内存位置的当前值。
2. 线程比较当前值与预期的旧值。
3. 如果相等，线程更新内存位置的值为新值；否则，线程重试。

## 使用 CAS 的优点

- **无锁**：CAS 是一种无锁操作，减少了线程上下文切换的开销，提高了性能。
- **高效性**：在竞争不激烈的情况下，CAS 操作通常比使用锁更高效。
- **简单性**：在某些情况下，CAS 提供了更简单的编程模型，避免了死锁和饥饿问题。

## 使用 CAS 的缺点

- **ABA 问题**：如果某个线程在检查和更新之间，另一个线程将值更改为另一个值，再改回原值，CAS 操作会误认为没有发生变化。可以通过引入版本号或使用其他机制来解决。
- **自旋**：在高竞争的情况下，CAS 可能导致线程不断重试（自旋），从而消耗 CPU 资源。
- **复杂性**：在复杂的数据结构中，使用 CAS 可能会使代码变得复杂。

## Java 中的 CAS 实现

Java 提供了原子变量类，使用 CAS 操作实现线程安全的操作。这些类位于 `java.util.concurrent.atomic` 包中。以下是常见的原子变量类和示例：

1. **AtomicInteger**:
   ```java
   import java.util.concurrent.atomic.AtomicInteger;
   
   public class AtomicIntegerExample {
       public static void main(String[] args) {
           AtomicInteger atomicInt = new AtomicInteger(0);
           
           // CAS 操作
           int oldValue = atomicInt.get(); // 获取当前值
           int newValue = oldValue + 1;     // 计算新值
           boolean success = atomicInt.compareAndSet(oldValue, newValue); // 尝试更新
           
           if (success) {
               System.out.println("Updated successfully: " + atomicInt.get());
           } else {
               System.out.println("Update failed.");
           }
       }
   }
   ```

2. **AtomicReference**:
   ```java
   import java.util.concurrent.atomic.AtomicReference;
   
   public class AtomicReferenceExample {
       public static void main(String[] args) {
           AtomicReference<String> atomicRef = new AtomicReference<>("Initial");
   
           // CAS 操作
           String oldValue = atomicRef.get();
           String newValue = "Updated";
           boolean success = atomicRef.compareAndSet(oldValue, newValue);
           
           if (success) {
               System.out.println("Updated successfully to: " + atomicRef.get());
           } else {
               System.out.println("Update failed.");
           }
       }
   }
   ```

## 总结

CAS 是一种强大的并发控制机制，能够在多线程环境中安全地更新共享变量。虽然它具有许多优点，如无锁和高效性，但也存在一些挑战，如 ABA 问题和自旋开销。在 Java 中，CAS 的实现通过原子变量类提供，简化了并发编程的复杂性，提升了性能。在设计并发系统时，理解 CAS 的工作原理及其适用场景非常重要。


# 8.AQS
### **AQS (AbstractQueuedSynchronizer)**

`AQS` 是 Java 并发包（`java.util.concurrent`）中的核心框架，用于实现锁和同步器（如 `ReentrantLock`、`Semaphore`、`CountDownLatch` 等）。它通过一个**FIFO 队列**管理线程，并提供了一种模板方法来帮助构建锁或其他同步器。

---

### **AQS 的核心组成**

1. **共享资源（state）**
   
    - AQS 使用一个 `int state` 变量表示共享资源，可以通过以下方法操作：
        - `getState()`：获取当前状态值。
        - `setState(int newState)`：设置状态值。
        - `compareAndSetState(int expect, int update)`：CAS 操作修改状态，确保原子性。
2. **等待队列**
   
    - AQS 维护一个 FIFO 的**等待队列**，当线程获取资源失败时会被加入到此队列中。
    - 节点结构：`Node`，用于表示等待线程。
        - **Exclusive 模式**：独占模式，如 `ReentrantLock`。
        - **Shared 模式**：共享模式，如 `Semaphore`。
3. **线程排队与唤醒机制**
   
    - 队列中节点通过 `prev` 和 `next` 链接形成双向链表。
    - 当线程释放资源时，会从队列中唤醒下一个节点。

---

### **AQS 的两种模式**

1. **独占模式 (Exclusive)**
   
    - 一个线程独占资源，其他线程必须等待。例如，`ReentrantLock`。
2. **共享模式 (Shared)**
   
    - 多个线程可以共享资源。例如，`Semaphore` 和 `CountDownLatch`。

---

### **AQS 的核心方法**

#### **模板方法**

这些方法需要子类重写，用于定义具体的同步逻辑：

- `tryAcquire(int arg)`：
    - 尝试获取资源，返回 `true` 表示成功。
    - 子类需要实现。
- `tryRelease(int arg)`：
    - 尝试释放资源，返回 `true` 表示释放成功。
    - 子类需要实现。
- `tryAcquireShared(int arg)`：
    - 尝试以共享模式获取资源，返回 >= 0 表示成功。
    - 子类需要实现。
- `tryReleaseShared(int arg)`：
    - 尝试以共享模式释放资源，返回 `true` 表示释放成功。
    - 子类需要实现。

#### **线程排队与唤醒**

- `acquire(int arg)`：以独占模式获取资源，如果获取失败，线程进入等待队列。
- `release(int arg)`：释放资源并唤醒等待队列中的下一个线程。
- `acquireShared(int arg)`：以共享模式获取资源。
- `releaseShared(int arg)`：以共享模式释放资源。

---

### **工作原理**

1. **获取资源**
   
    - 调用 `acquire(int arg)` 或 `acquireShared(int arg)`。
    - 检查当前状态 `state` 是否满足条件：
        - 如果满足，通过 CAS 操作更新 `state` 并成功返回。
        - 如果不满足，将当前线程包装为 `Node`，加入等待队列。
2. **释放资源**
   
    - 调用 `release(int arg)` 或 `releaseShared(int arg)`。
    - 更新 `state`，并从等待队列中唤醒下一个线程。
3. **等待队列**
   
    - 使用链表形式组织等待线程。
    - 每个线程在失败时会被封装为一个 `Node`，加入队列尾部。
    - 队列头表示当前持有资源的线程，释放时会唤醒下一个线程。

---

### **AQS 结构示意图**

1. **等待队列**
   
    ```
    Head -> Node1 -> Node2 -> Node3 -> Tail
    ```
    
    - `Head` 是哨兵节点，不存储线程，仅作为队列起点。
    - 每个节点关联一个等待线程。
    - FIFO 顺序：头部节点先唤醒。
2. **状态变化**
   
    ```
    state = 0 (资源空闲)
    state = 1 (资源被占用)
    ```
    

---

### **常见实现类**

1. **ReentrantLock**
   
    - 独占模式实现。
    - 使用 `tryAcquire` 和 `tryRelease` 实现加锁与解锁。
2. **Semaphore**
   
    - 共享模式实现。
    - 使用 `tryAcquireShared` 和 `tryReleaseShared` 实现信号量。
3. **CountDownLatch**
   
    - 共享模式实现。
    - 主线程等待其他线程完成工作，通过减少 `state` 到 0 来释放等待线程。
4. **ReentrantReadWriteLock**
   
    - 同时支持独占和共享模式。

---

### **代码示例：自定义独占锁**

以下是一个基于 AQS 的自定义独占锁实现：

```java
import java.util.concurrent.locks.AbstractQueuedSynchronizer;

public class MyLock {
    private final Sync sync = new Sync();

    // 内部类，继承 AQS
    private static class Sync extends AbstractQueuedSynchronizer {
        @Override
        protected boolean tryAcquire(int arg) {
            if (compareAndSetState(0, 1)) { // CAS 修改 state
                setExclusiveOwnerThread(Thread.currentThread()); // 设置当前线程为独占线程
                return true;
            }
            return false;
        }

        @Override
        protected boolean tryRelease(int arg) {
            if (getState() == 0) {
                throw new IllegalMonitorStateException();
            }
            setExclusiveOwnerThread(null); // 清除独占线程
            setState(0); // 修改 state 为 0
            return true;
        }

        @Override
        protected boolean isHeldExclusively() {
            return getState() == 1;
        }
    }

    public void lock() {
        sync.acquire(1); // 获取锁
    }

    public void unlock() {
        sync.release(1); // 释放锁
    }

    public boolean isLocked() {
        return sync.isHeldExclusively();
    }
}
```

---

### **代码解析**

1. **继承 AQS 实现同步逻辑**
   
    - `tryAcquire`：当 `state` 为 0 时，通过 CAS 设置为 1 并返回成功。
    - `tryRelease`：释放锁时，将 `state` 置为 0。
2. **同步操作**
   
    - 调用 `acquire(1)`，如果失败，线程进入等待队列。
    - 调用 `release(1)`，释放锁并唤醒等待队列中的线程。
3. **线程安全**
   
    - `compareAndSetState` 确保了状态修改的原子性。
    - AQS 的队列机制保证了线程的 FIFO 顺序。

---

### **常见面试问题**

1. **AQS 为什么使用队列管理线程？**
   
    - 使用 FIFO 队列可以保证线程获取资源的公平性。
    - 避免了线程之间的竞争和忙等（通过阻塞和唤醒机制）。
2. **AQS 的 CAS 操作为何重要？**
   
    - CAS 确保了对共享资源的原子性修改。
    - 在高并发场景下，可以避免锁竞争导致的性能问题。
3. **如何选择独占模式和共享模式？**
   
    - 独占模式：适用于仅允许一个线程访问资源的场景（如独占锁）。
    - 共享模式：适用于多个线程共享资源的场景（如读写锁）。

# 9.Synchronized
## **synchronized 介绍及原理**

`synchronized` 是 Java 提供的一种同步机制，用于保证多线程访问共享资源时的 **原子性、可见性和有序性**。它可以用来保护**方法**或**代码块**，确保同一时刻只有一个线程能够执行临界区代码。

---

## **1. synchronized 的基本使用**

`synchronized` 关键字可以作用在**实例方法、静态方法**和**代码块**上，具体方式如下：

### **1.1 修饰实例方法**

```java
public class SynchronizedExample {
    public synchronized void method() {
        System.out.println(Thread.currentThread().getName() + " is executing...");
    }
}
```

- 作用：锁的是当前对象 (`this`)，同一个实例的多个线程进入该方法时会同步，但不同实例的线程可以并发执行。

### **1.2 修饰静态方法**

```java
public class SynchronizedStaticExample {
    public static synchronized void staticMethod() {
        System.out.println(Thread.currentThread().getName() + " is executing static method...");
    }
}
```

- 作用：锁的是**类对象 (`Class<?>` 对象)**，即多个实例共享同一把锁，影响所有调用该静态方法的线程。

### **1.3 修饰代码块**

```java
public class SynchronizedBlockExample {
    private final Object lock = new Object(); // 自定义锁对象

    public void method() {
        synchronized (lock) {
            System.out.println(Thread.currentThread().getName() + " is executing synchronized block...");
        }
    }
}
```

- 作用：
    - **锁定某个特定对象**，避免锁整个方法，提高性能。
    - **可以自定义锁对象**，而不局限于 `this`。

---

## **2. synchronized 的底层原理**

`synchronized` 的底层是通过 **JVM 指令** 和 **对象头的 Mark Word** 实现的。

### **2.1 synchronized 的字节码指令**

我们使用 `javap -v` 来反编译以下代码：

```java
public void method() {
    synchronized (this) {
        System.out.println("Hello synchronized");
    }
}
```

生成的字节码：

```plaintext
monitorenter
invokestatic #2 // Method java/lang/System.out.println
monitorexit
```

- **monitorenter**：进入同步代码块时获取锁。
- **monitorexit**：离开同步代码块时释放锁。

### **2.2 synchronized 在对象头中的实现**

`synchronized` 依赖 **对象头 (Object Header)** 中的 `Mark Word` 进行锁的状态管理。

**对象头的组成**

|组件|作用|
|---|---|
|Mark Word|存储锁标记、哈希码、GC 年龄等|
|Klass Pointer|指向类的元数据|
|数组长度 (仅数组对象)|存储数组长度|

`synchronized` 主要通过 **Mark Word** 维护锁的状态：

- **无锁 (Normal)**：Mark Word 直接存储对象的哈希码。
- **偏向锁 (Biased Locking)**：存储线程 ID，避免 CAS 操作。
- **轻量级锁 (Lightweight Locking)**：使用 CAS 操作 Mark Word 实现。
- **重量级锁 (Heavyweight Locking)**：进入内核态，使用 `Monitor` 机制。

---

## **3. synchronized 的锁优化**

### **3.1 偏向锁**

- **原理**：如果一个线程多次进入同步代码块，JVM 让该线程直接获取锁，而**不进行 CAS 操作**。
- **适用场景**：线程竞争少的情况下，提高性能。
- **优化点**：避免无意义的 CAS 操作，减少 CPU 资源消耗。

### **3.2 轻量级锁**

- **原理**：当多个线程争用锁时，采用 **CAS (Compare And Swap) 操作** 竞争 Mark Word，而不使用重量级锁。
- **适用场景**：多个线程竞争但不会频繁阻塞的场景。
- **优化点**：减少线程切换和上下文切换的开销。

### **3.3 自旋锁**

- **原理**：如果一个线程尝试获取锁失败，会短暂地循环等待 (自旋)，而不是立即进入阻塞状态。
- **适用场景**：锁竞争不激烈，线程持有锁时间短。
- **优化点**：避免线程频繁切换到内核态，提高 CPU 使用率。

### **3.4 锁消除**

- **原理**：JVM 通过 **逃逸分析 (Escape Analysis)**，判断某些锁是否可以被消除，从而优化锁的开销。
- **示例**：
  
    ```java
    public void append(String s1, String s2) {
        StringBuffer sb = new StringBuffer();
        sb.append(s1);
        sb.append(s2);
    }
    ```
    
    - `sb` 是局部变量，**不会逃逸到其他线程**，所以 JVM **自动消除同步锁**。

---

## **4. synchronized 和其他锁的对比**

|特性|synchronized|ReentrantLock|
|---|---|---|
|锁类型|内置锁 (JVM 级别)|显式锁 (java.util.concurrent)|
|可重入|支持|支持|
|公平性|非公平|支持公平/非公平|
|锁细粒度|方法、代码块|代码块、方法|
|超时机制|不支持|支持 `tryLock()`|
|中断机制|不支持|支持 `lockInterruptibly()`|
|读写锁|不支持|`ReentrantReadWriteLock` 支持|
|性能|适合简单同步|适合复杂场景|

---

## **5. synchronized 使用建议**

1. **尽量使用代码块同步，而不是方法同步**，减少锁的粒度，提高并发性能。
2. **避免锁的竞争**，可以使用 `Lock` 或 `Atomic` 变量代替 `synchronized` 以提高性能。
3. **考虑使用 ReadWriteLock**，适用于读多写少的场景，提高吞吐量。
4. **结合锁优化策略**，如 `synchronized` + `volatile` 组合使用，避免不必要的同步开销。

---

## **总结**

- `synchronized` 通过 **Monitor (监视器锁) 和 Mark Word** 实现锁管理。
- JVM 采用 **偏向锁、轻量级锁、自旋锁、重量级锁** 进行优化。
- `synchronized` 适用于简单的同步需求，但在复杂场景下 `ReentrantLock` 提供更好的灵活性和性能优化。
- **理解 synchronized 的底层原理和优化机制**，有助于在高并发编程中正确选择合适的锁策略。

# 10.指令重排
指令重排（Instruction Reordering）是编译器、处理器和运行时环境为了提高程序执行效率而采用的一种优化技术。它允许在不改变程序语义的情况下重新安排指令的执行顺序。虽然指令重排通常对程序性能有积极影响，但在并发编程中，它可能导致一些意想不到的问题，特别是在多线程环境中。

## 1. **指令重排的类型**

指令重排主要可以分为以下几种类型：

- **编译器重排**：编译器在优化代码时，会改变指令的顺序，以提高执行效率。
- **处理器重排**：CPU 在执行指令时，可能会根据数据依赖性、流水线和缓存优化等策略进行重排。
- **程序运行时重排**：在某些情况下，JIT 编译器（Just-In-Time Compiler）也会进行重排。

## 2. **重排的原因**

- **提高性能**：通过重排指令，可以减少 CPU 等待数据的时间，提高指令的执行效率。
- **优化资源利用**：重排可以更好地利用 CPU 的流水线和缓存，从而提高系统整体性能。

## 3. **重排的影响**

指令重排在单线程环境中通常不会造成问题，因为程序的顺序执行仍然符合开发者的预期。然而，在多线程环境中，重排可能导致以下问题：

- **可见性问题**：一个线程对共享变量的修改可能不会被其他线程立即看到，因为重排可能导致读取旧值。
- **顺序问题**：某些操作的顺序可能会被打乱，导致程序的逻辑错误。

## 4. **示例**

考虑以下代码示例，展示了指令重排可能导致的问题：

```java
class SharedData {
    private int a = 0;
    private int b = 0;
    private int x = 0;
    private int y = 0;

    public void writer() {
        a = 1;        // 1
        x = b;        // 2
    }

    public void reader() {
        b = 1;        // 3
        y = a;        // 4
    }
}
```

假设有两个线程分别调用 `writer()` 和 `reader()` 方法。在没有适当同步的情况下，可能的执行顺序为：

1. 线程 A 执行 `a = 1;`（指令 1），然后被调度而暂停。
2. 线程 B 执行 `b = 1;`（指令 3），然后执行 `y = a;`（指令 4）。
3. 线程 B 可能会读取到 `y = 0;`，因为线程 A 的更新可能尚未可见。

这可能导致 `x` 和 `y` 的值并不符合预期。

## 5. **防止指令重排**

为了防止指令重排带来的问题，可以使用以下方法：

- **使用 `synchronized` 关键字**：Java 的 `synchronized` 可以保证在进入同步块时，所有的指令会按照顺序执行，并且可见性得以保证。
  
- **使用 `volatile` 关键字**：在 Java 中，`volatile` 关键字可以防止指令重排，确保对变量的读写操作具有可见性和原子性。

### 示例：

```java
class SharedData {
    private volatile int a = 0;
    private volatile int b = 0;
    private int x = 0;
    private int y = 0;

    public void writer() {
        a = 1;        // 1
        x = b;        // 2
    }

    public void reader() {
        b = 1;        // 3
        y = a;        // 4
    }
}
```

## 6. **总结**

指令重排是一种重要的优化技术，可以提高程序的性能，但在多线程环境中可能导致意想不到的结果。理解指令重排的原理和影响，有助于开发者在编写并发程序时采取适当的同步机制，确保程序的正确性和稳定性。在 Java 中，使用 `synchronized` 和 `volatile` 是防止指令重排导致问题的有效方法。

# 11.ThreadLocal
`ThreadLocal` 是 Java 中用于实现线程本地存储的类，它允许每个线程都拥有自己的独立变量副本。通过 `ThreadLocal`，每个线程可以访问和修改自己的数据，而不影响其他线程的数据。

## 1. **基本概念**

- **线程本地变量**：每个线程都保存一个副本，线程之间的数据不会相互干扰。
- **适用场景**：适用于需要在多线程环境中维护用户的临时状态或数据的场景，如数据库连接、用户会话、简单的缓存等。

## 2. **使用方法**

`ThreadLocal` 的使用非常简单，通常包括以下几个步骤：

1. 创建一个 `ThreadLocal` 实例。
2. 使用 `set()` 方法为当前线程设置值。
3. 使用 `get()` 方法获取当前线程的值。
4. 可选：使用 `remove()` 方法清除当前线程的值。

## 3. **示例代码**

以下是一个简单的示例，展示了如何使用 `ThreadLocal`：

```java
public class ThreadLocalExample {
    // 创建 ThreadLocal 变量
    private static ThreadLocal<Integer> threadLocalValue = ThreadLocal.withInitial(() -> 0);

    public static void main(String[] args) {
        // 创建多个线程
        Thread thread1 = new Thread(() -> {
            threadLocalValue.set(1); // 设置线程1的值
            System.out.println("Thread 1: " + threadLocalValue.get());
        });

        Thread thread2 = new Thread(() -> {
            threadLocalValue.set(2); // 设置线程2的值
            System.out.println("Thread 2: " + threadLocalValue.get());
        });

        thread1.start();
        thread2.start();

        try {
            thread1.join();
            thread2.join();
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        // 主线程访问 ThreadLocal 变量
        System.out.println("Main thread: " + threadLocalValue.get()); // 输出默认值 0
    }
}
```

## 4. **ThreadLocal 的特性**

1. **隔离性**：每个线程都有自己的副本，不会干扰其他线程的数据。
2. **自动清理**：当线程结束时，`ThreadLocal` 中的值会被自动清除，防止内存泄漏。
3. **初始值**：可以通过 `withInitial()` 方法设置初始值，确保每个线程在第一次调用 `get()` 时都有一个默认值。

## 5. **使用注意事项**

- **内存泄漏**：如果线程池中的线程被重复使用，而不调用 `remove()`，可能会导致内存泄漏。确保在合适的时机清除不再需要的值。
- **适用场景**：`ThreadLocal` 适合存储小型、短期的数据，避免用于存储大量数据或长期存储的数据。
- **性能**：虽然 `ThreadLocal` 提供了线程隔离的便利，但过度使用可能会引起性能问题，特别是在高并发环境中。

## 6. **总结**

`ThreadLocal` 是一种强大的工具，用于在多线程环境中管理线程本地的数据。它可以有效地隔离每个线程的数据，避免线程间的干扰。在使用时，需谨慎管理数据的生命周期，确保在不再需要时进行清理，以避免潜在的内存泄漏。

# 12. volatile的作用

#### 1. **`volatile`的作用**

- 可见性：
  - 修饰的变量会被直接存储在主内存中，每次读取时强制从主内存加载，而不是从线程的工作内存中读取。
- 禁止指令重排序：
  - 在编译阶段，`volatile`会插入内存屏障，确保写操作在屏障之前的指令不会被重排序到屏障之后。

#### 2. **局限性**

- 无法保证原子性

  ：

  - 如果多个线程同时对变量进行读改写操作，`volatile`无法保证操作的原子性。例如：`count++`并不是线程安全的，需要使用`AtomicInteger`或`synchronized`。

- 仅适用于单一变量

  ：

  - 适用于简单的状态标志或值，但不适用于涉及多个变量的复杂逻辑。

#### 3. **实际应用场景**

1. **状态标志控制**：

   - 在多线程环境中，通过`volatile`修饰一个布尔变量，用于控制线程的运行状态。

   ```
   
   public class VolatileExample {
       private static volatile boolean running = true;
   
       public static void main(String[] args) {
           Thread thread = new Thread(() -> {
               while (running) {
                   // 执行任务
               }
               System.out.println("Thread stopped.");
           });
           thread.start();
   
           try {
               Thread.sleep(1000); // 主线程等待1秒
           } catch (InterruptedException e) {
               Thread.currentThread().interrupt();
           }
           running = false; // 修改状态
       }
   }
   ```

2. **双重检查锁 (Double-Checked Locking)**：

   - 用于单例模式，确保对象的实例化过程是线程安全的。

   ```
   
   public class Singleton {
       private static volatile Singleton instance;
   
       private Singleton() {}
   
       public static Singleton getInstance() {
           if (instance == null) {
               synchronized (Singleton.class) {
                   if (instance == null) {
                       instance = new Singleton();
                   }
               }
           }
           return instance;
       }
   }
   ```

#### 4. **`volatile`与`synchronized`的区别**

| 特性   | `volatile` | `synchronized` |
| ---- | ---------- | -------------- |
| 可见性  | 是          | 是              |
| 原子性  | 否          | 是              |
| 性能开销 | 较低         | 较高             |
| 应用场景 | 状态标志、简单变量  | 复杂逻辑、原子性操作     |

# 13. synchronized和ReentrantLock的区别

### **1. `synchronized` 和 `ReentrantLock` 的主要区别**

| **特性**       | **`synchronized`**                               | **`ReentrantLock`**                        |
| -------------- | ------------------------------------------------ | ------------------------------------------ |
| **可重入性**   | 是可重入的。                                     | 也是可重入的。                             |
| **加锁机制**   | 隐式加锁和释放锁，基于 JVM 实现。                | 手动加锁和释放锁，基于 Java API 实现。     |
| **功能丰富性** | 功能简单，不支持细粒度控制和高级特性。           | 提供高级特性，如尝试锁、超时锁、条件锁等。 |
| **性能**       | 在高并发下，性能有所优化（如偏向锁、轻量级锁）。 | 性能略低于 `synchronized`，但灵活性更高。  |
| **锁状态查询** | 无法查询当前锁状态。                             | 可以通过方法（如`isLocked`）查询锁状态。   |
| **适用场景**   | 简单的同步场景，推荐使用。                       | 需要高级控制的同步场景，推荐使用。         |

------

### **2. 场景对比**

#### **什么时候选择 `synchronized`？**

- 简单的同步块或方法锁定，如线程安全的计数器、方法访问控制等。
- 希望让 JVM 自动处理锁的加解锁操作，避免手动释放锁的复杂性。

#### **什么时候选择 `ReentrantLock`？**

- **需要更细粒度的控制**：例如尝试获取锁（`tryLock`）、超时获取锁（`tryLock(timeout)`）。
- **需要条件锁**：在同步代码块中，需要让线程有条件地等待和唤醒。
- **需要查询锁状态**：例如判断当前锁是否被持有。
- **需要公平锁**：可以指定为公平锁，保证锁按线程请求的顺序分配。

------

### **3. 条件锁（Condition）和可重入性**

#### **可重入性**：

- 无论是 `synchronized` 还是 `ReentrantLock`，都支持可重入。
- 一个线程持有锁后，可以再次获取同一个锁，而不会导致死锁。

#### **条件锁（Condition）**：

- `Condition` 是 `ReentrantLock` 提供的高级功能，可以让线程在特定条件下等待或唤醒。
- 常见场景：生产者-消费者模型。

------

### **4. 示例代码**

#### **`synchronized` 示例**

```java
public class SynchronizedExample {
    public synchronized void method1() {
        System.out.println(Thread.currentThread().getName() + " is in method1");
        method2();
    }

    public synchronized void method2() {
        System.out.println(Thread.currentThread().getName() + " is in method2");
    }

    public static void main(String[] args) {
        SynchronizedExample example = new SynchronizedExample();
        new Thread(example::method1, "Thread-1").start();
    }
}
```

**输出结果**：
 线程可以重入方法1后继续调用方法2。

------

#### **`ReentrantLock` 示例**

**带条件锁的生产者-消费者模型**：

```java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class ProducerConsumer {
    private static int count = 0;
    private static final int MAX_CAPACITY = 5;

    private final Lock lock = new ReentrantLock();
    private final Condition notFull = lock.newCondition();
    private final Condition notEmpty = lock.newCondition();

    public void produce() throws InterruptedException {
        lock.lock();
        try {
            while (count == MAX_CAPACITY) {
                notFull.await(); // 等待消费者消费
            }
            count++;
            System.out.println(Thread.currentThread().getName() + " produced, count = " + count);
            notEmpty.signal(); // 唤醒等待的消费者
        } finally {
            lock.unlock();
        }
    }

    public void consume() throws InterruptedException {
        lock.lock();
        try {
            while (count == 0) {
                notEmpty.await(); // 等待生产者生产
            }
            count--;
            System.out.println(Thread.currentThread().getName() + " consumed, count = " + count);
            notFull.signal(); // 唤醒等待的生产者
        } finally {
            lock.unlock();
        }
    }

    public static void main(String[] args) {
        ProducerConsumer pc = new ProducerConsumer();

        // 启动生产者线程
        new Thread(() -> {
            try {
                while (true) pc.produce();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "Producer").start();

        // 启动消费者线程
        new Thread(() -> {
            try {
                while (true) pc.consume();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "Consumer").start();
    }
}
```

**输出结果（部分）：**

```
Producer produced, count = 1
Consumer consumed, count = 0
Producer produced, count = 1
Producer produced, count = 2
Consumer consumed, count = 1
```

### **总结**

- **`synchronized`**：简单易用，适合大多数同步场景。
- **`ReentrantLock`**：灵活强大，适合复杂的线程控制场景（如条件锁、超时锁）。

# 14. CAS的ABA解决方案
### **CAS 的 ABA 问题及解决方案**

在 Java 并发编程中，**CAS（Compare-And-Swap）** 是一种无锁并发机制，利用 CPU 指令级的原子操作来保证数据一致性。但是，CAS 存在一个 **ABA 问题**，可能导致错误的数据更新。

---

## **1. 什么是 ABA 问题？**

### **问题描述**

**ABA 问题** 发生在多线程环境下，当一个变量 `A` 被某个线程读取后，在它执行 CAS 操作前，其他线程已经将 `A` 修改成 `B`，然后又改回 `A`，此时 CAS 操作仍然会成功，但实际上该变量已经被其他线程修改过，导致潜在的逻辑错误。

### **示例**

假设有一个 CAS 操作：

```java
AtomicInteger atomicInteger = new AtomicInteger(100);

// 线程 1 读取 atomicInteger 的值
int oldValue = atomicInteger.get(); // oldValue = 100

// 线程 2 先将值改为 200，再改回 100
atomicInteger.compareAndSet(100, 200);
atomicInteger.compareAndSet(200, 100);

// 线程 1 继续执行 CAS，发现值仍然是 100，认为没有被修改，成功执行：
atomicInteger.compareAndSet(100, 300);
```

- **问题**：
    - `atomicInteger` 的值在中间经历了 `100 -> 200 -> 100` 的变化。
    - **线程 1 误以为 `100` 从未改变过，因此 CAS 继续成功执行，但实际情况已经变了**。
    - 可能导致线程 1 依赖的旧数据已经无效，进而发生数据不一致的情况。

---

## **2. 解决 ABA 问题的方法**

Java 提供了两种主要方法来解决 ABA 问题：

### **方案 1：使用 `AtomicStampedReference`**

**思路**：

- CAS 操作除了比较变量的值，还会**比较一个版本号**，确保变量没有经历“中间变化”。
- 每次更新变量时，同时更新版本号。
- 当 CAS 检测到版本号变更，说明变量被其他线程修改过，CAS 失败，强制重新执行逻辑。

**示例代码：**

```java
import java.util.concurrent.atomic.AtomicStampedReference;

public class AtomicStampedExample {
    public static void main(String[] args) {
        AtomicStampedReference<Integer> atomicStampedRef = new AtomicStampedReference<>(100, 1);

        Thread t1 = new Thread(() -> {
            int stamp = atomicStampedRef.getStamp();
            System.out.println("线程 1 初始版本号: " + stamp);

            // 休眠，确保线程 2 先执行修改
            try { Thread.sleep(1000); } catch (InterruptedException e) {}

            boolean success = atomicStampedRef.compareAndSet(100, 300, stamp, stamp + 1);
            System.out.println("线程 1 修改成功? " + success + "，当前版本号: " + atomicStampedRef.getStamp());
        });

        Thread t2 = new Thread(() -> {
            int stamp = atomicStampedRef.getStamp();
            System.out.println("线程 2 初始版本号: " + stamp);

            atomicStampedRef.compareAndSet(100, 200, stamp, stamp + 1);
            System.out.println("线程 2 修改成 200, 当前版本号: " + atomicStampedRef.getStamp());

            atomicStampedRef.compareAndSet(200, 100, atomicStampedRef.getStamp(), atomicStampedRef.getStamp() + 1);
            System.out.println("线程 2 修改回 100, 当前版本号: " + atomicStampedRef.getStamp());
        });

        t1.start();
        t2.start();
    }
}
```

**输出示例：**

```plaintext
线程 1 初始版本号: 1
线程 2 初始版本号: 1
线程 2 修改成 200, 当前版本号: 2
线程 2 修改回 100, 当前版本号: 3
线程 1 修改成功? false，当前版本号: 3
```

- **线程 1 发现版本号变化了**，即使变量值仍然是 `100`，但由于版本号不匹配，CAS 失败。
- 线程 1 需要重新获取最新值，确保逻辑正确。

**适用场景**：

- **适用于 CAS 变量有频繁变更的情况**，如 **队列、栈、引用更新** 等。

---

### **方案 2：使用 `LongAdder` 计数**

**思路**：

- 适用于 **计数场景**（如点击量、计数器），而不是替换值。
- `LongAdder` 采用 **分段累加**，避免多个线程修改同一变量造成 ABA 问题。

**示例代码**：

```java
import java.util.concurrent.atomic.LongAdder;

public class LongAdderExample {
    public static void main(String[] args) {
        LongAdder counter = new LongAdder();

        // 多线程累加
        for (int i = 0; i < 100; i++) {
            new Thread(counter::increment).start();
        }

        try { Thread.sleep(1000); } catch (InterruptedException e) {}

        System.out.println("最终计数值: " + counter.sum());
    }
}
```

**适用场景**：

- **适用于高并发计数**，如访问量、请求计数等。

---

### **方案 3：使用 `Lock` 或 `synchronized`**

**思路**：

- 直接用 `ReentrantLock` 或 `synchronized`，确保修改过程是**串行化**的，从而避免 ABA。
- 适用于 **多线程争用较高**，且 **CAS 方案不适用** 的场景。

**示例代码**：

```java
import java.util.concurrent.locks.ReentrantLock;

public class LockExample {
    private static int value = 100;
    private static final ReentrantLock lock = new ReentrantLock();

    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            lock.lock();
            try {
                System.out.println("线程 1 修改值...");
                value = 300;
            } finally {
                lock.unlock();
            }
        });

        Thread t2 = new Thread(() -> {
            lock.lock();
            try {
                System.out.println("线程 2 修改值...");
                value = 100;
            } finally {
                lock.unlock();
            }
        });

        t1.start();
        t2.start();
    }
}
```

**适用场景**：

- 适用于 **高并发情况下的复杂数据修改**，如**银行转账、账户余额修改**等。

---

## **3. 方案对比**

|方案|适用场景|优点|缺点|
|---|---|---|---|
|**AtomicStampedReference**|CAS 变量频繁变更|解决 ABA 问题，低成本|代码复杂度增加|
|**LongAdder**|高并发计数|无锁方案，性能高|仅适用于累加场景|
|**Lock / synchronized**|复杂并发场景|适用于复杂业务逻辑|开销大，影响并发性能|

---

## **4. 总结**

- **ABA 问题发生在 CAS 机制中**，由于变量在 CAS 操作前被其他线程修改并恢复，导致 CAS 误判变量未变更。
- **`AtomicStampedReference` 通过版本号机制** 解决 ABA 问题，适用于高并发场景。
- **`LongAdder` 适用于高并发累加**，但不适合替换值。
- **`Lock` 和 `synchronized` 适用于复杂数据修改**，但影响并发性能。

**推荐**：

- 如果可以使用 **无锁方案**（如 `AtomicStampedReference` 或 `LongAdder`），优先使用它们。
- **锁方案**（`Lock`、`synchronized`）适用于 **并发竞争极端严重** 且 **逻辑复杂** 的场景。

# 15. **死锁产生的条件及排查方案**

### **1. 什么是死锁？**

**死锁（Deadlock）** 是指两个或多个线程因争夺资源而**无限期等待**，导致程序无法继续执行。死锁通常发生在多线程并发编程中，多个线程持有部分资源并等待其他线程释放它们所需的资源。

---

## **2. 死锁的四个必要条件（“柯林斯四条件”）**

死锁的发生必须满足以下四个条件，缺少任何一个条件都不会产生死锁：

1. **互斥条件（Mutual Exclusion）**
   
    - 资源一次只能被一个线程占有，不能被多个线程共享使用。
2. **持有并等待（Hold and Wait）**
   
    - 线程持有一个资源，同时又在等待另一个资源，而不释放已持有的资源。
3. **不可剥夺（No Preemption）**
   
    - 线程获得的资源不能被其他线程强行剥夺，必须由线程自己释放。
4. **循环等待（Circular Wait）**
   
    - 存在一个**线程循环依赖链**，其中每个线程都在等待另一个线程释放资源。

**示例：**

```
线程 1 持有 资源 A，等待 资源 B
线程 2 持有 资源 B，等待 资源 A
```

**此时发生死锁，两个线程都无法继续执行。**

---

## **3. 死锁示例代码**

以下代码模拟了死锁：

- 线程 1 先锁 `lockA`，再尝试获取 `lockB`。
- 线程 2 先锁 `lockB`，再尝试获取 `lockA`。
- 由于资源获取顺序不同，两个线程都会**等待对方释放资源，形成死锁**。

```java
import java.util.concurrent.TimeUnit;

public class DeadlockExample {
    private static final Object lockA = new Object();
    private static final Object lockB = new Object();

    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            synchronized (lockA) {
                System.out.println("线程1 获取 lockA");
                try { TimeUnit.MILLISECONDS.sleep(100); } catch (InterruptedException e) {}
                
                synchronized (lockB) {
                    System.out.println("线程1 获取 lockB");
                }
            }
        });

        Thread t2 = new Thread(() -> {
            synchronized (lockB) {
                System.out.println("线程2 获取 lockB");
                try { TimeUnit.MILLISECONDS.sleep(100); } catch (InterruptedException e) {}

                synchronized (lockA) {
                    System.out.println("线程2 获取 lockA");
                }
            }
        });

        t1.start();
        t2.start();
    }
}
```

**输出（死锁）**

```plaintext
线程1 获取 lockA
线程2 获取 lockB
// 线程 1 等待 lockB，线程 2 等待 lockA，死锁发生
```

## **4. 如何排查死锁？**

    ```bash

    ```


2. **使用 `jstack` 查看线程状态**
   
    ```bash

    ```

## **5. 解决死锁的方法**

### **5.1 破坏循环等待：按顺序获取锁**

- 线程获取多个锁时，**保证所有线程按相同顺序获取锁**，可以避免死锁。

#### **优化代码**

```java
public class DeadlockSolution {
    private static final Object lockA = new Object();
    private static final Object lockB = new Object();

    public static void main(String[] args) {
        Thread t1 = new Thread(() -> acquireLocks(lockA, lockB), "线程1");
        Thread t2 = new Thread(() -> acquireLocks(lockA, lockB), "线程2");

        t1.start();
        t2.start();
    }

    private static void acquireLocks(Object firstLock, Object secondLock) {
        synchronized (firstLock) {
            System.out.println(Thread.currentThread().getName() + " 获取 " + firstLock);
            try { Thread.sleep(50); } catch (InterruptedException e) {}

            synchronized (secondLock) {
                System.out.println(Thread.currentThread().getName() + " 获取 " + secondLock);
            }
        }
    }
}
```

**改进点**

- 所有线程 **按照相同顺序** 获取 `lockA` -> `lockB`，避免循环等待。

---

### **5.2 设置超时**

- 线程尝试获取锁时，**设置超时**，避免无限等待。

#### **使用 `tryLock`**

```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;
import java.util.concurrent.TimeUnit;

public class DeadlockPrevention {
    private static final Lock lockA = new ReentrantLock();
    private static final Lock lockB = new ReentrantLock();

    public static void main(String[] args) {
        Thread t1 = new Thread(() -> acquireLocks(lockA, lockB), "线程1");
        Thread t2 = new Thread(() -> acquireLocks(lockB, lockA), "线程2");

        t1.start();
        t2.start();
    }

    private static void acquireLocks(Lock firstLock, Lock secondLock) {
        try {
            while (true) {
                if (firstLock.tryLock(50, TimeUnit.MILLISECONDS)) {
                    try {
                        if (secondLock.tryLock(50, TimeUnit.MILLISECONDS)) {
                            try {
                                System.out.println(Thread.currentThread().getName() + " 成功获取锁");
                                return;
                            } finally {
                                secondLock.unlock();
                            }
                        }
                    } finally {
                        firstLock.unlock();
                    }
                }
                Thread.sleep(50); // 失败后稍作等待，避免 CPU 过度占用
            }
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
    }
}
```

**改进点**

- **使用 `tryLock`** 尝试获取锁，避免死锁。
- **失败后短暂等待**，减少 CPU 资源浪费。

---

## **6. 总结**

|方法|解决方式|适用场景|
|---|---|---|
|**按顺序加锁**|保证线程按相同顺序获取资源|适用于多个锁的情况|
|**使用 `tryLock`**|失败后超时返回，避免无限等待|适用于高并发环境|
|**使用 `jstack` 监测**|运行时检测死锁|适用于排查死锁问题|
|**使用 VisualVM / jconsole**|GUI 工具检测线程状态|适用于性能监控|

**推荐**

- **代码层面**：优先**按顺序加锁**或**使用 `tryLock`**。
- **运行时排查**：`jstack` / `VisualVM` 结合 `jconsole`。
