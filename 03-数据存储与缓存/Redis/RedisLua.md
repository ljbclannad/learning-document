# Redis Lua：原子组合操作与使用边界

> **本文定位：**Lua 用于把多步 Redis 读写组合成一次原子执行，常见于安全解锁、限流、库存扣减与幂等状态迁移；它不是长事务、后台任务或业务编排引擎。

## 1. 为什么需要 Lua

单条 Redis 命令本身原子，但“读 → 判断 → 写”拆成多条命令会出现并发窗口。Lua 脚本在 Redis 服务器内按脚本整体串行执行，因此脚本中的命令不会与其他命令交错。

典型例子是安全解锁：只有锁 value 仍等于自己的 token 时才删除。

```lua
if redis.call('GET', KEYS[1]) == ARGV[1] then
  return redis.call('DEL', KEYS[1])
end
return 0
```

## 2. 调用约定

- `KEYS`：脚本访问的 Redis key，调用时显式传入；Cluster 下应保证相关 key 落在同一 hash slot。
- `ARGV`：普通参数，如 token、数量、TTL。
- `redis.call`：命令失败时让脚本报错；`redis.pcall`：将错误作为返回值交给脚本处理。
- `EVALSHA`：生产中优先缓存脚本 SHA 并调用；遇到 `NOSCRIPT` 时重新加载后重试。

## 3. 三个使用边界

1. **脚本要短且有界。**不能在 Lua 中执行大范围扫描、长循环或外部 I/O；脚本运行期间会阻塞该实例的其他命令。
2. **原子性不等于分布式事务。**脚本无法消除主从异步复制、故障切换、客户端超时重试和数据库/MQ 双写带来的不确定性。
3. **原子性不等于幂等。**对扣减、支付回调等副作用仍要有业务唯一键、状态机或数据库约束兜底。

## 4. 常见模式

| 场景 | Lua 负责的最小原子单元 | 仍需的业务保障 |
| --- | --- | --- |
| 分布式锁解锁/续期 | 校验 token 后删除或续 TTL | 限制租约、fencing token 或幂等 |
| 固定窗口限流 | 计数、首次设 TTL、返回是否放行 | key 维度与容量规划 |
| 库存预扣 | 校验库存并扣减 | 订单幂等、最终落库与补偿 |
| 回调幂等 | 检查状态并写入处理中标记 | DB 唯一约束、状态机与重试 |
