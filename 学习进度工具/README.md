# 研习手记 macOS 应用

使用独立的原生 macOS 窗口维护十二周学习计划，直接读写项目中的 Markdown。应用不使用浏览器或 WebView，不启动 HTTP 服务，不监听端口。当前构建面向本机 Apple Silicon，使用 SwiftUI 界面和系统 Python 3 文档存储模块。

## 启动与关闭

在 Finder 的“应用程序”中打开 **研习手记**（`/Applications/研习手记.app`）。应用自动读取当前项目的计划目录，关闭窗口即退出，无需保留终端。也可执行：

```sh
open '/Applications/研习手记.app'
```

本机需要 `/usr/bin/python3`，已验证为 Python 3.9.6。应用已作本机临时签名，没有开发者公证；当前交付面向这台 Mac，迁移其他电脑需重新检查环境和构建。若项目位置改变，可通过应用菜单“选择学习计划文件夹…”指定目录，再重启应用。

从源码重新构建并覆盖“应用程序”目录中的当前版本：

```sh
python3 '/Users/lejinbo/Documents/Obsidian Vault/Learning-document/学习进度工具/build_native.py'
```

构建默认先执行读取检查，再将应用安装到固定路径 `/Applications/研习手记.app`；只有应用代码更新并重新构建时才需要覆盖。学习文档更新后使用“重新加载”即可，无需重新构建。构建时会请求正在运行的应用正常退出，未保存内容仍由应用提示处理，不会强制终止。

可使用 `--no-install` 仅构建；单独安装已构建版本可运行 `python3 install_native.py`。更新前保留旧版本到 `.native-build/installed-backups/`，该目录不自动清理；安装只替换应用包，不改动项目中的学习记录。安装失败可在应用退出后恢复对应旧版。

此前浏览器草稿的 `index.html`、`app.js`、`style.css` 仅保留为未使用草稿。`启动学习工具.command` 已改为打开原生应用。原生应用只调用 `native_bridge.py` 以及 `server.py` 中的文档存储逻辑，不运行其 HTTP 入口。

## 使用方式

1. 左侧选择学习周，上方选择学习日。
2. 从下拉框选择学习状态和掌握程度，填写实际日期、时长。
3. 勾选已做的任务，填写学习记录；可展开本周复盘填写总结。
4. 点击“保存到文档”或按 `⌘S`。切换学习日、周次或关闭应用前先保存，未保存时会提示。

点击窗口顶部的侧边栏图标，或按 `⌃⌘S`，可隐藏或恢复左侧周次列表。隐藏后正文会使用腾出的空间，顶部按钮仍可点击；应用会记住上次的显示状态。切换侧边栏不会切换学习日或清除未保存输入。

窗口底部固定操作栏提供“前一天”和“后一天”按钮，滚动内容时仍可点击，在简洁视图和完整视图中均可使用。也可通过“学习日”菜单或快捷键 `⌘⌥←`（前一天）、`⌘⌥→`（后一天）切换相邻学习日，周末尾会自动衔接下一周。首日的“前一天”和末日的“后一天”按钮会禁用；有未保存内容时仍会提示。这里按计划中的学习日切换，不按自然日期计算。

简洁视图和完整视图均显示“本周阅读入口”，展开后点击笔记名称即可跳转。已安装 Obsidian 时，使用其官方 `obsidian://open?path=…` 协议按真实文件路径打开新标签页；未安装时使用系统默认应用打开 Markdown。笔记需属于 Obsidian 已登记的知识库。文件不存在时会在应用底部提示，不会创建空白笔记。标题的展示转换不会影响真实文件定位，也不会改变当前未保存的学习记录。

协议依据：[Obsidian URI 官方文档](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)。

学习状态支持未开始、学习中、待复习、已完成；掌握程度使用原计划中的五个等级。任务勾选、学习状态和掌握程度独立记录，不会因为勾完任务而自动判定掌握。

周状态、实际日期范围、每日汇总表及统一进度中的完成天数、时长自动计算。只将状态为“已完成”的学习日计入完成天数。“待复习”表示尚需完成复测，不计为完成。实际时长填写该学习日的累计小时数，重复点击保存不会重复累加。

保存未完成日时以该日为接续位置；保存已完成日时定位到最早未完成日。下次具体起点优先使用本次填写的内容。应用初始优先打开最早未完成周中的学习中或待复习日。

## 代码与实验记录

完整视图中，实际完成内容、待跟进问题与任务、下次起点和再次验证等四项放在“理解与思考”下方的“学习记录”中。“实践笔记”仅包含代码、图、实验或问答证据，位于学习记录之后；其后依次为今日安排、本周复盘和本周阅读入口。其中“代码、图、实验或问答证据”占用整行宽度，并提供“预览 / 源码”切换。默认预览识别三反引号或波浪线围栏，显示语言标签和等宽代码，保留缩进、空行与换行，长内容可滚动查看。在“源码”中粘贴或修改原始记录，切换不会改写内容；按 `⌘S` 保存。

代码仅展示，不执行。当前支持代码块展示，不提供语法着色；普通文字按原文展示，Mermaid 保留为原文或代码，并非完整 Markdown 图文渲染器。单独一行的本地 Markdown 图片引用支持预览；缺失或不支持的引用显示原文。

在实践笔记中点击“添加图片…”选择本地图片，或先复制图片／截图再点击“粘贴图片”。图片会转为 PNG，存入计划目录的 `附件/实践笔记/`，并在当前记录末尾插入 Markdown 相对路径引用；预览按比例缩小显示，原图保留。按 `⌘S` 后引用写入周计划，Obsidian 也可显示。图片文件在添加时即保存，若放弃笔记修改或删除引用，附件仍保留，不自动删除。当前支持静态图片，不保留动画；只预览计划目录内的本地图片，不下载远程图片。

## 日常学习外观

界面采用 GitHub 风格：中性的白色／深灰画布、浅灰／深灰侧栏、细边框和 6 点圆角，蓝色链接与导航选中态，绿色“保存到文档”主按钮。统一颜色定义在 `StudyTheme.swift`，自动跟随系统浅色与深色模式；侧栏选择同时使用色块和左侧标记。表单、按钮、键盘操作和数据保存仍使用现有原生控件。

Markdown 预览使用清晰的六级标题尺寸、等宽代码和柔和代码底色，段落分隔减少重复空白，正文周围增加阅读留白。颜色与排版只影响显示，不改写原文，也不新增 Markdown 语法支持。

应用图标采用暖白底、深绿色手记和叶片。矢量绘制源文件为 `Assets/DrawIcon.swift`；构建时自动生成各分辨率 PNG 并打包为 `StudyIcon.icns`，通过 `CFBundleIconFile` 注册，后续更新会保留图标。

应用窗口和菜单名称为“研习手记”，侧栏使用“工程实践 · 日常积累”。周主题、每日任务、状态选项采用中性的学习和工程实践表述；资料列表仅显示笔记名称，不展示原始目录路径。

“理解与思考”位于当天信息下方、任务清单之前，独占整行。编辑区域居中，最大宽度为 860 像素、高度为 420 像素，使用 15 点正文、6 点额外行距、12 点段后间距和内边距，长内容可滚动阅读和编辑。该区域在简洁视图和完整视图中均可使用。排版仅影响显示，不插入空行或改写笔记；默认显示 Markdown 预览，可通过“预览 / 编辑”切换到原文编辑。预览支持 `#` 至 `######` 标题、有序／无序列表及缩进、任务项、加粗、斜体、行内代码、围栏代码和本地图片；任务项在预览中仅展示。切换不会改写原文或自动保存，按 `⌘S` 保存。暂不提供完整 Markdown 渲染，表格、HTML 和 Mermaid 等保留为原文。

默认开启“简洁视图”，收起其余实践笔记和周总结，保留“理解与思考”和本周阅读入口。关闭侧栏的此开关即可编辑其余记录，切换视图不会丢失未保存输入。开关会记住上次选择。

文案转换仅发生在显示层：原始 Markdown、状态字段和用户输入不会被替换。展开笔记后仍显示自己填写的原文；在 Finder 或 Obsidian 打开文件时也仍能看到原有目录和内容。这是外观调整，不是文件隐藏功能。

“应用程序”目录中的固定名称为 `研习手记.app`，项目内的构建产物仍为 `学习进度.app`。日常使用请打开“应用程序”中的版本，避免同时运行两份应用。

## 字段合并与历史兼容

“未解决问题及核实方式”和“未完成任务与顺延原因”合并为“待跟进问题与任务”，可一起记录问题、核实方式、未完成任务、顺延原因及下一步安排。“反馈与需要修正的理解”不再显示或编辑。

读取旧记录时，两项非空内容按原字段名分段合并展示；读取本身不改写文件。保存当前学习日后新增 `#### 待跟进问题与任务`，以后以该字段为准，主动清空后也不会回填旧内容。旧的两个字段及反馈字段保持原文，仍可在 Obsidian 中查阅；不会批量迁移或删除历史数据。合并字段最多 41000 字符，以容纳两个原字段的内容。旧版本应用不识别新字段，请使用新版编辑。

## 数据与同步

- 数据源：`00-索引与面试/AI应用后端三个月复习/` 下的十二份周计划及 `学习进度记录.md`。
- 每次保存更新当前周文档和统一进度文档，其余周文件不改写。
- 每次保存前，在计划目录的 `.学习进度备份/时间戳-随机标识/` 中保留这两份原文档。恢复时先停止工具，核对并复制需要恢复的文件；备份不会自动清理。
- 支持继续使用 Obsidian 编辑。工具通过内容版本校验检测外部修改；冲突时保留窗口中的输入并拒绝本次保存，请先复制未保存内容，再重新加载文档。
- 不要在点击保存的同一时刻让其他程序写入同一文件。每个文件使用原子替换；普通写入异常会尝试回滚，突然断电仍可能使两个文件不同步，可用备份恢复。
- 学习记录和周复盘统一使用 `#### 字段名` 小标题，标题后留空行，正文直接使用标准 Markdown。保存不会给正文统一添加缩进，也不会把首行列表或代码围栏拼到字段名后面；正文内部的空行、列表缩进、代码、表格和图片相对路径按原样保留。首尾空行作为段落间隔统一处理。
- 兼容读取旧的 `- 字段名：` 格式，编辑保存的字段会转为小标题格式。代码围栏内的字段名和计划标题不会被当作文档边界；正文任务清单不会修改当天任务状态。未闭合代码围栏或与计划保留字段／标题冲突的正文会提示修正，避免保存后无法读取；示例标题可放进代码围栏，普通小标题可使用其他名称。未知状态仍会提示错误。
- 统一进度中的“跨日疑点与复测”“学习会话日志”“计划调整记录”，以及周汇总的复盘结论仍保留原文，由复习会话按实际内容维护；工具不自动编造这些记录。

原生应用只通过本地子进程和文件操作处理数据，不加载外部资源。

## 旧周计划格式迁移

`python3 migrate_notes.py` 默认只做试转换与内容核对；加 `--apply` 才执行。迁移将十二份周计划的每日记录和周复盘转成小标题正文，并解除旧代码围栏残留的外层缩进，保留代码内部相对缩进和所有文字。迁移前在计划目录的 `.学习进度备份/格式迁移-时间-随机标识/` 保存原始周计划与进度记录；写入前检查外部变化。再次执行不重复改变已转换文档。

迁移不改动进度记录、日期、时长、任务勾选和附件文件。建议先保存并退出旧版应用，完成迁移后使用新版重新加载。
