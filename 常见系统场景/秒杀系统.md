#### 🔐 第一步：预防层 — 控流、防刷、防重

- 使用 **限流组件（Sentinel）** 控制 QPS
    
- 接入滑动窗口/令牌桶限制单用户请求频率
    
- 用户维度做 **去重校验**（如手机号 + 商品ID做唯一）
    

---

#### ⚙️ 第二步：核心控制层 — 防止超卖的关键

1. **库存预扣减 + 原子操作**
    
    - 秒杀开始前将商品库存预热到 Redis
        
    - 使用 `Redis.decr()` 实现原子扣减（保证并发下库存准确）
        
2. **防止超卖的关键逻辑**
    
    - Redis 扣库存时判断 >= 0，负数视为卖完，直接拒绝请求
        
    - 若失败不下单；成功则将请求写入消息队列（MQ）做异步处理
        
3. **订单生成 + 库存落库异步处理**
    
    - 使用 RabbitMQ/Kafka 异步下单，缓解数据库压力
        
    - 处理时再校验库存（双保险）+ 落库 + 保证幂等性（orderId 唯一）
        

---

#### 💾 第三步：持久层 — 落库 + 幂等 + 最终一致性

- 使用**消息幂等处理机制**，避免重复消费生成重复订单
    
- 利用唯一索引、状态字段或 Redis 防止重复下单
    
- 对 MQ 做确认机制 + 重试策略 + 死信队列


---
### RabbitMQ 重试策略

- 消费失败用 `channel.basicNack(deliveryTag, false, true)` 表示重回队列
    
- **但会变成“疯狂重试”**，需要手动处理重试间隔
    
- 推荐做法：
    
    - 将失败消息发送到延迟队列（TTL + 死信交换机）
        
    - 控制重试次数（通过 header、Redis 计数等）
        
    - 多次失败转入死信队列
