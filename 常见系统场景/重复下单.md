### **使用分布式锁拦截重复下单**

在高并发场景下，为了避免重复下单，可以使用 **Redis 分布式锁** 确保同一用户或同一订单编号的请求串行执行。以下是完整的实现方式，包括 **Redis 分布式锁** 的获取、释放，以及异常情况下的处理。

---

## **1. Redis 分布式锁的基本原理**

- 订单请求到达后，先尝试 **获取锁**（基于订单号或用户 ID）。
- 如果锁已存在，说明有并发请求在处理，直接返回错误信息，防止重复下单。
- 如果获取到锁，则执行 **订单创建逻辑**。
- 订单处理完成后，**释放锁**，确保后续请求可以正常执行。

---

## **2. Redis 分布式锁实现**

### **2.1 依赖**

首先，需要引入 Redis 依赖：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
```

---

### **2.2 订单服务代码**

```java
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;
import java.util.concurrent.TimeUnit;

@Service
public class OrderService {
    
    private final StringRedisTemplate redisTemplate;
    
    public OrderService(StringRedisTemplate redisTemplate) {
        this.redisTemplate = redisTemplate;
    }
    
    public String createOrder(String userId, String orderNo) {
        String lockKey = "order:lock:" + userId; // 以用户 ID 作为锁的 key
        String lockValue = String.valueOf(System.currentTimeMillis() + 5000); // 过期时间 (防止死锁)
        
        // 尝试获取锁
        Boolean lockAcquired = redisTemplate.opsForValue().setIfAbsent(lockKey, lockValue, 5, TimeUnit.SECONDS);

        if (Boolean.FALSE.equals(lockAcquired)) {
            return "请勿重复提交订单"; // 如果无法获取锁，则拒绝请求
        }
        
        try {
            // 检查订单是否已经存在
            if (isOrderExists(orderNo)) {
                return "订单已存在，不能重复提交";
            }

            // 创建订单
            saveOrder(orderNo, userId);
            return "订单创建成功";
        } finally {
            // 释放锁，避免死锁
            releaseLock(lockKey, lockValue);
        }
    }
    
    private boolean isOrderExists(String orderNo) {
        // 模拟数据库查询订单是否已存在
        return false;
    }

    private void saveOrder(String orderNo, String userId) {
        // 模拟订单创建逻辑
        System.out.println("订单创建成功：" + orderNo);
    }

    private void releaseLock(String lockKey, String lockValue) {
        // 防止误删锁，确保锁是当前线程持有的
        String currentValue = redisTemplate.opsForValue().get(lockKey);
        if (lockValue.equals(currentValue)) {
            redisTemplate.delete(lockKey);
        }
    }
}
```

---

## **3. 代码解析**

### **3.1 `setIfAbsent()` 获取锁**

- `setIfAbsent()`（`SETNX`）用于尝试获取锁，只有当 `lockKey` 不存在时，才会成功获取。
- 过期时间 **5 秒**，防止出现死锁。

```java
Boolean lockAcquired = redisTemplate.opsForValue().setIfAbsent(lockKey, lockValue, 5, TimeUnit.SECONDS);
```

### **3.2 释放锁（防止误删）**

- 先检查 Redis 中的锁值是否仍然是当前线程设置的，避免误删其他请求的锁。
- 如果值匹配，则删除锁。

```java
private void releaseLock(String lockKey, String lockValue) {
    String currentValue = redisTemplate.opsForValue().get(lockKey);
    if (lockValue.equals(currentValue)) {
        redisTemplate.delete(lockKey);
    }
}
```

### **3.3 避免订单重复**

- 先检查订单是否已经存在：

```java
if (isOrderExists(orderNo)) {
    return "订单已存在，不能重复提交";
}
```

- 只有在锁住的情况下，才去创建订单，防止并发请求创建多个订单。

## **4. 使用 Redisson 实现分布式锁（推荐）**

除了 `StringRedisTemplate`，可以使用 **Redisson** 提供的分布式锁 API，使锁的管理更加高效和安全。

### **4.1 引入 Redisson 依赖**

```xml
<dependency>
    <groupId>org.redisson</groupId>
    <artifactId>redisson-spring-boot-starter</artifactId>
    <version>3.16.3</version>
</dependency>
```

### **4.2 订单服务代码**

```java
import org.redisson.api.RLock;
import org.redisson.api.RedissonClient;
import org.springframework.stereotype.Service;
import java.util.concurrent.TimeUnit;

@Service
public class OrderServiceWithRedisson {
    
    private final RedissonClient redissonClient;

    public OrderServiceWithRedisson(RedissonClient redissonClient) {
        this.redissonClient = redissonClient;
    }

    public String createOrder(String userId, String orderNo) {
        RLock lock = redissonClient.getLock("order:lock:" + userId);

        try {
            // 尝试加锁，最多等待3秒，锁定时间5秒
            if (!lock.tryLock(3, 5, TimeUnit.SECONDS)) {
                return "请勿重复提交订单";
            }

            // 检查订单是否已存在
            if (isOrderExists(orderNo)) {
                return "订单已存在，不能重复提交";
            }

            // 创建订单
            saveOrder(orderNo, userId);
            return "订单创建成功";
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            return "获取锁失败，请重试";
        } finally {
            lock.unlock(); // 释放锁
        }
    }

    private boolean isOrderExists(String orderNo) {
        return false; // 模拟查询
    }

    private void saveOrder(String orderNo, String userId) {
        System.out.println("订单创建成功：" + orderNo);
    }
}
```

### **4.3 Redisson 方案优势**

- **支持自动续期**：Redisson 会自动续约锁的过期时间，防止执行时间较长时锁被误删。
- **支持等待机制**：`tryLock(3, 5, TimeUnit.SECONDS)` 让线程最多等待 3 秒尝试获取锁。

---

## **5. 总结**

|方案|优点|缺点|
|---|---|---|
|**Redis + `setIfAbsent()`**|简单易用，低成本|需要手动释放锁，可能误删|
|**Redisson 分布式锁**|支持自动续期，防误删|依赖 Redisson，稍有额外开销|

在生产环境中，推荐使用 **Redisson** 来管理分布式锁，因为它 **自动续期** 并 **避免锁误删**，从而提高可靠性。
