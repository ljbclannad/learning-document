# 1. 计数器算法
**计数器算法**（Counter Algorithm）是一种简单的 **限流（Rate Limiting）** 方式，主要用于控制单位时间内的请求数量，以 **防止系统过载**。这种算法主要应用于 **API 限流、登录防暴力破解、爬虫限制** 等场景。

## 1.1 计数器算法的原理

- 设定一个时间窗口（如 1 秒、1 分钟）。
- 维护一个计数器（Counter），用于记录该时间窗口内的请求数量。
- 如果请求数未超出限制，则放行，并增加计数器。
- 如果超出限制，则 **拒绝请求**（返回 `429 Too Many Requests`）。
- 到达时间窗口结束时，**清零计数器**，重新开始计数。

**示例：** 假设 **最大 QPS（每秒查询数）= 10**：

- **第 1 秒**：
    - 0ms：第 1 次请求 ✅（计数器 = 1）
    - 100ms：第 2 次请求 ✅（计数器 = 2）
    - ...
    - 900ms：第 10 次请求 ✅（计数器 = 10）
    - 950ms：第 11 次请求 ❌（被拒绝）
- **第 2 秒**：
    - 计数器重置为 0，重新开始计数。

## 1.2 计数器算法的实现

```java
import java.util.concurrent.TimeUnit;

public class RateLimiter {
    // 最大请求数
    private final int limit;
    // 时间窗口(秒)
    private final long intervalSeconds;

    // 计数器
    private int counter;
    // 窗口开始时间(毫秒)
    private long startTimeMillis;

    public RateLimiter(int limit, long intervalSeconds) {
        this.limit = limit;
        this.intervalSeconds = intervalSeconds;
        this.counter = 0;
        this.startTimeMillis = System.currentTimeMillis();
    }

    public boolean allowRequest() {
        long currentTimeMillis = System.currentTimeMillis();

        // 如果超过时间窗口，重置计数器和开始时间
        if (currentTimeMillis - startTimeMillis >= TimeUnit.SECONDS.toMillis(intervalSeconds)) {
            counter = 0;
            startTimeMillis = currentTimeMillis;
        }

        // 判断是否超过限制
        if (counter < limit) {
            counter++;
            return true; // 允许请求
        } else {
            return false; // 拒绝请求
        }
    }

    // 简单测试
    public static void main(String[] args) throws InterruptedException {
        // 每秒最多5个请求
        RateLimiter limiter = new RateLimiter(5, 1);

        for (int i = 0; i < 10; i++) {
            if (limiter.allowRequest()) {
                System.out.println("请求 " + (i + 1) + " 通过");
            } else {
                System.out.println("请求 " + (i + 1) + " 被限流");
            }
            // 间隔200ms发送请求
            Thread.sleep(200);
        }
    }
}
```

```

请求 2 通过 ✅
请求 3 通过 ✅
请求 4 通过 ✅
请求 5 通过 ✅
请求 6 被限流 ❌
请求 7 被限流 ❌
请求 8 被限流 ❌
请求 9 被限流 ❌
请求 10 被限流 ❌
```

（下一秒后计数器重置，新的请求可以通过）

## 1.3 计数器算法的优缺点

### 1.3.1 优点

- **实现简单**，只需要一个计数器。
- **低开销**，适合高性能需求。
- **适用于固定时间窗口**，如 "每秒最多 10 次请求"。

### 1.3.2 缺点

- **突发流量问题**：
    - 如果窗口刚结束，计数器重置，可能导致**瞬间请求量过高**（如在窗口起始时涌入大量请求）。
- **不均匀限流**：
    - 在窗口内如果前几毫秒内请求已达上限，后面的请求都被拒绝。

## 1.4 计数器算法的实际应用

### 1.4.1 API 限流
- 例如：GitHub API 限制 **每个 IP 每分钟最多 60 次请求**。
- Nginx、Cloudflare 等都支持基于计数器的限流。

### 1.4.2 登录防暴力破解
- 限制同一 IP 在 1 分钟内最多尝试 5 次登录，防止暴力破解密码。

### 1.4.3 爬虫访问限制
- 限制同一用户的抓取频率，防止服务器被爬取过载。

## 1.5 总结

| 限流算法           | 适用场景                   | 主要特点                           |
| ------------------ | -------------------------- | ---------------------------------- |
| **计数器算法**     | 简单限流，适用于小型系统   | 简单高效，但容易产生突发流量问题   |
| **滑动窗口计数器** | API 请求限流               | 比计数器算法更平滑，但仍有突刺风险 |
| **漏桶算法**       | 稳定限流，防止瞬时过载     | 流量均匀，不支持突发流量           |
| **令牌桶算法**     | 允许短时突发，控制长期流量 | 支持突发流量，适合高并发           |

如果你的应用 **流量较小** 且 **对限流要求不高**，可以使用 **计数器算法**；  
如果 **流量大、突发流量问题明显**，建议使用 **令牌桶算法或漏桶算法**。

**建议：如果只是简单的限流需求，计数器算法是最简单、易实现的选择！**  
**如果需要更灵活的限流，可以考虑令牌桶或漏桶算法。**

# 2. 滑动时间窗口算法

## 2.1 什么是滑动时间窗口算法？

滑动时间窗口（Sliding Window）是一种 **改进版的计数器算法**，用于 **限流** 和 **流量控制**。它比 **固定窗口计数器（Fixed Window Counter）** 更加平滑，能够减少突发流量问题。

### 2.1.1 工作原理

- **维护多个小窗口**，记录一段时间内的请求数量。
- **不断滑动窗口**，计算最近时间段的总请求数。
- **如果请求数超出阈值，则进行限流**。

### 2.1.2 计数器 vs 滑动窗口

| 算法               | 适用场景                      | 问题                               |
| ------------------ | ----------------------------- | ---------------------------------- |
| **固定窗口计数器** | 简单限流，如“每秒 10 次请求”  | 流量突刺，窗口刚重置时流量可能激增 |
| **滑动窗口**       | 平滑限流，适用于 API 速率限制 | 相比计数器算法，计算更复杂         |

## 2.2 滑动窗口的实现

滑动窗口可以用 **两种方式** 实现：

1. **基于时间戳的滑动窗口**
2. **基于固定窗口加权计算的滑动窗口（滑动日志窗口）**

### 2.2.1 基于时间戳的滑动窗口

#### 2.2.1.1 思路

- **用一个队列（或有序列表）存储最近的请求时间戳**。
- **每次请求时，清理超过时间窗口的旧请求**。
- **计算最近时间窗口内的请求数**，判断是否超过限制。


```java
import java.util.ArrayDeque;
import java.util.Deque;

public class SlidingWindowRateLimiter {
    // 窗口最大请求数
    private final int maxRequests;
    // 窗口大小(秒)
    private final long windowSizeSeconds;
    // 存储请求时间戳(毫秒)
    private final Deque<Long> requestTimestamps = new ArrayDeque<>();

    public SlidingWindowRateLimiter(int maxRequests, long windowSizeSeconds) {
        this.maxRequests = maxRequests;
        this.windowSizeSeconds = windowSizeSeconds;
    }

    public synchronized boolean allowRequest() {
        long currentTimeMillis = System.currentTimeMillis();
        long windowStart = currentTimeMillis - windowSizeSeconds * 1000L;

        // 清除超出时间窗口的请求
        while (!requestTimestamps.isEmpty() && requestTimestamps.peekFirst() < windowStart) {
            requestTimestamps.pollFirst();
        }

        // 检查当前窗口内的请求数
        if (requestTimestamps.size() < maxRequests) {
            requestTimestamps.addLast(currentTimeMillis);
            return true; // 允许请求
        } else {
            return false; // 被限流
        }
    }

    // 测试
    public static void main(String[] args) throws InterruptedException {
        // 1秒内最多5个请求
        SlidingWindowRateLimiter limiter = new SlidingWindowRateLimiter(5, 1);

        for (int i = 0; i < 10; i++) {
            if (limiter.allowRequest()) {
                System.out.println("请求 " + (i + 1) + " 通过 ✅");
            } else {
                System.out.println("请求 " + (i + 1) + " 被限流 ❌");
            }
            // 每0.2秒发送一个请求
            Thread.sleep(200);
        }
    }
}
```

请求 8 被限流 ❌
请求 9 被限流 ❌

（下一秒后计数器滑动，新的请求可以通过）

#### 2.2.1.3 特点

- 适用于 **高并发 API 限流**（如 API Gateway）。
- 可以 **实时计算当前窗口内的请求数**，相比固定窗口更平滑。
- **缺点**：性能消耗较高，需要存储所有请求时间戳（固定窗口仅需要维护一个counter）。

### 2.2.2 基于固定窗口加权计算的滑动窗口

#### 2.2.2.1 思路

- **将时间窗口分成多个小窗口（如 1 分钟的窗口，分成 6 个 10 秒的小窗口）。**
- 计算当前时间窗口的**加权请求数**，防止突发流量。
- **比时间戳队列更节省内存**，适合高性能系统。

#### 2.2.2.2 实现

```java
public class SlidingWindowCounter {
    // 窗口最大请求数
    private final int maxRequests;
    // 窗口大小(秒)
    private final double windowSizeSeconds;
    // 将窗口分成多少个小格子
    private final int numBuckets;
    // 每个小窗口的请求数
    private final int[] buckets;
    // 每个小窗口的时间长度(毫秒)
    private final double bucketDurationMillis;
    // 上次检查时间(毫秒)
    private long lastCheckedMillis;

    public SlidingWindowCounter(int maxRequests, double windowSizeSeconds, int numBuckets) {
        this.maxRequests = maxRequests;
        this.windowSizeSeconds = windowSizeSeconds;
        this.numBuckets = numBuckets;
        this.buckets = new int[numBuckets];
        this.bucketDurationMillis = (windowSizeSeconds * 1000.0) / numBuckets;
        this.lastCheckedMillis = System.currentTimeMillis();
    }

    public SlidingWindowCounter(int maxRequests, double windowSizeSeconds) {
        this(maxRequests, windowSizeSeconds, 10);
    }

    public synchronized boolean allowRequest() {
        long currentTimeMillis = System.currentTimeMillis();
        long elapsedMillis = currentTimeMillis - lastCheckedMillis;

        // 计算需要滑动多少个小窗口
        int numSlides = (int) (elapsedMillis / bucketDurationMillis);

        if (numSlides > 0) {
            // 为了避免超出数组长度，这里最多滑动 numBuckets 个
            int slides = Math.min(numSlides, numBuckets);

            // 滑动窗口: 左移 slides 个 bucket，右侧补 0
            // 等价于 Python: self.buckets = self.buckets[num_slides:] + [0] * num_slides
            // 但我们保持数组长度不变
            System.arraycopy(buckets, slides, buckets, 0, numBuckets - slides);
            for (int i = numBuckets - slides; i < numBuckets; i++) {
                buckets[i] = 0;
            }

            lastCheckedMillis = currentTimeMillis;
        }

        // 计算总请求数
        int totalRequests = 0;
        for (int count : buckets) {
            totalRequests += count;
        }

        if (totalRequests < maxRequests) {
            // 在当前 bucket 添加请求(最新 bucket 在数组末尾)
            buckets[numBuckets - 1]++;
            return true; // 允许请求
        } else {
            return false; // 被限流
        }
    }

    // 测试
    public static void main(String[] args) throws InterruptedException {
        // 1秒最多5个请求
        SlidingWindowCounter limiter = new SlidingWindowCounter(5, 1.0);

        for (int i = 0; i < 10; i++) {
            if (limiter.allowRequest()) {
                System.out.println("请求 " + (i + 1) + " 通过 ✅");
            } else {
                System.out.println("请求 " + (i + 1) + " 被限流 ❌");
            }
            // 每0.2秒发送一个请求
            Thread.sleep(200);
        }
    }
}
```

#### 2.2.2.3 特点

- **节省内存**，只存储小窗口数据，不存请求时间戳。
- **更平滑**，不会因为某个时间点重置流量突刺。
- **适用于高并发场景，如 API 限流、负载均衡器。**

## 2.3 适用场景

| 场景                                   | 推荐算法               |
| -------------------------------------- | ---------------------- |
| **简单限流（每秒 N 次请求）**          | 固定窗口计数器         |
| **防止流量突刺，API 限流**             | 滑动窗口（基于时间戳） |
| **高性能限流（如 Nginx、Redis 限流）** | 滑动窗口（基于计数器） |
| **短信验证码、登录防暴力破解**         | 令牌桶算法             |

## 2.4 总结

| 限流算法               | 适用场景                      | 主要特点                         |
| ---------------------- | ----------------------------- | -------------------------------- |
| **固定窗口计数器**     | 低流量 API 限流               | 简单易实现，但可能存在流量突刺   |
| **滑动窗口（时间戳）** | 精确限流，适用于 API 速率限制 | 记录所有请求时间戳，内存占用较大 |
| **滑动窗口（计数器）** | 高性能限流（Redis / Nginx）   | 低内存占用，流量平滑             |

✅ **如果你的 API 需要更平滑的限流，而不是简单的时间段计数，推荐滑动窗口算法！**  
✅ **如果是高并发服务（如 API Gateway、Nginx），建议使用** **滑动窗口计数器或令牌桶算法**。


# 3.漏桶算法（Leaky Bucket Algorithm）

漏桶算法（Leaky Bucket Algorithm）是一种 **限流（Rate Limiting）** 算法，用于 **控制请求速率**，防止流量突刺，保证流量平稳。

## 3.1 漏桶算法原理

- **形象理解：**
    - 想象一个装水的桶，**水滴代表请求**，**桶的出口代表处理能力**。
    - **水（请求）以任意速率流入桶中**。
    - **水只能以固定速率流出（即请求被处理）**。
    - **如果桶满了（请求过多），新来的水（请求）会被丢弃**。
- **特点：**
    - **请求以平稳速率处理（限流）**。
    - **不允许突发流量**，所有请求必须按照设定速率通过。

### 3.1.1 漏桶算法与令牌桶算法对比

| 算法           | 处理方式                 | 适用场景                           |
| -------------- | ------------------------ | ---------------------------------- |
| **漏桶算法**   | 限制请求处理速率（匀速） | **流量稳定输出**（如音视频流）     |
| **令牌桶算法** | 允许突发流量             | **API 限流**（如支付、短信验证码） |

## 3.2 漏桶算法的实现

### 3.2.1 思路

- 维护一个 **队列（Bucket）** 存储请求。
- **请求到来时，加入队列**（如果桶未满）。
- **以固定速率处理请求**（定期从队列中取出请求）。
- **如果桶满了，新请求被丢弃**（限流）。

### 3.2.2 java实现

```java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class LeakyBucket {
    // 漏桶容量（最大请求数）
    private final int capacity;
    // 处理速率（每秒多少请求）
    private final double leakRate;

    // 存储请求的队列
    private final Deque<String> bucket = new ArrayDeque<>();
    // 线程安全锁
    private final Lock lock = new ReentrantLock();
    // 上次漏水时间(毫秒)
    private long lastLeakTimeMillis;

    public LeakyBucket(int capacity, double leakRate) {
        this.capacity = capacity;
        this.leakRate = leakRate;
        this.lastLeakTimeMillis = System.currentTimeMillis();
    }

    /**
     * 以固定速率处理请求
     */
    private void leak() {
        lock.lock();
        try {
            long currentTimeMillis = System.currentTimeMillis();
            long elapsedMillis = currentTimeMillis - lastLeakTimeMillis;
            if (elapsedMillis <= 0) {
                return;
            }
            double elapsedSeconds = elapsedMillis / 1000.0;
            int leaks = (int) (elapsedSeconds * leakRate); // 计算应处理的请求数量

            for (int i = 0; i < leaks; i++) {
                if (!bucket.isEmpty()) {
                    bucket.pollFirst(); // 处理一个请求
                } else {
                    break;
                }
            }

            if (leaks > 0) {
                lastLeakTimeMillis = currentTimeMillis;
            }
        } finally {
            lock.unlock();
        }
    }

    /**
     * 添加请求
     * @param request 请求内容
     * @return true=请求成功,false=被限流
     */
    public boolean addRequest(String request) {
        lock.lock();
        try {
            // 先处理已有请求
            leak();
            if (bucket.size() < capacity) {
                bucket.addLast(request);
                return true; // 请求成功
            } else {
                return false; // 请求被限流
            }
        } finally {
            lock.unlock();
        }
    }

    // 测试
    public static void main(String[] args) throws InterruptedException {
        // 5个请求容量，每秒处理2个请求
        LeakyBucket bucket = new LeakyBucket(5, 2.0);

        for (int i = 0; i < 10; i++) {
            String req = "请求 " + (i + 1);
            if (bucket.addRequest(req)) {
                System.out.println(req + " 通过 ✅");
            } else {
                System.out.println(req + " 被限流 ❌");
            }
            // 每0.3秒发送一个请求
            Thread.sleep(300);
        }
    }
}
```

```

请求 2 通过 ✅
请求 3 通过 ✅
请求 4 通过 ✅
请求 5 通过 ✅
请求 6 被限流 ❌
请求 7 被限流 ❌
请求 8 通过 ✅
请求 9 通过 ✅
请求 10 被限流 ❌
```

### 3.2.4 关键点

- **每次请求时，先“漏水”（处理已有请求）**，然后再尝试添加新请求。
- **处理速率是固定的**（即每秒只能处理 `leak_rate` 个请求）。
- **如果桶已满，新请求会被丢弃**，防止系统过载。

## 3.3 Redis 实现（分布式限流）

在分布式环境中，可以用 **Redis** 实现漏桶算法。

### 3.3.1 思路

1. **使用 Redis 计数器存储桶中的请求数**。
2. **使用 Lua 脚本保证原子性**（同时处理“入桶”和“漏水”）。

```lua
-- Redis 漏桶限流 Lua 脚本
local key = KEYS[1]  -- 漏桶的 key
local capacity = tonumber(ARGV[1])  -- 漏桶容量
local leak_rate = tonumber(ARGV[2])  -- 处理速率
local current_time = tonumber(ARGV[3])  -- 当前时间戳（秒）

-- 获取当前桶的请求数和上次更新时间
local bucket_info = redis.call("HMGET", key, "requests", "last_time")
local requests = tonumber(bucket_info[1]) or 0
local last_time = tonumber(bucket_info[2]) or current_time

-- 计算时间差，并处理“漏水”
local time_passed = current_time - last_time
local leaks = math.floor(time_passed * leak_rate)
requests = math.max(0, requests - leaks)

-- 判断是否能接收新请求
if requests < capacity then
    redis.call("HMSET", key, "requests", requests + 1, "last_time", current_time)
    redis.call("EXPIRE", key, 10)  -- 设置过期时间，防止长期占用 Redis
    return 1  -- 允许请求
else
    return 0  -- 拒绝请求
end
```

### 3.3.2 🚀 用法

```python
import redis
import time

# 连接 Redis
client = redis.StrictRedis(host='localhost', port=6379, decode_responses=True)

# 加载 Lua 脚本
script = client.script_load(open("leaky_bucket.lua").read())

def leaky_bucket_limiter(user_id):
    key = f"leaky_bucket:{user_id}"
    capacity = 5  # 漏桶容量
    leak_rate = 2  # 每秒处理 2 个请求
    current_time = int(time.time())

    # 执行 Lua 脚本
    allowed = client.evalsha(script, 1, key, capacity, leak_rate, current_time)

    if allowed == 1:
        print(f"请求通过 ✅ - {user_id}")
    else:
        print(f"请求被限流 ❌ - {user_id}")

# 测试限流
for i in range(10):
    leaky_bucket_limiter("user_123")
    time.sleep(0.3)
```

## 3.4 适用场景

| **场景**                 | **推荐算法** |
| ------------------------ | ------------ |
| **音视频流控制**         | 漏桶算法     |
| **恒定速率限流**         | 漏桶算法     |
| **API 限流（允许突发）** | 令牌桶算法   |
| **消息队列限流**         | 漏桶算法     |

## 3.5 总结

| **算法**       | **适用场景**           | **特点**                         |
| -------------- | ---------------------- | -------------------------------- |
| **漏桶算法**   | 平滑流量，防止突发流量 | **处理速率固定，不支持突发流量** |
| **令牌桶算法** | API 限流（允许突发）   | **允许短时间突发请求**           |

✅ **如果你需要“恒定速率”地处理请求，使用漏桶算法。**  
✅ **如果允许“短时间突发流量”，使用令牌桶算法更合适。**


# 4. 令牌桶算法

令牌桶算法（Token Bucket Algorithm）是一种 **流量控制算法**，用于 **限流（Rate Limiting）**，适用于 **API 请求限流、带宽控制、短信验证码防刷等** 场景。

## 4.1 令牌桶算法原理

- **有一个“桶”，里面存储一定数量的令牌（tokens）。**
- **系统按照固定速率向桶中添加令牌（即 refill 过程）。**
- **当请求到来时，从桶中取出一个令牌，才允许通过。**
- **如果桶是空的（令牌用完），则拒绝请求（被限流）。**

### 4.1.1 🆚 令牌桶 vs. 漏桶

| 算法           | 处理方式                 | 适用场景                           |
| -------------- | ------------------------ | ---------------------------------- |
| **漏桶算法**   | 限制请求处理速率（匀速） | **流量稳定输出**（如音视频流）     |
| **令牌桶算法** | 允许突发流量             | **API 限流**（如支付、短信验证码） |

## 4.2 令牌桶算法的 Java 实现

### 4.2.1 🔧 方式 1：基于 `ScheduledExecutorService` 的实现

```java
import java.util.concurrent.Executors;
import java.util.concurrent.ScheduledExecutorService;
import java.util.concurrent.TimeUnit;

public class TokenBucket {
    private final int capacity;  // 令牌桶容量
    private final int refillRate;  // 令牌生成速率（每秒生成多少个）
    private int tokens;  // 当前令牌数
    private final ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(1);

    public TokenBucket(int capacity, int refillRate) {
        this.capacity = capacity;
        this.refillRate = refillRate;
        this.tokens = capacity; // 初始时令牌桶满

        // 定时补充令牌
        scheduler.scheduleAtFixedRate(this::addTokens, 0, 1, TimeUnit.SECONDS);
    }

    private synchronized void addTokens() {
        tokens = Math.min(capacity, tokens + refillRate);  // 不能超过桶的最大容量
    }

    public synchronized boolean allowRequest() {
        if (tokens > 0) {
            tokens--;  // 取一个令牌
            return true;  // 允许请求
        }
        return false;  // 拒绝请求（限流）
    }

    public void stop() {
        scheduler.shutdown();
    }

    public static void main(String[] args) throws InterruptedException {
        TokenBucket bucket = new TokenBucket(5, 2);  // 令牌桶容量 5，每秒生成 2 个令牌

        for (int i = 0; i < 10; i++) {
            if (bucket.allowRequest()) {
                System.out.println("请求 " + (i + 1) + " 通过 ✅");
            } else {
                System.out.println("请求 " + (i + 1) + " 被限流 ❌");
            }
            Thread.sleep(300);  // 每 300ms 发送一个请求
        }

        bucket.stop();
    }
}
```

### 4.2.2 ✅ 运行结果（示例）

```
请求 1 通过 ✅
请求 2 通过 ✅
请求 3 通过 ✅
请求 4 通过 ✅
请求 5 通过 ✅
请求 6 被限流 ❌
请求 7 被限流 ❌
请求 8 通过 ✅
请求 9 通过 ✅
请求 10 被限流 ❌
```

**（前 5 个请求通过，后续请求因令牌不足被限流，1 秒后补充令牌，新的请求被允许）**

### 4.2.3 关键点

- **令牌以固定速率添加**，模拟真实限流。
- **突发请求可行（只要桶内有令牌）**，但长时间持续高频请求会触发限流。
- **适用于 API 限流、爬虫防刷等应用场景。**

## 4.3 方式 2：基于 `RateLimiter`（Google Guava）

Google 的 **Guava** 库提供了 **RateLimiter**，内部就是基于 **令牌桶算法** 实现的。

### 4.3.1 🔧 Guava 版令牌桶

```java
import com.google.common.util.concurrent.RateLimiter;

public class GuavaTokenBucket {
    public static void main(String[] args) {
        RateLimiter rateLimiter = RateLimiter.create(2.0); // 每秒 2 个令牌

        for (int i = 0; i < 10; i++) {
            if (rateLimiter.tryAcquire()) {
                System.out.println("请求 " + (i + 1) + " 通过 ✅");
            } else {
                System.out.println("请求 " + (i + 1) + " 被限流 ❌");
            }
            try {
                Thread.sleep(300); // 每 300ms 发送一个请求
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}
```

### 4.3.2 ✅ 运行结果（示例）

```
请求 1 通过 ✅
请求 2 通过 ✅
请求 3 被限流 ❌
请求 4 被限流 ❌
请求 5 通过 ✅
请求 6 通过 ✅
请求 7 被限流 ❌
请求 8 被限流 ❌
请求 9 通过 ✅
请求 10 通过 ✅
```

### 4.3.3 关键点

- **Guava `RateLimiter.create(rate)`** 直接实现令牌桶，无需手写逻辑。
- **`tryAcquire()`** 方法可以尝试获取令牌，若桶为空则拒绝请求。
- **非常适用于高并发限流 API**。

## 4.4 方式 3：Redis 分布式令牌桶（Lua 脚本）

#### 4.4.1 Redis Lua 脚本

```lua
local key = KEYS[1]
local capacity = tonumber(ARGV[1])
local refill_rate = tonumber(ARGV[2])
local current_time = tonumber(ARGV[3])

-- 获取当前桶状态
local bucket_info = redis.call("HMGET", key, "tokens", "last_time")
local tokens = tonumber(bucket_info[1]) or capacity
local last_time = tonumber(bucket_info[2]) or current_time

-- 计算令牌补充量
local time_passed = current_time - last_time
local new_tokens = math.min(capacity, tokens + time_passed * refill_rate)

-- 判断是否能通过请求
if new_tokens >= 1 then
    redis.call("HMSET", key, "tokens", new_tokens - 1, "last_time", current_time)
    redis.call("EXPIRE", key, 10)
    return 1  -- 允许请求
else
    return 0  -- 被限流
end
```

#### 4.4.2 Java 代码

```java
import redis.clients.jedis.Jedis;
import java.time.Instant;

public class RedisTokenBucket {
    private static final String LUA_SCRIPT = "【上面 Lua 脚本】";
    private final Jedis jedis;
    private final String key;
    private final int capacity;
    private final int refillRate;

    public RedisTokenBucket(Jedis jedis, String key, int capacity, int refillRate) {
        this.jedis = jedis;
        this.key = key;
        this.capacity = capacity;
        this.refillRate = refillRate;
    }

    public boolean allowRequest() {
        long currentTime = Instant.now().getEpochSecond();
        Object result = jedis.eval(LUA_SCRIPT, 1, key, String.valueOf(capacity), String.valueOf(refillRate), String.valueOf(currentTime));
        return result.equals(1L);
    }

    public static void main(String[] args) {
        Jedis jedis = new Jedis("localhost");
        RedisTokenBucket bucket = new RedisTokenBucket(jedis, "token_bucket", 5, 2);

        for (int i = 0; i < 10; i++) {
            System.out.println(bucket.allowRequest() ? "请求通过 ✅" : "请求被限流 ❌");
            try { Thread.sleep(300); } catch (InterruptedException ignored) {}
        }
    }
}
```

| 实现方式              | 适用场景        |
| --------------------- | --------------- |
| **Java 线程定时任务** | 单机限流        |
| **Guava RateLimiter** | 高性能 API 限流 |
