## 学习阶段

| 阶段 | 周次 | 重点 | 验收方式 |
| --- | --- | --- | --- |
| 原理学习 | 第 1～5 周 | Java 后端基础与 AI 应用原理 | 复述、画图、小场景判断，不提前要求密集面试追问 |
| 项目深入 | 第 6～9 周 | 体重管理、SQL 工具、动态权限及排障 | 结合真实代码解释正常路径、失败路径与证据 |
| 面试训练 | 第 10～12 周 | 闭卷、连续追问、系统设计、编码和完整模拟 | 限时回答、具体反馈与薄弱点复测 |

项目和原理穿插学习：事务联系 SQL 工具，缓存联系动态权限，并发联系 AI 请求。SQL 工具从相关基础阶段就逐步读代码，第 8 周集中串联。

## 每日时间安排

| 时长 | 内容 |
| --- | --- |
| 20 分钟 | 回顾上次内容，简短复述 |
| 80 分钟 | 一个核心主题的原理或项目学习 |
| 60 分钟 | 看代码、画流程、实验或模拟中的分析环节 |
| 50 分钟 | Java 编码或 SQL，交替安排 |
| 30 分钟 | 讨论疑点、反馈与记录 |
| 可选 60 分钟 | 补理解、完成实验，不强制新增主题 |

以上为净学习时间，休息另算。前四天推进主题，第五天串联与复盘；另两天用于休息和缓冲。模拟面试阶段可合并时间块，总量不变。

## 陪练方式与掌握标准

一次只处理一个明确问题，按“问题 → 机制 → 小例子 → 边界”推进。原理阶段讲解后轻量复述；后期先独立回答，再连续追问，最后反馈，不提前展示答案。

掌握程度使用：未评估、需提示、可独立解释、可动手验证、可应对追问。完成阅读不自动等于掌握。反馈区分概念错误、表达不清、实现未核实与项目未做过。

## 项目事实边界

根据用户在「完善」会话中的说明：体重管理所列模块已上线；动态权限已完成开发与联调，尚未上线；SQL 工具已进行真实双库验证，但用户说明代码主要由 AI 生成，内部原理仍需系统学习。后续状态变化以新证据更新。

设计文档是学习参考，不能直接充当真实经历。区分本人设计贡献、AI 辅助实现、团队工作、实测结果与目标估算。没有记录的指标不补造。实验优先本地合成数据；新的外部服务付费调用、数据库连接或写入须明确环境与授权。
