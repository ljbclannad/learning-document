# 后端考点补充笔记

## MongoDB 的嵌入与引用

患者档案和有数量上限的近期随访摘要常常一起读取，可以放在同一文档里更新。完整随访历史会一直增长，还要按日期分页，适合按患者 ID 单独建集合。即使当前文档小于 MongoDB 的 16 MiB 限制，也要考虑数组增长带来的更新成本。

若摘要和历史各存一份，先决定哪份是权威数据。允许短时延迟时可由历史重建摘要，并记录处理版本。业务要求两份数据同时可见时，则需要考虑事务成本和读取方式。

## Spark 的 Shuffle 与热点分区

假设某一家机构占一半数据。按机构分组时，同一键的数据会汇聚到一个目标分区。先在 Spark UI 比较各任务的 Shuffle Read、记录数、溢写量和耗时。若慢任务读了远多于其他任务的数据，加执行器也不能把同一个键自动拆开。

对于计数，可以把热机构按记录标识散到多个子键，先分别计数，再按机构求和。平均值要合并各组的总和与条数。优化后既要核对每个机构的结果，也要比较最慢任务的完成时间。

## 可复现的关联测试数据

先生成机构、医生和患者，再从有效主键池抽取外键。为父子实体约定同一机构等约束，最后检查孤儿记录和跨机构错配。随机数种子、生成器版本、配置和输入顺序共同决定结果。并行生成时，可以从稳定的实体标识派生子种子，让任务调度顺序不影响输出。

用同一组参数重跑，抽查相同实体是否生成相同内容。再检查字段分布、关联数量和稀有场景覆盖，例如零就诊和高频就诊患者是否都出现。

## 滚动发布时变更表结构

旧实例仍可能写旧列。先加一个新旧实例都能共存的新列，部署兼容写入，再补历史数据。回填时用版本或条件更新，防止旧快照覆盖线上新值。对比两列，确认追平后逐步切换读取。

保留回滚窗口，验证旧版本仍能读取有效数据。等旧实例、后台任务及回滚版本都退出后，再单独清理旧列。

## 从构建输入追溯到运行镜像

固定基础镜像摘要、构建工具版本和依赖版本，用构建阶段编译测试，只将 JAR 和运行依赖复制到运行阶段。这样生产镜像中的内容可以独立审查。

记录源码版本、构建参数、测试结果和镜像摘要。把已验收的同一镜像按摘要部署到生产，检查运行实例的实际镜像 ID。两个环境分别用同一标签重新构建，可能得到不同内容。
