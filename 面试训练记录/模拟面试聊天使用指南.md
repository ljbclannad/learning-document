# 模拟面试聊天使用指南

日常训练直接在 **Codex 聊天框**中进行。你用自然语言提出要求、回答问题，Codex 根据 `learning-adaptive-mock-interview` skill 出题和反馈，并在后台调用本地工具保存进度。你不需要编写 JSON、输入 `--input` 或手动启动数据库。

第一版的对话界面就是 Codex，没有独立的面试应用窗口。以下示例是可以在聊天框里说的话，不是终端命令，也不要求逐字照抄。

## 第一次开始

在 Codex 中打开当前 `Learning-document` 工作区，在聊天框输入：

> 使用 $learning-adaptive-mock-interview，对我进行 MySQL 模拟面试，范围包括事务、锁和索引。逐题提问，并使用当前工作区的本地工具记录进度。

也可以选择其他主题：

> 使用 $learning-adaptive-mock-interview，开始 Spring 模拟面试，重点考查事务传播和代理机制。

只指定主题即可开始。如果有明确要求，可以一并说明岗位、难度和版本，例如“按高级 Java 开发要求，以 MySQL 8.0 和 InnoDB 为前提”。这会影响出题范围，不代表工具能够直接评定岗位胜任度。

新主题首次使用时，Codex 会准备本地记录、说明保存位置，并提出一道题。尚未回答时只保留待答题，不给你记失误。已有主题会先读取进度，不从头重复建立记录。

## 回答一道题

看到问题后，直接在聊天框回答。可以用口语、分点说明或代码，不必按固定模板组织。

通常会经历以下过程：

1. Codex 提出一道问题，你独立作答。
2. 表述有歧义时，Codex 先进行一次中性澄清。
3. 确认回答后，Codex 说明答对部分、具体缺口和修正版要点。
4. 保存成功后，Codex 告知等级和权重变化，再进行修正复述或下一题。

如果暂时不会，可以说：

> 这题我不会，请记录并讲解。

这会作为一次不会的独立回答记录。如果只是暂时不想练，可以说：

> 跳过这道题，先练其他考点。

普通跳过不算不会。已经完成评分后再跳过修正复述，不会撤销原评分，也不会新增失误。

如果一开始回答了一部分，澄清后才说“这一点我确实不会”，两段回答会保留在同一次尝试中，不会重复计数。得到提示后继续补充，也会保存为学习反馈，但不会用它代替提示前的独立回答评分。

## 常用说法

| 你想做什么 | 可以在聊天框这样说 |
|---|---|
| 继续训练 | “使用模拟面试 skill，继续上次 MySQL 面试，先恢复待答题。” |
| 查看薄弱点 | “查看 MySQL 的薄弱点，列出具体缺口和重复失误，先不要出题。” |
| 查看本轮表现 | “总结一下本轮已回答的题目，区分首次作答和复测。” |
| 暂时跳过一个考点 | “本轮先不练 MVCC，换其他考点。” |
| 拉长复测间隔 | “MySQL 同一考点至少隔 5 道其他题再复测。” |
| 留到下轮复测 | “MySQL 的同一考点只在后续训练会话中复测。” |
| 立即巩固 | “刚才这题换一个场景让我再练一次，按练习处理。” |
| 质疑评分 | “我认为刚才的评分有误，请结合我的原回答重新核对，必要时修订记录。” |
| 纠正提示分类 | “刚才只是澄清我的意思，不是给我提示，请核对分类并修订受影响的评分。” |
| 核实技术争议 | “这个结论可能与版本有关，请核对官方资料，确认前暂不计分。” |
| 只导出记录 | “把 MySQL 已保存的训练记录导出成 Markdown，并给我文件链接。” |

这些是自然语言请求，由 Codex 理解后执行相应操作。你不需要记住内部命令、题目 ID 或数据库字段；有同名主题或指代不清时，Codex 可能需要确认目标。

中性澄清与提示分类错误时，Codex 会保留原始内容，追加修订原因并同步更新受影响的评分。练习题也可以暂存为待核实，核实后仍只记学习反馈，不会变成一次独立考试。

## 暂停和结束有什么区别

**暂停**适合稍后继续同一轮，保留当前待答题：

> 暂停这轮 MySQL 面试，保留当前问题，之后继续。

回来后说“继续上次 MySQL 面试”即可。直接关闭聊天不等于显式暂停，但已保存的进度仍会保留。

**结束**适合完成一轮训练并生成总结：

> 结束本轮 MySQL 面试，总结表现和优先复习点，并导出训练记录。

结束时尚未回答的题不会计为失误。之后继续练习会开启新一轮，仍沿用该主题的历史统计。已经回答但尚待核实的题会列为未决，不当作零分。

## 换聊天后如何继续

在**同一个工作区**打开新的 Codex 聊天，明确主题并调用 skill：

> 使用 $learning-adaptive-mock-interview，读取当前工作区的 MySQL 训练记录，继续未结束的面试。

进度来自本地记录，不要求你重新粘贴整段旧聊天。换聊天不会自动结束原训练会话，也不会把同一轮暂停恢复当作跨会话复测。

如果换了工作区或电脑，需要先保证工具和记录位于相应位置；第一版不自动跨设备同步。

## 两种反馈方式

默认采用训练方式，答完一题就反馈和讲解。

如果希望集中体验正式面试节奏，在开始一轮时说：

> 使用 $learning-adaptive-mock-interview，开始一轮 MySQL 严格面试。本轮结束前先不公布评分和讲解，结束时统一反馈。

严格模式中，评估仍会保存，只是延后展示。若希望切换模式，结束当前轮后按新模式开始，避免混淆本轮的反馈约定。

## 如何理解等级和权重

| 等级 | 含义 |
|---|---|
| 0 | 不会或核心错误 |
| 1 | 部分掌握，存在实质缺口 |
| 2 | 基本正确，只有轻微遗漏或表达问题 |
| 3 | 独立掌握本题要求的机制、边界或场景 |

权重表示**复习优先级**，不是难度或总成绩。反复失误会提高权重；合格的独立复测达到条件后才会降低权重。即时复述和得到答案后再练，不作为新的独立掌握证明。

第一版不支持直接说“把某题权重改成 8”来任意加权。你可以要求专项练习、调整间隔或暂缓某考点；Codex 不应为了改权重而伪造评分。

如果明确调整评分规则，例如“以后等级 0 增加 3 点权重”，新规则只作用于之后创建的题目。随后只修改另一项时，已设置的参数会保留，旧题继续按当时的规则计算。

## 记录在哪里

| 内容 | 当前工作区中的位置 |
|---|---|
| 新工具保存的训练事实与统计 | `面试训练记录/.state/training.sqlite3` |
| 可在 Obsidian 阅读的导出文档 | `面试训练记录/导出/<主题ID>.md` |
| 原 Java 并发训练历史 | `面试训练记录/Java并发.md` |

新工具主题以数据库为准，导出文档按需要更新，不能把直接编辑导出 Markdown 当作修改成绩。需要纠正记录时，在聊天中提出，Codex 会保留旧评估并追加修订。

原 Java 并发历史含人工加权，目前不能无损导入第一版工具。继续该主题时，Codex 应沿用原 Markdown 流程；新主题可以使用本地工具。开发完成不等于历史已经迁移，迁移需要你明确提出并通过预检。

## 如果没有保存成功

Codex 应区分“数据库已保存”和“Markdown 已导出”。导出失败不意味着答题记录丢失；保存状态不确定时，也不应声称已经记录。

可以说：

> 请先确认刚才那次回答是否已经保存；未保存则重试，避免重复计数。

工具主题出现错误时，应先核对并恢复原请求，不另建一份 Markdown 重复记账。日常训练无需你查看错误码；只有排查工具问题时才需要阅读 [CLI 使用与维护说明](../tools/mock_interview/README.md)。
