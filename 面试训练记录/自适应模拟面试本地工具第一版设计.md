# 自适应模拟面试本地工具第一版设计

日期：2026-11-12。状态：第一版本地 CLI 已实现，个人历史尚未导入。

第一版采用现有 `learning-adaptive-mock-interview` skill 配合本地 CLI 的方式。用户继续在 Codex 中回答问题；模型负责出题、澄清、评估和讲解，本地工具负责保存训练事实、计算权重、安排复测和生成记录。目标是让训练可以跨聊天继续，并使统计结果可核对、可纠正。

本文定义第一版的功能范围、命令契约、数据结构及验收标准。实际入口为 `python3 tools/mock-interview.py`，使用方法与已确定的字段契约见 [工具 README](../tools/mock_interview/README.md)。

实现说明：`init`、导出和备份也通过 `--input` 接收 `request_id`；增加只读 `session show` 便于恢复版本。事件顺序使用数据库内全局递增序号，间隔计算仍限定于同主题。导出写前日志用于恢复文件替换后的中断。旧记录中的人工加权不在第一版事件模型内，预检将其列为阻断项；现有 Java 并发历史继续保留原文件，不能无损导入。

1.1.0 一致性修复：允许中性澄清后追加 `cannot_answer`，保留首次答题时间和计数；新增不参与独立评分的 `supplement`；新增提示与澄清之间的分类修订命令，已有评估时原子更新分类和评估；练习题可以待核实，核实后仍为练习；评分规则按当前生效版本局部更新。表结构仍为版本 1，修订证据追加在原有事件表中。

## 一 目标与边界

### 使用前提

- 面向个人、单机使用；允许多个聊天访问同一份数据，但同一主题同一时间只保留一个未结束会话。
- 数据存放在当前工作区，默认时区为 `Asia/Shanghai`，不自动上传外部服务。
- Codex 是交互入口，Obsidian 用于查看导出的 Markdown。
- 与现有“学习进度工具”独立运行，第一版不修改其代码、数据格式或界面。
- 本地工具不直接调用模型或联网。技术资料核实仍由 Codex 完成，工具只保存来源及评估结果。模型在 Codex 中处理的内容仍受 Codex 自身的数据处理方式约束。

### 功能范围

| 功能 | 第一版交付 |
|---|---|
| 主题与会话 | 创建主题、保存版本范围、开始或恢复会话、暂停、结束、恢复待答题 |
| 考点 | 稳定 ID、代表问题、考查边界、难度；支持同一考点的不同问法 |
| 作答 | 保存实际问题、独立回答、澄清、提示、修正复述及跳过原因 |
| 评估 | 等级、依据、缺口、修正版要点、待核实状态和评估修订 |
| 统计 | 权重、独立作答次数、累计与连续失误、合格复测计数 |
| 调度 | 根据权重、复测间隔和历史顺序推荐考点，提供推荐原因 |
| 偏好 | 复测间隔、仅跨会话复测、本轮暂缓考点、训练或严格面试模式 |
| 查询与导出 | 薄弱点、会话总结、考点历史、Markdown 导出 |
| 历史兼容 | 旧 Markdown 的预检、核对报告和显式导入；保留原文件 |

非目标：语音、网页或原生界面、多用户、云同步、自动修改知识笔记、完整岗位题库、自动合并考点、自动推断岗位胜任度、Markdown 双向同步、通用规则编程语言。

第一版保留等级和训练统计。若输出百分制成绩，必须同时标注计算公式、样本数、首次与复测口径，不将其解释为岗位胜任度。

## 二 职责与整体结构

```text
用户与 Codex 对话
        ↓
skill：出题、澄清、评分建议、解释、资料核实
        ↓ JSON 输入与输出
本地 CLI：校验、状态流转、调度、统计、导出
        ↓
SQLite：训练事实与评估修订历史
        ↓
Markdown：供 Obsidian 阅读的派生文档
```

采用 Python 标准库中的命令行、JSON 和 SQLite 能力，避免第一版引入常驻服务。实现时先验证本机 Python 版本和 SQLite 能力，再确定最低运行版本。CLI、业务规则和存储层分离，便于后续接入其他界面。

| 模型负责 | 工具负责 |
|---|---|
| 识别主题和考查范围 | 保存主题、版本和偏好 |
| 选择已有考点或建议登记新考点 | 校验考点 ID 和主题归属 |
| 生成具体场景题 | 持久保存问题、会话位置和状态 |
| 判断是否需要澄清、是否有实质提示 | 保存交互证据，检查评估字段和约束 |
| 提交等级建议及其依据 | 执行权重规则并返回变化 |
| 核实争议、提出修订 | 保留历史、重新计算统计 |
| 用自然语言总结表现 | 返回可靠的统计和明确的统计口径 |

工具不能独立判断自然语言答案正确性，也不能自动保证“中性澄清”的标记准确。必须保存原始交互与评估依据，支持事后纠正。评分输入与规则计算分离，使模型误判和程序计算错误可以分别定位。

### 拟议目录

```text
Learning-document/
├── tools/mock_interview/                 # 未来的 CLI 与业务模块
└── 面试训练记录/
    ├── 自适应模拟面试本地工具第一版设计.md
    ├── Java并发.md                       # 原有文件，只读导入
    ├── .state/
    │   ├── training.sqlite3              # 结构化事实来源
    │   └── backups/                      # 显式备份和迁移前备份
    └── 导出/
        ├── java-concurrency.md           # 工具管理的派生文档
        └── mysql.md
```

导出文件采用受限的主题 ID 命名，避免把主题显示名称直接当作路径。数据库是统计的唯一依据；导出文档包含生成标识、生成时间和数据修订号。手写内容继续保存在原文件或独立笔记中。

## 三 核心概念与状态

### 考点和尝试

考点对应稳定的考查目标，而非某一句题目。同一目标的场景变式共用 `concept_id`；同一技术名词下的独立目标分别记录。考点的 `scope` 记录判断等价的边界，例如区分 `ThreadLocal` 引用关系与线程池上下文污染。

一次尝试对应一次实际提问及其回答过程。新题和独立复测属于可评分尝试；用户要求的即时重练属于练习，不能增加独立作答次数或影响权重。修正复述是原尝试的追加记录，不创建新的可评分尝试。

### 会话状态

`active → paused → active`，以及 `active/paused → ended`。结束不可重新打开；再次训练创建新会话。

暂停保留待答题。结束时未回答的题转为 `abandoned`，不计失误；已经回答但尚未评估或待核实的尝试仍可在会话结束后完成评估，并更新该会话总结。严格面试模式仅延后反馈展示，不延后保存已确认的评估。

### 尝试状态

| 状态 | 含义及允许动作 |
|---|---|
| `awaiting_answer` | 已保存题目，允许回答、跳过或结束后放弃 |
| `awaiting_evaluation` | 已收到回答，允许澄清、补充证据或提交评估 |
| `pending_verification` | 有争议，等待核实；暂不计评分统计 |
| `evaluated` | 已有正式评估，允许追加修正复述或修订评估 |
| `skipped` | 未说明不会的跳过，不计评分统计 |
| `abandoned` | 会话结束时未回答，不计评分统计 |
| `practice_completed` | 即时重练完成，仅保留学习反馈 |

同一会话至多有一道 `awaiting_answer` 或 `awaiting_evaluation` 的当前题。待核实题可以暂存并继续其他题；恢复时展示待核实清单，不重复出同一考点。

明确说“不会”或“因为不会而跳过”须保存为回答，并提交等级 0；普通跳过不允许自动转换成等级 0。

## 四 评分与调度规则

### 初始规则

沿用当前 skill：初始权重 1，上限 10，等级范围 0–3。每次正式评估的独立尝试计一次作答。

| 等级 | 失误处理 | 权重变化 | 连续合格复测计数 |
|---|---|---|---|
| 0 | 累计失误加 1，连续失误加 1 | 加 2；本次为连续第 2 次及以后再加 1 | 清零 |
| 1 | 累计失误加 1，连续失误加 1 | 加 1；本次为连续第 2 次及以后再加 1 | 清零 |
| 2 | 连续失误清零 | 不变 | 清零 |
| 3 | 连续失误清零 | 达成降权条件时减 1 | 按下述规则累计 |

更新后权重截断到 1–10。等级 0、1 为实质缺口；等级 2 的表达改进建议不自动作为失误。

降权要求两次连续、无实质提示的等级 3 独立复测，两次之间至少隔两道其他考点的有效独立作答，或属于不同会话。达成后权重减 1，计数归零；即使权重已经为 1，也消耗本次降权计数。首次诊断题的等级 3 不进入复测降权计数。

本设计将“其他题”明确为：其他考点已完成正式评估的独立尝试，按实际回答顺序计算；不包含跳过、即时重练、修正复述或尚待核实的回答。后续核实完成后重算相关资格。两次等级 3 距离不足时，后一次保留成绩但不增加降权计数，前一次资格保留。

有实质提示时，模型必须依据提示前的独立回答评分；工具拒绝带实质提示标记的等级 3。中性澄清不属于实质提示。用户在未作答前得到答案，且没有可评价的独立回答时，只记练习。

### 待核实与修订

第一版采用整次评估暂存：只要争议项影响等级，就将该尝试置为待核实，正式评分次数、失误和权重均暂不更新。已有正确内容和争议依据照常保存。

修订不得覆盖原评估。新版本包含旧版本号、修订原因和新的完整评估；按尝试实际回答顺序，使用各尝试绑定的规则重新计算该考点统计。由于间隔资格可能受到影响，还须重新计算同主题中受影响的其他考点。此前已实际提出的问题保持不变，后续推荐采用修订后的结果。

### 选题顺序

1. 返回当前待答题时不再推荐新题。
2. 排除本轮暂缓、尚待核实及未满足复测间隔的考点。
3. 以权重降序、最后独立作答时间升序、考点 ID 升序排序。
4. 有薄弱点时按“复测、复测、新题”的三个有效作答位置循环；薄弱点定义为权重大于 1 或最近正式等级为 0、1。
5. 无合格复测候选时返回 `new_question_needed`，由模型登记或选择新考点；不缩短间隔强行复测。

调度推荐为只读操作，不占用题目位置。仅正式完成的独立作答推进三题节奏；跳过和练习不推进。选择候选后创建题目时再次检查状态与间隔，防止两个聊天基于旧结果同时出题。

讲解或修正练习之后，默认至少隔两道其他题才能再次独立复测。间隔起点取该考点最近一次独立回答或学习反馈中较晚者。可配置 `min_other_questions` 与 `cross_session_only`；不同会话不受题数限制，但仍不得在同一会话中通过暂停、恢复伪造跨会话复测。

原聊天中的“拉长间隔”没有明确数值，不能静默转换成固定偏好。导入时列为待确认项；未配置时使用 skill 默认值 2。配置值第一版只允许不低于 2，立即重练通过练习模式完成。

## 五 CLI 命令契约

### 调用约定

下文以 `mock-interview` 表示未来入口。具体安装方式在实现阶段确定；命令名称和 JSON 契约与启动方式解耦。

- 全局参数 `--workspace PATH` 必须指向明确工作区；省略时使用当前目录，并在响应中返回解析后的绝对路径。不自动向上搜索或切换数据库。
- 复杂正文通过 `--input FILE` 或 `--input -` 的 UTF-8 JSON 输入，避免将用户答案拼进 shell 命令。
- 输出默认单个 JSON 对象；解释和错误信息使用简体中文，字段名使用英文。诊断日志写入标准错误，不混入标准输出。
- 所有写命令携带 `request_id`。同一 ID 和相同规范化请求重试返回原结果；同一 ID 不同内容返回冲突。
- 修改已有对象时携带 `expected_revision`，版本不一致时拒绝写入并返回当前版本。
- 不提供直接修改累计失误、权重或汇总计数的命令。

### 命令清单

| 命令 | 主要输入 | 输出或效果 |
|---|---|---|
| `init` | `--workspace` | 初始化空数据库和规则 v1；重复执行不清空数据 |
| `topic list` | 无 | 主题及摘要 |
| `topic create --input` | ID、名称、版本范围、时区 | 新主题 |
| `topic show --topic` | 主题 ID | 规则、偏好、当前会话、待答与待核实清单 |
| `topic configure --input` | 主题、版本、间隔、跨会话开关 | 更新未来调度偏好，保留修订记录 |
| `rule create --input` | 主题、支持的规则参数、生效时间、变更说明 | 创建不可变规则版本，只供后续题目使用 |
| `concept list --topic` | 主题 ID | 考点目录和边界 |
| `concept create --input` | ID、主题、代表问题、边界、难度 | 新考点；重复 ID 不自动覆盖 |
| `session start --input` | 主题、聊天标识、反馈模式 | 创建会话；存在未结束会话时返回冲突与恢复信息 |
| `session resume --input` | 会话 ID、版本、当前聊天标识 | 恢复会话，返回当前题及未决事项 |
| `session pause --input` | 会话 ID、版本 | 暂停并保留进度 |
| `session end --input` | 会话 ID、版本 | 结束会话，返回统计及未决事项 |
| `session defer --input` | 会话、考点、是否暂缓、理由 | 修改本轮考点暂缓设置 |
| `next --session` | 会话 ID | 只读候选、间隔证据及推荐原因 |
| `attempt create --input` | 会话、考点、实际问法、作答类型、会话版本 | 保存题目和规则快照，返回尝试 ID |
| `attempt show --attempt` | 尝试 ID | 问题、交互、评估版本及状态 |
| `attempt append --input` | 尝试、版本、交互类型、内容 | 追加回答、澄清、提示、讲解或修正复述 |
| `attempt skip --input` | 尝试、版本、理由 | 普通跳过，不评分 |
| `attempt evaluate --input` | 尝试、版本、评估对象 | 初次正式评估或标记待核实 |
| `attempt revise --input` | 尝试、版本、原评估版本、修订原因、评估对象 | 新建评估版本并重算 |
| `attempt reclassify --input` | 尝试、版本、事件 ID、新分类、理由；已有评估时附原评估版本和新评估 | 追加事件分类修订并原子更新受影响评估；历史题型来源缺失时明确提供 `restore_kind` |
| `report weaknesses --topic` | 主题 ID | 权重、失误、当前缺口、最后作答及证据 |
| `report session --session` | 会话 ID | 首次与复测分开统计，另列待核实、跳过和练习 |
| `export markdown --topic` | 主题 ID | 输出到固定导出目录，返回路径与数据修订号 |
| `import markdown --input` | 来源路径、主题、模式 `preview/apply`、报告指纹 | 预检报告，或按确认后的报告导入 |
| `check` | 可选主题 ID | 只读检查约束、历史与缓存一致性 |
| `stats rebuild --input` | 主题、预期数据修订号 | 从历史重新生成派生统计 |
| `backup create --input` | 请求 ID | 使用 SQLite 一致性备份，返回路径 |

`rule create` 只开放权重边界、等级增量、连续失误增量和合格复测次数等既定算法参数；拒绝不支持的规则表达式。首次仍使用 skill 的现有规则。第一版不支持回溯修改规则版本。

每次 `rule create` 以调用时当前生效版本为基础，合并指定字段并保存完整快照；遗漏字段不恢复默认值，已存在的未来排期快照也不自动改写。

### 评估输入示例

以下为接口说明中的虚构数据，不能作为真实训练记录导入。

```json
{
  "request_id": "req-example-eval-01",
  "attempt_id": "attempt-example-01",
  "expected_revision": 3,
  "evaluation": {
    "status": "confirmed",
    "grade": 1,
    "answer_event_ids": ["event-example-answer-01"],
    "substantive_hint": false,
    "basis": "能够说明快照读，但未区分当前读的取值依据。",
    "gaps": ["快照读与当前读的区别"],
    "corrected_points": ["分别解释两种读取方式的可见性规则"],
    "sources": []
  }
}
```

评估字段中，正式评分必须提供 `grade`、至少一个实际回答事件 ID 和非空依据。待核实评估的 `grade` 为 `null`，另提供 `disputed_points`。来源列表记录标题、URL 和核实说明，工具不自动访问 URL。练习只能提交反馈，等级为空且不生成评分统计。

### 响应与错误

成功响应统一包含 `ok`、`schema_version`、`workspace`、`data`、`warnings`。评估成功的 `data` 包含尝试 ID、对象版本、评估版本、权重前后值、统计变化、数据修订号和 `replayed`。

失败响应包含 `ok: false` 和 `error: {code, message, details}`；不得包含“已记录”等成功措辞。

| 退出码 | 典型错误 | 处理方式 |
|---|---|---|
| 0 | 无 | 正常结果，可能包含导出待更新提示 |
| 2 | `INVALID_INPUT` | 修正输入；不写数据库 |
| 3 | `NOT_FOUND` / `NOT_INITIALIZED` | 指明不存在的资源或缺少初始化 |
| 4 | `REVISION_CONFLICT` / `IDEMPOTENCY_CONFLICT` / `INVALID_STATE` | 读取最新状态，不盲目覆盖 |
| 5 | `STORAGE_ERROR` / `DATABASE_BUSY` | 保留请求，核对后使用原请求 ID 重试 |
| 6 | `IMPORT_REVIEW_REQUIRED` / `EXPORT_CONFLICT` | 返回具体差异，等待处理 |

导出失败不回滚已经提交的评估。响应明确区分“数据库已保存”和“Markdown 尚未更新”。

## 六 数据表结构

采用 SQLite。以下为逻辑表结构，不包含建表实现。ID 使用 TEXT；布尔字段使用 INTEGER 的 0/1；JSON 使用 TEXT 并由应用校验。新产生时间保存 UTC ISO 8601，同时按主题时区显示。缺失或只有日期的旧时间必须保留精度信息，不能伪造时分秒。

所有外键启用约束；业务历史不级联删除。新建 ID、请求记录、历史及派生统计在同一事务中提交。

### 主题与配置

| 表 | 字段与类型 | 约束及用途 |
|---|---|---|
| `topics` | `id TEXT`、`name TEXT`、`version_scope TEXT`、`timezone TEXT`、`revision INTEGER`、`created_at TEXT` | `id` 主键，仅允许小写字母、数字及连字符；名称用于显示 |
| `rule_versions` | `id TEXT`、`topic_id TEXT`、`version INTEGER`、`parameters_json TEXT`、`effective_at TEXT`、`reason TEXT`、`created_at TEXT` | 主键；主题外键；`(topic_id, version)` 唯一；创建后不可变 |
| `preference_versions` | `id TEXT`、`topic_id TEXT`、`version INTEGER`、`min_other_questions INTEGER`、`cross_session_only INTEGER`、`reason TEXT`、`created_at TEXT` | 主键；主题外键；版本唯一；间隔至少 2；追加保留旧版 |
| `concepts` | `id TEXT`、`topic_id TEXT`、`title TEXT`、`representative_question TEXT`、`scope TEXT`、`difficulty TEXT`、`created_at TEXT` | 主键；主题外键；难度为基础、中等、进阶；第一版不跨主题共享统计 |

### 会话与作答

| 表 | 字段与类型 | 约束及用途 |
|---|---|---|
| `sessions` | `id TEXT`、`topic_id TEXT`、`status TEXT`、`feedback_mode TEXT`、`started_at TEXT`、`ended_at TEXT NULL`、`revision INTEGER` | 主键；主题外键；状态限定；每主题至多一个 active/paused 会话 |
| `session_events` | `id TEXT`、`session_id TEXT`、`event_type TEXT`、`payload_json TEXT`、`created_at TEXT` | 追加式历史；保存开始、恢复、暂停、结束、聊天绑定、暂缓及取消暂缓 |
| `attempts` | `id TEXT`、`session_id TEXT`、`concept_id TEXT`、`rule_version_id TEXT`、`preference_version_id TEXT`、`question TEXT`、`kind TEXT`、`status TEXT`、`sequence INTEGER`、`answered_order INTEGER NULL`、`answered_at TEXT NULL`、`time_precision TEXT`、`created_at TEXT`、`revision INTEGER` | 外键；会话内 sequence 唯一；kind 为 diagnostic/retest/practice；主题一致性由事务校验 |
| `attempt_events` | `id TEXT`、`attempt_id TEXT`、`event_type TEXT`、`content TEXT`、`metadata_json TEXT`、`occurred_order INTEGER`、`occurred_at TEXT NULL`、`time_precision TEXT` | 外键；主题内顺序用于间隔计算；保存原始回答、明确不会、澄清提问与回答、提示、讲解、修正复述 |
| `evaluations` | `id TEXT`、`attempt_id TEXT`、`version INTEGER`、`status TEXT`、`grade INTEGER NULL`、`substantive_hint INTEGER`、`answer_event_ids_json TEXT`、`basis TEXT`、`gaps_json TEXT`、`corrected_points_json TEXT`、`sources_json TEXT`、`disputed_points_json TEXT`、`supersedes_id TEXT NULL`、`revision_reason TEXT NULL`、`created_at TEXT` | `(attempt_id, version)` 唯一；等级 0–3；最新版本为当前评估；旧版本不可覆盖 |

`answered_order` 使用首次实际回答事件的顺序，而非评估保存时间；迟到核实和评估修订不能改变实际答题顺序。主题内顺序在事务中分配。`session_events` 的暂缓记录包含考点 ID，聊天绑定包含 host 和 thread 标识，均不触发向其他聊天发送消息。

事件扩展约定：`supplement` 保存提示后的补充学习内容；`event_reclassification` 的 `metadata_json` 保存目标 `event_id`、`from_type`、`to_type` 和题型前后值，正文保存修订理由。原事件不覆盖；读取时折叠修订生成有效分类。答题前提示自动改为练习时，将原题型记入 `kind_before_hint`。分类修订不重置复测间隔，补充回答作为学习反馈重置间隔。

| 表 | 字段与类型 | 约束及用途 |
|---|---|---|
| `concept_stats` | `concept_id TEXT`、`weight INTEGER`、`attempt_count INTEGER`、`failure_count INTEGER`、`consecutive_failures INTEGER`、`qualified_retests INTEGER`、`qualification_anchor_id TEXT NULL`、`last_grade INTEGER NULL`、`last_answered_at TEXT NULL`、`last_answered_order INTEGER NULL`、`current_gaps_json TEXT`、`computed_revision INTEGER` | 考点主键和外键；可重建缓存；时间不完整时使用答题顺序排序 |
| `write_requests` | `request_id TEXT`、`operation TEXT`、`payload_hash TEXT`、`response_json TEXT`、`created_at TEXT` | 主键；用于幂等重试；哈希覆盖操作、目标和规范化业务输入 |
| `import_batches` | `id TEXT`、`source_path TEXT`、`source_hash TEXT`、`report_hash TEXT`、`status TEXT`、`mapping_json TEXT`、`created_at TEXT` | 来源和报告指纹；保存源段落与导入对象的对应关系 |
| `exports` | `topic_id TEXT`、`path TEXT`、`content_hash TEXT`、`data_revision INTEGER`、`exported_at TEXT` | 主题主键；检测导出文档被手工修改 |
| `app_meta` | `key TEXT`、`value TEXT` | 主键；记录 schema_version、数据修订号及各主题顺序计数器 |

统计保存最新有效评估的结果，完整依据保留在历史表。`current_gaps_json` 来自最近一次有效评估，不自动合并全部历史缺口。所有计数非负，正式等级 2、3 必须清零连续失误。

需要的索引：主题下的考点；主题下未结束会话的部分唯一索引；会话内题目顺序；主题内答题顺序；尝试下事件顺序；尝试下评估版本；规则生效时间。JSON 字段不作为第一版关键检索条件。

## 七 一致性与失败恢复

### 写入事务

每次写入依次检查请求是否已提交、目标版本和业务状态，再追加事实、计算统计、递增数据修订号并保存响应。上述步骤必须处于同一数据库事务。重复请求检查优先于对象版本检查，确保成功后的同一请求重试能返回原结果。

评估写入、状态更新和统计更新不得分批提交。多个聊天同时提交时，以数据库事务和 `expected_revision` 防止覆盖。数据库忙时限时返回错误，不长时间阻塞聊天。

### 导出与备份

导出从一致性快照读取数据，先写同目录临时文件，再原子替换工具管理的目标文档。若目标文件哈希与上次导出不符，返回冲突，不覆盖手工修改；没有导出登记但目标已存在时同样拒绝覆盖。导出中断后，若文件内容已经等于预期内容，可只补齐导出登记。

数据库提交和文件导出不承诺跨资源原子性。数据已经保存但导出失败时，可单独重试导出。备份使用 SQLite 一致性备份能力，不直接复制正在写入的数据库文件。数据库结构迁移前备份；第一版不提供自动删除备份或破坏性恢复命令。

### 故障后的用户反馈

- 没有成功响应时，不声称已经保存；用同一请求 ID 查询或重试确认结果。
- 存储失败时保留本次待保存内容及原尝试 ID，避免再次创建新尝试。
- `check` 检查历史、外键与缓存；缓存不一致时先报告，再显式重建。
- 不将工具失败、网络核实失败或用户离开计为知识失误。

## 八 旧记录导入

导入分为预检和应用两步，均不修改原 Markdown。

1. 读取指定文件并计算指纹，解析主题、规则、考点索引和尝试历史。
2. 以尝试历史为统计依据，与现有索引和总结对照，输出字段缺失、重复考点、次数差异和无法确认的提示情况。
3. 缺失时间保留日期或未知精度；缺少可靠顺序时保留源文件顺序并注明推断，不能据此自动授予降权资格。
4. 无法确认规则、等级或独立性且影响统计的条目列为阻断项，先修正导入映射；不能静默丢弃条目。
5. 应用时要求来源指纹和报告指纹仍一致，在一个事务中导入主题数据及来源映射。同一来源再次应用不得重复计数。

此前对话中的“43 个考点、46 次已评分独立作答”仅作为核对线索，不能用来强行改写历史。实施导入时须重新读取原文件，确认当前实际记录。

如果该主题已产生新的本地工具记录，第一版拒绝直接追加旧文件；需先明确映射和去重方案，避免将同一次答题计入两次。导入完成后对既有 Markdown 的编辑不会自动同步进数据库。

## 九 skill 接入与交付顺序

保持现有教学规则，仅调整数据操作路径：

1. 开始时读取主题状态和偏好，恢复待答题；无记录时从诊断题开始。
2. 出题前读取候选，保存实际问题后再展示。
3. 收到回答立即追加证据；澄清和提示独立标记。
4. 提交评估后使用工具返回的统计，不自行计算权重。
5. 讲解和修正复述追加到原尝试，明确其非独立复测性质。
6. 结束时读取会话报告，导出成功后给出 Markdown 链接。

首条实际回答前可以保存会话和待答题元数据，但不创建已评分记录、缺口或失误，不输出空白训练报告。该行为需在未来修改 skill 时明确，以兼容原 skill“不预填失误”的要求。

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| 一 | 存储、状态、评估、修订、权重计算 | 下列规则与一致性验收通过 |
| 二 | 会话恢复、调度、偏好、skill 接入 | 跨聊天训练流程与间隔验收通过 |
| 三 | 报告、导出、备份、旧记录导入 | 数据核对和兼容验收通过 |

已同步交付工具 README、命令帮助、JSON 契约样例和 skill 更新。使用临时数据库做定向测试，不在真实个人记录上做故障注入。

以下为第一版验收行为。对应自动化测试位于 `tools/mock_interview/tests/`，在临时数据库中执行；真实历史只做只读预检，不用于故障注入。

2026-11-12，1.1.0 验证结果：51 项自动化测试通过，包含独立 CLI 进程的完整操作流程及本次 5 项一致性修复的 10 项新增回归。旧 Java 并发记录识别为 43 个考点和 46 次尝试；人工加权及需人工确认的提示情况已在预检中列明，未导入。

### 整体完成标准

1.1.0 增补验收：

| 编号 | 场景 | 预期结果 |
|---|---|---|
| X01 | 已回答、中性澄清后明确不会 | 追加原话，保留首次时间与顺序，独立次数和失误只增加一次 |

用临时数据完成“诊断题 → 澄清 → 评估 → 讲解 → 暂停 → 换聊天恢复 → 间隔复测 → 纠正误判 → 总结导出”的完整流程；每一步的次数、权重和状态均能从历史重新推导。

试运行时使用真实训练的新数据验证体验，但不得为通过验收篡改旧记录。完成后用户无需再依赖模型临时编写脚本维护统计；原笔记、现有训练文件和学习进度应用保持独立。
