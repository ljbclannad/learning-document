# 2. 值传递
在 Java 中，所有方法的参数都是通过值传递的，但这个“值”可以是基本数据类型的值或对象的引用。以下是对 Java 值传递的详细说明：

### 1. 基本数据类型的值传递

对于基本数据类型（如 `int`、`double`、`char` 等），当你将它们作为参数传递给方法时，实际传递的是它们的值的副本。对参数的任何修改不会影响原始变量。

```java
public class ValuePassExample {
    public static void main(String[] args) {
        int num = 10;
        modifyValue(num);
        System.out.println(num); // 输出: 10
    }

    public static void modifyValue(int value) {
        value = 20; // 修改的是副本
    }
}
```

### 2. 对象的引用传递

对于对象类型（如 `String`、`ArrayList` 等），当你将对象作为参数传递时，传递的是对象引用的副本。这意味着你可以通过这个引用修改对象的内容，但无法改变引用本身指向的对象。

```java
import java.util.ArrayList;

public class ReferencePassExample {
    public static void main(String[] args) {
        ArrayList<String> list = new ArrayList<>();
        list.add("Hello");
        modifyList(list);
        System.out.println(list); // 输出: [Hello, World]
    }

    public static void modifyList(ArrayList<String> list) {
        list.add("World"); // 修改的是原对象
    }
}
```

### 3. 不能改变对象引用

虽然可以通过引用修改对象的状态，但不能改变引用使其指向其他对象。

```java
public class ReferenceChangeExample {
    public static void main(String[] args) {
        String str = "Hello";
        changeString(str);
        System.out.println(str); // 输出: Hello
    }

    public static void changeString(String s) {
        s = "World"; // 这不会影响原始字符串
    }
}
```

### 总结

- **基本数据类型**：通过值传递，修改不会影响原始值。
- **对象引用**：通过值传递引用，允许修改对象内容，但不能改变引用本身指向的对象。

理解这一点对于编写有效的 Java 代码非常重要，尤其是在处理方法参数和对象时。

# 3.String,StringBuffer,StringBuilder

在Java中，`String`、`StringBuffer`和`StringBuilder`是处理字符串的三种不同类，它们之间有一些重要的差异。以下是它们的主要区别：

### 1. **不可变性 vs 可变性**
- **String**：
  - `String`是不可变的。一旦创建，字符串的内容不能被改变。任何对`String`的修改都会创建一个新的`String`对象。
  ```java
  String str = "Hello";
  str = str + " World"; // 创建了一个新的String对象
  ```

- **StringBuffer** 和 **StringBuilder**：
  - 这两者都是可变的，可以在原有对象上进行修改，而不需要创建新的对象。
  ```java
  StringBuffer sb = new StringBuffer("Hello");
  sb.append(" World"); // 修改了原有的StringBuffer对象
  ```

### 2. **线程安全性**
- **StringBuffer**：
  - `StringBuffer`是线程安全的，适合在多线程环境中使用。它的方法是同步的。
  
- **StringBuilder**：
  - `StringBuilder`不是线程安全的，适合在单线程环境中使用，性能更高。

### 3. **性能**
- **String**：
  - 由于不可变性，频繁的字符串拼接会导致性能下降，因为每次拼接都会创建新的对象。

- **StringBuffer** 和 **StringBuilder**：
  - 在需要频繁修改字符串的情况下，`StringBuffer`和`StringBuilder`的性能更好。`StringBuilder`通常比`StringBuffer`更快，因为它没有同步开销。

### 4. **使用场景**
- **String**：
  - 适合用于不需要修改的字符串。

- **StringBuffer**：
  - 适合在多线程环境中需要修改字符串的场景。

- **StringBuilder**：
  - 适合在单线程环境中需要频繁修改字符串的场景。

### 示例代码
```java
// String 示例
String str = "Hello";
str += " World"; // 创建新的String对象

// StringBuffer 示例
StringBuffer sb = new StringBuffer("Hello");
sb.append(" World"); // 修改原有对象

// StringBuilder 示例
StringBuilder sb2 = new StringBuilder("Hello");
sb2.append(" World"); // 修改原有对象
```
