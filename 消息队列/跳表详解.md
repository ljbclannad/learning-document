
# 1. 总览

## **一、zset（Sorted Set）概述**

  

Redis 的有序集合（zset）结构提供：

- 元素唯一，类似 set；
    
- 每个元素关联一个 **score（double）**，按 score 自动排序；
    
- 常见命令：ZADD、ZRANGE、ZREM、ZINCRBY 等。
    

---

## **二、底层数据结构设计**

  

Redis 为了兼顾性能和空间，在不同规模下使用两种底层结构：

|**编码方式**|**使用条件**|**底层结构**|
|---|---|---|
|ziplist（< Redis 5.0）或 listpack（Redis 5.0+）|元素少、短字符串|压缩表（空间紧凑）|
|skiplist|元素多，性能优先|哈希表 + 跳表|

源码结构在 src/t_zset.c 中定义。

  

### **1.** 

### **zset**

###  **结构体定义（跳表编码）**

```
typedef struct zset {
    dict *dict;         // 快速查找 value -> score（哈希表）
    zskiplist *zsl;     // score 排序结构（跳表）
} zset;
```

- **dict**：提供 O(1) 查找功能；
    
- **zskiplist**：按 score 排序，支持快速范围查询（如 ZRANGE、ZRANK）；
    

  

### **2. 跳表结构**

  

Redis 自研跳表，定义如下：

```
typedef struct zskiplist {
    struct zskiplistNode *header, *tail;
    unsigned long length;
    int level;
} zskiplist;
```

每个节点是：

```
typedef struct zskiplistNode {
    sds ele;                 // 元素内容
    double score;            // 分值
    struct zskiplistNode *backward;
    struct zskiplistLevel {
        struct zskiplistNode *forward;
        unsigned int span;
    } level[];
} zskiplistNode;
```

### **✅ 1. ZADD：添加元素**

---

### **✅ 3. ZREM：删除元素**

```
int zsetDel(...) {
    dictDelete(dict, ele);            // 从 dict 删除
    zslDelete(zsl, score, ele);       // 从跳表删除
}
```

## **四、优化细节**

- 使用跳表而非红黑树，是为了更简单的实现多层查找逻辑；
    
- 每次插入用 randomLevel() 随机决定层数，减少维护平衡的复杂度；
    
- 跳表节点的 span 提供 rank 快速计算（优化 ZRANK、ZCOUNT）；
    
- dict 和 zskiplist 双结构配合，读写性能都很高；

# 2. 插入操作以及随机层数
### **1.** **跳表的基本结构**

  

跳表由多层链表组成，每一层指向更高层的节点。最低层包含所有节点，其他层则是跳跃路径，帮助加速查找过程。层数越高的层次，节点越少，形成一个稀疏的金字塔结构。

- **Level 0**：包含所有的节点，链表的最底层。
    
- **Level 1, 2, …**：逐层上升的跳跃路径，每一层的节点数逐渐减少。
    

  

### **2.**  **随机层数的作用**

  

对于每个节点，插入时要决定它的层数，这个层数是随机计算的。这个层数决定了节点会出现在多少层。

  

通常，跳表的层数是基于 **概率** 来决定的。比如在 Redis 中，通常使用 25% 的概率来决定节点能否晋升到上一层：

- 节点有 50% 的概率在第一层出现；
    
- 有 25% 的概率出现在第二层；
    
- 有 12.5% 的概率出现在第三层；
    
- 依此类推……
    

  

这个概率规则意味着，每一层的节点数量呈**几何分布**，随着层数的增加，节点的数量逐层减少。

  

### **3.** **插入节点的过程**

  

#### **步骤一：查找插入位置**

  

首先，从跳表的最高层（Level N）开始，从左到右遍历，找到应该插入节点的位置。每一层都试图跳过更多的节点，从而加快查找的速度。

  

假设我们正在插入一个分值为 score 的节点，插入过程是这样的：

1. **从最高层开始**，我们遍历该层的节点，直到我们找到一个节点的分值大于或等于目标分值 score，或者遍历到该层的最后一个节点。
    
2. 记录每一层的前驱节点（即插入位置的前一个节点）。
    

  

#### **步骤二：决定节点的层数**

  

然后，我们使用随机数生成算法来决定这个节点的层数。每次生成一个随机数来决定是否将节点提升到上一层。

  

假设我们使用概率 P = 0.25 来决定节点是否晋升：

1. 每次尝试晋升到上一层时，生成一个随机数。如果随机数小于 P（比如 25% 的概率），则晋升到更高一层。
    
2. 直到生成的随机数不小于 P，或者达到最大层数为止。
    

  

- 例如，如果随机数小于 0.25，节点就会晋升到第二层；如果连续两次都小于 0.25，它就会晋升到第三层。
    

  

#### **步骤三：更新前驱节点和 span 信息**

  

当层数确定后，我们开始插入节点：

1. **更新每一层的指针**：
    
    - 对于每一层，节点会插入到它前驱节点的后面，更新该层前驱节点的指针。
        
    - forward[i] 指针指向新插入节点。
        
    
2. **更新 span 信息**：
    
    - 每一层节点会维护一个 span 信息，表示从当前节点到下一个节点之间跳过的节点数。span 的计算方式非常重要，因为它可以帮助我们快速计算排名。
        
    - 新节点的 span[i] 由前驱节点的 span[i] 减去已经跳过的节点数来计算，确保在查询排名时能够高效计算。
        
    

  

#### **步骤四：调整高层的 span**

  

如果当前节点的层数比已经存在的层数多，那么必须在跳表的头部增加新的层，并且要调整高层的 span 值，使得这些层的 span 值正确。

---

### **4.** **总结：随机层数的优势**

  

通过随机生成层数来决定节点的插入层级，跳表实现了 **自平衡结构**，不需要复杂的旋转操作。每一层的节点数量呈几何分布，这种设计使得：

- **查找操作**：从高层开始查找，可以快速跳过大量不相关的节点，时间复杂度为 O(logN)；
    
- **插入和删除操作**：只需要调整几条指针，更新 span，时间复杂度也是 O(logN)，比红黑树等平衡树结构简单；
    
- **自平衡**：节点层数的随机性使得跳表无需像红黑树那样维护严格的平衡规则，结构自适应地保持了高效的查找性能。
    

---

### **5.**  **小结**

- 跳表通过随机决定每个节点的层数，避免了手动维护平衡树的复杂性，同时保证了高效的查询和操作。
    
- 每一层节点数逐渐减少，节点随机分布在各个层级上，形成一种稀疏的“金字塔结构”，让查找变得高效。
    
- 随机层数为跳表带来了灵活的自平衡特性，不需要复杂的旋转或重排操作。
