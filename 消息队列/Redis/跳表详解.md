# 1. zset（Sorted Set）概述
- 元素唯一，类似 set；
- 每个元素关联一个 **score（double）**，按 score 自动排序；
- 常见命令：ZADD、ZRANGE、ZREM、ZINCRBY 等。

# 2. 底层数据结构设计
Redis 为了兼顾性能和空间，在不同规模下使用两种底层结构：
| 编码方式                                        | 使用条件         | 底层结构           |
| ----------------------------------------------- | ---------------- | ------------------ |
| ziplist（< Redis 5.0）或 listpack（Redis 5.0+） | 元素少、短字符串 | 压缩表（空间紧凑） |
| skiplist                                        | 元素多，性能优先 | 哈希表 + 跳表      |

# 3. zset 结构体定义（跳表编码）
``` c
typedef struct zset {
    dict *dict;         // 快速查找 value -> score（哈希表）提供 O(1) 查找功能
    zskiplist *zsl;     // score 排序结构（跳表） zskiplist：按 score 排序，支持快速范围查询（如 ZRANGE、ZRANK）；
} zset;

typedef struct zskiplist {
    struct zskiplistNode *header, *tail;
    unsigned long length;
    int level;
} zskiplist;

typedef struct zskiplistNode {
    sds ele;                 // 元素内容
    double score;            // 分值
    struct zskiplistNode *backward; /* level0 的反向指针，支持逆序遍历 */
    struct zskiplistLevel {
        struct zskiplistNode *forward; /* 当前层的 forward 指针 */
        unsigned int span; /* 当前层的跨度 */
    } level[]; /* 当前节点的 level 数组，每个 level 包含 forward 和 span */
} zskiplistNode;
```

# 4. 关键操作源码解析

### 4.1 ZADD：添加元素
``` c
/* 插入 (score, ele)，返回新节点指针 */
zskiplistNode *zslInsert(zskiplist *zsl, double score, const char *ele) {
    zskiplistNode *update[ZSKIPLIST_MAXLEVEL];
    unsigned long rank[ZSKIPLIST_MAXLEVEL];

    zskiplistNode *x = zsl->header;

    /* 1) 从最高层往下走：找每一层“最后一个 < (score,ele) 的节点” */
    for (int i = zsl->level - 1; i >= 0; i--) {
        /* rank[i]：到达 update[i] 时，已经跨过的 level0 节点数 */
        rank[i] = (i == zsl->level - 1) ? 0 : rank[i + 1];

        while (x->level[i].forward &&
               zslNodeCompare(x->level[i].forward->score, x->level[i].forward->ele,
                              score, ele) < 0)
        {
            rank[i] += x->level[i].span; /* span 累加：跨过多少个 level0 节点 */
            x = x->level[i].forward;
        }
        update[i] = x;
    }

    /* 2) 随机层高 */
    int level = zslRandomLevel();

    /* 如果新节点层数超过当前最高层：补齐 update/rank，并初始化 header 的 span */
    if (level > zsl->level) {
        for (int i = zsl->level; i < level; i++) {
            rank[i] = 0;
            update[i] = zsl->header;
            /* 这层原本没有索引，新节点会成为第一个 forward，所以 span=length */
            update[i]->level[i].span = zsl->length;
        }
        zsl->level = level;
    }

    /* 3) 创建节点并“逐层插入” */
    x = zslCreateNode(level, score, ele);

    for (int i = 0; i < level; i++) {
        /* 经典链表插入：x 接到 update[i] 后面 */
        x->level[i].forward = update[i]->level[i].forward;
        update[i]->level[i].forward = x;

        /*
         * span 的精髓：
         * - update[i]->span 表示 update[i] 到它原 forward 跨过多少 level0 节点
         * - 插入 x 以后，这个跨度要被“切开”
         *
         * rank[0]：在 level0 上，新节点左侧跨过的节点数
         * rank[i]：在第 i 层上，update[i] 左侧跨过的节点数
         *
         * (rank[0] - rank[i]) 就是：从 update[i] 到 x 的 level0 距离
         */
        x->level[i].span = update[i]->level[i].span - (rank[0] - rank[i]);
        update[i]->level[i].span = (rank[0] - rank[i]) + 1;
    }

    /* 4) 对于没被新节点覆盖到的更高层：它们的 span 也要 +1（因为 level0 多了一个节点） */
    for (int i = level; i < zsl->level; i++) {
        update[i]->level[i].span++;
    }

    /* 5) 维护 backward / tail（只在 level0 维护 backward） */
    x->backward = (update[0] == zsl->header) ? NULL : update[0];

    if (x->level[0].forward) {
        x->level[0].forward->backward = x;
    } else {
        zsl->tail = x;
    }

    zsl->length++;
    return x;
}
```

> 随机跳表的高度分布类似于平衡树，但实现更简单高效。

### 4.2 ZRANGE：按 score 排序范围查询

```c
static int zslValueGteMin(double value, const zrangespec *range) {
    return range->minex ? (value > range->min) : (value >= range->min);
}
static int zslValueLteMax(double value, const zrangespec *range) {
    return range->maxex ? (value < range->max) : (value <= range->max);
}

static int zslIsInRange(const zskiplist *zsl, const zrangespec *range) {
    if (range->min > range->max) return 0;
    if (range->min == range->max && (range->minex || range->maxex)) return 0;

    if (zsl->tail == NULL) return 0;

    /* 最小值都比尾节点还大 => 不可能有 */
    if (!zslValueGteMin(zsl->tail->score, range)) return 0;

    /* 最大值都比首节点还小 => 不可能有（首节点是 header->level0->forward） */
    zskiplistNode *first = zsl->header->level[0].forward;
    if (!first || !zslValueLteMax(first->score, range)) return 0;

    return 1;
}

/* 找到范围内第一个节点（按 score） */
zskiplistNode *zslFirstInRange(zskiplist *zsl, const zrangespec *range) {
    if (!zslIsInRange(zsl, range)) return NULL;

    zskiplistNode *x = zsl->header;

    for (int i = zsl->level - 1; i >= 0; i--) {
        while (x->level[i].forward &&
               !zslValueGteMin(x->level[i].forward->score, range))
        {
            x = x->level[i].forward;
        }
    }

    x = x->level[0].forward;
    if (!x) return NULL;
    if (!zslValueLteMax(x->score, range)) return NULL;
    return x;
}

/* 示例：打印 score 范围内的元素 */
void zslRangeByScorePrint(zskiplist *zsl, double min, double max, int minex, int maxex) {
    zrangespec range = {.min=min, .max=max, .minex=minex, .maxex=maxex};
    zskiplistNode *x = zslFirstInRange(zsl, &range);
    while (x && zslValueLteMax(x->score, &range)) {
        printf("(%f, %s)\n", x->score, x->ele);
        x = x->level[0].forward; /* 只需要 level0 顺序扫 */
    }
}
```

### 4.3 ZRANGE：按rank排序范围查询

```c
/*
 * 取第 rank 个元素（rank 从 1 开始）
 * Redis：ZRANGE 的 start/stop 会先换算成 rank 再调用类似逻辑。
 */
zskiplistNode *zslGetElementByRank(zskiplist *zsl, unsigned long rank) {
    if (rank == 0 || rank > zsl->length) return NULL;

    unsigned long traversed = 0;
    zskiplistNode *x = zsl->header;

    for (int i = zsl->level - 1; i >= 0; i--) {
        while (x->level[i].forward &&
               (traversed + x->level[i].span) <= rank)
        {
            traversed += x->level[i].span;
            x = x->level[i].forward;
        }
        if (traversed == rank) {
            return x;
        }
    }
    return NULL;
}

/* 示例：打印 rank 范围 [start, stop]（start/stop 从 0 开始更像 ZRANGE） */
void zslRangeByRankPrint(zskiplist *zsl, long start, long stop) {
    if (start < 0) start = 0;
    if (stop < 0) return;
    if ((unsigned long)start >= zsl->length) return;
    if ((unsigned long)stop >= zsl->length) stop = (long)zsl->length - 1;

    unsigned long rank = (unsigned long)start + 1; /* 转成 1-based rank */
    zskiplistNode *x = zslGetElementByRank(zsl, rank);

    for (long i = start; x && i <= stop; i++) {
        printf("#%ld -> (%f, %s)\n", i, x->score, x->ele);
        x = x->level[0].forward;
    }
}
```

### 4.4 ZREM：删除元素

```c
/* 内部删除：update[] 已经是每层的前驱，x 是要删的节点 */
static void zslDeleteNode(zskiplist *zsl, zskiplistNode *x, zskiplistNode **update) {
    for (int i = 0; i < zsl->level; i++) {
        if (update[i]->level[i].forward == x) {
            /* 这一层确实指向 x：断开并把 span“拼回去” */
            update[i]->level[i].span += x->level[i].span - 1;
            update[i]->level[i].forward = x->level[i].forward;
        } else {
            /*
             * 这一层没直接指向 x，但 level0 少了一个节点，
             * 所以这层路径上的 span 也要 -1
             */
            update[i]->level[i].span -= 1;
        }
    }

    /* 修 backward / tail */
    if (x->level[0].forward) {
        x->level[0].forward->backward = x->backward;
    } else {
        zsl->tail = x->backward;
    }

    /* 如果最高层已经空了，降低 zsl->level（保持 level 紧凑） */
    while (zsl->level > 1 && zsl->header->level[zsl->level - 1].forward == NULL) {
        zsl->level--;
    }

    zsl->length--;
}

/* 删除精确元素 (score, ele)，成功返回 1，否则 0 */
int zslDelete(zskiplist *zsl, double score, const char *ele) {
    zskiplistNode *update[ZSKIPLIST_MAXLEVEL];
    zskiplistNode *x = zsl->header;

    /* 1) 找到每一层的前驱 */
    for (int i = zsl->level - 1; i >= 0; i--) {
        while (x->level[i].forward &&
               zslNodeCompare(x->level[i].forward->score, x->level[i].forward->ele,
                              score, ele) < 0)
        {
            x = x->level[i].forward;
        }
        update[i] = x;
    }

    /* 2) 候选节点在 level0 的 forward */
    x = x->level[0].forward;

    /* 3) 必须精确匹配 (score, ele) */
    if (x && score == x->score && strcmp(x->ele, ele) == 0) {
        zslDeleteNode(zsl, x, update);
        free(x->ele);
        free(x);
        return 1;
    }
    return 0;
}
```

# 5. Java 版本实现

## 数据结构与操作总结

### 核心数据结构
```java
SkipList<T> {
    Node<T> header;      // 头节点（哨兵）
    Node<T> tail;        // 尾节点
    int level;           // 当前最大层数
    long length;         // 元素总数
}

Node<T> {
    double score;        // 分数（排序依据）
    T value;             // 元素值
    Node<T> backward;    // 后向指针（仅level 0）
    Level[] levels;      // 层级数组
}

Level {
    Node<?> forward;     // 前向指针
    long span;           // 跨度（到forward的level 0距离）
}
```

### 主要操作
| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| insert(score, value) | O(log n) | 随机层数，逐层插入，维护span |
| delete(score, value) | O(log n) | 找到前驱，逐层删除，更新span |
| rangeByScore(min, max) | O(log n + m) | 定位起点 + level 0遍历 |
| rangeByRank(start, stop) | O(log n + m) | 利用span定位 + level 0遍历 |
| getByRank(rank) | O(log n) | 累加span快速定位 |
| getRank(score, value) | O(log n) | 查找时累加span得到排名 |

### 关键特性
- **随机层数**：P=0.25，期望层数1.33，空间复杂度O(n)
- **span字段**：支持O(log n)按排名查询，span表示到forward的level 0距离
- **backward指针**：仅level 0维护，支持逆序遍历
- **查找策略**：从最高层开始，逐层下降，最终在level 0定位

## 5层跳表结构示例

以下是一个包含5层的跳表结构示例，展示了跳表的多层索引特性：

```
Level 4: head --------→ 40 ----------------→ 80 → null
Level 3: head ----→ 20 → 40 --------→ 60 → 80 → null  
Level 2: head → 10 → 20 → 40 → 50 → 60 → 80 → null
Level 1: head → 10 → 20 → 30 → 40 → 50 → 60 → 70 → 80 → null
Level 0: head → 10 → 15 → 20 → 30 → 35 → 40 → 45 → 50 → 55 → 60 → 70 → 80 → null
```

**结构说明：**
- **Level 0（底层）**：包含所有元素的完整有序链表
- **Level 1-4（索引层）**：每层节点数递减，形成多级索引
- **head**：哨兵节点，不存储实际数据，每层都有指针
- **查找过程**：从最高层开始，逐层下降，快速定位目标位置

**查找示例（查找 score=50）：**
1. Level 4: head → 40（40 < 50，继续）→ 80（80 > 50，下降）
2. Level 3: 40 → 60（60 > 50，下降）
3. Level 2: 40 → 50（找到！）

通过高层索引快速跳过大量节点，时间复杂度为 O(log n)。

### 5.1 核心数据结构

```java
import java.util.*;

/**
 * 跳表（Skip List）实现
 * 
 * 跳表是一种概率型数据结构，通过多层索引实现快速查找、插入和删除
 * 时间复杂度：查找/插入/删除均为 O(log n)
 * 空间复杂度：O(n)
 * 
 * 核心特点：
 * 1. 底层是有序链表（level 0）
 * 2. 上层是索引层，每层节点数约为下层的 1/4（由概率 P=0.25 决定）
 * 3. 通过 span 字段记录跨度，支持 O(log n) 时间复杂度的按排名查询
 * 
 * @param <T> 元素类型
 */
public class SkipList<T> {
    // 最大层数限制（Redis 使用 32 层）
    private static final int MAX_LEVEL = 32;
    
    // 随机层数的概率因子（P=0.25 意味着每层节点数约为下层的 1/4）
    // 这个值越小，层数越少，空间占用越小，但查询性能会下降
    private static final double P = 0.25;
    
    // 头节点：哨兵节点，不存储实际数据，简化边界处理
    private final Node<T> header;
    
    // 尾节点：指向最后一个节点，方便逆序遍历
    private Node<T> tail;
    
    // 当前跳表的最大层数（动态变化，初始为 1）
    private int level;
    
    // 跳表中的元素总数
    private long length;
    
    // 随机数生成器，用于生成节点的随机层数
    private final Random random;
    
    /**
     * 跳表节点
     * 每个节点包含：score（分数）、value（值）、backward（后向指针）、levels（层级数组）
     */
    static class Node<T> {
        final double score;      // 分数，用于排序
        final T value;           // 实际存储的值
        Node<T> backward;        // 后向指针，仅在 level 0 维护，用于逆序遍历
        final Level[] levels;    // 层级数组，每层包含 forward 指针和 span 跨度
        
        /**
         * 层级结构
         * forward：指向当前层的下一个节点（后继指针）
         * span：跨度，表示从当前节点到 forward 节点，在 level 0 上跨过的节点数
         * 
         * span 的精确定义：
         * - 如果 A.levels[i].forward = B，A.levels[i].span = n
         * - 则从 A 到 B 之间（不包括 A，包括 B），level 0 上有 n 个节点
         * - 换句话说：B 在 level 0 的位置 = A 在 level 0 的位置 + span
         * 
         * span 的作用：
         * 1. 支持 O(log n) 时间复杂度的按排名查询（ZRANK、ZRANGE by rank）
         * 2. 在插入/删除时需要维护 span 的正确性
         * 
         * 示例：
         * Level 1: A --(span=3)--> D
         * Level 0: A → B → C → D
         * A.levels[1].span = 3，表示从A到D跨过3个level 0节点（B, C, D）
         */
        static class Level {
            Node<?> forward;  // 后继指针（指向下一个节点）
            long span;        // 跨度（到forward节点跨过的level 0节点数，包括forward）
            
            Level() {
                this.forward = null;
                this.span = 0;
            }
        }
        
        /**
         * 创建节点
         * @param level 节点的层数
         * @param score 分数
         * @param value 值
         */
        Node(int level, double score, T value) {
            this.score = score;
            this.value = value;
            this.levels = new Level[level];
            // 初始化每一层
            for (int i = 0; i < level; i++) {
                this.levels[i] = new Level();
            }
        }
    }
    
    /**
     * 构造函数：初始化空跳表
     */
    public SkipList() {
        // 创建头节点，层数为 MAX_LEVEL，不存储实际数据
        this.header = new Node<>(MAX_LEVEL, 0, null);
        this.tail = null;
        this.level = 1;  // 初始层数为 1
        this.length = 0;
        this.random = new Random();
    }
    
    /**
     * 随机生成节点的层数
     * 
     * 算法：从 level 1 开始，每次以概率 P 决定是否增加一层
     * 期望层数：E[level] = 1/(1-P) = 1.33（当 P=0.25 时）
     * 
     * 为什么使用随机层数？
     * 1. 避免了平衡树的复杂旋转操作
     * 2. 通过概率保证平均性能
     * 3. 实现简单，代码量少
     * 
     * @return 随机层数（1 到 MAX_LEVEL 之间）
     */
    private int randomLevel() {
        int level = 1;
        // 每次有 P 的概率继续增加层数
        while (random.nextDouble() < P && level < MAX_LEVEL) {
            level++;
        }
        return level;
    }
    
    /**
     * 比较两个节点的大小
     * 
     * 比较规则：
     * 1. 先比较 score，score 小的排在前面
     * 2. 如果 score 相同，再比较 value 的字典序
     * 
     * 这个规则保证了：
     * 1. 相同 score 的元素按 value 排序（Redis 的行为）
     * 2. 元素的唯一性由 (score, value) 二元组决定
     * 
     * @return 负数表示 node1 < node2，0 表示相等，正数表示 node1 > node2
     */
    private int compareNode(double score1, T value1, double score2, T value2) {
        // 先比较 score
        if (score1 != score2) {
            return Double.compare(score1, score2);
        }
        // score 相同时比较 value
        if (value1 == null || value2 == null) {
            return 0;
        }
        return value1.toString().compareTo(value2.toString());
    }
}
```

### 5.2 插入操作

```java
/**
 * 插入元素到跳表
 * 
 * 算法步骤：
 * 1. 从最高层开始，找到每一层中最后一个小于待插入元素的节点（前驱节点）
 * 2. 随机生成新节点的层数
 * 3. 创建新节点并逐层插入
 * 4. 更新所有相关节点的 span 值
 * 5. 维护 backward 指针和 tail 指针
 * 
 * 时间复杂度：O(log n)
 * 
 * 关键点：
 * - update[i]：第 i 层的前驱节点
 * - rank[i]：到达 update[i] 时，已经跨过的 level 0 节点数
 * - span 的维护是插入操作的核心难点
 * 
 * @param score 分数
 * @param value 值
 */
public void insert(double score, T value) {
    // update[i]：记录每一层的前驱节点（即插入位置的前一个节点）
    Node<T>[] update = new Node[MAX_LEVEL];
    
    // rank[i]：记录到达 update[i] 时，从 header 开始已经跨过的 level 0 节点数
    // 用于计算 span 值
    long[] rank = new long[MAX_LEVEL];
    
    Node<T> x = header;
    
    // 【步骤1】从最高层往下找每一层的前驱节点
    // 
    // 核心思想：逐层下降查找，每层都在上一层的基础上继续向右移动
    // - 从最高层开始，在当前层尽可能向右走，直到遇到 >= 插入值的节点
    // - 记录该层的前驱节点（update[i]）和累计跨度（rank[i]）
    // - 下降到下一层，继承上一层的位置和累计值，继续查找
    // 
    // 示例：插入 score=45 到跳表 [20, 30, 40, 50]
    // Level 2: head --(3)-> 20 --(3)-> 50     → 停在20，rank[2]=3
    // Level 1: 20 --(1)-> 30 --(2)-> 50       → 停在30，rank[1]=4（继承3+1）
    // Level 0: 30 --(1)-> 40 --(1)-> 50       → 停在40，rank[0]=5（继承4+1）
    // 结果：update=[40,30,20]，新节点插入到40之后，位置为5
    //
    for (int i = level - 1; i >= 0; i--) {
        // rank[i] 继承上一层的累计值
        // 最高层从 0 开始，其他层继承上一层的 rank[i+1]
        rank[i] = (i == level - 1) ? 0 : rank[i + 1];
        
        // 在第 i 层向右移动，找到最后一个 < 插入值的节点
        while (x.levels[i].forward != null &&
               compareNode(x.levels[i].forward.score, 
                          (T) x.levels[i].forward.value,
                          score, value) < 0) {
            // 累加跨度：记录跨过了多少个 level 0 节点
            rank[i] += x.levels[i].span;
            // 向右移动到下一个节点
            x = (Node<T>) x.levels[i].forward;
        }
        // 记录第 i 层的前驱节点（插入位置的左侧节点）
        update[i] = x;
    }
    
    // 【步骤2】随机生成新节点的层高
    // 这是跳表的核心：通过随机层数保证概率平衡
    int newLevel = randomLevel();
    
    // 【步骤3】如果新层高超过当前最大层高，需要初始化新层
    if (newLevel > level) {
        for (int i = level; i < newLevel; i++) {
            rank[i] = 0;  // 新层的 rank 为 0
            update[i] = header;  // 新层的前驱是 header
            // 新层的 span 初始化为当前跳表长度（因为 header 直接跨到末尾）
            update[i].levels[i].span = length;
        }
        level = newLevel;  // 更新跳表的最大层数
    }
    
    // 【步骤4】创建新节点
    x = new Node<>(newLevel, score, value);
    
    // 【步骤5】逐层插入新节点
    // 
    // 为什么要在每一层都插入？
    // - 新节点的层数决定了它在哪些层级作为索引节点存在
    // - 只在 level 0 插入会导致高层查找时跳过该节点，失去索引效果
    // - 在 [0, newLevel) 的每一层插入，让新节点在对应层级可见
    // 
    // 示例：插入 score=35，newLevel=3
    // Level 2: 20 → 35 → 50  ← 35作为索引，可以从20快速跳到35
    // Level 1: 20 → 30 → 35 → 50  ← 35作为索引
    // Level 0: 20 → 30 → 35 → 40 → 50  ← 35的完整数据
    //
    for (int i = 0; i < newLevel; i++) {
        // 标准链表插入：x 插入到 update[i] 和 update[i].forward 之间
        x.levels[i].forward = update[i].levels[i].forward;
        update[i].levels[i].forward = x;
        
        // 【关键】更新 span 值
        // 
        // 插入前：update[i] --span--> update[i].forward
        // 插入后：update[i] --span1--> x --span2--> update[i].forward
        //
        // rank[0]：新节点在 level 0 的位置（从 header 开始的偏移）
        // rank[i]：update[i] 在 level 0 的位置
        // (rank[0] - rank[i])：从 update[i] 到新节点 x 的 level 0 距离
        //
        // 新节点的 span = 原 span - 左侧距离
        x.levels[i].span = update[i].levels[i].span - (rank[0] - rank[i]);
        // 前驱节点的 span = 左侧距离 + 1（+1 是因为新节点本身占一个位置）
        update[i].levels[i].span = (rank[0] - rank[i]) + 1;
    }
    
    // 【步骤6】更新未被新节点覆盖的更高层的 span
    // 这些层没有新节点，但 level 0 多了一个节点，所以 span 要 +1
    for (int i = newLevel; i < level; i++) {
        update[i].levels[i].span++;
    }
    
    // 【步骤7】维护 backward 指针（仅在 level 0 维护）
    x.backward = (update[0] == header) ? null : update[0];
    if (x.levels[0].forward != null) {
        ((Node<T>) x.levels[0].forward).backward = x;
    } else {
        // 如果新节点是最后一个节点，更新 tail
        tail = x;
    }
    
    // 【步骤8】更新跳表长度
    length++;
}
```

### 5.3 按 Score 范围查询

```java
/**
 * 按 score 范围查询元素
 * 
 * 对应 Redis 命令：ZRANGEBYSCORE key min max [WITHSCORES]
 * 
 * 算法步骤：
 * 1. 检查范围是否有效
 * 2. 找到范围内的第一个节点
 * 3. 从第一个节点开始，沿着 level 0 顺序遍历，直到超出范围
 * 
 * 时间复杂度：O(log n + m)，其中 m 是结果集大小
 * 
 * @param min 最小分数
 * @param max 最大分数
 * @param minExclusive 是否排除最小值（true 表示开区间）
 * @param maxExclusive 是否排除最大值（true 表示开区间）
 * @return 范围内的元素列表
 */
public List<T> rangeByScore(double min, double max, 
                            boolean minExclusive, boolean maxExclusive) {
    List<T> result = new ArrayList<>();
    
    // 快速检查：范围是否有效
    if (!isInRange(min, max, minExclusive, maxExclusive)) {
        return result;
    }
    
    // 找到范围内的第一个节点
    Node<T> x = firstInRange(min, max, minExclusive, maxExclusive);
    
    // 从第一个节点开始，沿着 level 0 顺序遍历
    while (x != null && valueLteMax(x.score, max, maxExclusive)) {
        result.add(x.value);
        x = (Node<T>) x.levels[0].forward;
    }
    
    return result;
}

/**
 * 检查跳表中是否存在指定范围内的元素
 * 
 * 优化：通过检查头尾节点快速判断，避免不必要的遍历
 * 
 * @return true 表示范围内可能有元素，false 表示肯定没有
 */
private boolean isInRange(double min, double max, 
                         boolean minExclusive, boolean maxExclusive) {
    // 检查1：范围本身是否有效
    if (min > max || (min == max && (minExclusive || maxExclusive))) {
        return false;
    }
    
    // 检查2：跳表是否为空
    if (tail == null) {
        return false;
    }
    
    // 检查3：最小值是否大于尾节点的 score
    // 如果 min > tail.score，说明范围完全在跳表右侧，不可能有交集
    if (!valueGteMin(tail.score, min, minExclusive)) {
        return false;
    }
    
    // 检查4：最大值是否小于首节点的 score
    // 如果 max < first.score，说明范围完全在跳表左侧，不可能有交集
    Node<T> first = (Node<T>) header.levels[0].forward;
    if (first == null || !valueLteMax(first.score, max, maxExclusive)) {
        return false;
    }
    
    return true;
}

/**
 * 找到范围内的第一个节点
 * 
 * 算法：从最高层开始，逐层下降，找到第一个 score >= min 的节点
 * 
 * 时间复杂度：O(log n)
 * 
 * @return 范围内的第一个节点，如果不存在则返回 null
 */
private Node<T> firstInRange(double min, double max, 
                             boolean minExclusive, boolean maxExclusive) {
    if (!isInRange(min, max, minExclusive, maxExclusive)) {
        return null;
    }
    
    Node<T> x = header;
    
    // 从最高层开始，找到第一个 score >= min 的节点
    for (int i = level - 1; i >= 0; i--) {
        // 在第 i 层向右移动，直到下一个节点的 score >= min
        while (x.levels[i].forward != null &&
               !valueGteMin(x.levels[i].forward.score, min, minExclusive)) {
            x = (Node<T>) x.levels[i].forward;
        }
    }
    
    // 移动到 level 0 的下一个节点（候选节点）
    x = (Node<T>) x.levels[0].forward;
    
    // 检查候选节点是否在范围内
    if (x == null || !valueLteMax(x.score, max, maxExclusive)) {
        return null;
    }
    
    return x;
}

/**
 * 检查 value 是否 >= min
 * @param exclusive true 表示开区间（value > min），false 表示闭区间（value >= min）
 */
private boolean valueGteMin(double value, double min, boolean exclusive) {
    return exclusive ? (value > min) : (value >= min);
}

/**
 * 检查 value 是否 <= max
 * @param exclusive true 表示开区间（value < max），false 表示闭区间（value <= max）
 */
private boolean valueLteMax(double value, double max, boolean exclusive) {
    return exclusive ? (value < max) : (value <= max);
}
```

### 5.4 按 Rank 查询

```java
/**
 * 根据排名获取元素
 * 
 * 对应 Redis 命令：ZRANGE key start stop（按索引范围查询）
 * 
 * 排名从 1 开始（Redis 的 ZRANGE 从 0 开始，这里为了与 C 代码保持一致使用 1-based）
 * 
 * 算法核心：利用 span 字段快速定位
 * - 从最高层开始，累加 span 值
 * - 当累加值 + 当前 span <= rank 时，可以安全地跳过
 * - 逐层下降，最终定位到目标节点
 * 
 * 时间复杂度：O(log n)
 * 
 * 这是跳表相比普通有序链表的重要优势：
 * 普通链表按排名查询需要 O(n)，跳表只需 O(log n)
 * 
 * @param rank 排名（从 1 开始）
 * @return 对应排名的元素，如果排名无效则返回 null
 */
public T getByRank(long rank) {
    // 边界检查：排名必须在 [1, length] 范围内
    if (rank <= 0 || rank > length) {
        return null;
    }
    
    long traversed = 0;  // 已经跨过的 level 0 节点数
    Node<T> x = header;
    
    // 从最高层开始，逐层下降
    for (int i = level - 1; i >= 0; i--) {
        // 在第 i 层向右移动，只要不超过目标 rank
        while (x.levels[i].forward != null &&
               (traversed + x.levels[i].span) <= rank) {
            // 累加跨度
            traversed += x.levels[i].span;
            // 移动到下一个节点
            x = (Node<T>) x.levels[i].forward;
        }
        
        // 如果已经到达目标 rank，直接返回
        if (traversed == rank) {
            return x.value;
        }
    }
    
    return null;
}

/**
 * 按排名范围查询元素列表
 * 
 * 对应 Redis 命令：ZRANGE key start stop
 * 
 * 注意：这里的 start 和 stop 是 0-based（与 Redis 一致）
 * 
 * 算法步骤：
 * 1. 先用 getNodeByRank 定位到起始节点（O(log n)）
 * 2. 然后沿着 level 0 顺序遍历（O(m)，m 是结果集大小）
 * 
 * 时间复杂度：O(log n + m)
 * 
 * @param start 起始排名（0-based，包含）
 * @param stop 结束排名（0-based，包含）
 * @return 范围内的元素列表
 */
public List<T> rangeByRank(long start, long stop) {
    List<T> result = new ArrayList<>();
    
    // 边界处理
    if (start < 0) start = 0;
    if (stop < 0) return result;
    if (start >= length) return result;
    if (stop >= length) stop = length - 1;
    
    // 转换为 1-based rank
    long rank = start + 1;
    Node<T> x = getNodeByRank(rank);
    
    // 从起始节点开始，沿着 level 0 遍历
    for (long i = start; x != null && i <= stop; i++) {
        result.add(x.value);
        x = (Node<T>) x.levels[0].forward;
    }
    
    return result;
}

/**
 * 根据排名获取节点（内部方法）
 * 
 * 与 getByRank 类似，但返回节点而不是值
 * 
 * @param rank 排名（1-based）
 * @return 对应排名的节点
 */
private Node<T> getNodeByRank(long rank) {
    if (rank <= 0 || rank > length) {
        return null;
    }
    
    long traversed = 0;
    Node<T> x = header;
    
    for (int i = level - 1; i >= 0; i--) {
        while (x.levels[i].forward != null &&
               (traversed + x.levels[i].span) <= rank) {
            traversed += x.levels[i].span;
            x = (Node<T>) x.levels[i].forward;
        }
        
        if (traversed == rank) {
            return x;
        }
    }
    
    return null;
}

/**
 * 获取元素的排名
 * 
 * 对应 Redis 命令：ZRANK key member
 * 
 * 算法：查找元素的同时累加 span，最终得到排名
 * 
 * 时间复杂度：O(log n)
 * 
 * @param score 分数
 * @param value 值
 * @return 排名（0-based），如果元素不存在则返回 -1
 */
public long getRank(double score, T value) {
    long rank = 0;
    Node<T> x = header;
    
    // 从最高层开始查找
    for (int i = level - 1; i >= 0; i--) {
        while (x.levels[i].forward != null &&
               compareNode(x.levels[i].forward.score,
                          (T) x.levels[i].forward.value,
                          score, value) <= 0) {
            // 累加跨度
            rank += x.levels[i].span;
            x = (Node<T>) x.levels[i].forward;
        }
        
        // 如果找到了目标元素
        if (x.value != null && x.score == score && value.equals(x.value)) {
            return rank - 1;  // 转换为 0-based
        }
    }
    
    return -1;  // 未找到
}
```

### 5.5 删除操作

```java
/**
 * 删除指定元素
 * 
 * 对应 Redis 命令：ZREM key member
 * 
 * 算法步骤：
 * 1. 找到每一层的前驱节点（与插入类似）
 * 2. 检查目标节点是否存在且精确匹配
 * 3. 逐层删除节点并更新 span
 * 4. 维护 backward 指针和 tail 指针
 * 5. 如果最高层变空，降低跳表的层数
 * 
 * 时间复杂度：O(log n)
 * 
 * @param score 分数
 * @param value 值
 * @return true 表示删除成功，false 表示元素不存在
 */
public boolean delete(double score, T value) {
    // update[i]：记录每一层的前驱节点
    Node<T>[] update = new Node[MAX_LEVEL];
    Node<T> x = header;
    
    // 【步骤1】找到每一层的前驱节点
    for (int i = level - 1; i >= 0; i--) {
        // 在第 i 层向右移动，直到找到第一个 >= (score, value) 的节点
        while (x.levels[i].forward != null &&
               compareNode(x.levels[i].forward.score,
                          (T) x.levels[i].forward.value,
                          score, value) < 0) {
            x = (Node<T>) x.levels[i].forward;
        }
        update[i] = x;
    }
    
    // 【步骤2】候选节点在 level 0 的 forward
    x = (Node<T>) x.levels[0].forward;
    
    // 【步骤3】必须精确匹配 (score, value)
    if (x != null && x.score == score && 
        (value == null || value.equals(x.value))) {
        deleteNode(x, update);
        return true;
    }
    
    return false;
}

/**
 * 内部删除方法：执行实际的删除操作
 * 
 * 前提：update[] 数组已经包含了每一层的前驱节点
 * 
 * 关键点：
 * 1. 如果某层直接指向待删除节点，需要"拼接" span
 * 2. 如果某层不直接指向待删除节点，但 level 0 少了一个节点，span 要 -1
 * 3. 维护 backward 指针和 tail 指针
 * 4. 如果最高层变空，降低跳表层数（保持层数紧凑）
 * 
 * @param x 待删除的节点
 * @param update 每一层的前驱节点数组
 */
private void deleteNode(Node<T> x, Node<T>[] update) {
    // 【步骤1】更新每一层的指针和 span
    for (int i = 0; i < level; i++) {
        if (update[i].levels[i].forward == x) {
            // 这一层直接指向 x：需要断开并"拼接" span
            // 
            // 删除前：update[i] --span1--> x --span2--> x.forward
            // 删除后：update[i] --span1+span2-1--> x.forward
            // 
            // 为什么是 -1？因为 x 本身占一个位置，删除后要减去
            update[i].levels[i].span += x.levels[i].span - 1;
            update[i].levels[i].forward = x.levels[i].forward;
        } else {
            // 这一层没有直接指向 x，但 level 0 少了一个节点
            // 所以这层路径上的 span 也要 -1
            update[i].levels[i].span--;
        }
    }
    
    // 【步骤2】维护 backward 指针
    if (x.levels[0].forward != null) {
        // 如果 x 不是最后一个节点，更新后继节点的 backward
        ((Node<T>) x.levels[0].forward).backward = x.backward;
    } else {
        // 如果 x 是最后一个节点，更新 tail
        tail = x.backward;
    }
    
    // 【步骤3】降低层高（如果最高层已经空了）
    // 保持 level 紧凑，避免浪费空间
    while (level > 1 && header.levels[level - 1].forward == null) {
        level--;
    }
    
    // 【步骤4】更新跳表长度
    length--;
}

/**
 * 按 score 范围删除元素
 * 
 * 对应 Redis 命令：ZREMRANGEBYSCORE key min max
 * 
 * 算法：先找到范围内的所有节点，然后逐个删除
 * 
 * 时间复杂度：O(log n + m)，其中 m 是删除的元素数量
 * 
 * @param min 最小分数
 * @param max 最大分数
 * @param minExclusive 是否排除最小值
 * @param maxExclusive 是否排除最大值
 * @return 删除的元素数量
 */
public long deleteRangeByScore(double min, double max,
                               boolean minExclusive, boolean maxExclusive) {
    Node<T>[] update = new Node[MAX_LEVEL];
    Node<T> x = header;
    long removed = 0;
    
    // 找到每一层的前驱节点
    for (int i = level - 1; i >= 0; i--) {
        while (x.levels[i].forward != null &&
               !valueGteMin(x.levels[i].forward.score, min, minExclusive)) {
            x = (Node<T>) x.levels[i].forward;
        }
        update[i] = x;
    }
    
    // 移动到第一个在范围内的节点
    x = (Node<T>) x.levels[0].forward;
    
    // 删除范围内的所有节点
    while (x != null && valueLteMax(x.score, max, maxExclusive)) {
        Node<T> next = (Node<T>) x.levels[0].forward;
        deleteNode(x, update);
        removed++;
        x = next;
    }
    
    return removed;
}

/**
 * 按排名范围删除元素
 * 
 * 对应 Redis 命令：ZREMRANGEBYRANK key start stop
 * 
 * @param start 起始排名（0-based，包含）
 * @param stop 结束排名（0-based，包含）
 * @return 删除的元素数量
 */
public long deleteRangeByRank(long start, long stop) {
    Node<T>[] update = new Node[MAX_LEVEL];
    long traversed = 0;
    long removed = 0;
    Node<T> x = header;
    
    // 边界处理
    if (start < 0) start = 0;
    if (stop < 0) return 0;
    if (start >= length) return 0;
    if (stop >= length) stop = length - 1;
    
    long rank = start + 1;  // 转换为 1-based
    
    // 找到起始位置的前驱节点
    for (int i = level - 1; i >= 0; i--) {
        while (x.levels[i].forward != null &&
               (traversed + x.levels[i].span) < rank) {
            traversed += x.levels[i].span;
            x = (Node<T>) x.levels[i].forward;
        }
        update[i] = x;
    }
    
    // 移动到起始节点
    x = (Node<T>) x.levels[0].forward;
    
    // 删除范围内的所有节点
    for (long i = start; x != null && i <= stop; i++) {
        Node<T> next = (Node<T>) x.levels[0].forward;
        deleteNode(x, update);
        removed++;
        x = next;
    }
    
    return removed;
}

    return length;

    return level;
```

```java
/**
 * 游戏排行榜系统
 * 
 * 功能：
 * 1. 更新玩家分数
 * 2. 查询玩家排名
 * 3. 获取 Top N 玩家
 * 4. 获取玩家周围的排名
 */
public class GameLeaderboard {
    private final SkipList<String> leaderboard;
    
    public GameLeaderboard() {
        this.leaderboard = new SkipList<>();
    }
    
    /**
     * 更新玩家分数
     * @param playerId 玩家ID
     * @param score 新分数
     */
    public void updateScore(String playerId, double score) {
        // 先删除旧分数（如果存在）
        // 注意：实际应用中需要维护一个 Map<playerId, oldScore> 来快速查找旧分数
        // 这里简化处理
        leaderboard.insert(score, playerId);
    }
    
    /**
     * 获取玩家排名
     * @param playerId 玩家ID
     * @param score 玩家分数
     * @return 排名（从1开始，分数越高排名越靠前）
     */
    public long getPlayerRank(String playerId, double score) {
        long rank = leaderboard.getRank(score, playerId);
        if (rank == -1) {
            return -1;  // 玩家不存在
        }
        // 转换为从高到低的排名（分数越高排名越小）
        return leaderboard.size() - rank;
    }
    
    /**
     * 获取 Top N 玩家
     * @param n 排名数量
     * @return 玩家列表（按分数从高到低）
     */
    public List<String> getTopN(int n) {
        long size = leaderboard.size();
        if (n > size) {
            n = (int) size;
        }
        // 从后往前取（因为跳表是从小到大排序）
        List<String> result = leaderboard.rangeByRank(size - n, size - 1);
        // 反转列表，使其从高到低
        Collections.reverse(result);
        return result;
    }
    
    /**
     * 获取玩家周围的排名
     * @param playerId 玩家ID
     * @param score 玩家分数
     * @param range 上下范围
     * @return 玩家周围的排名列表
     */
    public List<String> getNearbyPlayers(String playerId, double score, int range) {
        long rank = leaderboard.getRank(score, playerId);
        if (rank == -1) {
            return Collections.emptyList();
        }
        
        long start = Math.max(0, rank - range);
        long end = Math.min(leaderboard.size() - 1, rank + range);
        
        return leaderboard.rangeByRank(start, end);
    }

        leaderboard.updateScore("player4", 2000);
```

```java
/**
 * 延迟任务调度器
 * 
 * 使用跳表按执行时间排序任务，支持：
 * 1. 添加延迟任务
 * 2. 获取到期任务
 * 3. 取消任务
 */
public class DelayedTaskScheduler {
    private final SkipList<Task> taskQueue;
    private long taskIdCounter = 0;
    
    static class Task {
        final long id;
        final String name;
        final Runnable action;
        final long executeTime;
        
        Task(long id, String name, Runnable action, long executeTime) {
            this.id = id;
            this.name = name;
            this.action = action;
            this.executeTime = executeTime;
        }
        
        @Override
        public String toString() {
            return "Task{id=" + id + ", name='" + name + "'}";
        }
    }
    
    public DelayedTaskScheduler() {
        this.taskQueue = new SkipList<>();
    }
    
    /**
     * 添加延迟任务
     * @param name 任务名称
     * @param action 任务执行逻辑
     * @param delayMs 延迟时间（毫秒）
     * @return 任务ID
     */
    public long scheduleTask(String name, Runnable action, long delayMs) {
        long taskId = taskIdCounter++;
        long executeTime = System.currentTimeMillis() + delayMs;
        Task task = new Task(taskId, name, action, executeTime);
        taskQueue.insert(executeTime, task);
        System.out.println("已添加任务: " + task + ", 执行时间: " + executeTime);
        return taskId;
    }
    
    /**
     * 获取并执行所有到期任务
     * @return 执行的任务数量
     */
    public int executeDueTasks() {
        long now = System.currentTimeMillis();
        List<Task> dueTasks = taskQueue.rangeByScore(0, now, false, false);
        
        for (Task task : dueTasks) {
            try {
                System.out.println("执行任务: " + task);
                task.action.run();
                // 执行完成后删除任务
                taskQueue.delete(task.executeTime, task);
            } catch (Exception e) {
                System.err.println("任务执行失败: " + task + ", 错误: " + e.getMessage());
            }
        }
        
        return dueTasks.size();
    }
    
    /**
     * 取消任务
     * @param taskId 任务ID
     * @param executeTime 任务执行时间
     * @return 是否取消成功
     */
    public boolean cancelTask(long taskId, long executeTime, Task task) {
        return taskQueue.delete(executeTime, task);
    }
    
    /**
     * 获取待执行任务数量
     */
    public long getPendingTaskCount() {
        return taskQueue.size();
    }
    
    // 使用示例
    public static void main(String[] args) throws InterruptedException {
        DelayedTaskScheduler scheduler = new DelayedTaskScheduler();
        
        // 添加延迟任务
        scheduler.scheduleTask("task1", 
            () -> System.out.println("  -> 执行 task1"), 1000);
        scheduler.scheduleTask("task2", 
            () -> System.out.println("  -> 执行 task2"), 2000);
        scheduler.scheduleTask("task3", 
            () -> System.out.println("  -> 执行 task3"), 500);
        
        System.out.println("\n待执行任务数: " + scheduler.getPendingTaskCount());
        
        // 模拟任务调度循环
        for (int i = 0; i < 5; i++) {
            Thread.sleep(600);
            System.out.println("\n--- 检查到期任务 (第" + (i+1) + "次) ---");
            int executed = scheduler.executeDueTasks();
            System.out.println("执行了 " + executed + " 个任务");
            System.out.println("剩余任务数: " + scheduler.getPendingTaskCount());
        }
    }
}
```

```java
        dataStore.insert(timestamp, point);
    }

     * 按时间范围查询

     * @param n 数据条数
     * @return 数据点列表（按时间从新到旧）

        if (n > size) {

        Collections.reverse(result);
```

### 5.8 backward指针的作用

backward指针仅在level 0维护，用于支持逆序遍历：

```java
/**
 * 逆序遍历跳表（从大到小）
 * 对应Redis命令：ZREVRANGE
 * 
 * 时间复杂度：O(log n + m)
 * - O(log n)：定位到结束位置
 * - O(m)：逆序遍历m个元素
 */
public List<T> reverseRange(long start, long stop) {
    List<T> result = new ArrayList<>();
    
    // 边界处理
    if (start < 0) start = 0;
    if (stop < 0) return result;
    if (start >= length) return result;
    if (stop >= length) stop = length - 1;
    
    // 先定位到stop位置（从前往后）
    long rank = stop + 1;  // 转换为1-based
    Node<T> x = getNodeByRank(rank);
    
    // 从stop位置开始，沿着backward逆序遍历到start
    for (long i = stop; x != null && i >= start; i--) {
        result.add(x.value);
        x = x.backward;  // 向前移动
    }
    
    return result;
}

/**
 * 按score逆序范围查询
 * 对应Redis命令：ZREVRANGEBYSCORE key max min
 * 
 * 注意：参数顺序是max在前，min在后（与正序相反）
 */
public List<T> reverseRangeByScore(double max, double min,
                                   boolean maxExclusive, boolean minExclusive) {
    List<T> result = new ArrayList<>();
    
    if (!isInRange(min, max, minExclusive, maxExclusive)) {
        return result;
    }
    
    // 找到范围内的最后一个节点（score最大的）
    Node<T> x = lastInRange(min, max, minExclusive, maxExclusive);
    
    // 从最后一个节点开始，沿着backward逆序遍历
    while (x != null && valueGteMin(x.score, min, minExclusive)) {
        result.add(x.value);
        x = x.backward;
    }
    
    return result;
}

/**
 * 找到范围内的最后一个节点（score最大的）
 */
private Node<T> lastInRange(double min, double max,
                            boolean minExclusive, boolean maxExclusive) {
    if (!isInRange(min, max, minExclusive, maxExclusive)) {
        return null;
    }
    
    Node<T> x = header;
    
    // 从最高层开始，找到最后一个 score <= max 的节点
    for (int i = level - 1; i >= 0; i--) {
        while (x.levels[i].forward != null &&
               valueLteMax(x.levels[i].forward.score, max, maxExclusive)) {
            x = (Node<T>) x.levels[i].forward;
        }
    }
    
    // x现在指向最后一个在范围内的节点
    if (x == header || !valueGteMin(x.score, min, minExclusive)) {
        return null;
    }
    
    return x;
}
```

**为什么只在level 0维护backward？**
- **逆序遍历只需要在最底层进行**：level 0包含所有节点，逆序遍历不需要跳跃
- **高层索引不需要反向指针**：高层用于快速定位，定位后在level 0遍历即可
- **节省空间开销**：如果每层都维护backward，空间开销会翻倍

**backward的维护时机：**
```java
// 插入时维护
x.backward = (update[0] == header) ? null : update[0];
if (x.levels[0].forward != null) {
    x.levels[0].forward.backward = x;
}

// 删除时维护
if (x.levels[0].forward != null) {
    x.levels[0].forward.backward = x.backward;
} else {
    tail = x.backward;
}
```

# 6. 性能分析与对比

## 6.1 时间复杂度对比

| 操作 | 跳表 | 平衡树(AVL/红黑树) | 有序数组 | 普通链表 |
|------|------|-------------------|---------|---------|
| 查找 | O(log n) | O(log n) | O(log n) | O(n) |
| 插入 | O(log n) | O(log n) | O(n) | O(n) |
| 删除 | O(log n) | O(log n) | O(n) | O(n) |
| 按排名查询 | O(log n) | O(log n)* | O(1) | O(n) |
| 范围查询 | O(log n + m) | O(log n + m) | O(log n + m) | O(n) |
| 逆序遍历 | O(log n + m) | O(log n + m) | O(m) | O(n) |

*平衡树需要额外维护size字段才能支持O(log n)的按排名查询

## 6.2 空间复杂度对比

| 数据结构 | 空间复杂度 | 额外空间说明 |
|---------|-----------|------------|
| 跳表 | O(n) | 平均每个节点1.33个指针（P=0.25） |
| 红黑树 | O(n) | 每个节点2个指针+1个颜色位 |
| AVL树 | O(n) | 每个节点2个指针+1个高度字段 |
| 有序数组 | O(n) | 无额外空间 |

## 6.3 跳表的优势

### 1. 实现简单
```
代码行数对比（核心操作）：
- 跳表：约200-300行
- 红黑树：约500-800行（包含复杂的旋转逻辑）
- AVL树：约400-600行
```

**跳表的插入操作**：
- 找到位置 → 随机层数 → 逐层插入 → 更新span
- 无需旋转、无需颜色调整、无需高度平衡

**红黑树的插入操作**：
- 找到位置 → 插入 → 检查颜色冲突 → 旋转+重新着色
- 需要处理6种不同的情况

### 2. 无需旋转
- **跳表**：插入删除只影响相邻节点，局部修改
- **平衡树**：旋转可能影响多个节点，甚至传播到根节点

### 3. 并发友好
```java
// 跳表：可以对单个节点加锁
lock(update[i]);
update[i].forward = newNode;
unlock(update[i]);

// 红黑树：旋转时需要锁住多个节点
lock(parent, grandparent, uncle);
rotate();
unlock(...);
```

### 4. 空间局部性好
```
跳表的level 0：
[node1] → [node2] → [node3] → [node4] → ...
连续访问，缓存友好

红黑树：
       [node3]
      /      \
  [node1]   [node5]
     \      /
   [node2][node4]
节点分散，缓存命中率低
```

### 5. 支持范围查询
- **跳表**：找到起点后，沿level 0顺序遍历
- **红黑树**：需要中序遍历，涉及递归或栈操作

### 6. 调试友好
- **跳表**：结构直观，可以直接打印每一层
- **红黑树**：结构复杂，需要可视化工具

## 6.4 跳表的劣势

### 1. 空间开销
- 平均每个节点需要1.33个指针（P=0.25时）
- 红黑树每个节点固定2个指针

### 2. 概率平衡
- 最坏情况可能退化到O(n)（概率极低：(1/4)^k）
- 平衡树严格保证O(log n)

### 3. 不适合频繁修改
- 相比哈希表，写入性能稍差
- 但提供了有序性保证

## 6.5 为什么Redis选择跳表？

Redis作者Antirez在选择zset底层结构时，选择了跳表而非红黑树，主要原因：

### 1. 实现简单
```
Redis跳表实现：约200行C代码
Redis如果用红黑树：约500行C代码
```
- 代码量少，易于维护
- Bug少，稳定性高
- 新人容易理解

### 2. 范围查询性能
```c
// 跳表：找到起点后，沿level 0顺序遍历

while (x && x->score <= max) {
    // 处理节点
    x = x->level[0].forward;  // 简单的指针移动
}

// 红黑树：需要中序遍历
void inorderTraversal(Node* node) {
    if (node == NULL) return;
    inorderTraversal(node->left);   // 递归
    // 处理节点
    inorderTraversal(node->right);  // 递归
}
```

### 3. 内存局部性
- **跳表**：level 0是连续的链表，范围查询时缓存友好
- **红黑树**：节点分散在内存中，缓存命中率较低

### 4. 并发性能
- **跳表**：修改局部化，易于实现细粒度锁或无锁结构
- **红黑树**：旋转可能影响多个节点，锁粒度大

### 5. 调试友好
```
跳表可视化：
Level 2: head → 20 → 50 → 80
Level 1: head → 20 → 30 → 50 → 60 → 80
Level 0: head → 20 → 25 → 30 → 50 → 55 → 60 → 80

红黑树可视化：需要画树形图，不直观
```

### 6. Antirez的原话
> "There are a few reasons:
> 1. They are not very memory intensive. It's up to you basically. Changing parameters about the probability of a node to have a given number of levels will make then less memory intensive than btrees.
> 2. A sorted set is often target of many ZRANGE or ZREVRANGE operations, that is, traversing the skip list as a linked list. With this operation the cache locality of skip lists is at least as good as with other kind of balanced trees.
> 3. They are simpler to implement, debug, and so forth. For instance thanks to the skip list simplicity I received a patch (already in Redis master) with augmented skip lists implementing ZRANK in O(log(N)). It required little changes to the code."

# 7. 常见问题FAQ

## Q1: 为什么span不包括当前节点？

**A:** span表示"跨过的距离"，从A到B的span包括B但不包括A，这样设计便于计算：

```
B的位置 = A的位置 + A.span

示例：
Level 0: head(位置0) → node1(位置1) → node2(位置2)
head.span = 1  // 从head到node1跨过1个节点（node1本身）
node1.span = 1 // 从node1到node2跨过1个节点（node2本身）

验证：
node1的位置 = head的位置 + head.span = 0 + 1 = 1 ✓
node2的位置 = node1的位置 + node1.span = 1 + 1 = 2 ✓
```

如果span包括当前节点，计算会变复杂：
```
B的位置 = A的位置 + A.span - 1  // 需要额外减1
```

## Q2: 为什么要从最高层开始查找？

**A:** 高层节点稀疏，可以快速跳过大量节点。从低层开始会退化成O(n)的链表遍历。

```
查找score=50的对比：

从Level 2开始（正确）：
Level 2: head → 20 → 50 ✓  // 2次比较
总比较次数：2次

从Level 0开始（错误）：
Level 0: head → 10 → 15 → 20 → 30 → 35 → 40 → 45 → 50 ✓
总比较次数：8次

效率差距：4倍
```

## Q3: 随机层数会不会导致性能不稳定？

**A:** 不会。虽然单次插入的层数是随机的，但大量插入后，层级分布符合几何分布，平均性能稳定在O(log n)。

**数学证明**：
```
P(level = k) = P^(k-1) * (1-P)  // 几何分布

当P=0.25时：
P(level = 1) = 0.75    // 75%的节点只有1层
P(level = 2) = 0.1875  // 18.75%的节点有2层
P(level = 3) = 0.0469  // 4.69%的节点有3层
P(level = 4) = 0.0117  // 1.17%的节点有4层

期望层数 E[level] = 1/(1-P) = 1.33
```

**实际测试**（插入100万个元素）：
- 最高层数：约20层（理论值：log₄(1000000) ≈ 10层）
- 平均查找次数：约13次（理论值：log₄(1000000) ≈ 10次）
- 性能波动：< 5%

## Q4: 跳表的空间复杂度是多少？

**A:** O(n)。虽然有多层索引，但期望的总指针数约为n/(1-P)，当P=0.25时约为1.33n。

**详细计算**：
```
第0层：n个节点，每个1个指针 = n个指针
第1层：n*P个节点，每个1个指针 = n*P个指针
第2层：n*P²个节点，每个1个指针 = n*P²个指针
...

总指针数 = n + n*P + n*P² + ... = n * (1 + P + P² + ...) = n / (1-P)

当P=0.25时：
总指针数 = n / 0.75 = 1.33n

额外空间 = 0.33n个指针
```

**对比**：
- 跳表：1.33n个指针
- 红黑树：2n个指针（每个节点2个子指针）
- 跳表的空间效率更高！

## Q5: 为什么范围查询只在level 0遍历？

**A:** 因为只有level 0包含所有节点。高层索引用于快速定位起点，找到起点后必须在level 0遍历才能保证不漏掉任何元素。

```
示例：查询范围[30, 60]

如果在Level 1遍历：
Level 1: 20 → 40 → 50 → 60
结果：[40, 50, 60]  // 漏掉了30, 35, 55 ✗

在Level 0遍历：
Level 0: 30 → 35 → 40 → 45 → 50 → 55 → 60
结果：[30, 35, 40, 45, 50, 55, 60]  // 完整结果 ✓
```

**查询过程**：
1. **阶段1（多层查找）**：从最高层开始，快速定位到起点附近 - O(log n)
2. **阶段2（level 0遍历）**：沿着level 0顺序遍历，收集所有结果 - O(m)
3. **总复杂度**：O(log n + m)

## Q6: 跳表支持并发吗？

**A:** 跳表天然支持并发。可以对每个节点加锁，或使用CAS实现无锁跳表。

**并发跳表的实现方式**：

### 方式1：细粒度锁
```java
public void insert(double score, T value) {
    Node<T>[] update = new Node[MAX_LEVEL];
    
    // 查找阶段：不加锁（读操作）
    findUpdateNodes(score, value, update);
    
    // 修改阶段：只锁住相关节点
    for (int i = 0; i < newLevel; i++) {
        update[i].lock();  // 锁住前驱节点
    }
    
    try {
        // 执行插入
        insertNode(newNode, update);
    } finally {
        for (int i = 0; i < newLevel; i++) {
            update[i].unlock();
        }
    }
}
```

### 方式2：无锁CAS
```java
public void insert(double score, T value) {
    while (true) {
        Node<T>[] update = findUpdateNodes(score, value);
        Node<T> newNode = new Node<>(level, score, value);
        
        // 使用CAS原子更新
        if (casUpdate(update, newNode)) {
            break;  // 成功
        }
        // 失败则重试
    }
}
```

**Redis的选择**：
- Redis是单线程模型，跳表不需要并发控制
- 但跳表的局部修改特性，使其易于扩展到多线程场景

## Q7: 跳表的最大层数为什么是32？

**A:** 32层足以支持2³²个元素（约42亿），同时避免浪费空间。

**计算**：
```
当P=0.25时，n个元素的期望最大层数：
E[maxLevel] = log₄(n)

n = 2³² 时：
E[maxLevel] = log₄(2³²) = 32 / 2 = 16层

实际设置为32层是为了留有余量，避免极端情况。
```

**如果层数不够会怎样？**
- 最高层的节点数会增多
- 查找效率下降，但不会出错
- 例如：MAX_LEVEL=10时，100万元素的查找次数会从13次增加到20次左右

## Q8: 为什么P=0.25而不是P=0.5？

**A:** P=0.25是空间和时间的最佳平衡点。

**对比分析**：

| P值 | 期望层数 | 空间开销 | 查找次数 | 特点 |
|-----|---------|---------|---------|------|
| 0.5 | 2.0 | 2n | log₂(n) | 空间大，速度快 |
| 0.25 | 1.33 | 1.33n | log₄(n) | **平衡最优** |
| 0.125 | 1.14 | 1.14n | log₈(n) | 空间小，速度慢 |

**Redis选择P=0.25的原因**：
1. 空间开销适中（1.33n）
2. 查找性能优秀（log₄(n) ≈ 0.5 * log₂(n)）
3. 工程实践证明效果最好

## Q9: 跳表能否支持重复的score？

**A:** 可以。Redis的zset通过(score, value)二元组保证唯一性。

```java
// 比较规则
private int compareNode(double score1, T value1, double score2, T value2) {
    // 先比较score
    if (score1 != score2) {
        return Double.compare(score1, score2);
    }
    // score相同时比较value
    return value1.toString().compareTo(value2.toString());
}
```

**示例**：
```
插入：(10, "a"), (10, "b"), (10, "c")
结果：
Level 0: (10,"a") → (10,"b") → (10,"c")
按字典序排序
```

## Q10: 跳表适合什么场景？

**A:** 跳表适合需要有序性+范围查询的场景。

**适合的场景**：
- ✅ 排行榜系统（游戏、社交）
- ✅ 延迟任务调度
- ✅ 时间序列数据
- ✅ 范围查询频繁的场景
- ✅ 需要按排名查询的场景

**不适合的场景**：
- ❌ 纯KV查询（用哈希表）
- ❌ 不需要有序性（用哈希表）
- ❌ 内存极度受限（用B+树）
- ❌ 需要严格O(log n)保证（用平衡树）
