3. 装饰器类是对功能的增强，这也是装饰器模式应用场景的一个重要特点。实际上，符合“组合关系”这种代码结构的设计模式有很多，比如之前讲过的代理模式、桥接模式，还有现在的装饰器模式。尽管它们的代码结构很相似，但是每种设计模式的意图是不同的。就拿比较相似的代理模式和装饰器模式来说吧，代理模式中，代理类附加的是跟原始类无关的功能，而在装饰器模式中，装饰器类附加的是跟原始类相关的增强功能。

# 装饰和适配器的区别
装饰模式（Decorator Pattern）和适配模式（Adapter Pattern）都是结构型设计模式，但它们的目的、使用场景和实现方式有所不同。以下是它们之间的主要区别：

### 1. 定义

- **装饰模式**：
  - 装饰模式是一种结构型设计模式，允许通过将对象包装在另一个对象中来动态地添加功能或行为。它通过组合的方式实现对对象的增强，而不需要修改原有对象的结构。

- **适配模式**：
  - 适配模式是一种结构型设计模式，用于将一个类的接口转换成客户端所期望的接口，从而使原本由于接口不兼容而无法一起工作的类能够协同工作。

### 2. 目的

- **装饰模式**：
  - 目的是在不改变对象自身的情况下，动态地增加或改变对象的功能。适用于需要扩展类的功能而不使用子类的场景。

- **适配模式**：
  - 目的是解决接口不兼容的问题，使得不同的类可以一起工作。适用于需要让不同接口的类能够互相合作的场景。

### 3. 结构

- **装饰模式**：
  - 包含一个组件接口、具体组件类和多个装饰类。装饰类持有一个对组件接口的引用，并在实现接口的方法时添加额外的功能。

- **适配模式**：
  - 包含一个目标接口、适配者类和适配器类。适配器类实现目标接口，并持有一个适配者的引用，将适配者的方法转换为目标接口的方法。

### 4. 使用场景

- **装饰模式**：
  - 适用于需要在运行时动态地增加对象功能的场景，如图形界面组件的样式、输入流的装饰（如压缩、加密）等。

- **适配模式**：
  - 适用于在系统中引入新的类时，现有代码无法与新类兼容的情况，如将旧系统中的接口转换为新系统所需的接口。

### 5. 复杂性

- **装饰模式**：
  - 相对简单，主要是通过组合来增强功能，保持了类的灵活性和可扩展性。

- **适配模式**：
  - 可能涉及到多个类和接口，适配器类的实现可能会增加一定的复杂性，但通常是为了实现不同接口之间的协作。

### 6. 示例

- **装饰模式示例**：
  ```java
  // 组件接口
  public interface Coffee {
      String getDescription();
      double cost();
  }

  // 具体组件
  public class SimpleCoffee implements Coffee {
      @Override
      public String getDescription() {
          return "Simple Coffee";
      }

      @Override
      public double cost() {
          return 2.0;
      }
  }

  // 装饰类
  public class MilkDecorator implements Coffee {
      private Coffee coffee;

      public MilkDecorator(Coffee coffee) {
          this.coffee = coffee;
      }

      @Override
      public String getDescription() {
          return coffee.getDescription() + ", Milk";
      }

      @Override
      public double cost() {
          return coffee.cost() + 0.5;
      }
  }
  ```

- **适配模式示例**：
  ```java
  // 目标接口
  public interface Target {
      void request();
  }

  // 适配者类
  public class Adaptee {
      public void specificRequest() {
          System.out.println("Specific request");
      }
  }

  // 适配器类
  public class Adapter implements Target {
      private Adaptee adaptee;

      public Adapter(Adaptee adaptee) {
          this.adaptee = adaptee;
      }

      @Override
      public void request() {
          adaptee.specificRequest();
      }
  }
  ```

### 总结

- **装饰模式**用于动态地扩展对象的功能，强调在不改变对象的情况下增加新功能。
- **适配模式**用于解决接口不兼容的问题，强调在不同接口之间建立联系，使得不同类可以协同工作。

选择使用哪种模式，应根据具体需求和场景来决定。
