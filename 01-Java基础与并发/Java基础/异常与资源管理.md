# 异常与资源管理

基线：Java 17。主线是“一次导出任务发生异常时，哪些资源被关闭，最终保留哪个失败”。数据库事务是否回滚属于框架与业务契约，见 [[02-Spring与微服务/Spring/Spring核心原理]]。

## 1. 异常类型与调用方责任

Throwable 下包含 Error 和 Exception；RuntimeException 及其子类属于非受检异常，Error 及其子类也不要求调用方捕获或声明。其他受检异常需由编译器检查 catch 或 throws。

受检不等于可恢复，运行时异常也不等于程序必须退出。是否重试取决于失败原因、操作幂等性和副作用是否已发生。参数错误重试相同输入没有意义；网络超时可能发生在对方成功之后，不能直接视作“没有执行”。

方法抛出异常会沿调用栈寻找匹配处理器，过程中执行适用的清理逻辑。catch 后返回空列表可能把“读取失败”伪装为“没有数据”，尤其会污染报告或授权判断。处理层应决定传播、转换或恢复，并保留原因。

```java
// 方法体片段：业务上下文补充在外层，原始原因保存在 cause。
try {
    exportReport();
} catch (IOException cause) {
    throw new IllegalStateException("报告导出失败", cause);
}
```

这里的 IOException 需导入，exportReport 是业务占位方法。日志在能提供上下文的边界记录一次即可；异常链供排查，返回给客户端的信息还需避免暴露路径、SQL 或敏感数据。

## 2. try-with-resources 的关闭顺序

资源实现 AutoCloseable，放入资源声明后由语言机制管理。资源按声明顺序初始化，按相反顺序关闭；后续资源初始化失败，前面成功初始化的资源仍会关闭。尚未成功构造的对象，其内部已申请资源是否释放由构造过程负责。

```java
// 完整方法片段，需要导入 IOException、Path、Files、StandardCharsets。
static String firstLine(Path path) throws IOException {
    try (var reader = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
        return reader.readLine();
    }
}
```

返回 null 在这里仅表示文件没有首行。读取抛异常则继续传播，不能混成同一种状态。只有拥有资源生命周期的一方才应关闭它：关闭借来的共享连接、System.out 或由框架管理的流，可能影响其他调用者。

## 3. 主异常与 suppressed 异常

| 失败时序 | 向外抛出的异常 | suppressed 中记录什么 |
| --- | --- | --- |
| 主体失败，关闭也失败 | 主体异常 | 关闭异常，按关闭发生顺序加入 |
| 主体成功，多个关闭失败 | 首个关闭异常 | 后续关闭异常 |
| 第二个资源初始化失败，首个关闭失败 | 初始化异常 | 首个资源的关闭异常 |

suppressed 表达清理期间并存的失败；cause 表达异常转换时的因果链，两者用途不同。此机制见 [JLS 17 §14.20.3](https://docs.oracle.com/javase/specs/jls/se17/html/jls-14.html#jls-14.20.3)。实验会同时检查主异常、suppressed 的顺序和资源事件日志。

不要在 finally 中 return 或抛一个无关新异常，否则可能覆盖原来的返回或失败。finally 也不是进程级可靠性机制：进程被强制终止、JVM 崩溃或操作系统退出时，不能依靠它完成业务补偿。

## 4. 释放资源与提交业务是两个问题

文件流关闭可能刷新缓冲并抛错；方法主体生成完内容不代表最终落盘成功。数据库连接 close 也不等于显式 commit；池化连接的 close 通常是归还连接。连接在未结束事务时关闭的具体行为不能由这个语法推断。

教学场景：SQL 兼容性工具在目标库执行测试 DML 后需要恢复数据。它要明确事务开启、回滚、恢复验证与异常传播，再用 try-with-resources 管理连接/语句/结果集的生命周期。只有连接被释放，不能证明测试数据已恢复，见 [[07-项目复盘与方案/SQL兼容性工具/SQL兼容性验证原理与项目核实]]。

InterruptedException 则表示协作式取消信号。能够向上传播时保留传播；若接口不允许传播，应在中止本层工作时按设计恢复中断标记，例如 `Thread.currentThread().interrupt()`，并返回失败或取消状态。不要捕获后无条件继续下一轮工作。
