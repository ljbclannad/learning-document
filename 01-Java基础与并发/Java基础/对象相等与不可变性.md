# 对象相等与不可变性

基线：Java 17。主线是“把一个业务身份放入 Map 后还能稳定找到它”。HashMap 的桶结构见 [[集合]]；金额特有的比较语义见 [[时间与金额处理]]。

## 1. 先定义两个对象什么时候算同一个业务值

引用的 `==` 比较是否指向同一对象；`equals` 表达类型定义的逻辑相等。Object 默认仍按对象身份比较，创建两个字段相同的普通对象并不会自动让 equals 返回 true。

equals 应满足自反、对称、传递和状态未变时的一致性，并对 null 返回 false。相等对象必须有相同 hashCode，反过来不成立：哈希冲突不能当作对象相等。覆盖 equals 时通常必须配套覆盖 hashCode。依据：[Object 的相等与哈希契约](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Object.html#equals(java.lang.Object))。

对于多租户用户，本例将 `(tenantId, userId)` 定义为身份。若只比较 userId，不同租户相同编号会在集合里被当成同一个键。若把显示名也纳入身份，改名又会改变相等关系。参与比较的字段应来自领域定义。

```java
// 类型片段；record 自 Java 16 正式可用，本专题按 Java 17 编译。
record UserKey(String tenantId, String userId) {}
```

该 record 按两个组件生成相等与哈希行为，适合作为本教学模型的键。正式入口仍需检查 null、空白、大小写和编号格式；record 不会自动提供业务校验。

## 2. 为什么修改键会导致“明明存在却查不到”

假设可变键初始 `id=1`，hashCode 取 id：

1. put 时按照旧哈希把节点放入桶，并保存当时的哈希。
2. 外部代码将 id 改为 2，Map 不会自动搬动节点。
3. get 时计算新哈希，无法按正常查找规则找到旧节点。
4. size 仍可能为 1；遍历能看到对象，查询却返回 null。

这不是并发问题，单线程也能复现。换成 ConcurrentHashMap 不会修复键的相等契约。应使用稳定身份作为键；确需改变身份时，应在旧身份仍有效时移除，再以新键插入，并处理同步与冲突。

实体使用数据库生成 ID 时还要考虑“插入前没有 ID、插入后才有 ID”的变化。不要让已经放入 Set 的实体在持久化后改变 equals/hashCode；可改用单独的稳定键对象。继承层次中父类按部分字段比较、子类加字段比较，也容易破坏对称性，设计值对象时优先明确类型边界。

## 3. final、不可修改视图和快照的区别

| 形式 | 保证 | 不保证 |
| --- | --- | --- |
| `final List<X> items` | 引用变量不再重新赋值 | 列表或元素不变 |
| `Collections.unmodifiableList(source)` | 不能通过包装视图修改列表结构 | source 不会被其他引用修改 |
| `List.copyOf(source)` | 获得不随 source 后续结构修改而改变的不可修改列表 | 元素对象深度不可变 |
| 含可变组件的 record | 组件引用固定 | 组件内部状态不变 |

`List.copyOf` 不接受 null 元素，且可能复用合适的不可修改输入实例，不能依赖每次产生新的对象身份。[List 的不可修改列表约定](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/List.html#unmodifiable)。

下面是可以隔离输入列表结构变化的类型片段；需要导入 `java.util.List`：

```java
record PermissionSnapshot(List<String> scopes) {
    PermissionSnapshot {
        scopes = List.copyOf(scopes);
    }
}
```

因为元素是不可变 String，这个示例能稳定保存范围列表。若元素变成可变 Permission，则还需转换成不可变值对象或按契约复制。数组同样需要在构造入口和对外访问时保护；默认 record 的数组组件相等比较也不会自动变成数组内容比较。

## 4. 语言中的不可变不能替代业务时效

教学场景：请求持有一份权限快照。防御性复制能阻止调用方意外修改快照，但管理员撤权后，旧快照仍然是旧事实。需要另外绑定 policyVersion，并在需要的业务边界重新校验，见 [[07-项目复盘与方案/动态权限/动态权限原理与项目核实]]。

类似地，String 不可变不意味着存放它的共享变量不会被多个线程竞争写入；不可变对象也不能保证“检查版本后写数据库”的整段流程原子。这里仅讨论对象内容与引用的约束，并发可见性与事务需要各自的机制。
