# 1. 多态

重载先在编译期依据接收者及实参的静态类型选择方法签名；对于可重写的实例方法，运行时再根据接收者实际类型确定实现。常说“编译时多态是重载，运行时多态是重写”，但不能把两步合成“运行时总会挑最具体参数的方法”。依据：[JLS 17 方法调用](https://docs.oracle.com/javase/specs/jls/se17/html/jls-15.html#jls-15.12)。

```java
// 类型及方法体片段，完整断言见配套实验。
class Parent {
    String select(Object value) { return "父类Object"; }
}
class Child extends Parent {
    @Override String select(Object value) { return "子类Object"; }
    String select(String value) { return "子类String"; }
}
// Parent p = new Child();
// p.select("输入") 返回 "子类Object"，不会选择子类新增的 String 重载。
```

字段访问和静态方法隐藏不具有同样的实例方法动态分派语义；private 方法也不是可由子类重写的方法。接口可以表达能力契约，抽象类可以承载公共状态与实现，但两者都不能替代业务参数校验。实验通过不同静态类型的调用验证选择结果。

# 2. 值传递
在 Java 中，所有方法的参数都是通过值传递的，但这个“值”可以是基本数据类型的值或对象的引用。以下是对 Java 值传递的详细说明：

### 1. 基本数据类型的值传递

对于基本数据类型（如 `int`、`double`、`char` 等），当你将它们作为参数传递给方法时，实际传递的是它们的值的副本。对参数的任何修改不会影响原始变量。

```java
public class ValuePassExample {
    public static void main(String[] args) {
        int num = 10;
        modifyValue(num);
        System.out.println(num); // 输出: 10
    }

    public static void modifyValue(int value) {
        value = 20; // 修改的是副本
    }
}
```

### 2. 对象引用值的副本

对于对象类型（如 `String`、`ArrayList` 等），当你将对象作为参数传递时，传递的是对象引用的副本。这意味着你可以通过这个引用修改对象的内容，但在被调用方法中重新绑定参数，不会重新绑定调用方的变量。

```java
import java.util.ArrayList;

public class ReferencePassExample {
    public static void main(String[] args) {
        ArrayList<String> list = new ArrayList<>();
        list.add("Hello");
        modifyList(list);
        System.out.println(list); // 输出: [Hello, World]
    }

    public static void modifyList(ArrayList<String> list) {
        list.add("World"); // 修改的是原对象
    }
}
```

### 3. 重绑形参不改变调用方变量

形参本身可以指向另一个对象；它只是与调用方变量不同的局部变量。重新赋值只改变这个局部变量，调用方变量仍保存原先的引用值。

```java
public class ReferenceChangeExample {
    public static void main(String[] args) {
        String str = "Hello";
        changeString(str);
        System.out.println(str); // 输出: Hello
    }

    public static void changeString(String s) {
        s = "World"; // 这不会影响原始字符串
    }
}
```

### 总结

- **基本数据类型**：通过值传递，修改不会影响原始值。
- **对象引用**：通过值传递引用，允许通过副本修改共享的可变对象；重绑形参不会改变调用方变量。

理解这一点对于编写有效的 Java 代码非常重要，尤其是在处理方法参数和对象时。

# 3.String,StringBuffer,StringBuilder

在Java中，`String`、`StringBuffer`和`StringBuilder`是处理字符串的三种不同类，它们之间有一些重要的差异。以下是它们的主要区别：

### 1. **不可变性 vs 可变性**
- **String**：
  - `String`是不可变的。一旦创建，字符串的内容不能被改变。看起来像修改的操作会返回结果，原字符串不变；不保证每次调用都创建新实例，例如 `str.concat("")` 可以返回原对象。
  ```java
  String str = "Hello";
  str = str + " World"; // 创建了一个新的String对象
  ```

- **StringBuffer** 和 **StringBuilder**：
  - 这两者都是可变的，可以在原有对象上进行修改，而不需要创建新的对象。
  ```java
  StringBuffer sb = new StringBuffer("Hello");
  sb.append(" World"); // 修改了原有的StringBuffer对象
  ```

### 2. **线程安全性**
- **StringBuffer**：
  - `StringBuffer`是线程安全的，适合在多线程环境中使用。相关操作通过同步保护内部状态，但“先检查长度再追加”等多个调用不自动形成业务原子操作。
  
- **StringBuilder**：
  - `StringBuilder`不是线程安全的，适合线程内构建或外部已正确同步的场景，不作无条件性能承诺。

### 3. **性能**
- **String**：
  - 循环累积不可变字符串可能反复复制已有内容，增长输入下成本明显；常量表达式可能在编译期折叠，固定表达式的拼接也可能被编译器优化，不能只凭一个 `+` 断定分配次数。

- **StringBuffer** 和 **StringBuilder**：
  - 长度随循环增长时，可用构建器积累内容。`StringBuilder`没有 `StringBuffer` 的同步语义，但实际性能仍取决于输入、使用方式与运行环境，应以同条件测量为准。

### 4. **使用场景**
- **String**：
  - 适合用于不需要修改的字符串。

- **StringBuffer**：
  - 适合在多线程环境中需要修改字符串的场景。

- **StringBuilder**：
  - 适合在单线程环境中需要频繁修改字符串的场景。

### 示例代码
```java
// String 示例
String str = "Hello";
str += " World"; // 创建新的String对象

// StringBuffer 示例
StringBuffer sb = new StringBuffer("Hello");
sb.append(" World"); // 修改原有对象

// StringBuilder 示例
StringBuilder sb2 = new StringBuilder("Hello");
sb2.append(" World"); // 修改原有对象
```



## 字符串内容、字符和编码边界

文本内容比较使用 equals，不依赖常量池导致的 `==` 偶然相等。String 的索引和 length 以 UTF-16 代码单元计算，一个补充字符可能占两个 char；按用户看到的字符截断比按代码单元更复杂，code point 也不总等于一个可见字形。字节与文本转换需显式约定编码，避免依赖机器默认值。依据：[String API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/String.html)。

例如 `"😀".length()` 为 2。若接口限制的是 UTF-8 字节数，就应按编码后字节计算并在完整字符边界处理，不能用 String.length 直接替代。模型输入预算也不等于 Java 字符串长度。
