# 注解与反射

基线：Java 17。理解主线：框架读取声明元数据，找到方法，再按自己的规则执行。注解本身不会启动事务、检查权限或调用业务代码；这些行为来自处理它的编译器、处理器或运行时框架。

## 1. 注解保存在哪里

| RetentionPolicy | 保存阶段 | 适用理解 |
| --- | --- | --- |
| SOURCE | 源码阶段 | 编译期检查或生成，不保留到类文件 |
| CLASS | 类文件 | 可供字节码工具处理，普通运行时反射不可读取 |
| RUNTIME | 类文件与运行时 | 可由反射 API 读取 |

没有声明 Retention 时默认 CLASS，而不是 RUNTIME。[Retention 官方约定](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/annotation/Retention.html)。Target 指定注解可以出现的位置，不代表业务访问权限。运行时注解遗漏 Retention 时，“代码编译正常但扫描不到”是常见结果。

```java
// 类型片段；需要导入 java.lang.annotation 下对应类型。
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface ExportField {
    String value();
}
```

`@Inherited` 只影响类注解沿父类查找，不会让方法注解自动继承，也不沿接口继承。[Inherited 官方边界](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/annotation/Inherited.html)。Spring 等框架可以另行实现合并注解规则，不能将其当成 Java 反射的默认能力。

## 2. 从 Class 到 Method，再到调用

| 操作 | 语义与边界 |
| --- | --- |
| `getMethod(name, types)` | 查找 public 方法，包括继承的方法 |
| `getDeclaredMethod(name, types)` | 查当前类声明的方法，不沿父类自动查找；可找到非 public 声明 |
| `getDeclaredMethods()` | 枚举声明方法，顺序不作为业务顺序契约，可能含桥接/合成方法 |
| `method.invoke(target, args)` | 在通过访问和参数检查后调用；目标抛出的异常包装为 InvocationTargetException |

查找方法需要匹配声明参数类型，`int.class` 与 `Integer.class` 不能随意替换。反射调用本身允许规定的拆箱与基本类型扩宽，但这不等于方法查找会像源代码重载一样自动猜测目标。依据：[Method API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/reflect/Method.html)。

调用失败要区分：没有这个方法、当前代码无权访问、参数不匹配，以及业务方法自己抛错。处理 InvocationTargetException 时查看 cause；把包装异常全部翻译成“反射失败”会丢失真实业务原因。

“当前类声明的方法”包括编译器生成的方法，不等于源码里手写的方法。本次在 javac 17.0.11 上观察到：公开子类继承非公开父类的 public 方法时，子类类文件中出现了转发方法。基础实验将父类设为 public，以隔离普通继承查找；排查框架扫描结果时仍应结合 isBridge、isSynthetic 和 `javap` 输出判断，不仅对照源码文本。

## 3. 找到私有成员不等于能够访问

Java 17 的语言访问控制和模块边界仍然适用。`setAccessible(true)` 不是任意打开所有 JDK 内部成员的万能开关；跨模块深反射还受包是否开放等条件约束。`trySetAccessible()` 在不能开启访问时可返回 false，相关调用也可能受到安全检查限制。依据：[AccessibleObject](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/reflect/AccessibleObject.html)。

排查框架升级后出现的访问问题，应明确调用方模块、目标模块、包、成员可见性及依赖版本，再决定改用公共 API、升级依赖或受控开放。不要为了让实验成功随意开放全部内部包。

Class 不只是类名：相同名字由不同定义类加载器加载，可能是不同类型。插件注册、缓存和热加载时，不能只按类名当作唯一身份；长期持有 Class/Method 的全局缓存还可能阻止对应类加载器回收。此处是设计风险说明，不是已经测得本项目存在泄漏。

## 4. 注解如何变成框架行为

一个导出框架可以在注册阶段扫描 ExportField，校验允许的方法签名，生成稳定的字段映射；运行时按这份映射调用。字段顺序应来自显式 order 或配置，不能依赖反射返回顺序。重名、空名称、桥接方法重复出现都应在注册阶段报错。

若外部请求直接提供类名、方法名和参数，然后由后端反射调用任意方法，就绕过了服务原本的接口边界。应使用服务端维护的允许列表和固定参数契约，业务授权仍在执行入口检查。反射可访问性不是用户授权。

Spring 的事务、自调用与代理边界属于另一层：有注解但调用没有经过处理它的代理/拦截链，行为可能不会生效。相关机制回到 [[代理]] 和 [[02-Spring与微服务/Spring/Spring核心原理]]；本文不重复实现代理框架。
