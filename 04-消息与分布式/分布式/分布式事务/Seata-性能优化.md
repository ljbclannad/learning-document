# Seata 性能优化运行手册

> 主文：[[Seata]]。本文用于容量评估、压测与性能优化；先理解 AT、TCC、Saga 的语义边界，再执行优化。

## 1. 先确认问题是否属于 Seata

将一次慢请求拆成以下阶段并分别记录耗时：

1. `GlobalBegin` 与 `BranchRegister`：TC RPC、会话存储、全局锁冲突。
2. RM 一阶段：SQL 解析、前后镜像、`undo_log` 写入、数据库行锁和连接池。
3. 业务依赖：下游 RPC、数据库慢 SQL、缓存或第三方服务。
4. 二阶段：提交/回滚队列、`undo_log` 清理、回滚重试。

没有分段指标时，不要把慢请求直接归因于 TC、RM 或数据库中的任一方。

## 2. 关键指标

| 维度 | 指标 | 异常含义 |
|------|------|----------|
| 全局事务 | 创建量、成功率、P95/P99、超时率 | 事务范围过大、依赖变慢或超时设置不合理 |
| TC | Begin/Register 时延、CPU、GC、存储延迟 | 协调端或其存储成为瓶颈 |
| AT 锁 | 冲突率、重试次数、热点 `lockKey` | 热点写入或事务未决窗口过长 |
| RM/DB | 镜像 SQL 时延、`undo_log` 写入/清理时延、行锁等待 | SQL、索引、IO、连接池或清理积压问题 |
| 二阶段 | 待提交/回滚数量、重试年龄、死信/异常池 | 故障恢复能力下降，可能阻塞后续业务 |

## 3. 优化决策顺序

1. **缩小全局事务范围**：将通知、统计、搜索索引等非核心写移至本地事务消息表和异步消费者。
2. **治理热点资源**：按商品、账户、号源等业务键限流或排队；避免把同一热点行暴露给大量 AT 分支。
3. **优化本地数据库路径**：验证 DML 和镜像查询索引，控制单事务影响行数与镜像行宽，监控 `undo_log` 生命周期。
4. **调整重试与超时**：锁冲突快速失败、带退避重试；避免无限重试把短暂故障扩大为队列堆积。
5. **再评估模式**：资源预留场景优先考虑 TCC；跨系统且允许延迟的流程使用本地消息、对账与补偿。

## 4. 压测方法

必须同时准备基线与故障注入：

- 基线：无全局事务、本地事务、目标事务模式分别测量。
- 变量：并发/到达率、分支数量、数据量、热点比例、镜像行宽、网络时延。
- 故障：TC 短暂不可用、锁冲突、数据库慢查询、二阶段回滚与消息积压。
- 结果：记录吞吐、P50/P95/P99、锁冲突率、全局超时率、二阶段积压和恢复时间。

不要复用其他环境的固定 TPS、延迟或“提升百分比”作为容量结论。

## 5. 经版本核对的配置项（Seata 2.6）

以下键名来自 [Seata 2.6 参数配置](https://seata.apache.org/docs/user/configurations/)；只给出用途，不给出脱离负载的推荐数值。修改前应记录当前值，并在压测和故障注入中验证。

| 配置项 | 用途 | 调整时关注 |
|--------|------|------------|
| `client.rm.asyncCommitBufferLimit` | RM 二阶段异步提交清理队列上限 | 队列积压、`undo_log` 清理延迟、内存占用 |
| `client.rm.lock.retryInterval` / `client.rm.lock.retryTimes` | AT 全局锁占用或校验冲突的重试策略 | 快速失败、冲突率与业务重试风暴 |
| `client.tm.defaultGlobalTransactionTimeout` | TM 默认全局事务超时 | 业务最长路径、超时回滚量和误回滚风险 |
| `metrics.enabled` / `metrics.exporterList` | 指标开关与导出器选择 | 指标可用性和监控采集成本 |

示例命令只用于确认指标端点是否可达，端口以实际配置为准：

```sh
curl -fsS "http://<tc-host>:<metrics-port>/metrics"
```

## 6. 上线前检查

- [ ] 全局事务只覆盖必须同步确认的数据写入。
- [ ] 热点资源有参数级限流、快速失败与降级策略。
- [ ] `undo_log`、TC 存储与数据库锁等待均有监控和告警。
- [ ] 二阶段任务有重试上限、异常池、对账和人工处置路径。
- [ ] 已在目标版本、目标数据规模和故障条件下完成压测。
