# 1. Http请求结构
HTTP 请求是客户端向服务器发送的消息，用于请求资源。一个完整的 HTTP 请求通常包含以下几个主要部分：

### 1. 请求行（Request Line）

请求行包含三个主要部分：

- **HTTP 方法**：指定请求的类型，常见的方法有：
  - `GET`：请求获取指定资源。
  - `POST`：向指定资源提交数据。
  - `PUT`：更新指定资源。
  - `DELETE`：删除指定资源。
  - `HEAD`：获取资源的元信息。
  - `OPTIONS`：获取支持的请求方法和其他选项。

- **请求 URI**：指定请求的资源路径，通常以 `/` 开头，可能包含查询参数，例如 `/api/users?id=1`。

- **HTTP 版本**：指明所使用的 HTTP 协议版本，通常是 `HTTP/1.1` 或 `HTTP/2`。

**示例**：
```
GET /api/users?id=1 HTTP/1.1
```

### 2. 请求头（Request Headers）

请求头包含关于请求的附加信息，通常包括：

- **Host**：请求的主机名和端口号（如 `Host: www.example.com`）。
- **User-Agent**：客户端软件的信息（如浏览器类型）。
- **Accept**：客户端能够处理的内容类型（如 `Accept: application/json`）。
- **Content-Type**：请求体的媒体类型（如 `Content-Type: application/json`，通常在 `POST` 和 `PUT` 请求中使用）。
- **Authorization**：用于身份验证的凭据（如 `Bearer token`）。

**示例**：
```
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: application/json
Content-Type: application/json
Authorization: Bearer token
```

### 3. 空行

请求头和请求体之间有一个空行，表示请求头的结束。

### 4. 请求体（Request Body）

请求体是可选的，主要用于包含要发送到服务器的数据，尤其是在 `POST` 和 `PUT` 请求中。请求体的内容根据 `Content-Type` 进行格式化，可以是 JSON、表单数据、XML 等。

**示例**（JSON 格式）：
```json
{
    "name": "John",
    "age": 30
}
```

### 5. 示例完整的 HTTP 请求

以下是一个完整的 HTTP POST 请求示例：

```
POST /api/users HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: application/json
Content-Type: application/json
Authorization: Bearer token

{
    "name": "John",
    "age": 30
}
```

### 总结

一个完整的 HTTP 请求包含请求行、请求头、空行和请求体。每个部分都有其特定的作用，组合在一起用于向服务器发起请求并传递必要的信息。理解这些内容有助于更好地进行网络编程和调试。

# 2. Https请求内容
HTTPS（超文本传输安全协议）是基于 HTTP 的安全协议，通过 SSL/TLS 加密保障数据传输的安全性。HTTPS 请求的流程主要包括以下几个步骤：

### 1. 客户端发起请求

1. **DNS 解析**：
   - 客户端首先通过 DNS 解析域名，获取目标服务器的 IP 地址。

2. **建立 TCP 连接**：
   - 客户端与服务器之间建立 TCP 连接，通常使用三次握手。

### 2. TLS 握手阶段

在 TCP 连接建立后，开始进行 TLS 握手，以确保安全通信：

1. **Client Hello**：
   - 客户端发送 `Client Hello` 消息，包含支持的 TLS 版本、加密算法、随机数等信息。

2. **Server Hello**：
   - 服务器回应 `Server Hello` 消息，选择 TLS 版本、加密算法，并发送随机数。

3. **服务器证书**：
   - 服务器向客户端发送其 SSL/TLS 证书，证书中包含公钥和服务器的信息。

4. **验证证书**：
   - 客户端验证服务器的证书是否有效（签名、过期、是否被信任等）。

5. **生成会话密钥**：
   - 客户端生成一个预主密钥（Pre-Master Secret），使用服务器的公钥加密后发送给服务器。

6. **双方生成会话密钥**：
   - 客户端和服务器根据预主密钥和之前的随机数生成会话密钥，用于后续的加密通信。

7. **Finished 消息**：
   - 客户端发送 `Finished` 消息，表示握手结束。
   - 服务器回应 `Finished` 消息，确认握手完成。

### 3. 发送 HTTPS 请求

1. **构建 HTTP 请求**：
   - 客户端在建立的安全连接上构建 HTTPS 请求，包括请求行、请求头和请求体。

2. **发送请求**：
   - 客户端通过加密的 TCP 连接将 HTTPS 请求发送到服务器。

### 4. 服务器处理请求

1. **接收请求**：
   - 服务器接收客户端的 HTTPS 请求并解密。

2. **处理请求**：
   - 服务器处理请求，生成响应。

3. **构建 HTTP 响应**：
   - 服务器构建 HTTP 响应，包括状态行、响应头和响应体。

### 5. 返回 HTTPS 响应

1. **发送响应**：
   - 服务器通过加密的连接将 HTTPS 响应发送回客户端。

2. **客户端解密**：
   - 客户端接收并解密响应。

### 6. 关闭连接

1. **关闭 TCP 连接**：
   - 客户端和服务器可以选择关闭 TCP 连接，通常使用四次挥手。

### 总结

HTTPS 请求流程涉及 DNS 解析、TCP 连接建立、TLS 握手、HTTP 请求的发送与处理，以及最后的响应返回。通过加密和身份验证，HTTPS 确保数据在传输过程中的安全性和完整性。
