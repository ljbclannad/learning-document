# 计算机网络 - 后端开发核心知识

## 一、HTTP/HTTPS 协议

### 1.1 必知必会

#### HTTP 基础

**请求方法**
- **GET**：获取资源，幂等、可缓存、参数在 URL 中
- **POST**：创建资源，非幂等、不可缓存、参数在请求体中
- **PUT**：更新资源（完整替换），幂等
- **PATCH**：部分更新资源，幂等
- **DELETE**：删除资源，幂等

**常用状态码**
- **2xx 成功**
  - 200 OK：请求成功
  - 201 Created：资源创建成功
  - 204 No Content：成功但无返回内容（常用于 DELETE）
- **3xx 重定向**
  - 301 Moved Permanently：永久重定向
  - 302 Found：临时重定向
  - 304 Not Modified：资源未修改，使用缓存
- **4xx 客户端错误**
  - 400 Bad Request：请求参数错误
  - 401 Unauthorized：未认证
  - 403 Forbidden：无权限
  - 404 Not Found：资源不存在
  - 429 Too Many Requests：请求过多，触发限流
- **5xx 服务端错误**
  - 500 Internal Server Error：服务器内部错误
  - 502 Bad Gateway：网关错误，上游服务不可达
  - 503 Service Unavailable：服务不可用（过载或维护）
  - 504 Gateway Timeout：网关超时，上游响应超时

**核心头部字段**
- **Content-Type**：请求/响应体的数据格式（application/json、multipart/form-data）
- **Authorization**：认证信息（Bearer token、Basic auth）
- **Cookie / Set-Cookie**：会话管理
- **Cache-Control**：缓存策略（max-age、no-cache、no-store）
- **Connection**：连接管理（keep-alive、close）
- **Accept-Encoding**：支持的压缩格式（gzip、br）

#### HTTP 版本演进

**HTTP/1.0**
- 特点：短连接，每次请求都要建立 TCP 连接
- 问题：频繁握手，性能差

**HTTP/1.1**
- 改进：
  - 持久连接（Keep-Alive）：复用 TCP 连接
  - 管道化（Pipelining）：批量发送请求
  - Host 头部：支持虚拟主机
  - 分块传输编码（Chunked Transfer Encoding）
- 问题：队头阻塞（一个慢响应阻塞后续请求）

**HTTP/2**
- 改进：
  - 二进制分帧：更高效的解析
  - 多路复用：多个请求共享一个 TCP 连接，并发处理
  - 头部压缩（HPACK）：减少重复头部传输
  - 服务器推送：主动推送资源
- 问题：仍基于 TCP，存在 TCP 层队头阻塞

**HTTP/3**
- 改进：
  - 基于 QUIC（UDP）：解决 TCP 队头阻塞
  - 更快的连接建立：0-RTT 握手
  - 更好的移动网络支持：连接迁移

#### HTTPS 加密原理

**加密方案**
- 对称加密：加密和解密使用相同密钥，速度快（AES）
- 非对称加密：公钥加密、私钥解密，速度慢（RSA）
- HTTPS 混合方案：用非对称加密协商对称密钥，用对称加密传输数据

**简化流程**
1. 客户端发起 HTTPS 请求
2. 服务器返回证书（包含公钥）
3. 客户端验证证书合法性
4. 客户端生成随机对称密钥，用服务器公钥加密发送
5. 服务器用私钥解密，得到对称密钥
6. 双方使用对称密钥加密通信

### 1.2 深入理解

#### HTTP/1.1 持久连接

**Keep-Alive 机制**
- 作用：复用 TCP 连接，减少握手开销
- 配置：`Connection: keep-alive` 和 `Keep-Alive: timeout=5, max=100`
- 适用场景：高频 API 调用、微服务通信

**管道化（Pipelining）**
- 作用：客户端批量发送请求，不等待响应
- 限制：响应必须按请求顺序返回
- 问题：队头阻塞（Head-of-Line Blocking）
- 现状：浏览器默认禁用，实际应用少

**队头阻塞问题**
- 现象：一个慢响应阻塞后续所有请求
- 原因：HTTP/1.1 要求响应按序返回
- 解决：升级到 HTTP/2 多路复用

#### HTTP/2 多路复用

**核心概念**
- **流（Stream）**：一个请求-响应对，有唯一 ID
- **消息（Message）**：完整的请求或响应
- **帧（Frame）**：最小传输单位，包含流 ID

**工作原理**
- 多个流共享一个 TCP 连接
- 帧可以交错发送，不阻塞
- 接收方根据流 ID 重组消息

**优先级和流量控制**
- 优先级：客户端可指定流的优先级，服务器优先处理高优先级请求
- 流量控制：防止发送方过快，接收方来不及处理

**头部压缩（HPACK）**
- 问题：HTTP 头部重复多（如 Cookie、User-Agent）
- 方案：维护头部索引表，只传输差异
- 效果：减少 80% 以上头部大小

#### HTTPS 完整握手流程

**详细步骤**
1. **ClientHello**
   - 客户端发送：支持的 TLS 版本、加密套件列表、随机数 1
2. **ServerHello**
   - 服务器返回：选择的 TLS 版本、加密套件、随机数 2、服务器证书
3. **证书验证**
   - 客户端验证：证书有效期、证书链、域名匹配、是否被吊销
4. **密钥交换**
   - 客户端生成随机数 3（Pre-Master Secret）
   - 用服务器公钥加密，发送给服务器
5. **生成会话密钥**
   - 双方用随机数 1、2、3 生成相同的对称密钥（Master Secret）
6. **加密通信**
   - 双方使用对称密钥加密后续通信

**证书链验证**
- 根证书（Root CA）：操作系统或浏览器内置，绝对信任
- 中间证书（Intermediate CA）：根证书签发
- 服务器证书：中间证书签发
- 验证链：服务器证书 → 中间证书 → 根证书

#### 连接管理

**短连接**
- 特点：每次请求建立新连接，请求完成后立即关闭
- 适用场景：低频请求、一次性任务
- 缺点：频繁握手，性能差

**长连接**
- 特点：复用连接，多个请求共享
- 适用场景：高频 API 调用、实时通信
- 配置：设置合理的超时时间，避免连接泄漏

**连接池**
- 作用：预先建立多个连接，提高并发能力
- 参数：
  - 最大连接数：根据 QPS 和响应时间计算
  - 最大空闲连接：避免频繁创建销毁
  - 连接存活时间：防止连接长时间占用
- 适用场景：微服务调用、数据库连接、HTTP 客户端

### 1.3 生产实战

#### API 超时配置最佳实践

**场景**：调用第三方 API 或微服务

**方案**：
- **连接超时（Connect Timeout）**：3-5 秒，防止连接建立过慢
- **读超时（Read Timeout）**：根据业务调整
  - 普通 API：10-30 秒
  - LLM API：60-120 秒（生成时间长）
  - 数据库查询：5-10 秒
- **总超时（Total Timeout）**：防止重试导致总时间过长

**示例（Java OkHttp）**：
```java
OkHttpClient client = new OkHttpClient.Builder()
    .connectTimeout(5, TimeUnit.SECONDS)      // 连接超时 5 秒
    .readTimeout(30, TimeUnit.SECONDS)        // 读超时 30 秒
    .writeTimeout(30, TimeUnit.SECONDS)       // 写超时 30 秒
    .callTimeout(60, TimeUnit.SECONDS)        // 总超时 60 秒
    .retryOnConnectionFailure(true)           // 连接失败自动重试
    .build();
```

**示例（Spring RestTemplate）**：
```java
@Configuration
public class RestTemplateConfig {
    
    @Bean
    public RestTemplate restTemplate() {
        HttpComponentsClientHttpRequestFactory factory = 
            new HttpComponentsClientHttpRequestFactory();
        
        factory.setConnectTimeout(5000);      // 连接超时 5 秒
        factory.setReadTimeout(30000);        // 读超时 30 秒
        factory.setConnectionRequestTimeout(3000);  // 从连接池获取连接超时 3 秒
        
        return new RestTemplate(factory);
    }
}
```

#### 连接池参数调优

**场景**：高并发 API 网关或微服务调用

**计算公式**：
```
所需连接数 = (QPS × 平均响应时间) / 1000
例如：QPS=1000，RT=100ms，需要 (1000 × 100) / 1000 = 100 个连接
```

**方案**：
- **最大连接数（maxTotal）**：根据公式计算，留 20% 余量
- **每个路由最大连接数（maxPerRoute）**：maxTotal / 路由数
- **最大空闲连接**：避免频繁创建销毁
- **连接存活时间**：防止连接长时间占用

**示例（Apache HttpClient）**：
```java
@Configuration
public class HttpClientConfig {
    
    @Bean
    public CloseableHttpClient httpClient() {
        PoolingHttpClientConnectionManager connectionManager = 
            new PoolingHttpClientConnectionManager();
        
        connectionManager.setMaxTotal(200);              // 最大连接数 200
        connectionManager.setDefaultMaxPerRoute(20);     // 每个路由最大 20 个连接
        connectionManager.setValidateAfterInactivity(2000);  // 空闲 2 秒后验证连接
        
        return HttpClients.custom()
            .setConnectionManager(connectionManager)
            .setKeepAliveStrategy((response, context) -> 30 * 1000)  // 保持 30 秒
            .setDefaultRequestConfig(RequestConfig.custom()
                .setConnectTimeout(5000)
                .setSocketTimeout(30000)
                .setConnectionRequestTimeout(3000)
                .build())
            .build();
    }
}
```

**示例（Nginx upstream）**：
```nginx
upstream backend {
    server 127.0.0.1:8080 max_conns=100;  # 每个后端最大 100 个连接
    server 127.0.0.1:8081 max_conns=100;
    
    keepalive 32;              # 保持 32 个空闲连接
    keepalive_timeout 60s;     # 空闲连接超时 60 秒
    keepalive_requests 100;    # 每个连接最多处理 100 个请求
}

server {
    location /api/ {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";  # 启用长连接
    }
}
```

#### HTTPS 证书配置与续期

**场景**：生产环境 HTTPS 部署

**方案**：
- 使用 Let's Encrypt 免费证书（90 天有效期）
- 配置自动续期（certbot）
- 配置完整证书链（包含中间证书）
- 启用 HSTS（强制 HTTPS）
- 禁用弱加密套件

**示例（Let's Encrypt 申请）**：
```bash
# 安装 certbot
sudo apt-get install certbot

# 申请证书（需要域名解析到服务器）
sudo certbot certonly --standalone -d example.com -d www.example.com

# 自动续期（添加到 crontab）
0 0 * * * certbot renew --quiet
```

**示例（Spring Boot application.yml）**：
```yaml
server:
  port: 8443
  ssl:
    enabled: true
    key-store: classpath:keystore.p12
    key-store-password: changeit
    key-store-type: PKCS12
    protocol: TLS
    enabled-protocols: TLSv1.2,TLSv1.3
    ciphers: TLS_AES_128_GCM_SHA256,TLS_AES_256_GCM_SHA384,TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256
```

**示例（Nginx 配置）**：
```nginx
server {
    listen 443 ssl http2;
    server_name example.com;
    
    # 证书配置
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    
    # 协议和加密套件
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers 'ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384';
    ssl_prefer_server_ciphers on;
    
    # HSTS（强制 HTTPS）
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    
    # OCSP Stapling（加速证书验证）
    ssl_stapling on;
    ssl_stapling_verify on;
    ssl_trusted_certificate /etc/letsencrypt/live/example.com/chain.pem;
}

# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name example.com;
    return 301 https://$server_name$request_uri;
}
```

#### 常见 HTTP 问题排查

**502 Bad Gateway**
- 原因：上游服务不可达
- 排查：
  1. 检查上游服务是否启动：`curl http://backend:8080/health`
  2. 检查网络连通性：`telnet backend 8080`
  3. 检查防火墙规则
  4. 查看网关日志

**504 Gateway Timeout**
- 原因：上游响应超时
- 排查：
  1. 检查上游服务性能（慢查询、死锁）
  2. 检查超时配置是否合理
  3. 查看上游服务日志
  4. 使用 APM 工具分析慢请求

**429 Too Many Requests**
- 原因：触发限流
- 排查：
  1. 检查请求频率是否异常
  2. 查看限流规则配置
  3. 确认是否需要调整限流阈值
  4. 检查是否有恶意请求

**证书错误**
- 常见错误：
  - 证书过期：检查有效期，重新申请
  - 域名不匹配：检查证书 CN 或 SAN 字段
  - 证书链不完整：配置中间证书
  - 证书被吊销：检查 CRL 或 OCSP
- 排查工具：
  ```bash
  # 查看证书信息
  openssl s_client -connect example.com:443 -showcerts
  
  # 验证证书链
  openssl verify -CAfile chain.pem server.crt
  
  # 检查证书有效期
  openssl x509 -in server.crt -noout -dates
  ```

## 二、TCP/IP 协议

### 2.1 必知必会

#### TCP 三次握手与四次挥手

**三次握手（建立连接）**
1. **第一次握手**：客户端发送 SYN 包（seq=x），进入 SYN_SENT 状态
2. **第二次握手**：服务端返回 SYN+ACK 包（seq=y, ack=x+1），进入 SYN_RCVD 状态
3. **第三次握手**：客户端发送 ACK 包（ack=y+1），双方进入 ESTABLISHED 状态

**为什么需要三次握手？**
- 确认双方的收发能力都正常
- 协商初始序列号（ISN），防止旧连接的数据包干扰
- 防止已失效的连接请求突然传到服务端

**四次挥手（关闭连接）**
1. **第一次挥手**：客户端发送 FIN 包，进入 FIN_WAIT_1 状态
2. **第二次挥手**：服务端返回 ACK 包，进入 CLOSE_WAIT 状态；客户端进入 FIN_WAIT_2 状态
3. **第三次挥手**：服务端发送 FIN 包，进入 LAST_ACK 状态
4. **第四次挥手**：客户端返回 ACK 包，进入 TIME_WAIT 状态（等待 2MSL）；服务端收到后进入 CLOSED 状态

**为什么需要四次挥手？**
- 服务端收到 FIN 后可能还有数据要发送，所以 ACK 和 FIN 分开
- TCP 是全双工通信，双方都需要主动关闭

**为什么有 TIME_WAIT 状态？**
- 确保最后的 ACK 能到达服务端（如果丢失，服务端会重发 FIN）
- 等待 2MSL（Maximum Segment Lifetime），确保旧连接的数据包在网络中消失

#### TCP 与 UDP 的区别

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠传输（确认、重传） | 不可靠（尽力而为） |
| 有序性 | 保证有序到达 | 不保证顺序 |
| 流量控制 | 有（滑动窗口） | 无 |
| 拥塞控制 | 有（慢启动、拥塞避免） | 无 |
| 开销 | 大（20 字节头部） | 小（8 字节头部） |
| 速度 | 慢 | 快 |
| 应用场景 | HTTP、HTTPS、数据库连接、文件传输 | DNS、视频流、游戏、实时通信 |

#### TCP 可靠性保证机制

**序列号和确认号**
- 每个字节都有序列号，保证数据有序和完整
- 接收方返回确认号（ACK），表示已收到的数据

**超时重传**
- 发送方发送数据后启动定时器
- 超时未收到 ACK，则重传数据
- RTO（Retransmission Timeout）动态调整

**校验和**
- 检测数据在传输过程中是否损坏
- 损坏的数据包会被丢弃，触发重传

**流量控制**
- 接收方通过窗口大小（rwnd）告知发送方自己的缓冲区大小
- 防止发送方发送过快，接收方来不及处理

**拥塞控制**
- 检测网络拥塞，动态调整发送速率
- 防止网络过载

### 2.2 深入理解

#### TCP 状态机

**主要状态**
- **CLOSED**：初始状态，无连接
- **LISTEN**：服务端监听状态，等待连接
- **SYN_SENT**：客户端发送 SYN 后的状态
- **SYN_RCVD**：服务端收到 SYN 后的状态
- **ESTABLISHED**：连接建立，可以传输数据
- **FIN_WAIT_1**：主动关闭方发送 FIN 后的状态
- **FIN_WAIT_2**：主动关闭方收到 ACK 后的状态
- **CLOSE_WAIT**：被动关闭方收到 FIN 后的状态
- **LAST_ACK**：被动关闭方发送 FIN 后的状态
- **TIME_WAIT**：主动关闭方收到 FIN 后的状态，等待 2MSL
- **CLOSING**：双方同时关闭时的状态

**关键状态说明**
- **ESTABLISHED**：正常数据传输状态
- **TIME_WAIT**：主动关闭方等待 2MSL（通常 60 秒），确保对方收到最后的 ACK
- **CLOSE_WAIT**：被动关闭方收到 FIN 但还未发送自己的 FIN，通常是应用层未正确关闭连接

**常见问题**
- **TIME_WAIT 过多**：高并发短连接场景，主动关闭方积累大量 TIME_WAIT
- **CLOSE_WAIT 过多**：应用层未正确关闭连接，导致连接泄漏

#### 超时重传机制

**RTO（Retransmission Timeout）计算**
- 基于 RTT（Round-Trip Time）动态调整
- 公式：`RTO = SRTT + 4 × RTTVAR`
  - SRTT：平滑 RTT
  - RTTVAR：RTT 方差

**指数退避**
- 每次重传 RTO 翻倍（1s → 2s → 4s → 8s）
- 避免网络拥塞时雪上加霜
- 达到最大重传次数后放弃连接

**快速重传**
- 收到 3 个重复 ACK 立即重传，不等超时
- 比超时重传更快恢复

**SACK（Selective Acknowledgment）**
- 选择性确认，告知发送方哪些数据已收到
- 避免重传已收到的数据

#### 流量控制（滑动窗口）

**接收窗口（rwnd）**
- 接收方告知发送方自己的缓冲区大小
- 发送方根据 rwnd 调整发送速率

**发送窗口**
- 发送方维护的窗口，表示可以发送但未确认的数据量
- 窗口大小 = min(rwnd, cwnd)

**零窗口探测**
- 接收方窗口为 0 时，发送方停止发送
- 发送方定期发送零窗口探测包，询问接收方窗口是否恢复

**窗口缩放（Window Scaling）**
- TCP 头部窗口字段只有 16 位，最大 64KB
- 窗口缩放选项可以扩展到 1GB

#### 拥塞控制

**慢启动（Slow Start）**
- 初始拥塞窗口（cwnd）很小（通常 10 个 MSS）
- 每收到一个 ACK，cwnd 翻倍（指数增长）
- 快速探测网络容量

**拥塞避免（Congestion Avoidance）**
- 达到慢启动阈值（ssthresh）后，进入拥塞避免
- 每个 RTT，cwnd 增加 1 个 MSS（线性增长）
- 平稳增长，避免网络拥塞

**快速恢复（Fast Recovery）**
- 检测到丢包（3 个重复 ACK）后，快速降低 cwnd
- ssthresh = cwnd / 2
- cwnd = ssthresh + 3
- 然后线性增长

**拥塞窗口（cwnd）**
- 发送方维护，防止网络过载
- 实际发送窗口 = min(rwnd, cwnd)

**场景**：高并发短连接场景（如爬虫、压测），主动关闭方积累大量 TIME_WAIT

**影响**：

### 3.1 必知必会

#### 优化目标

**延迟（Latency）**
- 定义：请求到响应的时间
- 影响：用户体验、实时性
- 衡量指标：P50、P95、P99 延迟
- 优化方向：减少网络往返、缓存、CDN

**吞吐量（Throughput）**
- 定义：单位时间内处理的请求数或数据量
- 影响：系统容量、并发能力
- 衡量指标：QPS、TPS、带宽利用率
- 优化方向：连接复用、批量处理、压缩

**并发（Concurrency）**
- 定义：同时处理的请求数
- 影响：资源利用率、系统负载
- 衡量指标：并发连接数、活跃线程数
- 优化方向：连接池、异步处理、负载均衡

**权衡**
- 低延迟 vs 高吞吐量：批量处理提高吞吐但增加延迟
- 并发 vs 资源消耗：高并发需要更多内存和 CPU
- 需根据业务场景选择优化重点

#### 优化层次

**应用层优化**

- 缓存策略：本地缓存、分布式缓存
- 异步处理：消息队列、事件驱动

**传输层优化**
- 连接复用：HTTP Keep-Alive、HTTP/2
- 压缩：Gzip、Brotli
- 流式传输：SSE、WebSocket
- 协议选择：HTTP/2、gRPC、QUIC

**网络层优化**
- CDN：内容分发网络

### 3.2 深入理解

#### 连接优化

**连接复用**
- HTTP/1.1 Keep-Alive：复用 TCP 连接，减少握手开销
- HTTP/2 多路复用：多个请求共享一个连接
- 效果：减少连接建立时间（3-RTT：DNS + TCP + TLS）

**连接池**
- 作用：预先建立连接，避免临时创建
- 参数：最大连接数、最大空闲连接、连接存活时间
- 适用场景：微服务调用、数据库连接、HTTP 客户端

**DNS 预解析**
- 作用：提前解析域名，减少 DNS 查询时间
- 实现：`<link rel="dns-prefetch" href="//api.example.com">`
- 效果：节省 20-120ms（DNS 查询时间）

**预连接**
- 作用：提前建立 TCP 连接和 TLS 握手
- 实现：`<link rel="preconnect" href="//api.example.com">`
- 效果：节省首次请求的连接时间

#### 传输优化

**数据压缩**
- Gzip：通用压缩算法，压缩率 60-80%
- Brotli：Google 开发，压缩率比 Gzip 高 20%
- 适用场景：文本数据（JSON、HTML、CSS、JS）
- 不适用：图片、视频（已压缩）

**分片传输**
- 作用：大文件分块传输，支持断点续传
- 实现：Range 请求头
- 适用场景：大文件下载、视频点播

**流式传输**
- 作用：边生成边传输，降低首字节时间（TTFB）
- 实现：Chunked Transfer Encoding、SSE
- 适用场景：LLM 流式输出、实时日志

**协议选择**
- HTTP/1.1：简单场景、兼容性要求高
- HTTP/2：多资源加载、Web 应用
- gRPC：微服务通信、高性能 RPC
- WebSocket：双向实时通信

#### CDN 工作原理

**边缘节点**
- 作用：将内容缓存到离用户最近的节点
- 效果：减少网络延迟、降低源站压力

**回源策略**
- 缓存未命中：从源站获取内容
- 缓存过期：验证内容是否更新
- 主动预热：提前将热点内容推送到边缘节点

**缓存更新**
- 基于 TTL：设置缓存过期时间
- 主动刷新：通过 API 刷新指定内容
- 版本化：URL 带版本号或哈希值

**适用场景**
- 静态资源：图片、CSS、JS、字体
- API 响应：需考虑缓存一致性
- 视频点播：分片缓存

#### 缓存策略

**强缓存**
- Cache-Control: max-age=3600：缓存 1 小时
- 直接使用本地缓存，不发送请求
- 适用场景：静态资源、不常变化的数据

**协商缓存**
- ETag：内容哈希值
- Last-Modified：最后修改时间
- 向服务器验证是否过期，返回 304 则使用缓存
- 适用场景：可能更新的资源

**缓存层次**
- 浏览器缓存：客户端本地缓存
- CDN 缓存：边缘节点缓存
- 应用缓存：Redis、Memcached
- 数据库缓存：查询缓存、结果集缓存

**缓存一致性**
- 写穿（Write-Through）：写入时同步更新缓存
- 写回（Write-Back）：异步更新缓存
- 失效策略：TTL、LRU、主动失效

#### 大文件上传/下载优化

**场景**：处理大文件（如视频、模型文件）

**上传优化：分片上传**
```java
@RestController
@Slf4j
public class FileUploadController {
    
    @Value("${upload.temp.dir:/tmp/uploads}")
    private String tempDir;
    
    // 分片上传
    @PostMapping("/upload/chunk")
    public ResponseEntity<ChunkUploadResponse> uploadChunk(
        @RequestParam("file") MultipartFile file,
        @RequestParam("chunkIndex") int chunkIndex,
        @RequestParam("totalChunks") int totalChunks,
        @RequestParam("fileId") String fileId,
        @RequestParam("fileName") String fileName) throws IOException {
        
        // 创建临时目录
        Path chunkDir = Paths.get(tempDir, fileId);
        Files.createDirectories(chunkDir);
        
        // 保存分片
        Path chunkPath = chunkDir.resolve("chunk_" + chunkIndex);
        file.transferTo(chunkPath.toFile());
        
        log.info("Chunk uploaded: fileId={}, chunk={}/{}", fileId, chunkIndex + 1, totalChunks);
        
        // 所有分片上传完成后合并
        if (chunkIndex == totalChunks - 1) {
            String finalPath = mergeChunks(fileId, fileName, totalChunks);
            return ResponseEntity.ok(new ChunkUploadResponse(true, finalPath));
        }
        
        return ResponseEntity.ok(new ChunkUploadResponse(false, null));
    }
    
    // 合并分片
    private String mergeChunks(String fileId, String fileName, int totalChunks) throws IOException {
        Path chunkDir = Paths.get(tempDir, fileId);
        Path finalPath = Paths.get(tempDir, fileName);
        
        try (FileOutputStream fos = new FileOutputStream(finalPath.toFile())) {
            for (int i = 0; i < totalChunks; i++) {
                Path chunkPath = chunkDir.resolve("chunk_" + i);
                Files.copy(chunkPath, fos);
            }
        }
        
        // 删除临时分片
        Files.walk(chunkDir)
            .sorted(Comparator.reverseOrder())
            .forEach(path -> {
                try {
                    Files.delete(path);
                } catch (IOException e) {
                    log.error("Failed to delete chunk: {}", path, e);
                }
            });
        
        log.info("File merged: fileId={}, path={}", fileId, finalPath);
        return finalPath.toString();
    }
    
    @Data
    @AllArgsConstructor
    static class ChunkUploadResponse {
        private boolean completed;
        private String filePath;
    }
}
```

**下载优化：流式下载**
```java
@RestController
public class FileDownloadController {
    
    // 流式下载（避免 OOM）
    @GetMapping("/download/large-file")
    public ResponseEntity<StreamingResponseBody> downloadLargeFile(
        @RequestParam String filePath) {
        
        File file = new File(filePath);
        if (!file.exists()) {
            return ResponseEntity.notFound().build();
        }
        
        StreamingResponseBody stream = outputStream -> {
            try (InputStream input = new FileInputStream(file)) {
                byte[] buffer = new byte[8192];
                int bytesRead;
                while ((bytesRead = input.read(buffer)) != -1) {
                    outputStream.write(buffer, 0, bytesRead);
                }
            }
        };
        
        return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION, 
                "attachment; filename=" + file.getName())
            .header(HttpHeaders.CONTENT_LENGTH, String.valueOf(file.length()))
            .contentType(MediaType.APPLICATION_OCTET_STREAM)
            .body(stream);
    }
    
    // 支持断点续传
    @GetMapping("/download/resumable")
    public ResponseEntity<StreamingResponseBody> downloadResumable(
        @RequestParam String filePath,
        @RequestHeader(value = "Range", required = false) String rangeHeader) throws IOException {
        
        File file = new File(filePath);
        if (!file.exists()) {
            return ResponseEntity.notFound().build();
        }
        
        long fileSize = file.length();
        long start = 0;
        long end = fileSize - 1;
        
        // 解析 Range 头部
        if (rangeHeader != null && rangeHeader.startsWith("bytes=")) {
            String[] ranges = rangeHeader.substring(6).split("-");
            start = Long.parseLong(ranges[0]);
            if (ranges.length > 1 && !ranges[1].isEmpty()) {
                end = Long.parseLong(ranges[1]);
            }
        }
        
        long contentLength = end - start + 1;
        long finalStart = start;
        
        StreamingResponseBody stream = outputStream -> {
            try (RandomAccessFile raf = new RandomAccessFile(file, "r")) {
                raf.seek(finalStart);
                byte[] buffer = new byte[8192];
                long remaining = contentLength;
                
                while (remaining > 0) {
                    int toRead = (int) Math.min(buffer.length, remaining);
                    int bytesRead = raf.read(buffer, 0, toRead);
                    if (bytesRead == -1) break;
                    
                    outputStream.write(buffer, 0, bytesRead);
                    remaining -= bytesRead;
                }
            }
        };
        
        return ResponseEntity.status(HttpStatus.PARTIAL_CONTENT)
            .header(HttpHeaders.CONTENT_DISPOSITION, 
                "attachment; filename=" + file.getName())
            .header(HttpHeaders.CONTENT_LENGTH, String.valueOf(contentLength))
            .header(HttpHeaders.CONTENT_RANGE, 
                String.format("bytes %d-%d/%d", start, end, fileSize))
            .header(HttpHeaders.ACCEPT_RANGES, "bytes")
            .contentType(MediaType.APPLICATION_OCTET_STREAM)
            .body(stream);
    }
}
```

## 四、网络安全

### 4.1 必知必会

#### HTTPS 为什么安全

**三大安全保障**
- **加密（Encryption）**：防止数据被窃听
  - 使用对称加密（AES）传输数据
  - 即使被截获，也无法解密
- **认证（Authentication）**：防止中间人攻击
  - 通过证书验证服务器身份
  - 确保连接的是真实服务器，不是伪造的
- **完整性（Integrity）**：防止数据被篡改
  - 使用 MAC（Message Authentication Code）校验
  - 任何篡改都会被检测到

**为什么需要 HTTPS**
- HTTP 明文传输，容易被窃听和篡改
- 敏感信息（密码、支付信息）必须加密
- 搜索引擎优先收录 HTTPS 网站
- 浏览器对 HTTP 网站显示"不安全"警告

#### 常见 Web 攻击类型

**SQL 注入（SQL Injection）**
- 原理：通过输入恶意 SQL 代码操纵数据库
- 示例：`username = "admin' OR '1'='1"`
- 危害：数据泄露、数据篡改、数据库被删除

**XSS（跨站脚本攻击，Cross-Site Scripting）**
- 原理：注入恶意脚本到页面，窃取用户信息
- 类型：
  - 存储型：恶意脚本存储在数据库中
  - 反射型：恶意脚本在 URL 中
  - DOM 型：通过修改 DOM 执行脚本
- 危害：窃取 Cookie、劫持会话、钓鱼

**CSRF（跨站请求伪造，Cross-Site Request Forgery）**
- 原理：利用用户身份执行非预期操作
- 示例：用户登录后，访问恶意网站，恶意网站发起转账请求
- 危害：未经授权的操作（转账、修改密码）

**DDoS（分布式拒绝服务攻击）**
- 原理：大量请求耗尽服务器资源
- 类型：
  - SYN Flood：大量 SYN 包耗尽连接队列
  - HTTP Flood：大量 HTTP 请求耗尽服务器资源
- 危害：服务不可用

#### 认证与授权的区别

**认证（Authentication）**
- 定义：验证"你是谁"
- 目的：确认用户身份
- 方式：用户名密码、手机验证码、生物识别
- 示例：登录系统

**授权（Authorization）**
- 定义：验证"你能做什么"
- 目的：控制资源访问权限
- 方式：角色权限、ACL、RBAC
- 示例：管理员可以删除用户，普通用户不能

**流程**
1. 用户登录（认证）
2. 系统验证身份
3. 分配权限（授权）
4. 访问资源时检查权限

### 4.2 深入理解

#### TLS 1.2 vs TLS 1.3

**TLS 1.3 主要改进**

**1. 握手更快**
- TLS 1.2：2-RTT 握手（往返两次）
- TLS 1.3：1-RTT 握手（往返一次）
- 0-RTT 恢复：会话恢复时无需握手

**2. 更安全**
- 移除弱加密算法：RSA 密钥交换、SHA-1、RC4、3DES、CBC 模式
- 强制前向保密（Forward Secrecy）：即使私钥泄露，历史通信也安全
- 加密握手消息：握手过程也加密

**3. 简化配置**
- 减少加密套件选择：从 37 个减少到 5 个
- 降低配置错误风险

**生产建议**
- 优先使用 TLS 1.3
- 最低支持 TLS 1.2
- 禁用 TLS 1.0 和 1.1（已废弃）

#### 证书类型与验证流程

**证书类型**

**1. DV（域名验证，Domain Validation）**
- 验证：只验证域名所有权
- 申请：自动化，几分钟完成
- 价格：免费（Let's Encrypt）
- 适用：个人网站、小型项目

**2. OV（组织验证，Organization Validation）**
- 验证：验证组织身份
- 申请：需要提供企业证明文件
- 价格：付费
- 适用：企业网站

**3. EV（扩展验证，Extended Validation）**
- 验证：最高级别验证
- 申请：严格审核
- 价格：较贵
- 适用：金融、电商等高安全要求场景
- 特点：浏览器地址栏显示绿色企业名称

**证书验证流程**

1. **检查证书有效期**
   - 验证 notBefore 和 notAfter 时间
   - 过期证书无效

2. **验证证书链**
   - 服务器证书 → 中间证书 → 根证书
   - 根证书必须在操作系统或浏览器的信任列表中

3. **检查证书是否被吊销**
   - CRL（证书吊销列表）：下载完整列表，体积大
   - OCSP（在线证书状态协议）：实时查询，更快

4. **验证域名匹配**
   - 检查证书的 CN（Common Name）或 SAN（Subject Alternative Name）
   - 支持通配符：`*.example.com`

#### OWASP Top 10 核心漏洞

**A01: 访问控制失效（Broken Access Control）**
- 问题：未授权访问、越权操作
- 示例：修改 URL 参数访问他人数据
- 防护：严格的权限检查、最小权限原则

**A02: 加密失效（Cryptographic Failures）**
- 问题：敏感数据未加密或使用弱加密
- 示例：明文存储密码、使用 MD5 加密
- 防护：HTTPS、强加密算法、加盐哈希

**A03: 注入攻击（Injection）**
- 问题：SQL 注入、NoSQL 注入、命令注入
- 示例：拼接 SQL 语句
- 防护：参数化查询、输入验证、ORM 框架

**A04: 不安全设计（Insecure Design）**
- 问题：缺少安全控制、设计缺陷
- 示例：无限制的密码重试
- 防护：威胁建模、安全设计模式

**A05: 安全配置错误（Security Misconfiguration）**
- 问题：默认配置、开放端口、详细错误信息
- 示例：使用默认密码、暴露管理后台
- 防护：最小化配置、定期审计

**A06: 易受攻击的组件（Vulnerable and Outdated Components）**
- 问题：使用过期或有漏洞的依赖
- 示例：Log4j 漏洞
- 防护：定期更新依赖、漏洞扫描

**A07: 身份认证失效（Identification and Authentication Failures）**
- 问题：弱密码、会话劫持、凭证泄露
- 示例：无验证码、会话固定攻击
- 防护：强密码策略、MFA、会话管理

**A08: 软件和数据完整性失效（Software and Data Integrity Failures）**
- 问题：供应链攻击、未验证的更新
- 示例：从不可信源下载依赖
- 防护：签名验证、依赖锁定

**A09: 安全日志和监控失效（Security Logging and Monitoring Failures）**
- 问题：无法检测攻击、日志不足
- 示例：不记录登录失败、无告警
- 防护：完善日志、实时监控、告警机制

**A10: 服务端请求伪造（Server-Side Request Forgery, SSRF）**
- 问题：服务器被诱导访问内部资源
- 示例：通过 URL 参数访问内网服务
- 防护：URL 白名单、禁止访问内网 IP

#### JWT 工作原理与安全性

**JWT 结构**
```
Header.Payload.Signature
```

**1. Header（头部）**
```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

**2. Payload（负载）**
```json
{
  "sub": "1234567890",
  "name": "John Doe",
  "iat": 1516239022,
  "exp": 1516242622
}
```

**3. Signature（签名）**
```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

**工作流程**
1. 用户登录，服务器验证身份
2. 服务器生成 JWT，包含用户信息和过期时间
3. 客户端存储 JWT（localStorage 或 Cookie）
4. 后续请求携带 JWT（`Authorization: Bearer <token>`）
5. 服务器验证签名和有效期

**安全问题**

**1. 无法主动失效**
- 问题：JWT 一旦签发，无法撤销
- 解决：
  - 短期有效期（15 分钟）+ Refresh Token
  - 维护黑名单（Redis）
  - 版本号机制

**2. Payload 可被解码**
- 问题：Base64 编码可逆，不要存敏感信息
- 解决：只存用户 ID、角色等非敏感信息

**3. XSS 窃取 Token**
- 问题：存储在 localStorage 容易被 XSS 窃取
- 解决：
  - 存储在 HttpOnly Cookie
  - 实施 CSP（Content Security Policy）
  - 输出编码防止 XSS

**4. 算法混淆攻击**
- 问题：将 RS256 改为 HS256，用公钥作为密钥
- 解决：验证时强制指定算法

### 4.3 生产实战

#### HTTPS 安全配置清单

**场景**：生产环境 HTTPS 部署

**配置清单**
- ✅ 使用 TLS 1.2+ 协议
- ✅ 禁用弱加密套件
- ✅ 启用 HSTS（强制 HTTPS）
- ✅ 配置 OCSP Stapling
- ✅ 设置安全响应头
- ✅ 证书自动续期

**示例（Spring Boot）**：
```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {
    
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            // 强制 HTTPS
            .requiresChannel(channel -> channel
                .anyRequest().requiresSecure())
            
            // 安全响应头
            .headers(headers -> headers
                // HSTS：强制 HTTPS，1 年有效期
                .httpStrictTransportSecurity(hsts -> hsts
                    .includeSubDomains(true)
                    .preload(true)
                    .maxAgeInSeconds(31536000))
                
                // CSP：内容安全策略
                .contentSecurityPolicy(csp -> csp
                    .policyDirectives("default-src 'self'; " +
                        "script-src 'self' 'unsafe-inline'; " +
                        "style-src 'self' 'unsafe-inline'; " +
                        "img-src 'self' data: https:;"))
                
                // X-Frame-Options：防止点击劫持
                .frameOptions(frame -> frame.deny())
                
                // X-Content-Type-Options：防止 MIME 类型嗅探
                .contentTypeOptions(Customizer.withDefaults())
                
                // X-XSS-Protection：XSS 保护
                .xssProtection(xss -> xss.block(true))
                
                // Referrer-Policy：控制 Referer 头
                .referrerPolicy(referrer -> referrer
                    .policy(ReferrerPolicyHeaderWriter.ReferrerPolicy.STRICT_ORIGIN_WHEN_CROSS_ORIGIN)));
        
        return http.build();
    }
}
```

#### SQL 注入防护实践

**场景**：用户输入拼接到 SQL 查询

**错误示例（存在注入风险）**：
```java
// 危险：直接拼接 SQL
String sql = "SELECT * FROM users WHERE username = '" + username + "'";
// 攻击：username = "admin' OR '1'='1"
// 结果：SELECT * FROM users WHERE username = 'admin' OR '1'='1'
```

**正确示例（MyBatis）**：
```java
@Mapper
public interface UserMapper {
    
    // 正确：使用 #{} 参数化查询
    @Select("SELECT * FROM users WHERE username = #{username}")
    User findByUsername(@Param("username") String username);
    
    // 正确：多个参数
    @Select("SELECT * FROM users WHERE username = #{username} AND status = #{status}")
    List<User> findByUsernameAndStatus(
        @Param("username") String username, 
        @Param("status") String status);
    
    // 错误：使用 ${} 直接拼接（存在注入风险）
    // @Select("SELECT * FROM users WHERE username = '${username}'")
    
    // 动态排序需要白名单验证
    @Select("SELECT * FROM users ORDER BY ${orderBy} ${direction}")
    List<User> findAllOrdered(
        @Param("orderBy") String orderBy,
        @Param("direction") String direction);
}

@Service
public class UserService {
    
    @Autowired
    private UserMapper userMapper;
    
    // 白名单验证
    public List<User> findAllOrdered(String orderBy, String direction) {
        // 验证排序字段
        Set<String> allowedColumns = Set.of("id", "username", "created_at", "updated_at");
        if (!allowedColumns.contains(orderBy)) {
            throw new IllegalArgumentException("Invalid order by column: " + orderBy);
        }

        if (!allowedDirections.contains(upperDirection)) {
            throw new IllegalArgumentException("Invalid direction: " + direction);
        }
        
        return userMapper.findAllOrdered(orderBy, upperDirection);
    }
}
```

```java
            .anyMatch(origin -> referer.startsWith(origin));
```

#### API 认证方案选择

**JWT 方案**

**适用场景**
- 无状态 API
- 微服务架构
- 移动端应用

**优点**
- 无需服务端存储
- 跨域友好

**缺点**

```java
@Component
public class JwtTokenProvider {
    
    @Value("${jwt.secret}")
    private String secretKey;
    
    @Value("${jwt.expiration:900000}")  // 默认 15 分钟
    private long validityInMilliseconds;
    
    @PostConstruct
    protected void init() {
        secretKey = Base64.getEncoder().encodeToString(secretKey.getBytes());
    }
    
    // 生成 Access Token
    public String createAccessToken(String username, List<String> roles) {
        Claims claims = Jwts.claims().setSubject(username);
        claims.put("roles", roles);
        
        Date now = new Date();
        Date validity = new Date(now.getTime() + validityInMilliseconds);
        
        return Jwts.builder()
            .setClaims(claims)
            .setIssuedAt(now)
            .setExpiration(validity)
            .signWith(SignatureAlgorithm.HS256, secretKey)
            .compact();
    }
    
    // 生成 Refresh Token（有效期更长）
    public String createRefreshToken(String username) {
        Date now = new Date();
        Date validity = new Date(now.getTime() + 7 * 24 * 60 * 60 * 1000);  // 7 天
        
        return Jwts.builder()
            .setSubject(username)
            .setIssuedAt(now)
            .setExpiration(validity)
            .signWith(SignatureAlgorithm.HS256, secretKey)
            .compact();
    }
    
    // 验证 Token
    public boolean validateToken(String token) {
        try {
            Jws<Claims> claims = Jwts.parserBuilder()
                .setSigningKey(secretKey)
                .build()
                .parseClaimsJws(token);
            
            return !claims.getBody().getExpiration().before(new Date());
        } catch (JwtException | IllegalArgumentException e) {
            return false;
        }
    }
    
    // 从 Token 获取用户名
    public String getUsername(String token) {
        return Jwts.parserBuilder()
            .setSigningKey(secretKey)
            .build()
            .parseClaimsJws(token)
            .getBody()
            .getSubject();
    }
    
    // 从 Token 获取角色
    @SuppressWarnings("unchecked")
    public List<String> getRoles(String token) {
        Claims claims = Jwts.parserBuilder()
            .setSigningKey(secretKey)
            .build()
            .parseClaimsJws(token)
            .getBody();
        
        return (List<String>) claims.get("roles");
    }
}

// JWT 认证过滤器
@Component
@Slf4j
public class JwtTokenFilter extends OncePerRequestFilter {
    
    @Autowired
    private JwtTokenProvider jwtTokenProvider;
    
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    
    @Override
    protected void doFilterInternal(HttpServletRequest request, 
                                    HttpServletResponse response, 
                                    FilterChain filterChain) 
        throws ServletException, IOException {
        
        String token = resolveToken(request);
        
        if (token != null && jwtTokenProvider.validateToken(token)) {
            // 检查黑名单（用于主动失效）
            if (isTokenBlacklisted(token)) {
                response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
                response.getWriter().write("Token has been revoked");
                return;
            }
            
            String username = jwtTokenProvider.getUsername(token);
            List<String> roles = jwtTokenProvider.getRoles(token);
            
            List<GrantedAuthority> authorities = roles.stream()
                .map(SimpleGrantedAuthority::new)
                .collect(Collectors.toList());
            
            UsernamePasswordAuthenticationToken auth = 
                new UsernamePasswordAuthenticationToken(username, null, authorities);
            SecurityContextHolder.getContext().setAuthentication(auth);
        }
        
        filterChain.doFilter(request, response);
    }
    
    private String resolveToken(HttpServletRequest request) {
        String bearerToken = request.getHeader("Authorization");
        if (bearerToken != null && bearerToken.startsWith("Bearer ")) {
            return bearerToken.substring(7);
        }
        return null;
    }
    
    private boolean isTokenBlacklisted(String token) {
        String key = "jwt:blacklist:" + token;
        return Boolean.TRUE.equals(redisTemplate.hasKey(key));
    }
}

@RestController
@RequestMapping("/auth")
public class AuthController {
    
    @Autowired
    private JwtTokenProvider jwtTokenProvider;
    
    @Autowired
    private AuthenticationManager authenticationManager;
    
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    
    @PostMapping("/login")
    public ResponseEntity<TokenResponse> login(@RequestBody LoginRequest request) {
        // 验证用户名密码
        Authentication authentication = authenticationManager.authenticate(
            new UsernamePasswordAuthenticationToken(
                request.getUsername(), 
                request.getPassword()));
        
        SecurityContextHolder.getContext().setAuthentication(authentication);
        
        // 生成 Token
        String username = authentication.getName();
        List<String> roles = authentication.getAuthorities().stream()
            .map(GrantedAuthority::getAuthority)
            .collect(Collectors.toList());
        
        String accessToken = jwtTokenProvider.createAccessToken(username, roles);
        String refreshToken = jwtTokenProvider.createRefreshToken(username);
        
        // 存储 Refresh Token（用于验证）
        redisTemplate.opsForValue().set(
            "jwt:refresh:" + username, 
            refreshToken, 
            7, 
            TimeUnit.DAYS);
        
        return ResponseEntity.ok(new TokenResponse(accessToken, refreshToken));
    }
    
    @PostMapping("/refresh")
    public ResponseEntity<TokenResponse> refresh(@RequestBody RefreshRequest request) {
        String refreshToken = request.getRefreshToken();
        
        if (!jwtTokenProvider.validateToken(refreshToken)) {
            return ResponseEntity.status(HttpStatus.UNAUTHORIZED).build();
        }
        
        String username = jwtTokenProvider.getUsername(refreshToken);
        
        // 验证 Refresh Token 是否匹配
        String storedToken = redisTemplate.opsForValue().get("jwt:refresh:" + username);
        if (!refreshToken.equals(storedToken)) {
            return ResponseEntity.status(HttpStatus.UNAUTHORIZED).build();
        }
        
        // 生成新的 Access Token
        // 这里需要从数据库获取用户角色
        List<String> roles = getUserRoles(username);
        String accessToken = jwtTokenProvider.createAccessToken(username, roles);
        
        return ResponseEntity.ok(new TokenResponse(accessToken, refreshToken));
    }
    
    @PostMapping("/logout")
    public ResponseEntity<Void> logout(@RequestHeader("Authorization") String authHeader) {
        String token = authHeader.substring(7);
        String username = jwtTokenProvider.getUsername(token);
        
        // 将 Token 加入黑名单
        redisTemplate.opsForValue().set(
            "jwt:blacklist:" + token, 
            "revoked", 
            15, 
            TimeUnit.MINUTES);  // Access Token 有效期
        
        // 删除 Refresh Token
        redisTemplate.delete("jwt:refresh:" + username);
        
        return ResponseEntity.ok().build();
    }
    
    private List<String> getUserRoles(String username) {
        // 从数据库获取用户角色
        return List.of("ROLE_USER");
    }
}
```

#### 限流与防刷策略

**场景**：防止恶意请求、保护系统资源

**限流算法**

**1. 令牌桶（Token Bucket）**
- 特点：平滑限流，允许突发流量
- 实现：固定速率生成令牌，请求消耗令牌

**2. 漏桶（Leaky Bucket）**
- 特点：固定速率处理，削峰填谷
- 实现：请求进入队列，固定速率处理

**3. 滑动窗口（Sliding Window）**
- 特点：精确统计时间窗口内请求数
- 实现：记录每个请求时间戳

**单机限流（Guava RateLimiter）**：
```java
@Component
public class RateLimiterService {
    
    // 全局限流：每秒 100 个请求
    private final RateLimiter globalLimiter = RateLimiter.create(100.0);
    
    // 按接口限流
    private final Map<String, RateLimiter> apiLimiters = new ConcurrentHashMap<>();
    
    public boolean tryAcquire() {
        return globalLimiter.tryAcquire(100, TimeUnit.MILLISECONDS);
    }
    
    public boolean tryAcquireForApi(String apiPath, double permitsPerSecond) {
        RateLimiter limiter = apiLimiters.computeIfAbsent(
            apiPath, 
            k -> RateLimiter.create(permitsPerSecond));
        
        return limiter.tryAcquire(100, TimeUnit.MILLISECONDS);
    }
}

@Aspect
@Component
@Slf4j
public class RateLimitAspect {
    
    @Autowired
    private RateLimiterService rateLimiterService;
    
    @Around("@annotation(rateLimit)")
    public Object rateLimit(ProceedingJoinPoint joinPoint, RateLimit rateLimit) throws Throwable {
        String apiPath = joinPoint.getSignature().toShortString();
        
        if (!rateLimiterService.tryAcquireForApi(apiPath, rateLimit.value())) {
            log.warn("Rate limit exceeded for API: {}", apiPath);
            throw new RateLimitExceededException("Too many requests");
        }
        
        return joinPoint.proceed();
    }
}
```

```java
@Component
public class RedisRateLimiter {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    // Lua 脚本：滑动窗口限流
    private static final String SLIDING_WINDOW_SCRIPT = 
        "local key = KEYS[1]\n" +
        "local limit = tonumber(ARGV[1])\n" +
        "local window = tonumber(ARGV[2])\n" +
        "local now = tonumber(ARGV[3])\n" +
        "local clearBefore = now - window\n" +
        "redis.call('ZREMRANGEBYSCORE', key, 0, clearBefore)\n" +
        "local count = redis.call('ZCARD', key)\n" +
        "if count < limit then\n" +
        "    redis.call('ZADD', key, now, now)\n" +
        "    redis.call('EXPIRE', key, window)\n" +
        "    return 1\n" +
        "else\n" +
        "    return 0\n" +
        "end";
    
    // 固定窗口限流（更简单）
    private static final String FIXED_WINDOW_SCRIPT = 
        "local key = KEYS[1]\n" +
        "local limit = tonumber(ARGV[1])\n" +
        "local window = tonumber(ARGV[2])\n" +
        "local current = tonumber(redis.call('GET', key) or '0')\n" +
        "if current < limit then\n" +
        "    redis.call('INCR', key)\n" +
        "    if current == 0 then\n" +
        "        redis.call('EXPIRE', key, window)\n" +
        "    end\n" +
        "    return 1\n" +
        "else\n" +
        "    return 0\n" +
        "end";
    
    // 固定窗口限流
    public boolean isAllowedFixedWindow(String key, int limit, int windowSeconds) {
        DefaultRedisScript<Long> script = new DefaultRedisScript<>();
        script.setScriptText(FIXED_WINDOW_SCRIPT);
        script.setResultType(Long.class);
        
        Long result = redisTemplate.execute(
            script,
            Collections.singletonList(key),
            String.valueOf(limit),
            String.valueOf(windowSeconds)
        );
        
        return result != null && result == 1;
    }
    
    // 滑动窗口限流（更精确）
    public boolean isAllowedSlidingWindow(String key, int limit, int windowSeconds) {
        DefaultRedisScript<Long> script = new DefaultRedisScript<>();
        script.setScriptText(SLIDING_WINDOW_SCRIPT);
        script.setResultType(Long.class);
        
        long now = System.currentTimeMillis();
        
        Long result = redisTemplate.execute(
            script,
            Collections.singletonList(key),
            String.valueOf(limit),
            String.valueOf(windowSeconds * 1000),
            String.valueOf(now)
        );
        
        return result != null && result == 1;
    }
}

// 限流拦截器
@Component
@Slf4j
public class RateLimitInterceptor implements HandlerInterceptor {
    
    @Autowired
    private RedisRateLimiter rateLimiter;
    
    @Override
    public boolean preHandle(HttpServletRequest request, 
                             HttpServletResponse response, 
                             Object handler) throws Exception {
        
        String clientIp = getClientIp(request);
        String uri = request.getRequestURI();
        
        // 全局限流：每个 IP 每分钟最多 60 次请求
        String globalKey = "rate_limit:global:" + clientIp;
        if (!rateLimiter.isAllowedFixedWindow(globalKey, 60, 60)) {
            log.warn("Global rate limit exceeded: ip={}", clientIp);
            sendRateLimitResponse(response);
            return false;
        }
        
        // 接口级限流：每个 IP 每分钟最多 10 次请求
        String apiKey = "rate_limit:api:" + uri + ":" + clientIp;
        if (!rateLimiter.isAllowedSlidingWindow(apiKey, 10, 60)) {
            log.warn("API rate limit exceeded: ip={}, uri={}", clientIp, uri);
            sendRateLimitResponse(response);
            return false;
        }
        
        return true;
    }
    
    private String getClientIp(HttpServletRequest request) {
        String ip = request.getHeader("X-Forwarded-For");
        if (ip == null || ip.isEmpty() || "unknown".equalsIgnoreCase(ip)) {
            ip = request.getHeader("X-Real-IP");
        }
        if (ip == null || ip.isEmpty() || "unknown".equalsIgnoreCase(ip)) {
            ip = request.getRemoteAddr();
        }
        // 处理多个 IP 的情况（取第一个）
        if (ip != null && ip.contains(",")) {
            ip = ip.split(",")[0].trim();
        }
        return ip;
    }
    
    private void sendRateLimitResponse(HttpServletResponse response) throws IOException {
        response.setStatus(429);  // Too Many Requests
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write("{\"error\":\"Rate limit exceeded\",\"message\":\"Too many requests, please try again later\"}");
    }
}
```
